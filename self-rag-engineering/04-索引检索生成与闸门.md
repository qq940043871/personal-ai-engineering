# 04 · 索引、检索、生成与闸门

> 定位：ownrag 的**检索与生成链路设计**——切分、索引、混合检索、直击库、Prompt 管理、两道纯代码闸门、模型矩阵。
> 原理深度（为什么混合检索、chunk 怎么调、幻觉怎么防）**不在此重复**，指向 `../../personal-investment-notes/02-AI智能体/00-知识库/RAG/` 对应桶与 `00-知识库/00-RAG面试实战手册.md`；本档只写"ownrag 怎么实现"。

## 一、切分（结构感知，不是定长硬切）

| 规则 | 设计 | 为什么 |
|---|---|---|
| 标题树切分 | 按 Markdown 标题层级先切大段，段内再按 max_tokens 切 | 章节是文档自带的语义边界 |
| 表格整体 | HTML 表**永不跨块**（超限整块保留或单表独立成块） | 表格切碎=表格报废 |
| 锚点保留 | 每块携带：来源 / 章节路径 / 页码或 `mm:ss` / 行区间 | 引用粒度在切分层固化 |
| 重叠 | 相邻块 overlap（默认 64 token），仅在长段落内部 | 防边界句两边都不完整 |
| 块头增强 | 块首注入"文档标题 > 章节路径"短头 | 裸块在向量空间里缺主语，召回漂移 |
| Excel 特例 | row_card 每行一块；aggregate 每分组一块 | 见 03 文档 §4.2 |

**索引侧决定天花板**（解析 / 切块 / 元数据），切分参数变更必须过评测集回归——没有例外。

## 二、索引（双通道写入，原子替换）

```
块 → embedder（Ollama /api/embed，bge-m3，批量）
   → 向量库 Chroma：collection 按知识库分；metadata 存全部锚点字段（可 where 过滤）
块 → SQLite FTS5：正文 + metadata（BM25 通道；unicode61 不切 CJK，骨架期两侧同函数字符化兜底，jieba 预分词为 M2 增强）
写入：按 doc_id 先删后插（事务内）——重跑 / 增量更新同一条路
版本：内容 hash 变了才重建该 doc；embedding 模型版本变了**全量重建**（跨版本向量不可比，
     混用=静默降召回——RAG 静默故障的头号来源，见 05 文档 §四）
```

- 元数据字段即 03 文档 §1.1 公共字段全集——**入库前定死**，下游过滤不将就。
- 直击库单独建表（不走向量）：见 §四。

## 三、检索（混合召回 → RRF → rerank → 候选池）

```
query（可选：查询改写/扩展——后置到 M3 阶段，先跑通裸链路）
  ① 元数据过滤（先过滤后召回）：知识库/时间/密级 —— 权限在中台执行
  ② 双路召回：向量 top-20 + BM25 top-20
  ③ RRF 融合（k=60）：名次融合不比分数，免去两路分数量纲问题
  ④ rerank（可选）：bge-reranker-v2-m3 外部服务；未启用时 RRF 顺序兜底
  ⑤ 候选池裁剪：宁窄勿宽——宽了就是给模型编造的机会
```

| 设计点 | 决策 | 一句话理由 |
|---|---|---|
| 先过滤后召回 vs 先召回后过滤 | **先过滤**（权限类字段必须前置） | 召回进上下文再被过滤=已泄漏；性能靠元数据索引兜 |
| 向量 / BM25 权重 | RRF 等权起步 | 没有评测集之前调权重都是猜（评测先行原则） |
| top-k | 20/20 → 融合后取 8-10 | 公司口径"宁窄勿宽" |
| 查询改写 | M3 后置 | 先有基线再优化；改写本身会引入新故障面 |

## 四、直击库（高频问题不进 RAG）

三层口径**复用公司设计**（权威版：`../../personal-investment-notes/02-AI智能体/03-业务设计/RAG直击库-方案与治理.md`），ownrag 实现其工程壳：

| 层 | 内容 | ownrag 落点 |
|---|---|---|
| L0 | 标准问 + 标准答（人工维护） | SQLite 表 + 精确/别名匹配 |
| L1 | 同义问泛化（同一答案覆盖变体问法） | embedding 相似度阈值命中 |
| L2 | 待沉淀候选（RAG 答过且用户确认对的问答对） | Q&A 日志回流（§六 trace 表） |

- 命中校验四关（阈值 / 生效期 / 权限 / 答案完整性）在命中后、返回前执行——**直击库答错比 RAG 答错更伤信任**，因为它看起来最权威。
- 收益：高频题零检索零生成成本 + 答案完全可控。

## 五、生成（Ollama + Prompt 版本化）

### 5.1 调用与上下文预算

- 端点：Ollama native `/api/chat`（流式），切换远程模型 = 换 OpenAI 兼容端点配置。
- **上下文预算先算再拼**：`num_ctx` 固定预算 → 系统指令 + 候选块（按 rerank 分配额）+ 历史轮次（可压缩）→ 超预算砍历史不砍证据块。
- 流式：SSE 逐 token 推流；闸门二在**完整答案聚合后**执行——首 token 前推"检索依据"，答案本体后置校验（引用不实时纠偏重答）。

### 5.2 Prompt 版本化（配置即代码）

```yaml
# configs/prompts/policy_strict_v3.yaml
name: policy_strict_v3
system: |
  你只能依据【资料】回答；每个结论标注来源块编号；
  资料不足以回答时，回复"未找到有效依据"并列出已检索路径；不得补写、不得推断。
template: |
  【资料】
  {context_blocks}
  【问题】{question}
  【回答要求】逐条结论 + [来源: 块N]；涉及数字/日期只允许来自资料原文。
```

- Prompt 是**文件进 Git**，改动走 PR；AB = 两版本 + 固定评测集对比（M2 阶段起可执行）。
- 否决"Prompt 存数据库界面改"：单人工程，Git 就是最好的 Prompt 管理台，还免费送历史与回滚。

## 六、两道纯代码闸门（★确定性的事不交给模型）

> 同构公司政策解读两道闸门口径；ownrag 的规则表更短，但**机制完全一致**。

### 闸门一 · 生成前（sufficiency_check）

| 规则 | 动作 |
|---|---|
| 候选池为空 / 最高分低于阈值 | 返回"未找到有效依据"+ 检索路径，**不进模型** |
| 直击库已命中 | 走直击库答案，跳过生成 |
| 候选块时效字段过期 | 剔除过期块；全过期则转"依据已失效"回复 |

### 闸门二 · 生成后（citation_check / schema_check）

| 规则 | 动作 |
|---|---|
| 引用的块编号必须在候选池内 | 引用不实 → 剔除该引用；关键结论失引 → 整体降级重答一次 |
| 数字 / 日期必须能在引用块原文中找到 | 找不到 → 该句剔除（防数字幻觉） |
| 输出结构（JSON 模式时）schema 校验失败 | 带错误反馈重试一次，再败降级模板输出 |

**闸门的本质**：把"模型会错"从故障变成**可测试的规则集**——规则表进 Git、随评测集回归，这就是"确定性的事不交给模型"的工程落地。

## 七、模型矩阵（本地优先，端点中立）

| 用途 | 本地首选（Ollama） | 备选 / 远程切换 | 预算口径 |
|---|---|---|---|
| chat 生成 | qwen 系 7B-8B Q4 | 14B（显存允许）/ 远程 OpenAI 兼容 | ~5-6GB 显存 `【设计】` |
| embedding | bge-m3 | text-embedding 远程 | 常驻 ~1-2GB |
| rerank | ——（Ollama 不支持） | bge-reranker-v2-m3 独立服务（可选组件） | 无服务则 RRF 兜底 |
| ASR | faster-whisper medium | FunASR paraformer-zh / large-v3 | CPU 2-4GB 内存 `【设计】` |
| 解析 VLM 后端 | 按需加载 | MinerU 支持的开源 VLM | 与 chat 抢显存，队列排程 |

**切换纪律**：模型版本（尤其 embedding）是索引兼容性的一部分——换即全量重建，见 §二。
