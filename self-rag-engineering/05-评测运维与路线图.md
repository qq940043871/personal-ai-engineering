# 05 · 评测、运维与路线图

> 定位：ownrag 的**持续变好机制**——评测集、trace 观测、Ollama 运维、失败链路、四阶段路线图、风险清单。
> 原则：**先有基线，才敢报数**；全部指标 `【待实测】`，本档给的是度量口径与验证方法，不是数字。

---

## 一、评测先行（自研路线最大的反超点）

Dify 的召回测试是界面点选；ownrag 的评测是**脚本 + 固定数据集 + 可进 CI**——自研让"每次改动跑一遍回归"成为默认动作。

### 1.1 三类评测资产

| 资产 | 内容 | 产出指标（口径） |
|---|---|---|
| **解析抽取集** | 按类型分桶抽样：电子版 / 扫描件 / 多栏 / 嵌套表 / 长音频 / 带合并单元格 Excel | 解析成功率 = 产出结构可用 Markdown 且表格未破损的比例，**分桶报** |
| **固定问答集** | 每知识库 30-50 题：问题 + 标准答案 + 应命中的块 id | Top-K 命中率 / 空结果率 / 引用准确率（引用块确实含答案） |
| **闸门规则集** | 每条闸门规则的正反例（过期文件、假引用、越权问题） | 规则误杀率 / 拦截有效率 |

### 1.2 评测脚本与用法

```
python scripts/eval_recall.py --qa-set data/eval/policy_qa_v1.jsonl
  → 逐题跑检索链路（不出答案，只测检索）
  → 输出：分库命中率、失配题清单（题 id + 实际召回块）
  → 失配题人工归因 → 切分问题 / embedding 不适配 / 缺关键词通道 / top-k 太小
```

**纪律**：解析脚本 / 切分参数 / embedding 模型 / Prompt 版本——任何一项变更，评测三件套先跑后合。这就是"改好了 A 场景、改坏了 B 场景你不知道"的解法。

## 二、trace 与观测（每步可见）

| 记录 | 字段 | 用途 |
|---|---|---|
| 步骤 trace | trace_id / doc_id / 步骤 / 状态 / 耗时 / 产出计数（页、块、行）/ 错误分类 | 排障：慢在哪、败在哪 |
| 问答日志 | 问题 / 应用 / 命中块 id 列表 / 答案 / 用户反馈（赞/踩+纠错文本） | 评测集扩充 + 直击库 L2 回流 |
| 模型调用计量 | 端点 / 模型 / token in-out / 耗时 / 排队时长 | 成本口径（远程模型即真实费用）+ 并发治理 |

观测的**最低标准**：任何一次"答案不对"，能在 10 分钟内回答三件事——召回给了什么块、模型看到了什么上下文、闸门放过了什么。

## 三、Ollama 运维要点（本地化的真实约束）

| 项 | 配置 / 做法 | 说明 |
|---|---|---|
| 并发 | `OLLAMA_NUM_PARALLEL`（默认按显存自算） | 本地吞吐有限，ownrag 侧另设应用级队列上限，双保险 |
| 常驻 | `OLLAMA_KEEP_ALIVE`：embedding 常驻，chat 按需 | 模型换载是分钟级，embedding 反复加载最伤 |
| 显存挤兑 | chat / VLM / rerank 共享单卡 → 任务队列全局排程 | 见 01 文档 §四；重活错峰是设计不是调优 |
| 量化 | Q4 起步，质量不达标再升 Q5/Q8（逐档评测） | 量化档位变更=chat 侧重测，不动索引 |
| 健康检查 | `/api/tags` 定期探测 + 请求超时熔断 | Ollama 卡死时问答侧快速失败转"稍后重试"，不吊死请求 |

## 四、三条失败链路（每条都要能单独讲）

### A. 解析失败不静默丢文档（同构公司口径）

现象 → 某批 PDF 超时 / 空 Markdown，文档"消失"且安静。处置：失败入待办 + 告警钩子；按类型降级（VLM↔pipeline 互换 → PyMuPDF 纯文本 → 人工）；保留源文件可重跑；批量可续跑。

### B. 检索空结果 / 证据不足

允许"我不知道"：候选不足直接返回"未找到有效依据"+ 检索路径，**不让模型补一段**。空结果率是评测集的固定指标——静默降召回的探针。

### C. RAG 静默故障（升级完悄悄失效）

换 embedding 模型 / 解析器版本 / 切分参数后召回悄悄下降，无人报错。对策：**固定评测集 + 定期召回测试 + 版本升级前后对比**；embedding 版本与向量库 collection 绑定记录，跨版本向量禁止混用。

## 五、四阶段路线图（每阶段有验收，不带数字承诺）

| 阶段 | 范围 | 验收标准（可演示 / 可回归） |
|---|---|---|
| **M1 跑通** | PDF+Excel 两条管道、Ollama chat+embedding、Chroma+FTS5、SSE 问答 | 一份 PDF 与一份 Excel 上传→问答→带引用答案，全程 trace 可查 |
| **M2 管住** | 任务表完整状态机、失败降级链、待办表、评测三件套上线并出**第一版基线** | 解析失败有出口可演示；评测脚本一键出分桶报告 |
| **M3 用好** | 音视频链路（ffmpeg+ASR+时间戳锚点）、直击库三层、两道闸门、查询改写实验 | 音频问答带 `[mm:ss]` 回跳锚点；假引用样本被闸门拦截 |
| **M4 提速** | rerank 服务接入、并发与缓存（高频题直击化）、管理 API 完整化、页面壳（可选） | 并发压测报告（吞吐/排队/首 token 延迟口径）；评测集不回退 |

**当前状态**：设计全量完成；代码骨架落位（`ownrag/`），M1 链路可按 README 起步。基线数字属 M2 产出，现在一概 `【待实测】`。

## 六、风险清单（自研路线的代价，写出来不藏着）

| 风险 | 影响 | 应对 |
|---|---|---|
| **显存墙** | 单卡装不下 chat+VLM+rerank 全家桶 | 模型矩阵按需加载 + 全局队列排程；升档硬件前接受降级链 |
| **ASR 质量长尾** | 口音/噪声段转写错 → 检索与答案带噪 | 低置信度标记；关键语料人工校对；FunASR 切换通道 |
| **MinerU 依赖重** | 版本升级 / 模型下载 / VLM 后端门槛 | 接口化隔离（ParsedDoc）；PyMuPDF 纯文本降级保证"内容总在" |
| **单人维护面宽** | 每个模块的坑都要自己扛 | 模块边界小而清晰；评测集是安全网；**承认这就是自研的代价**（复盘 §3.1 的亲身体感，本身是叙事素材） |
| **无界面运营成本** | 知识库治理靠 API/SQL | 页面壳后置到 M4；配置驱动让治理动作可脚本化 |
| **Excel 列映射错** | 语义映射错 → 检索全错 | LLM 只建议、**人工确认生效**（HITL 卡点）；staging 原表保留可回查 |

## 七、与选型复盘的闭环（讲完工程收这句）
