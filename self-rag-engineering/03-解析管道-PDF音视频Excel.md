# 03 · 解析管道：MinerU PDF / ffmpeg+本地ASR 音视频 / Excel 临时表

> 定位：ownrag 的**数据接入层设计**——三条解析链路 + 统一中间态契约 + 调度与失败兜底。
> 口径：MinerU 四层增强与批量调度兜底的**方法论同构自公司项目**（个人主责环节，见 `../../personal-investment-notes/02-AI智能体/05-项目底稿/ai-project-overview.md` §一 ②④）；本档写的是 ownrag 里如何复刻同一套方法。

---

## 一、统一中间态契约（ParsedDoc）——三条链路的汇合点

> **换解析器不动向量库**的前提：所有解析链路收敛到同一个契约。

```python
# ingest/base.py —— 契约示意
@dataclass
class ParsedDoc:
    doc_id: str
    source_type: str            # pdf | av | excel
    markdown: str               # 统一正文（锚点内嵌，见下）
    metadata: dict              # 公共元数据（见 1.1）
    structures: list[Structure] # 结构清单：表格/图片/公式/关键帧（位置+指针）
    assets: dict[str, str]      # 产物指针：图片/关键帧/字幕文件路径
    stats: dict                 # 页数/时长/行列数/耗时——喂给调度与评测
```

### 1.1 公共元数据字段（入库前定死，不等下游要）

| 字段 | PDF | 音视频 | Excel |
|---|---|---|---|
| 来源标识 | 文号 / 文件名 | 文件名 + 节目标题 | 表名 / sheet 名 |
| 结构路径 | 章节路径（h1-h4 树） | 段落序号 | sheet → 表 → 行区间 |
| 位置锚点 | 页码 | `mm:ss` 时间戳 | 行号区间 |
| 时效字段 | 发布日期 / 有效期（可解析时） | 录制日期 | 数据日期 |
| 版本指纹 | 内容 hash（增量更新与重跑判断） | 同左 | 同左 |

- **锚点即引用**：PDF 答案引用到"第 X 页"、音视频引用到 `[12:34]`（前端可回跳）、Excel 引用到"表 A 第 3-7 行"——引用粒度在解析层就决定了，生成层只是透传。
- 图片 / 关键帧存本地对象目录，Markdown 内嵌位置占位（`![](asset:key)`），检索命中带图回显。

## 二、链路 A：MinerU 识别 PDF

### 2.1 页级路由（双后端）

| 判定 | 后端 | 理由 |
|---|---|---|
| 原生电子版、版式简单 | pipeline（模型无关的版面分析流水线） | 快、稳、CPU 友好 |
| 扫描件 / 多栏 / 嵌套表 / 公式密集 | VLM 后端 | 还原质量高，但慢且占显存 |

- 探测步骤（`detect_pages`）抽样前几页判版式，逐页可覆盖修正（判定错了两头不讨好——该慢的没慢、该准的不准，所以**允许人工在待办里改判重跑**）。
- 全走 VLM 太慢太贵、全走 pipeline 复杂版式错得多——与公司项目同款取舍。

### 2.2 四层增强（复刻口径）

1. **图像预处理**：扫描件超分 / 去噪 / 倾斜矫正（低分辨率直接毁 OCR，先救图再识别）。
2. **双后端页级路由**：上表。
3. **专项增强**：多栏 XY-cut 阅读顺序修复 / 嵌套表二次识别输出 HTML 表 / 公式增强与低置信度回填。
4. **统一 Markdown 中间态**：本档 §一 契约。

> 深度原理与八工具选型对比**不在此重复**，权威版见 `../../personal-investment-notes/02-AI智能体/02-平台工程/minerU复杂PDF识别优化方案与选型分析.md`。

### 2.3 调用形态

- **服务化（推荐长批）**：MinerU 起 HTTP 服务，ownrag 走客户端适配器——显存可独立管理、并发可控。
- **CLI 拉起（省资源档）**：子进程逐文档调用，代价是模型加载开销。
- 两种形态同接口（`parse(file, backend) -> ParsedDoc`），配置切换。

### 2.4 失败兜底（绝不静默丢文档）

```
parse_mineru 失败
  → fallback 链（DSL 声明）：VLM↔pipeline 互换 → parse_pymupdf 纯文本兜底 → fail
  → fail 落待办表 + 告警钩子；保留 source.pdf 可重跑
  → validate（空 Markdown / 页数缺失 / 表格破损计数）独立于 parse 存在：
     "解析成功但产出不可用"与"解析失败"同等待遇
```

- 批量导入：队列分批、按页数估时长、控并发（与 ASR / VLM 共享显存预算）、**可续跑可重入**（幂等键 doc_id+step）。
- 成功口径：产出结构可用的 Markdown **且表格未破损**，按文档类型分桶统计——`【待实测】`。

## 三、链路 B：ffmpeg + 本地语音识别（音视频）

### 3.1 五步流水

```
源文件(mp4/mp3/wav)
  → ① ffprobe 探测：时长/音轨/分辨率（估时长的依据）
  → ② ffmpeg 抽音轨：-vn -ac 1 -ar 16000（ASR 标准输入；视频同时按场景抽关键帧）
  → ③ 本地 ASR 转写（带段级/词级时间戳）
  → ④ 转写整形：说话人分段(可选) → 标点恢复 → 按话题/时长切块(每块 ≤60s)
  → ⑤ ParsedDoc：正文=带 [mm:ss] 锚点的 Markdown；关键帧图挂锚点；字幕文件入 assets
```

### 3.2 本地 ASR 选型（双引擎，配置切换）

| | faster-whisper（主） | FunASR paraformer-zh（中文备选） |
|---|---|---|
| 底座 | CTranslate2 int8，CPU 可跑 | 达摩院 paraformer，中文标点/热词强 |
| 时间戳 | 词级 | 字级 |
| 取舍 | 通用性强、多语种 | 中文专精、VAD+标点一体化 |

- 长音频**按段喂**不整段进显存（VAD 切段）；CPU 档 small/medium 可跑，GPU 档 large-v3。
- ASR 错误是**链路噪声不是静默失败**：低置信度段在 Markdown 上标记（如 `[?12:30]`），检索照常、答案引用时人可自查。
- 视频特有的**画面信息**：关键帧 + OCR（可选步骤）随锚点入库——"画面里的表格"不靠语音转写。

### 3.3 为什么切块按时间不按 token

音视频没有"章节标题"可依附，**时间戳是唯一可靠结构**。块边界对齐自然停顿（VAD 段边界），每块自带起止锚点；检索命中后回跳源视频前后 ±15s 即可人工核验——引用可回跳，是音视频 RAG 可用的底线。

## 四、链路 C：Excel 转临时表（staging）

### 4.1 四步（先落地、再理解、后文本化）

```
① excel_stage：pandas 逐 sheet 读 → SQLite staging 临时表
   规则：全 TEXT 保真落地（不猜类型，类型是推断出来的结论不是前提）
   附加落地：_src_file/_sheet/_rownum 三列溯源
② schema_infer：列名 / 非空率 / 样本值 / 类型推断（数值/日期/枚举/自由文本）
③ column_mapping：列语义映射——LLM 给建议映射（"金额→amount"），**人工在待办确认后生效**
④ textualize：两种策略（按表特征自动选 / 配置指定）
```

### 4.2 两种文本化策略（Excel 进向量库的核心取舍）

| 策略 | 做法 | 适用 |
|---|---|---|
| **row_card 行级卡片** | 每行渲染成一张"字段: 值"卡片文本，一行一块 | 明细查询类："A 公司 3 月的欠款余额" |
| **aggregate 聚合摘要** | 按 key 列分组聚合 → 摘要文本（可先 SQL 后 LLM 润色，数字必须来自 SQL 结果） | 统计类问题："华东区总欠款多少" |

- **数字问题的正确性来自 SQL 不来自向量**：聚合策略里 LLM 只做"问题→SQL→把结果说成人话"，SQL 结果直接进答案（确定性的事不交给模型——同构公司闸门口径）。
- staging 表**保留可查询**：row_card 命中后可回查原行；未来工具网关接"查 staging"即天然获得数据类问答能力。
- 临时表生命周期：随文档版本存续，重跑 = 重建同 schema 新表 + 原子换名。

## 五、调度与失败兜底（三链路共用）

| 机制 | 设计 | 同构来源 |
|---|---|---|
| 任务队列 | SQLite 任务表：状态机 pending→parsing→chunking→indexing→done/failed | 公司批量解析调度方法论 |
| 并发控制 | 全局并发上限 + 按类型预估时长（页数/时长/行列数）排程；解析、ASR、VLM 共享"重活预算" | "按页数与类型估时长、控并发" |
| 重试与幂等 | 步骤级重试（指数退避）；幂等键 doc_id+step；重跑不产生重复索引 | Saga/幂等同构 |
| 待办表 | 一切 fail 的终点是**人工队列**（改判页级路由 / 确认列映射 / 手工处理坏件） | "失败入待办 + 告警" |
| 可观测 | 每步 trace：耗时 / 产出计数（页数/块数/行数）/ 失败原因分类 | trace_id 全链路 |

**失败分类账**（运维视角的必答题）：解析失败 / 解析成功但验证不过 / 切分零块 / 向量化失败 / 索引写入冲突——五类各有出口，没有一类是"丢掉"。
