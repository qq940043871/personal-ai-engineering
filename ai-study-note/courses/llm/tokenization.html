1 什么是 Tokenization

Tokenization（分词）是将原始文本转换为模型可以处理的离散单元（Token）的过程。 它是 NLP 管线的第一步，直接影响模型的理解能力。

示例: "我喜欢学习人工智能" 按字符分词 (Character-level): ['我', '喜', '欢', '学', '习', '人', '工', '智', '能'] → 9 tokens, 每个 token 语义信息少 按词分词 (Word-level): ['我', '喜欢', '学习', '人工智能'] → 4 tokens, OOV (未登录词) 问题严重 按子词分词 (Subword-level): ['我', '喜欢', '学习', '人工', '智能'] → 5 tokens, 平衡语义和 OOV

Tokenization 的核心挑战

  • · OOV 问题：如何处理从未见过的词？
  • · 多语言支持：中英混合、代码、特殊符号
  • · 效率平衡：token 太多效率低，太少语义不足

2 分词策略对比

策略 原理 优点 缺点 代表
字符级 按字符切分 无 OOV，词汇表极小 序列长，语义弱 char-CNN
词级 按空格/标点切分 语义完整 OOV严重，词汇表巨大 Word2Vec
BPE 统计高频字节对合并 平衡OOV和效率 — GPT 系列
WordPiece 概率式合并 更优的合并选择 计算稍复杂 BERT
SentencePiece 直接处理原始文本 语言无关，多语言友好 — LLaMA, T5

3 BPE (Byte Pair Encoding)

BPE 是最常用的子词分词算法，GPT 系列模型的核心选择。 核心思想：从字符开始，反复合并最频繁出现的相邻符号对。

BPE 训练过程示例: 语料: "low lower lowest" 步骤1: 初始化为字符级 'l o w', 'l o w e r', 'l o w e s t' 步骤2: 统计频次，合并最常见对 ('l','o') 出现 3次 → 合并为 'lo' 'lo w', 'lo w e r', 'lo w e s t' 步骤3: 继续合并 ('lo','w') 出现 3次 → 合并为 'low' 'low', 'low e r', 'low e s t' 步骤4: 继续... ('e','r') 出现 1次 → 合并 'er' ('e','s') 出现 1次 → 合并 'es' ('es','t') 出现 1次 → 合并 'est' 最终词表: ['l','o','w','e','r','s','t','lo','low','er','es','est'] 编码 "lowest": 'low' + 'est' → [low, est] (用已学习的子词组合)

4 WordPiece / SentencePiece

WordPiece (BERT)

与 BPE 类似但使用似然概率而非频率来选择合并。选择能使训练数据概率最大化的合并对。

BERT Tokenizer 示例: "playing" → ['play', '##ing'] "player" → ['play', '##er'] "unhappy" → ['un', '##happy'] (## 表示该 token 是前一个 token 的延续)

SentencePiece (LLaMA / T5)

直接在原始字节流上操作，不依赖预分词（如空格分割），天然支持任何语言。

SentencePiece 优势: - 不需要预先分词（语言无关） - 将空格也作为一个 token "▁" 处理 - 可逆编码：token → 原始文本 无信息丢失 - 支持 BPE 和 Unigram 两种算法 LLaMA Tokenizer 示例 (基于 SentencePiece BPE): "Hello World" → ['▁Hello', '▁World'] ("▁" 表示前导空格)

5 什么是 Embedding

Embedding（嵌入）将离散的 Token ID 映射为连续的稠密向量，使语义相似的词在向量空间中距离更近。

Token → ID → Embedding 流程: "我爱学习" ↓ Tokenize [我, 爱, 学习] ↓ Token ID [234, 567, 890] ↓ Embedding Layer (查表) ┌──────────────────────────────┐ │ 我: [0.12, -0.34, 0.56, ...] d=768 │ 爱: [0.78, 0.23, -0.45, ...] d=768 │ 学习: [0.11, -0.67, 0.89, ...] d=768 └──────────────────────────────┘ ↓ 形状: [3, 768] (seq_len=3, d_model=768)

Token Embedding

每个 token 的语义表示。通过 Embedding 矩阵 W_E (vocab_size × d_model) 查表获得。

Positional Embedding

表示 token 在序列中的位置。与 Token Embedding 相加后输入模型。

6 位置编码

Transformer 没有循环结构，无法天然捕获顺序信息，需要通过位置编码告诉模型 token 的位置。

类型 说明 使用模型
正弦位置编码 用 sin/cos 函数生成固定编码，无需学习 Transformer (原始), LLaMA
可学习位置编码 随机初始化，训练中优化 BERT, GPT
RoPE (旋转位置编码) 用旋转矩阵编码相对位置，外推性好 LLaMA, Qwen, ChatGLM
ALiBi 加性线性偏置，外推能力最强 BLOOM

RoPE 旋转位置编码

RoPE (Rotary Position Embedding) - 当前主流方案 核心思想: 通过旋转矩阵为 Q 和 K 向量注入位置信息， 使注意力计算时能感知 token 之间的相对位置。 公式: Q_pos = R(θ · pos) · Q K_pos = R(θ · pos) · K 优点: - 相对位置自然编码（距离越远，旋转角度差越大） - 序列长度外推能力强（训练 4K → 推理 32K） - 计算高效，无需额外参数

7 实战示例

from transformers import AutoTokenizer # 加载 GPT-2 的 BPE Tokenizer tokenizer = AutoTokenizer.from_pretrained("gpt2") # 编码 text = "Hello, 我爱AI!" tokens = tokenizer.tokenize(text) ids = tokenizer.encode(text) print(f"原文: {text}") print(f"Tokens: {tokens}") print(f"IDs: {ids}") print(f"长度: {len(ids)} tokens") # 输出: # 原文: Hello, 我爱AI! # Tokens: ['Hello', ',', 'æ', 'Ī', 'ģ', 'ç', 'Ħ', '±', 'AI', '!'] # IDs: [15496, 11, 232, 140, 163, 121, 196, 177, 9552, 0] # 长度: 10 tokens # 解码回原文 decoded = tokenizer.decode(ids) print(f"还原: {decoded}") # === 不同模型 Tokenizer 对比 === # "我爱学习人工智能" 不同模型的编码长度: # GPT-2 (BPE): ~12 tokens # BERT (WordPiece): ~10 tokens # LLaMA (SentencePiece): ~8 tokens # Qwen (自己的): ~5 tokens (中文优化)

Tokenization 是 LLM 的第一道工序，Embedding 是语义理解的基石！

好的分词器 = 更少 Token + 更好语义 + 更快速度
