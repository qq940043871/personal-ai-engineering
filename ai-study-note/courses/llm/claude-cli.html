1 Claude CLI 整体架构

Claude CLI 的架构设计体现了生产级 Agent 系统的最佳实践。它不是简单的"模型+提示词"封装，而是一个分层解耦、可扩展、可观测的 Agent 运行时。

分层设计

Agent → Harness → Loop → Tools 四层解耦，每层职责清晰，可独立测试和替换。

安全沙箱

所有工具调用经过权限系统过滤，支持 permissive/normal/禁默 三种模式，每次执行都可审计。

可扩展

MCP 协议 + Skills 插件系统使功能可以无限扩展，任何外部能力都能通过标准接口集成。

2 Agent 类型详解

Claude CLI 内置多种专门化 Agent，每种 Agent 针对特定任务类型优化。这体现了"单一职责"的 Agent 设计哲学。

Agent 类型 能力 适用场景
claude 全工具访问，无限制的通用 Agent 编码、调试、重构、架构设计、代码审查
general-purpose 搜索、阅读、Web 获取等研究能力 技术调研、问题定位、多步骤研究任务
Explore 只读：搜索、grep、glob、Glob、WebFetch 代码库探索、架构梳理、命名约定发现
Plan 只读：专注于架构设计与规划 技术方案设计、重构计划、架构评审
code-review 差异分析、代码审查、Bug 检测 PR Review、代码质量审计、安全审查
# 实际使用示例 — 按需选择合适的 Agent 类型 # 通用开发任务 claude "为这个模块添加单元测试" # 只探索不修改 — 理解代码库结构 claude --agent Explore "梳理项目的目录结构和服务依赖关系" # 先做架构设计 — 不写代码 claude --agent Plan "设计一个微服务拆分方案"

3 Harness 执行框架

Harness 是 Claude CLI 的执行引擎核心，负责工具发现、调用路由、权限管控和并发调度。它是 Agent 与底层能力之间的中间层。

工具发现

Harness 自动扫描注册的工具列表，并将 JSON Schema 描述注入到模型上下文。Agent 无需预知工具存在，按需发现使用。

权限过滤

每次工具调用前经过 Permission Manager，支持 Prompt（询问用户）/ Allow（直接放行）/ Deny（拒绝）三级策略。

并发槽位

支持最多 16 个并发 Agent 调用（取决于 CPU 核心数），Workflow 编排时自动管理槽位分配，超出排队。

ToolSearch

延迟加载机制：工具 Schema 按需加载（select / keyword 两种模式），避免一次性注入过多工具占用上下文。

# Harness 的核心数据结构（示意） interface ToolRegistration { name: string; // 工具名，如 "Read", "Edit", "Bash" schema: JSONSchema; // 参数 Schema，用于模型理解 executor: Function; // 实际执行函数 permission: 'prompt' | 'allow' | 'deny'; } // Harness 执行流程 Agent 输出 Tool Call → Harness 解析 → Permission Check ↓ [允许] → 执行 → 返回结果 [拒绝] → 返回权限拒绝消息 [提示] → 等待用户确认

4 Loop 主循环机制

Loop 是 Agent 的"心跳"——它驱动着"思考→行动→观察→再思考"的 ReAct 循环，是 Agent 区别于普通 LLM 调用的关键特征。

Loop 主循环伪代码（ReAct Pattern）: ┌─────────────────────────────────────────────────────────────────────┐ │ while (task_not_complete) { │ │ ① 构造 Prompt（系统消息 + 历史 + 工具定义 + 用户消息） │ │ ② 调用 LLM API → 获取 Response │ │ ③ 解析 Response: │ │ ├─ 文本输出 → 追加到对话历史 │ │ ├─ Tool Call → 进入工具执行子流程 │ │ │ ├─ 查找 Tool 注册 │ │ │ ├─ 权限检查 │ │ │ ├─ 执行 Tool（同步/异步） │ │ │ └─ 将结果追加到对话历史 │ │ └─ Stop Sequence → 结束循环 │ │ ④ 上下文管理: │ │ ├─ Token 计数 │ │ ├─ 超长时摘要历史（Summarization） │ │ └─ 裁切最早消息（Sliding Window） │ │ } │ └─────────────────────────────────────────────────────────────────────┘

上下文管理

当对话超长时自动触发摘要，压缩历史但保留关键信息。支持 Token 精确计数，避免超出模型上下文窗口。

流式输出

支持 SSE 流式响应，用户能实时看到思考过程。工具调用时显示"正在执行..."状态，提升交互体验。

最大步数保护

防止 Agent 陷入无限循环，设有最大 Tool Call 次数上限。达到上限后强制结束，防止 Token 消耗失控。

6 多智能体编排 (Workflow)

Workflow 是 Claude CLI 最强大的特性之一——它允许用 JavaScript 脚本编排多个 Agent 协同工作，实现复杂的多步骤、多智能体协作流程。

🔄 pipeline()

默认模式：每个项目依次经过所有阶段，无屏障等待。A 在阶段2时 B 可能在阶段1——最大化并行度。

⛔ parallel()

屏障模式：等待所有并发任务完成后再继续。适用于需要"全部结果"才能进行下一步的场景。

🎯 agent()

核心单元：启动一个子 Agent，支持 schema 约束输出格式、isolation 隔离执行、model 覆盖指定模型。

📊 budget 控制

总 Token 预算管理：total/spent/remaining 三级控制，支持动态循环（loop-until-budget）。

// Workflow 脚本示例 — 代码审查流水线 export const meta = { name: 'review-changes', description: '多维度审查变更代码', phases: [{ title: 'Review' }, { title: 'Verify' }], } const DIMENSIONS = [ { key: 'bugs', prompt: '审查 Bug 和逻辑错误' }, { key: 'security', prompt: '审查安全漏洞' }, { key: 'perf', prompt: '审查性能问题' }, ] const results = await pipeline( DIMENSIONS, d => agent(d.prompt, { phase: 'Review', schema: FINDINGS_SCHEMA }), review => parallel(review.findings.map(f => () => agent(`验证: ${f.title}`, { phase: 'Verify', schema: VERDICT_SCHEMA }) .then(v => ({ ...f, verdict: v })) )) ) return results.filter(Boolean).flat().filter(f => f.verdict?.isReal)

💡 Workflow 设计模式

  • · Adversarial Verify — 每个发现由多个"怀疑派" Agent 验证，多数通过才保留
  • · Judge Panel — 多个 Agent 从不同角度生成方案，评分合成最优解
  • · Loop-Until-Dry — 持续挖掘直到连续 K 轮无新发现
  • · Multi-Modal Sweep — 不同搜索角度的 Agent 并行探查，覆盖全面
  • · Completeness Critic — 最终 Agent 检查"遗漏了什么"，驱动下一轮迭代

7 记忆与持久化

Claude CLI 实现了文件级持久记忆系统——通过 MEMORY.md 索引和 Markdown 文件存储，在工作会话间保持关键信息的连续性。

用户记忆

角色、专业领域、偏好信息。可持久化跨会话复用，减少重复描述。

反馈记忆

用户对工作方式的纠正和确认，包括"为什么"和"如何应用"，持续优化 Agent 行为。

项目记忆

项目目标、约束、架构决策，从代码和 git 无法直接获取的上下文信息。

# 记忆文件格式 --- name: user-preferences description: 用户偏好和常用设置 metadata: type: user --- 用户是后端工程师，熟悉 Java/Go/Python。 偏好生产级质量的代码，注重可测试性和可维护性。 **Why:** 首次交互中用户明确表达了代码质量要求 **How to apply:** 每次生成代码时自动包含单元测试和错误处理

8 MCP 协议集成

MCP (Model Context Protocol) 是 Anthropic 推出的开放协议，为 LLM 应用提供标准化的工具和上下文接口。Claude CLI 原生支持 MCP，可连接任意 MCP 服务器。

MCP 服务器示例

  • · 文件系统 — 安全受限的文件操作
  • · 数据库 — SQL 查询与 schema 探索
  • · 版本控制 — Git 操作封装
  • · 云服务 — AWS/GCP/Azure API
  • · 飞书集成 — 通过 lark-* skills 连接飞书生态

MCP vs Function Calling

  • · 标准化 — MCP 是开放协议，不绑定具体模型
  • · 动态注册 — 服务启动时声明能力，无需硬编码
  • · 安全边界 — 服务器进程隔离，权限独立管控
  • · 可复用 — 同一 MCP 服务器可被任何 MCP 客户端使用

9 深度分析实战案例

案例一：代码库深度审计

用户请求: "对项目的支付模块进行安全审计" Claude CLI 执行过程: ① [Explore Agent] 探索代码结构 Glob "**/*.java" → 找到 47 个 Java 文件 Grep "payment" "*.java" → 定位支付模块文件 ② [Plan Agent] 制定审计计划 输出审计维度: SQL注入/XSS/权限/金额校验/日志 ③ [claude Agent] 逐维度审查 Read PaymentService.java → 发现金额未做精度校验 Read PaymentController.java→ 发现参数未做 XSS 过滤 Grep "SQL" "Payment*" → 发现拼接 SQL 语句 ④ [Workflow] 多智能体验证 pipeline(发现列表, d => agent("验证: " + d, {schema: VERDICT}), v => agent("修复: " + v, {schema: FIX}) ) ⑤ 生成审计报告 5 个安全漏洞 | 3 个高危 | 2 个中危 | 附修复代码

整个过程中，Claude CLI 自主完成了"探索→规划→执行→验证→报告"的完整审计流程，无需人工干预。

案例二：技术方案调研

用户请求: "对比 Spring AI 和 AgentScope 的架构差异" 执行流程: ① [Explore] 收集信息 - 读取项目中相关的 markdown 文档 - 搜索两个框架的核心概念和设计文档 ② [general-purpose] 深度阅读 - 跨文件对比：架构图、组件、工具系统 - 提取关键差异点 ③ [Plan] 生成对比框架 - 确定对比维度：设计哲学/工具模型/多Agent/部署 - 输出结构化对比表 ④ 合成最终报告 - 完整的差异化分析和选型建议

Claude CLI 的 Explore/Plan 分工使得调研过程既有广度又有深度，最终产出结构清晰的技术对比报告。

案例三：深度研究 Workflow

// deep-research 内置 Skill 的实现模式 export const meta = { name: 'deep-research', description: '多源深度研究：搜索 → 获取 → 验证 → 合成', } // ① 多角度并行搜索 const searches = await parallel([ () => agent("搜索引文1", {schema: SEARCH_RESULTS}), () => agent("搜索引文2", {schema: SEARCH_RESULTS}), () => agent("搜索引文3", {schema: SEARCH_RESULTS}), ]) // ② 获取原文并深度阅读 const sources = await parallel( searches.flat().map(s => () => agent(`获取并阅读: ${s.url}`, {schema: SOURCE_SUMMARY}) ) ) // ③ 对抗验证 const verified = await parallel( sources.map(s => () => agent(`质疑性地验证: ${s.claim}`, {schema: VERIFICATION}) ) ) // ④ 合成带引用的报告 return agent( `合成研究结论，来源: ${verified.filter(v => v.confirmed).map(...)}`, {schema: REPORT} )

这个模式正是 deep-research Skill 的核心逻辑——搜索→阅读→验证→合成的完整研究闭环。

+ 最佳实践：如何用好 Claude CLI 做深度分析

✅ 明确指定 Agent 类型

不需要写代码时主动使用 --agent Explore 或 --agent Plan，避免误操作且更快。

✅ 利用 Workflow 批量分析

面对大规模代码库时，编写 Workflow 脚本实现"多维度并行审查 → 对抗验证 → 综合报告"的流水线。

✅ 持久化关键发现

使用记忆系统保存架构决策和项目约束，让 Agent 从一次分析中学习，在后续会话中复用。

✅ Skills 扩展能力

通过 install 自定义 Skill 封装常用分析流程，如 /security-review、/ deep-research。

⚠️ 注意事项

  • · 深度分析需要多轮交互，预留足够的 Token 预算（可指定 +500k 增加上下文窗口）
  • · 超大代码库建议先用 Explore Agent 梳理结构，再针对性深入
  • · Workflow 并行 Agent 数量受 CPU 核心限制，默认 ~10 并发
  • · 敏感操作（写文件、执行命令）注意权限审核
