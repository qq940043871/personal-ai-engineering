1. Harness 是什么？

核心定义

Harness（工具执行框架）是 AI Agent 与外部工具之间的中间层。它负责：

  • 注册和管理所有可用的工具（Tool Schema）
  • 拦截 AI 发出的工具调用请求
  • 验证参数是否符合 Schema 定义
  • 向用户发起权限确认（Permission Prompt）
  • 执行工具调用并捕获结果
  • 将结果格式化为标准格式回传给 AI
为什么需要 Harness？
1. 安全管控：AI 不能直接执行任意命令，需要权限拦截
2. 标准化：每个工具有自己的接口，Harness 统一包装为标准格式
3. 错误处理：工具执行可能失败，Harness 负责捕获并优雅降级
4. 审计追踪：记录每次工具调用，便于调试和审计

2. Tool Schema 注册中心

工具注册机制

每个工具在 Harness 中注册为一个 Tool Schema，包含元数据、参数定义和执行函数。

Tool Schema 结构：
{
name: "Read", // 工具名称（唯一标识）
description: "读取文件内容", // 功能描述（给 LLM 看）
parameters: { // JSON Schema 参数定义
type: "object",
properties: {
file_path: { type: "string", description: "文件路径" },
},
required: ["file_path"]
},
handler: async (args) => { /* 实际执行代码 */ }
}
注册流程：
1. 定义 Tool Schema（名称、描述、参数、处理函数）
2. 调用 registerTool(schema) 注册到 Harness 的 Schema 注册表
3. Harness 将 Schema 编译为 LLM 可理解的 tool_definition JSON
4. 在 API 请求中注入 tools 参数，LLM 就知道了可用工具
参数校验（Schema Validation）

当 LLM 返回 tool_calls 时，Harness 会做以下校验：

1. 校验工具名称是否已注册
2. 校验参数类型是否正确（string / number / boolean / array / object）
3. 校验必填字段是否缺失
4. 校验枚举值是否合法（如果定义了 enum）
5. 校验参数范围（minLength / maxLength / minimum / maximum）
校验失败 → 返回格式化的校验错误，而不是崩溃

3. 权限管控引擎

权限模型

权限管控是 Harness 最核心的安全机制。它决定了哪些工具调用需要用户确认，哪些可以自动放行。

权限级别：
Allow — 自动放行
读操作（Read、Glob、Grep）默认允许，不弹窗
Prompt — 弹窗确认
写操作（Edit、Write、Bash）默认需要用户确认
Deny — 拒绝执行
危险操作（如 rm -rf、格式化磁盘）被策略禁止
权限决策流程：
1. 检查用户设置（settings.json 中的 allowlist / denylist）
2. 检查项目级设置（.claude/settings.json）
3. 检查会话级设置（用户本次会话中已确认的权限）
4. 如果都不匹配 → 弹窗让用户选择
用户选择：
• Allow — 仅本次允许
• Allow Always — 加入 allowlist，以后自动放行
• Deny — 拒绝此次调用
• Deny Always — 加入 denylist，以后自动拒绝
安全策略示例：
{
"allowlist": [
{ "tool": "Read", "allow": true },
{ "tool": "Bash", "pattern": "npm*", "allow": true }
],
"denylist": [
{ "tool": "Bash", "pattern": "rm -rf /*" }
]
}

策略文件让用户可以预先授权安全操作，减少重复弹窗

4. 工具调用执行流水线

完整执行链路
[LLM] 返回响应
└ content: "我来读取文件内容..."
└ tool_calls: [{
id: "call_abc123",
type: "function",
function: {
name: "Read",
arguments: '{"file_path": "src/main.py"}'
}
}]
↓
Phase 1: 解析 (Parsing)
• 提取 tool_calls 数组
• 解析每个调用的 name 和 arguments
• arguments 是 JSON 字符串 → 解析为对象
• 过滤掉非 function 类型的调用
↓
Phase 2: 校验 (Validation)
• 在 Schema 注册表中查找 name 对应的 Tool Schema
• 用 JSON Schema 校验 arguments
• 类型检查、必填检查、枚举检查、范围检查
• 校验失败 → 返回错误信息，不执行
↓
Phase 3: 权限 (Permission)
• 查询权限策略（allowlist / denylist）
• 匹配模式规则
• 命中 denylist → 直接拒绝
• 命中 allowlist → 直接放行
• 未命中任何规则 → 弹窗让用户选择
↓
Phase 4: 执行 (Execution)
• 调用 handler 函数，传入 validated_args
• 设置超时时间（防止工具卡死）
• 捕获异常（throw、超时、内存溢出）
• 记录执行日志（开始时间、结束时间、耗时）
↓
Phase 5: 回传 (Report)
• 将执行结果包装为 tool_result 对象
• 包含: tool_call_id, role: "tool", content
• 如果执行失败 → 包含 error 信息
• 将 tool_result 追加到消息历史中
• 触发 LLM 继续推理（使用工具结果）
文件状态追踪（File State Tracking）

Harness 还维护一个文件状态跟踪器，记录每次写操作后的文件内容：

// 每次 Edit/Write 成功后，Harness 更新内部缓存
// 下次 Read 同一文件时，可以直接返回缓存内容（无需重新读取磁盘）
// 这保证了对同一文件的多次操作不会丢失中间状态
重要：Edit 操作要求必须先 Read 文件，否则会失败 — 这是 Harness 的强制约束

5. 结果处理与回传

Tool Result 消息格式
成功结果：
{
  role: "tool",
  tool_call_id: "call_abc123",
  content: "文件内容: ..."
}
content 是字符串，直接给 LLM 阅读
错误结果：
{
  role: "tool",
  tool_call_id: "call_abc123",
  content: "Error: 文件不存在: /path/to/file"
}
错误信息被格式化为可读文本，LLM 可以据此调整策略
被拒绝的结果：
{
  role: "tool",
  tool_call_id: "call_abc123",
  content: "Permission denied: 用户拒绝了该操作"
}
终止条件处理：

当工具执行遇到以下情况时，Harness 会终止执行：

- 超时（timeout）：工具执行超过设定的最大时间
- 达到最大 token 限制：工具返回结果太长
- 工具本身抛出异常：handler 内部崩溃
- 用户手动取消：用户点击取消按钮

所有终止情况都被优雅处理，不会导致整个系统崩溃

6. 完整伪代码

// ============================================
// Harness — 工具执行框架 核心伪代码
// ============================================
 
class ToolHarness {
 
// 注册表：存储所有 Tool Schema
schemas = new Map()
permissionStore = new PermissionStore()
fileStateTracker = new FileStateTracker()
 
// ---------- 注册工具 ----------
registerTool(name, description, parameters, handler) {
schema = {
name, description,
parameters: compileJSONSchema(parameters),
handler
}
this.schemas.set(name, schema)
}
 
// ---------- 获取 LLM 可用的 Tool Definitions ----------
getToolDefinitions() {
return Array.from(this.schemas.values())
.map(schema => ({
type: "function",
function: {
name: schema.name,
description: schema.description,
parameters: schema.parameters
}
}))
}
 
// ---------- 核心：执行工具调用 ----------
async executeToolCall(toolCall) {
 
// Phase 1：解析
toolName = toolCall.function.name
rawArgs = JSON.parse(toolCall.function.arguments)
 
// Phase 2：校验 Schema
schema = this.schemas.get(toolName)
if (!schema) {
return { error: `未知工具: ${toolName}` }
}
 
validationResult = validateJSONSchema(
schema.parameters, rawArgs
)
if (!validationResult.valid) {
return { error: `参数校验失败: ${validationResult.error}` }
}
 
// Phase 3：权限检查
permission = await this.permissionStore
.checkPermission(toolName, rawArgs)
 
if (permission === 'deny') {
return { error: "用户拒绝了该操作" }
}
 
// Phase 4：执行
try {
result = await withTimeout(
schema.handler(rawArgs),
this.config.timeoutMs
)
 
// 文件状态追踪（写操作）
if (isWriteOperation(toolName)) {
this.fileStateTracker
.recordWrite(rawArgs.file_path, result)
}
 
// Phase 5：回传
return {
role: "tool",
tool_call_id: toolCall.id,
content: formatResult(result)
}
 
} catch (error) {
return {
role: "tool",
tool_call_id: toolCall.id,
content: `执行失败: ${error.message}`
}
}
}
 
// ---------- 批量执行（并行工具调用） ----------
async executeToolCalls(toolCalls) {
return await Promise.all(
toolCalls.map(tc => this.executeToolCall(tc))
)
}
}

7. 关键点总结

关键点 1：Schema 驱动

一切工具调用都基于 JSON Schema 定义。LLM 通过 Schema 了解工具的用途和参数，Harness 通过 Schema 校验参数的合法性。Schema 是 AI 和工具之间的"契约"。

关键点 2：权限分层

权限系统采用分层设计：全局设置 → 项目设置 → 会话设置 → 单次弹窗。上层优先，命中即终止。这种设计既保证了安全，又避免了频繁弹窗打扰用户。

关键点 3：优雅的错误处理

所有工具执行过程中的错误（参数校验失败、权限拒绝、执行超时、handler 崩溃）都被捕获并格式化为可读文本回传给 LLM，而不是抛出未捕获异常。LLM 可以基于错误信息调整策略重试。

关键点 4：文件状态一致性

Harness 维护文件状态跟踪器，确保 Read → Edit → Read 的链式操作不会丢失中间状态。Edit 前必须 Read 的强制约束保证了文件内容的一致性。

关键点 5：并行执行

LLM 可以一次发出多个工具调用（如同时读取多个文件），Harness 使用 Promise.all 并行执行它们，显著提升效率。但写操作通常串行执行以避免竞态条件。

关键点 6：Tool 与 Tool 的区别

Read/Glob/Grep — 读操作，通常自动放行，返回文件内容
Edit/Write — 写操作，需要权限确认，会触发文件状态追踪
Bash — 命令执行，最敏感，需要严格权限控制
Agent — 子 Agent 调用，需要隔离的工作环境
