0 什么是"普通智能体"？

在 AI Agent 的语境中，"普通智能体" 指的是不依赖超大规模算力、不依赖特定硬件、可在通用 API 上调用的智能体实现。它们通常由以下核心组件构成：

🧠
LLM 大脑
推理与决策核心
🔧
工具集
与环境交互的接口
💾
记忆
短期/长期上下文
🔄
控制循环
决定何时调用什么

核心洞察：不同的实现方式本质上是对这 4 个组件的编排策略不同。选择哪种方式，取决于你的任务复杂度、对延迟的容忍度、以及需要多少可解释性。

1 ReAct 模式 — 推理与行动循环

经典范式 论文: ReAct (ICLR 2023) 易于实现

ReAct = Reasoning + Acting。它让 LLM 在"思考→行动→观察→再思考"的循环中完成任务。每一步，模型输出一个"思考"（Thought）和一个"行动"（Action），然后根据行动结果更新上下文。

Thought → Action → Observation → Thought → ... 循环直到 Final Answer 
# ReAct 伪代码 — 最简实现仅需 ~50 行
def react_agent(prompt, tools, max_steps=10):
    messages = [{"role": "system", "content": system_prompt}]
    messages.append({"role": "user", "content": prompt})

    for step in range(max_steps):
        response = llm.chat(messages, tools=tool_defs)  # ← 模型返回 Thought + Action

        if response.has_final_answer():
            return response.final_answer

        action = parse_action(response)                 # 解析工具调用
        observation = execute_tool(action)              # 执行工具
        messages.append(response)                       # 追加思考+行动
        messages.append({"role": "tool", "content": observation})  # 追加观察

    return "Max steps reached"

优点

  • 实现简单，核心逻辑可写在一页内
  • 每一步可解释（Thought 就是推理链）
  • 灵活适应各种任务类型
  • 无需提前规划，边做边想

缺点

  • 可能陷入循环（同一个错误反复犯）
  • 无全局规划，可能走弯路
  • Token 消耗随步数线性增长
  • 对模型推理能力要求较高

代表框架： LangChain ReAct Agent, AutoGPT (早期), 手写 ReAct Loop

2 Plan & Execute — 先规划后执行

结构化 代表: Plan-and-Solve (ICLR 2023) 适合复杂任务

与 ReAct 的"边想边做"不同，Plan & Execute 将任务分为两个阶段：先由 Planner 制定完整计划，再由 Executor 按计划逐步执行。执行中遇到问题可以反馈给 Planner 调整计划。

🗺️ Planner — 制定计划
1. 搜索数据 → 2. 清洗数据 → 3. 统计分析 → 4. 生成报告
⚡ Executor — 按步执行
✅ 完成 → 输出最终结果
← 遇到错误可回退给 Planner 重新规划

优点

  • 全局视野，避免局部最优
  • 计划可审查、可人工干预
  • 适合长链路、多步骤任务
  • 执行阶段可复用相同 Plan

缺点

  • 计划可能过于理想化（脱离实际）
  • 环境变化时计划失效
  • 两阶段增加延迟
  • 需要额外维护计划状态

代表框架： LangChain Plan-and-Execute Agent, BabyAGI, HuggingGPT

3 Function Calling — 工具调用范式

API 原生 OpenAI / Claude 原生支持 生产首选

Function Calling 是现代 LLM API 原生支持的 Agent 范式。模型在生成回复时，不是输出文本格式的"Action"，而是直接输出结构化的工具调用请求（JSON）。框架负责将工具结果回传给模型。 

// 工具定义（JSON Schema 格式）
const tools = [{
    name: "get_weather",
    description: "获取指定城市的天气",
    parameters: {
        type: "object",
        properties: {
            city: { type: "string", description: "城市名" }
        },
        required: ["city"]
    }
}]

// 调用时传入工具定义
const response = await client.chat.completions.create({
    model: "claude-sonnet-4-6",
    messages: [{ role: "user", content: "北京今天冷吗？" }],
    tools: tools  // ← 模型原生识别工具并调用
})

// 模型的响应可能包含:
// { role: "assistant", content: null, tool_calls: [{
//   function: { name: "get_weather", arguments: '{"city":"北京"}' }
// }] }

优点

  • 模型原生支持，输出格式稳定
  • 无需手工解析文本，可靠性高
  • 支持并行工具调用（同时调多个）
  • 主流模型（GPT/Claude/Gemini）均支持

缺点

  • 依赖 API 原生支持（非通用）
  • 工具定义越多，Token 消耗越大
  • 复杂嵌套工具调用可能出错
  • 模型可能产生幻觉工具调用

代表框架： OpenAI Assistants API, Claude Tool Use, LangChain Tool Calling Agent, Vercel AI SDK

4 Conversation Agent — 对话驱动型

交互式 适合 Chatbot 有状态

对话驱动型 Agent 以多轮对话为核心交互方式。它维护一个对话状态，在每轮对话中判断是否需要调用工具、查询知识库或反问用户澄清。核心差异在于它以对话轮次而非任务步骤为驱动单位。

👤 用户输入 🤔 意图识别 🔧 工具调用 | 💬 直接回复 | ❓ 追问澄清 📦 回复用户
← 每轮对话重复此流程，状态在上下文中累积 →

🔑 关键设计要素

  • 对话状态管理：维护会话历史、用户意图、已收集信息
  • 槽位填充（Slot Filling）：逐步收集完成工具调用所需的参数
  • 主动澄清：信息不足时反问，而非猜测或报错
  • 上下文窗口管理：摘要历史、滑动窗口、丢弃不相关信息
  • 人格与风格：保持一致的回复风格和角色设定

优点

  • 用户体验自然，交互友好
  • 渐进式信息收集，降低单次输入要求
  • 可处理模糊需求，通过澄清逐步明确
  • 适合客服、助手等场景

缺点

  • 非任务最优（对话轮次多）
  • 状态管理复杂
  • 长时间对话容易"迷失"
  • 不适合批量/自动化处理

代表框架： Rasa, Dialogflow, LangChain Conversation Agent, Coze Bot

5 Code Agent — 代码即行动

高自由度 代表: Code Interpreter 需沙箱

Code Agent 的核心思想是让 LLM 生成代码片段（Python、JavaScript、Shell 等），然后由执行环境运行并返回结果。不同于调用预定义工具，代码可以表达任意逻辑，灵活性最高但风险也最大。 

# Code Agent 的典型交互流程

# 用户请求：分析这份销售数据，画个趋势图
User: 帮我分析 sales.csv 的数据趋势

# 模型生成代码
Assistant:
```python
import pandas as pd
import matplotlib.pyplot as plt

df = pd.read_csv('sales.csv')
df['date'] = pd.to_datetime(df['date'])
monthly = df.resample('M', on='date')['revenue'].sum()

plt.figure(figsize=(10, 5))
plt.plot(monthly.index, monthly.values, marker='o')
plt.title('月度营收趋势')
plt.savefig('trend.png')
print(f"最高月: {monthly.idxmax().strftime('%Y-%m')} = {monthly.max():.0f}")
```

# 执行环境返回结果
System:
最高月: 2024-12 = 128000
[图片: trend.png]

优点

  • 表达力最强，无工具数量限制
  • 可处理全新、未见过的任务
  • 生成图表、文件等富输出
  • 适合数据分析、脚本编写

缺点

  • 安全风险最高（代码执行）
  • 需要沙箱隔离环境
  • 生成的代码可能包含 bug
  • 调试困难，错误信息可能不明确

代表框架： OpenAI Code Interpreter (GPT-4), Claude Code, Open Interpreter, NoteBook Agent

6 Multi-Agent — 多智能体协作

高级范式 代表: AutoGen, CrewAI 分布式

Multi-Agent 系统由多个专用 Agent 组成，每个 Agent 有独立的角色、工具、记忆，通过消息传递协作完成任务。常见的协作模式包括：

👑

Orchestrator

一个主 Agent 调度多个 Worker Agent，适合任务分解

Orchestrator → Worker A, B, C
💬

Debate

多个 Agent 辩论/讨论，达成共识，提高决策质量

Agent A ↔ Agent B ↔ Agent C
🔗

Pipeline

流水线式处理，每个 Agent 的输出是下一个的输入

A → B → C → D
# CrewAI 示例 — 多智能体协作写文章
from crewai import Agent, Task, Crew

# 定义 3 个角色
researcher = Agent(role='研究员', goal='收集和分析信息', tools=[search_tool])
writer = Agent(role='写手', goal='撰写清晰的文章')
reviewer = Agent(role='审稿人', goal='检查质量和准确性')

# 定义任务
research_task = Task(description='收集 AI Agent 最新进展', agent=researcher)
write_task = Task(description='撰写技术文章', agent=writer)
review_task = Task(description='审核并修改文章', agent=reviewer)

# 组建团队
crew = Crew(agents=[researcher, writer, reviewer], tasks=[research_task, write_task, review_task])
result = crew.kickoff()  # ← 多 Agent 自动协作完成

优点

  • 分工明确，每个 Agent 专精一项
  • 可模拟真实团队协作流程
  • 辩论模式提高输出质量
  • 系统整体鲁棒性更强

缺点

  • 系统复杂度大幅增加
  • Token 消耗呈倍增长
  • Agent 间协调困难
  • 调试和追踪极具挑战

代表框架： AutoGen (Microsoft), CrewAI, LangGraph, MetaGPT, ChatDev

📋 选型决策指南

1.
快速验证 / 原型： 选 ReAct 或 Function Calling。实现简单，马上能看到效果。
2.
生产级 API 服务： 选 Function Calling。稳定性最好，API 原生支持。
3.
复杂的多步骤任务： 选 Plan & Execute。先规划再执行，步骤可控。
4.
用户交互式应用： 选 Conversation Agent。对话体验最重要。
5.
数据分析 / 自动化： 选 Code Agent。灵活生成代码处理数据。
6.
复杂系统 / 模拟： 选 Multi-Agent。但先问自己：单 Agent 是否真的不够？
