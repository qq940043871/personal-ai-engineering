1. 自回归生成

1.1 什么是自回归生成？

Autoregressive Generation（自回归生成）

核心思想：每次生成一个词，然后把生成的词加到输入中，继续生成下一个词！就像写作文：写完一个词，再写下一个词，直到写完为止。

时间步 0: 输入 [BOS] "今天天气" → 预测 "真"

时间步 1: 输入 [BOS] "今天天气真" → 预测 "好"

时间步 2: 输入 [BOS] "今天天气真好" → 预测 "！"

时间步 3: 输入 [BOS] "今天天气真好！" → 预测 [EOS]（结束）

1.2 自回归生成流程

Step 0：初始化

输入: [BOS] + 用户提示，例如: [BOS] "请写一首关于春天的诗"

↓
Step 1：第一次前向传播
模型输出概率分布：
词表: [春, 夏, 秋, 冬, 风, 花, 雪, 月, ...]
概率: [0.15, 0.05, 0.03, 0.02, 0.20, 0.10, ...]
采样得到: "春"
↓
Step 2：第二次前向传播

新输入: [BOS] "请写一首关于春天的诗" "春" → 采样得到: "风"

↓
Step 3-N：继续生成...

"春风吹绿了柳枝，""桃花朵朵开满园。" ...

↓
终止条件

1. 生成了 [EOS] (End of Sequence) token   2. 达到最大长度限制 (max_length)   3. 其他停止条件

1.3 伪代码实现

def generate(model, prompt, max_length=100):
# 初始化
tokens = tokenize(prompt) # [BOS, w1, w2, ...]
 
for _ in range(max_length):
# 前向传播
logits = model(tokens) # [seq_len, vocab_size]
 
# 取最后一个位置的预测
next_token_logits = logits[-1, :] # [vocab_size]
 
# 采样得到下一个词
next_token = sample(next_token_logits) # 整数
 
# 检查是否结束
if next_token == EOS:
break
 
# 加入序列
tokens.append(next_token)
 
return detokenize(tokens)

2. 解码策略详解

2.1 Greedy Search（贪心搜索）

Greedy Search

策略：每次选择概率最大的词

输入: "今天天气"
时间步 1: 概率分布: {真: 0.4, 很: 0.3, 不: 0.2, 太: 0.1}
选择: "真"（概率最大）
时间步 2: 输入: "今天天气真"，概率分布: {好: 0.5, 棒: 0.3, 差: 0.2}
选择: "好"（概率最大）
优点

简单快速

确定性（每次结果相同）

缺点

容易陷入重复

可能错过更好的整体结果

输出缺乏多样性

Greedy Search 的重复问题：
输入: "从前有座山"
输出: "从前有座山，山里有座庙，庙里有个老和尚，老和尚在给小和尚讲故事，讲的什么故事呢？从前有座山，山里有座庙，庙里有个老和尚，老和尚在给小和尚讲故事，讲的什么故事呢？从前有座山..." (无限循环)

原因：模型学到了这个模式，每次都选择概率最高的词，导致陷入循环！

2.2 Beam Search（集束搜索）

Beam Search

策略：同时保留 top-k 个候选序列，最后选择最优的

示例 (beam_size = 2)：
时间步 0：输入: "今天天气"，候选: [([今天天气], 1.0)]
时间步 1：保留 top-2：
[今天天气真], 0.4
[今天天气很], 0.3
时间步 2：保留 top-2：
[今天天气真好], 0.4 × 0.5 = 0.20
[今天天气真棒], 0.4 × 0.3 = 0.12
最终：选择累计概率最高的序列
优点

考虑全局最优

结果更稳定

缺点

计算量大（beam_size 倍）

仍然缺乏多样性

Beam Search 可视化：
                    [今天天气]
                         |
            ├─────────┟─────────┟
            |                   |
          真(0.4)             很(0.3)
              |                   |
        ├─────┟─────┟     ├─────┟─────┟
        |           |     |           |
      好(0.5)    棒(0.3)   好(0.4)    热(0.3)
        |           |     |           |
      真好(0.20)  真棒(0.12) 很好(0.12) 很热(0.09)
保留 top-2: [真好, 真棒]

3. 采样技术

3.1 为什么需要采样？

问题：Greedy 和 Beam Search 都太确定性了！

用户: "给我讲个笑话"

期望: 每次问都能得到不同的笑话！

但 Greedy 每次都会输出相同的笑话...

解决方案：引入随机性！从概率分布中采样，而不是总是选最大的。

3.2 Temperature（温度参数）

Temperature Scaling
scaled_logits = logits / temperature
probs = softmax(scaled_logits)
Temperature < 1（例如 0.5）：

- 放大差异，让高概率词更突出   - 输出更确定、更保守   - 更容易重复

原始概率: [0.4, 0.3, 0.2, 0.1]
T=0.5: [0.55, 0.25, 0.13, 0.07] ← 更尖锐
Temperature = 1：

- 保持原始概率分布   - 标准采样

Temperature > 1（例如 2.0）：

- 缩小差异，让分布更平坦   - 输出更随机、更有创意   - 可能产生奇怪结果

原始概率: [0.4, 0.3, 0.2, 0.1]
T=2.0: [0.32, 0.28, 0.24, 0.16] ← 更平坦
T = 0.5 (尖锐)

3.3 Top-k Sampling

Top-k Sampling

策略：只从概率最高的 k 个词中采样，其他词概率设为 0

示例 (k = 3)：
原始概率分布（已排序）：
风(0.20) > 春(0.15) > 花(0.10) > 雪(0.08) > 月(0.07) > ...
保留 top-3：风(0.20), 春(0.15), 花(0.10)
重新归一化：
风: 0.20 / 0.45 = 0.44 | 春: 0.15 / 0.45 = 0.33 | 花: 0.10 / 0.45 = 0.22
从这三个词中采样！
优点

避免采样到极低概率的奇怪词 · 保持一定随机性 · k 越小越确定，k 越大越随机

常用值: k = 50, k = 40

3.4 Top-p Sampling (Nucleus Sampling)

Top-p (Nucleus) Sampling

策略：选择概率累计达到 p 的最小词集，从中采样

原始概率分布（已排序）：
风: 0.20 春: 0.15 花: 0.10 雪: 0.08 月: 0.07 夏: 0.05 秋: 0.03 ...
累计: 0.20 → 0.35 → 0.45 → 0.53 → 0.60 → 0.65 → 0.68 → ...

找最小词集使得累计概率 ≥ 0.9：假设需要前 10 个词才能达到 0.9 → 就从前 10 个词中采样！

优点

动态调整候选集大小 · 高确定性时候选集小，低确定性时候选集大 · 比 Top-k 更灵活

常用值: p = 0.9, p = 0.95

3.5 组合策略

实际应用中，通常组合多种策略：

常见配置 1：
Temperature = 0.7 Top-k = 50 Top-p = 0.95
流程：
1. 对 logits 除以 temperature   2. 应用 top-k（只保留前50个）
3. 应用 top-p（只保留累计概率达0.95的）  4. 重新归一化   5. 采样
常见配置 2（更确定）：
Temperature = 0.3 Top-p = 0.9
常见配置 3（更有创意）：
Temperature = 1.2 Top-k = 100 Top-p = 0.99

4. 推理优化技术

4.1 KV Cache（键值缓存）

KV Cache
问题：自回归生成时，每次都要重新计算所有位置的 K 和 V！
时间步 1: 输入 [w₁] → 计算 Q₁, K₁, V₁
时间步 2: 输入 [w₁, w₂] → 计算 Q₁,K₁,V₁, Q₂,K₂,V₂ ← 重复计算！
时间步 3: 输入 [w₁, w₂, w₃] → 全部重新计算... ← 更浪费！
解决方案：缓存已计算的 K 和 V！
时间步 1：
输入: [w₁]   计算: K₁, V₁   缓存: KV_Cache = [(K₁, V₁)]
时间步 2：
输入: [w₂] ← 只输入新词！
计算: K₂, V₂   缓存: KV_Cache = [(K₁, V₁), (K₂, V₂)]
注意力计算: Q₂ × [K₁, K₂]^T × [V₁, V₂]
时间步 3：
缓存: KV_Cache = [(K₁, V₁), (K₂, V₂), (K₃, V₃)]
无 KV Cache：
时间步 1: O(1)
时间步 2: O(2)
时间步 N: O(N)
总复杂度: O(N²)
有 KV Cache：
每个时间步: O(1)
 
 
总复杂度: O(N)
加速：约 N 倍！

4.2 Flash Attention

Flash Attention
问题：标准 attention 需要存储巨大的中间矩阵！
标准实现：
1. 计算 S = QK^T [seq_len, seq_len] ← 大矩阵！
2. S = S / √d_k
3. P = softmax(S) [seq_len, seq_len] ← 又一个大矩阵！
4. O = PV [seq_len, d_k]
对于 seq_len = 8192: S 矩阵: 8192² × 4 bytes = 256 MB，P 矩阵: 256 MB，总共: 512 MB（单个注意力层！）
Flash Attention 的创新：

- 分块计算 (Tiling)：把大矩阵分成小块

- 在 SRAM 中计算小块，避免频繁访问 HBM

- 重新计算而不是存储 (Recomputation)

- 融合 softmax 和矩阵乘法

显存占用从 O(N²) 降到 O(N)

速度提升 2-4 倍

支持更长序列 (32K, 128K, ...)

4.3 量化 (Quantization)

Quantization

目标：用更低位数表示权重，减少显存占用和加速计算

精度对比：
FP32 4 字节/参数 | 7B 模型: 28 GB | 精度最高
FP16 2 字节/参数 | 7B 模型: 14 GB | 常用于训练和推理
INT8 1 字节/参数 | 7B 模型: 7 GB | 推理常用
INT4 0.5 字节/参数 | 7B 模型: 3.5 GB | 极限压缩！
量化方法：
1. Post-Training Quantization (PTQ)：

训练后量化，不需要重新训练 · 简单快速 · 可能损失精度

2. Quantization-Aware Training (QAT)：

训练时就考虑量化 · 精度更好 · 需要重新训练

3. GPTQ, AWQ, GGUF：

先进的量化算法 · INT4 量化效果很好

常用工具：
bitsandbytes: INT8/INT4 量化 GPTQ-for-LLaMA: GPTQ 量化 llama.cpp: GGUF 格式，CPU 推理 AutoGPTQ, AutoAWQ

4.4 其他优化技术

其他推理优化技术
1.
Paged Attention (vLLM)：把 KV Cache 分页管理，支持动态内存分配，大幅提高吞吐量
2.
Speculative Decoding：用小模型快速生成候选，大模型验证，加速 2-3 倍
3.
Continuous Batching：动态调整 batch，提高吞吐量
4.
Multi-Query Attention (MQA)：多个头共享 K 和 V，减少 KV Cache 大小。Llama 2 等模型使用
5.
Grouped-Query Attention (GQA)：MQA 的扩展，平衡效果和效率。Llama 3 使用

5. 批量推理与部署

5.1 批量推理 (Batch Inference)

Batch Inference

单个请求推理 → GPU 利用率低，吞吐量差

批量推理：
请求 1: "翻译: Hello"
请求 2: "翻译: World"
请求 3: "翻译: AI"
[PAD, PAD, 翻, 译, :, H, e, l, l, o]
[PAD, PAD, PAD, 翻, 译, :, W, o, r, l, d]
[PAD, PAD, PAD, PAD, 翻, 译, :, A, I]
一次前向传播处理所有请求！
挑战：

- 不同请求长度不同 → Padding 浪费   - 不同请求生成速度不同 → 需要动态调度

解决方案：

- Continuous Batching (vLLM, TGI)   - 动态添加/移除请求   - 最大化 GPU 利用率
