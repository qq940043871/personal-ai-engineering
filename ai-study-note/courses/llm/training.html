训练流程详解

大语言模型的训练过程通常包含几个关键阶段：预训练、监督微调、人类反馈强化学习。让我们一步步来看！

目录

1. 阶段1：预训练 (Pre-training) 2. 阶段2：监督微调 (SFT) 3. 阶段3：人类反馈强化学习 (RLHF) 4. 训练技术详解 5. 完整训练流程总结

1. 预训练阶段 (Pre-training)

1.1 什么是预训练？

Pre-training（预训练）

目标：让模型从海量文本中学习语言的通用规律

输入数据：大规模互联网文本（书籍、网页、代码、...）例如: GPT-3 训练了 45TB 文本数据！

任务：自监督学习 - 给定上文，预测下一个词 (Next Token Prediction)

1.2 预训练数据准备

原始数据收集：
网页 书籍 代码 论文 社交媒体 新闻 ...
↓
数据清洗和预处理：
- 去重 - 过滤低质量内容 - 隐私处理 - 格式统一 ...
↓
分词处理 (Tokenization)：
"Hello,world!" → [15496, 11, 995, 0]
↓
构建训练数据集：

序列长度: 例如 2048 个token

训练样本: (context, target) → (w₀..w₂₀₄₇, w₁..w₂₀₄₈)

1.3 预训练任务详解

Next Token Prediction（下一词预测）：

输入序列: "The cat sat on the"

↓

模型预测: "mat"

The cat sat on the ?
↓
Transformer
↓
cat: 0.01 dog: 0.02 mat: 0.85 table: 0.03 ...
目标函数 (Loss Function)：
Loss = -log P(w_t | w₀, w₁, ..., w_{t-1})

直观理解：希望模型对真实下一个词的预测概率最大化！

Loss = - Σ_{t=1 to T} log P(w_t | w₀ ... w_{t-1})

1.4 模型学到了什么？

1. 语法知识 (Syntax)- 主语/谓语/宾语关系 - 时态一致 - 词性搭配
2. 语义理解 (Semantics)- 词语含义 - 语义相似度 - 逻辑推理
3. 世界知识 (World Knowledge)- 事实（巴黎是法国首都）- 常识（水在零度结冰）- 常识推理
4. 创作能力 (Writing Skills)- 文章结构 - 风格适配 - 修辞技巧
5. 知识整合 (Knowledge Integration)- 跨领域理解 - 上下文理解 - 逻辑链构建

2. 监督微调阶段 (Supervised Fine-tuning, SFT)

2.1 为什么需要 SFT？

预训练模型虽然很强，但它是一个"通用模型"！

问题：

- 它只会续写文本，不一定"听话"

- 它不一定会用对话格式回答

- 它可能输出不安全或不合适的内容

- 它可能不会遵循指令 (Instruction Following)

解决方案：监督微调！

2.2 SFT 数据收集

构建高质量的指令遵循数据集：

1. 人工撰写：人类专家写的高质量问答对；例如: Alpaca, ShareGPT

2. 收集现有的对话：社交媒体对话、客服聊天记录，过滤和清洗

3. 让模型自生成 (Self-Instruct)：给模型几个例子，让它生成更多，过滤和审核

4. 合成数据 (Synthetic Data)：用 GPT-4 等强模型生成，用脚本生成模式化数据

数据格式：
<system> 你是一个有帮助的AI助手，友好且诚实。</system>
<user> 解释什么是机器学习？</user>
<assistant> 机器学习是...</assistant>

2.3 SFT 训练过程

预训练模型
↓
使用 SFT 数据集训练
Input: <user>问题
Target: <assistant>答案
Loss = -log P(target|input)
↓
SFT 模型（会说话了！）
注意：
  • - 训练步数少（通常几千步）
  • - 学习率小
  • - 目标是对齐，不是重新学习

3. 人类反馈强化学习 (RLHF)

3.1 RLHF 为什么重要？

SFT 模型虽然会听话了，但：

- 输出可能有偏见 (Bias)

- 可能编造事实 (Hallucinations)

- 可能回避问题或绕圈子

- 可能输出不安全内容

- 可能不够有帮助性或友好度不够

因为：用监督信号训练的模型只是模仿数据中的行为！

我们想要的是：让模型学会「人类喜欢的行为」！

3.2 RLHF 完整流程三步曲

3.3 步骤 1：收集人类偏好数据

输入："给我讲一个关于猫的笑话"

生成多个回复：
Response A: 为什么猫喜欢看医生？因为它们有 purr-fect 的视力！
Response B: 猫很可爱，喵~喵~
Response C: 我不会讲笑话。
Response D: 在一个遥远的星球上... [长篇故事]
人类打标：对这些回复进行排序或比较
A > B > D > C
或: A > C
或: B = D (并列)

3.4 步骤 2：训练奖励模型 (RM)

输入
(Prompt, Response)
输出
奖励分数 (scalar value)
训练目标：对于两个回复 r1 和 r2，如果人类偏好 r1 > r2，则：
P( r1 > r2 ) = exp(R(r1)) / [exp(R(r1)) + exp(R(r2))]
训练过程：
SFT Model → 去掉最后的语言模型头，换一个回归头
Loss = - Σ log exp(R_better) / [exp(R_better) + exp(R_worse)]

3.5 步骤 3：PPO 强化学习训练

PPO Training (Proximal Policy Optimization)：

这是 RLHF 中最复杂的一步！

目标：

- 最大化奖励模型的分数

- 同时不要离原始 SFT 模型太远 (KL 惩罚)

1. 对于给定的提示：

SFT Model (Reference) → 参考输出

Policy（正在训练） → 生成当前输出

2. 计算奖励：
R_final = Reward_Model(Output) - β × KL(Policy || SFT_Model)
奖励模型分数        KL散度惩罚（不偏离太远）
3. PPO 更新：

- 使用策略梯度优化 R_final

- 使用 PPO 的 clipped 损失约束步幅

KL 散度 (KL Divergence) 很重要：

KL(Policy || Reference) 衡量两个分布的差异

太大？模型可能"模式崩溃" (mode collapse)

太小？模型可能变化不够快

4. 训练技术详解

4.1 混合精度训练 (AMP: Automatic Mixed Precision)

为什么需要混合精度？

- 32位浮点数占用显存太多 (FP32)

- 训练大模型时显存不够用

- 有些计算单元更快支持 FP16/BF16

精度格式：
FP32(Full Precision): 4字节，高精度
FP16(Half Precision): 2字节，半精度
BF16(BFloat16): 2字节，类似 FP16，但是范围更大
训练流程：
模型权重 (FP32) ← 保持 FP32 作为主权重 (数值稳定)
↓ 复制 / ↑ 梯度累加
前向传播 (FP16/BF16) ← 前向计算用半精度，节省显存
↓
反向传播 (FP16/BF16) ← 梯度计算也用半精度
↓
损失缩放 (Loss Scaling) ← 防止 FP16 underflow
↓
梯度转换回 FP32 ← 用 FP32 优化

显存占用减半！

通常更快！

支持训练更大模型！

4.2 梯度累积 (Gradient Accumulation)

问题：大批次训练会超出显存！

GPU 显存就这么大，批大小（Batch Size）不能无限大

解决方案：梯度累积！
正常训练 (1步 = 1个batch)：

Batch 1 → 前向 → 反向 → 更新权重

Batch 2 → 前向 → 反向 → 更新权重

梯度累积 (4步 = 1个有效batch)：

Batch 1 → 前向 → 反向 → 累积梯度 → 不更新

Batch 2 → 前向 → 反向 → 累积梯度 → 不更新

Batch 3 → 前向 → 反向 → 累积梯度 → 不更新

Batch 4 → 前向 → 反向 → 累积梯度 → 更新权重！

optimizer.zero_grad()
for i in range(gradient_accumulation_steps):
loss = model(batch_i)
loss.backward()
if (i + 1) % gradient_accumulation_steps == 0:
optimizer.step()
optimizer.zero_grad()
效果：用小GPU也能模拟大批次训练！

4.3 分布式训练 (Distributed Training)

大模型必须多卡多机训练！

1. 数据并行 (Data Parallelism, DP/DDP)：
  • - 每个 GPU 有完整模型副本
  • - 每个 GPU 训练不同数据
  • - 聚合梯度 (All-Reduce)
  • - 同步更新所有模型副本
GPU1 GPU2 GPU3 GPU4 → 聚合梯度
2. 张量并行 (Tensor Parallelism, TP)：

模型太大，单个 GPU 放不下，把权重切分到多个 GPU，前向反向时需要通信

3. 流水线并行 (Pipeline Parallelism, PP)：

按层切分模型到不同 GPU，"流水线"式处理数据，类似工厂流水线作业

4. 三维并行 (3D Parallelism)：

数据 + 张量 + 流水线并行，例如 Megatron-LM

4.4 优化器 (Optimizers)

1. AdamW：

Adam + 权重衰减 (Weight Decay)，最常用的默认优化器，稳定、收敛快

Warmup → Cosine Decay → Plateau
2. Lion (Evolved Sign Momentum)：

只用到梯度的符号 (sign(g))，更新更小、性能更好，显存占用更少！

学习率调度过程：
Learning Rate
|
| /↑
| / ↑
|/ ↑
|─────────────────────
|
| Warmup Decay
| 0 5k 100k step

1. Warmup：学习率从0线性增加到目标值

2. Cosine Decay：余弦式下降

3. Plateau：如果不再改进，可能调整或停止

4.5 ZeRO (Zero Redundancy Optimizer)

ZeRO (来自 DeepSpeed) 优化器族。目标：进一步节省显存，支持更大模型！

ZeRO-0 基础优化
ZeRO-1 分割优化器状态 (Shard optimizer states)
ZeRO-2 + 分割梯度 (Shard gradients)
ZeRO-3 + 分割模型参数 (Shard parameters)
效果：显存占用几乎线性降低！在 PaLM、Llama 等训练中都用这个！

5. 完整训练流程总结

5.1 完整训练阶段一览

Phase 0：预训练前 (Pre-Pretraining) （可选）

可能有一些初始化或准备步骤，例如: 训练 tokenizer, 收集数据等

↓
Phase 1：预训练 (Pre-training)

大规模文本数据 | 自监督学习：预测下一个词 | 学习通用知识和能力 | 大规模计算资源 | (模型: GPT-3, Llama, PaLM)

↓
Phase 2：监督微调 (SFT)

高质量指令数据 | 学习对齐 (Alignment) | 学会"听话" | 步数少，学习率小

↓
Phase 3：奖励模型 (RM)

收集人类偏好数据 | 训练 RM: (Prompt, Response) → Reward | 让 RM 学会"人类喜欢什么"

↓
Phase 4：PPO (RLHF)

用 RM 作为奖励训练 SFT 模型 | 加上 KL 惩罚防止偏离 | 可能还有其他技巧 (PPO-max, Rejection Sampling, etc.)

↓
Phase 5：后处理 (Post-Processing)

安全过滤 (Safety Filtering) | 去水印 (Watermarking) | 其他安全措施

↓
模型最终可用！
