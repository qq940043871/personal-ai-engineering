## 一、项目亮点（Project Highlights）

### 1.1 Agent Harness 项目 —— 企业级 LLM 应用框架

**背景与痛点**：企业内部 LLM 应用开发混乱（Prompt 硬编码、工具调用成功率低、无评估体系、生产环境黑盒）。目标：构建统一 Agent 框架，支持多模型、多工具、可观测、可评估。

**六大核心亮点**（面试时按"分层 + 量化"展开）：

```
Client 层（FastAPI + WebSocket + SSE Streaming）
  ↓ 请求接入与流式响应

Infra 层（OpenTelemetry 可观测 + Redis 缓存 + Prometheus 监控）
```

**面试深度追问**：每层职责边界如何划分？
- Client 层：处理用户交互（HTTP/WebSocket），支持 SSE Streaming（首 Token 延迟 TTFT < 200ms）
- Agent 层：核心智能（工具选择、调度、记忆），DAG 调度器用拓扑排序处理工具依赖
- Execution 层：工具执行可靠性（超时、重试、降级），保证"工具调用失败不影响主流程"
- Provider 层：模型抽象（统一接口，支持 Qwen/LLaMA/GLM/Claude），基于难度的动态路由
- Gateway 层：企业级特性（安全、限流、多租户隔离）
- Infra 层：可观测性（Tracing/Metrics/Logging 三位一体）

#### 亮点 2：DAG 动态调度器（依赖感知 + 并行执行）

**问题**：传统串行工具调用（A→B→C）总延迟 = sum(各工具延迟)。实际场景（"查北京天气、查上海天气、比较两城"）中 A、B 可并行。

**方案**：构建工具调用 DAG，拓扑排序分层，同层并行。

```python
def topological_sort(dag):
    # Kahn's Algorithm：输出 [[layer1],[layer2],...] 同层可并行
    in_degree = {n: 0 for n in dag}
    for n, deps in dag.items():
        for d in deps: in_degree[n] += 1
    queue = deque([n for n in dag if in_degree[n] == 0])
    layers = []
    while queue:
        layer = list(queue); layers.append(layer); queue.clear()
        for node in layer:
            for nb in dag:
                if node in dag[nb]:
                    in_degree[nb] -= 1
                    if in_degree[nb] == 0: queue.append(nb)
    return layers
```

**性能**：3 个独立工具延迟 3.6s → 1.2s（-67%）；调度开销 < 5ms；工具调用成功率 +49%（55% → 82%）。

### 1.2 RAG 系统 —— 三代演进

| 版本 | 核心技术 | Recall@10 | 关键突破 |
|------|---------|-----------|---------|
| V1 | ChromaDB + OpenAI Embedding | 42% | 基础可用 |
| V2 | Milvus + BGE-M3 + BM25 混合 + RRF | 68% | 多路召回 |
| V3 | GraphRAG + 自适应 Chunking | 85% | 知识图谱 |

**GraphRAG 核心**：实体抽取 → 子图抽取（max_hops=2）→ PageRank 路径排序。解决传统 RAG "全局视野"缺失（如"通策医疗的竞争对手是谁"需图谱关系）。缺陷：图谱构建成本高、长尾知识缺失。

## 二、技术难点（Technical Difficulties）

### 2.1 Transformer 注意力机制进化：MHA → MQA → GQA → MLA

| 方案 | KV Cache（13B/FP16） | 显存占比 | 质量损失 |
|------|---------------------|---------|---------|
| MHA | 2560 MB | 100% | 0% |
| MQA | 1280 MB | 50% | -1.5% |
| GQA | 1600 MB | 62.5% | -0.5% |
| MLA | 384 MB | 15% | -0.3% |

**MLA（DeepSeek-V3）核心**：K/V 低秩压缩（latent_dim 512 ≪ num_heads×head_dim），推理时只缓存 K_latent/V_latent，计算时再上投影解压，显存 -85%。质量损失小（深层结构补偿信息损失）。

### 2.2 位置编码：RoPE → YaRN

**RoPE 数学核心**：对 Q、K 应用旋转矩阵，使内积只依赖相对位置：
$$<q_m, k_n> = <q, k> \cdot R_{(m-n)}(\theta),\quad \theta_i = 1/\text{base}^{2i/d}$$

**YaRN（长度外推 8x 无损）**：NTK-aware 插值 —— 高频维度保留、低频维度插值，缩放 base：$\text{base}' = \text{base} \cdot (L'/L)^{\alpha}$。

### 2.3 训练稳定性：Loss Spike 根因

学习率过大(40%) / 数据质量差(25%) / 梯度爆炸(15%) / Embedding 不稳定(10%) / 注意力崩溃(5%) / 硬件故障(5%)。排查 SOP：保存检查点 → 查学习率 → 查数据 PPL → 梯度裁剪(1.0) → 查硬件。

### 2.4 KV Cache 工程化：PagedAttention → MLA

传统连续分配利用率 ~60%（40% 碎片）；PagedAttention 分页管理（灵感来自 OS 虚拟内存）利用率 → 92%；MLA 低秩压缩再降 82.6%。

### 2.5 Flash Attention：IO 感知计算

Tiling（分块放入 SRAM）+ Online Softmax（增量更新，无需存整个 S 矩阵）+ Kernel Fusion（HBM 访问 -94%）。加速 3.75x，显存 -66%，长上下文（>2048）收益显著。

## 三、常见问答（Common Interview Q&A）

### Q1：Transformer 为什么用 Attention 而不是 RNN？
1. 序列建模演进：RNN 梯度消失 → LSTM 局部依赖 → Attention 全局依赖
2. 数学：Attention 任意位置依赖 = 1 次矩阵乘法；RNN 需连乘 t 次（梯度消失/爆炸）
3. 并行性：Attention 完全并行，RNN 必须串行（训练快 10-100x）
4. 归纳偏见：Attention 无局部性偏见，数据驱动更灵活
5. 代码级：能手写 Attention 公式与含 Mask/KV Cache 的前向传播

### Q2：LoRA 原理？为何比全量微调高效？
$\Delta W = B \cdot A$（低秩分解，参数量 0.4%）。7B 模型参数量从 16.8M 降到 65K（-99.6%）。变体：QLoRA（4-bit 量化，消费级 GPU 微调 65B）、AdaLoRA（自适应秩）、DoRA（方向+幅度分解）。局限：推理时额外计算（可 merge 消除）。

### Q3：RAG 与 Fine-tuning 如何选？
知识时效（实时→RAG）/ 能力类型（知识密集→RAG，能力密集→FT）/ 可解释（需溯源→RAG）/ 成本（有限→RAG）。混合：RAG + 轻量微调，效果 +10-15%。

### Q4：如何设计百万级用户 LLM 服务？
接入层（LB+JWT）→ 路由层（难度分类 + 语义缓存命中 40%）→ 推理层（vLLM + PagedAttention + Prefix Caching + Continuous Batching）→ 监控层（Prometheus/Grafana）。成本优化：模型路由 -80%、语义缓存 -40%、量化 -50%。

### Q6：MoE 负载均衡如何做？
传统 Auxiliary Loss 影响主任务；DeepSeek-V3 **Auxiliary-Loss-Free**：给每个专家加 bias 项，每 N 步按负载上调/下调 bias（过载 b_i -= ε，欠载 b_i += ε，限幅 |b_i| < δ），无辅助损失、动态均衡。

## 四、3 个针对性模拟面试题（含参考答案要点）

### 模拟题 1：设计一个支持流式输出 + 多轮对话 + 工具调用的生产级 Agent 引擎

**参考要点（分层展开）**：

1. **并发与状态**：多轮对话需会话状态（Session），流式输出用 SSE/WebSocket；同一 Session 内工具调用需串行保证依赖，跨 Session 并行。
2. **工具调用可靠性**：JSON Schema 强校验 + 双模式降级 + 指数退避重试（max_retries=3，2^n 退避）+ 超时熔断。
3. **记忆一致性**：三层记忆（工作/短期/长期），写入前冲突检测，超窗 LLM 摘要。
4. **可观测性**：OTel 全链路 Trace（tool_selection → llm_inference → tool_execution），监控 TTFT/TPOT/成功率。
5. **故障降级**：模型不可用 → 降级小模型；工具失败 → 返回缓存/优雅提示；限流熔断防雪崩。
6. **量化目标**：TTFT < 200ms、成功率 > 82%、P99 < 3s。

**加分项**：能画六层架构图 + 给出 DAG 拓扑排序伪代码 + 说明 TraceId 跨服务传递。

### 模拟题 2：长上下文位置编码长度外推 —— 请从 RoPE 推导到 YaRN

**参考要点（数学推导）**：

1. **RoPE 相对位置性质推导**：旋转矩阵使 $<q_m,k_n>$ 仅含 $(m-n)$，故天然支持相对位置，但训练长度 L 外推到 L' 时高频维度会"混淆"（mθ_i 超 2π）。
2. **NTK-aware 插值**：标准 RoPE 频率 $\theta_i=1/\text{base}^{2i/d}$ 不变导致外推退化；YaRN 将 base 缩放为 $\text{base}'=\text{base}\cdot(L'/L)^{\alpha}$，并做 attention 缩放（temperature scaling）补偿高频信息损失。
3. **效果对比**：RoPE 外推 2x 明显退化；YaRN 8x 几乎无损（困惑度回退 < 5%）。
4. **工程落地**：LLaMA-3 用 YaRN 将 8K 上下文扩到 128K；推理时无需重训，仅改位置编码计算。

**加分项**：能手写 RoPE 旋转矩阵公式 + 解释 NTK（神经正切核）为何对高频保真。

### 模拟题 3：将大模型服务成本从 $1.6M/月 优化到 $300K/月

**参考要点（系统 + 量化）**：

| 优化策略 | 成本节省 | 实施 |
|----------|---------|------|
| 模型路由（80% 流量走 7B） | -80% | BERT 难度分类器 |
| 语义缓存（命中 40%） | -40% | Redis 向量检索 |

**关键权衡**：模型路由以质量 -5~10% 换成本 -80%；量化以精度损失 <2% 换吞吐翻倍。最终：$1.6M → $295K/月（-82%）。
