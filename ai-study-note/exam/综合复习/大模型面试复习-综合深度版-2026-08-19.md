## 二、技术难点（Technical Difficulties）

> 本期聚焦**训练系统工程与对齐**，这是 08-18（架构/推理）之外的第二块核心深水区。

### 2.1 大模型分布式训练：为什么需要 3D 并行？

**单卡瓶颈**：100B 模型 FP16 参数 ≈ 200GB，远超单卡显存；且激活、优化器状态、梯度还需数倍显存。

**三维并行各解决什么**：

| 维度 | 切分对象 | 通信模式 | 解决的核心问题 |
|------|---------|---------|---------------|
| DP（数据并行） | Batch 维度 | All-Reduce 梯度 | 吞吐（多卡同时训不同数据） |
| TP（张量并行） | 权重矩阵 | 层内 All-Reduce | 单卡放不下整层（Megatron 列/行并行） |
| PP（流水线并行） | 层（Stage） | P2P 激活传递 | 单卡放不下整模型（GPipe/1F1B） |

**数学直觉**：
- TP（Megatron）：`Y = X·A·B = (X·A)·B`，`A` 按列切（列并行，各卡算部分隐藏层），`B` 按行切（行并行，各卡算部分输出，最后 All-Reduce 求和）。
- PP 气泡率：`bubble = (p−1)/m`，`p`=流水线 stage 数，`m`=micro-batch 数；用 1F1B 调度填满气泡。

**ZeRO 与 3D 的关系**：ZeRO（零冗余优化器）在 DP 维度进一步切分优化器状态/梯度/参数（ZeRO-1/2/3），与 TP/PP 正交叠加，才能训超大模型。

**MoE 专家并行（EP）**：不同 Expert 放在不同 GPU，Token 经 Router 用 **All-to-All** 分发到目标专家再汇聚——通信量与专家数成正比，是 MoE 训练的主要通信开销。

### 2.2 对齐技术：RLHF / DPO / KTO（本期重点）

**RLHF 三段式**：SFT（监督微调）→ RM（奖励模型训练）→ PPO（强化学习对齐）。

**Reward Model 损失**（Bradley-Terry）：
$$L_{RM} = -\mathbb{E}_{(x,y_w,y_l)}\big[\log \sigma(r_\phi(x,y_w) - r_\phi(x,y_l))\big]$$

**PPO 策略目标**（带 KL 约束，防止偏离 SFT 太远）：
$$L^{PPO} = \mathbb{E}\big[\min(\rho_t \hat{A}_t,\ \text{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat{A}_t)\big] - \beta\, D_{KL}(\pi_\theta\|\pi_{ref})$$
其中 $\rho_t = \pi_\theta(a_t|s_t)/\pi_{ref}(a_t|s_t)$ 为重要性采样比。

**DPO（直接偏好优化，免 RM、免 RL）**：把 RM 用策略与参考策略的比值代换，直接优化：
$$L_{DPO} = -\mathbb{E}\Big[\log \sigma\Big(\beta\big(\log\tfrac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \log\tfrac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\big)\Big)\Big]$$

**KTO（Kahneman-Taleb，支持非配对数据）**：只需"可取/不可取"单条信号，用参考策略概率比 + 数据集规模加权 KL 惩罚 $\lambda$：
$$L_{KTO} = \mathbb{E}_{(x,y)}\Big[\lambda_y - \log\sigma\Big(\beta\,\lambda_y\, \text{KL}\big[\pi_\theta(y|x)\|\pi_{ref}(y|x)\big]\Big)\Big]$$
$\lambda_y>0$ 对应可取样本，反之不可取。

**三者对比**：

| 方法 | 需 RM | 需 RL | 数据要求 | 成本 | 稳定性 |
|------|------|------|---------|------|--------|
| RLHF/PPO | 是 | 是（4 模型同驻） | 配对偏好 | 极高 | 易崩溃 |
| DPO | 否 | 否 | 配对偏好 | 低 | 稳定 |
| KTO | 否 | 否 | 非配对单标签 | 低 | 稳定 |

**深度追问**：PPO 为何要同时加载 4 个模型（policy/ref/value/reward）？→ 显存与通信开销爆炸，是 RLHF 工程化最大痛点，DPO/KTO 正是为此而生。

### 2.3 长上下文：Ring Attention（突破单卡显存上限）

**问题**：上下文 N=1M 时，注意力中间矩阵 O(N²) 与 KV Cache 都远超单卡显存。

**Ring Attention 核心**：将序列维度分块切到多卡，每块只持有局部 Q/K/V；沿"环"依次传递 K/V 块，每块用 **Online Softmax**（增量维护 max/sum_exp）局部计算注意力，通信与计算重叠。

```text
Device i 持有 Q_i；K/V 块沿环传递：
  for step in 0..k-1:
      K_blk, V_blk = ring_recv()          # 从邻居取下一个 K/V 块
      # 局部注意力：Q_i × K_blk，Online Softmax 增量更新
      attn_local(Q_i, K_blk, V_blk) -> 累加到输出 & 维护 running max/sumexp
      ring_send(K_blk, V_blk)             # 传给下一个邻居（与计算重叠）
```

**收益**：显存随卡数线性分摊，可训可推"百万级 token"；通信量 = 2×(N/k)×(d×k) 量级，与序列长度成线性而非平方。配合 **注意力 Sink**（保留首 token KV）与 **分块 Prefix Caching** 落地。

### 2.4 推理引擎：Continuous Batching 与 Prefill/Decode 分离

**Continuous Batching（连续批处理）**：传统静态批处理把所有请求 pad 到最长序列，GPU 大量空转；连续批处理在 decode 每步动态"加入新请求、移除已完成请求"，使 GPU 利用率从 ~40% 提到 ~90%+（vLLM/TensorRT-LLM 标配）。

**Prefill 与 Decode 两阶段分离（Disaggregated）**：
- **Prefill**：一次性算完 Prompt 全部 token 的 KV，计算密集（大矩阵乘）、吞吐高；
- **Decode**：逐 token 生成，访存密集（每步只算 1 个 token 却要读全量 KV）、算术强度极低；
- **为何分离**：两者计算特征迥异，混部时 decode 小 batch 会拖垮 prefill 吞吐；分离后各自独立调度与扩缩容（DistServe 工作），TTFT 与 TPOT 可分别优化。

### 2.5 模型量化：GPTQ vs AWQ

| 维度 | GPTQ | AWQ |
|------|------|-----|
| 原理 | 二阶（Hessian/OBQ）逐层补偿量化误差 | 激活感知，保护"显著权重"（大激活幅值） |
| 精度 | 4-bit 较强，部分任务略降 | 4-bit 保留 outlier 更稳 |
| 成本 | 需校准集 + 较重计算 | 更轻，仅统计激活幅值 |
| 适用 | 通用权重 4-bit | 保护关键通道，边缘/推理友好 |

**KV Cache 量化**：KV 占显存大头（长上下文时），可对 KV 做 INT8/INT4 + 稀疏，进一步放大并发。

## 三、常见问答（Common Interview Q&A）

### Q1：大模型分布式训练为什么需要 3D 并行？各维解决什么问题？
- DP 解决吞吐（多卡训不同数据，All-Reduce 同步梯度），但不降低单卡显存；
- TP 解决"单层放不下"（Megatron 列/行并行，层内 All-Reduce，依赖高速 NVLink）；
- PP 解决"整模型放不下"（切层成 Stage，1F1B 调度，气泡率 (p-1)/m）；
- 三者正交，叠加 ZeRO（在 DP 维切分优化器/梯度/参数）才能训 100B+ 模型。

### Q2：RLHF 完整流程？PPO 损失构成？与 DPO 核心区别？
- 流程：SFT → 训 RM（Bradley-Terry 配对损失）→ PPO 对齐（policy/ref/value/reward 四模型同驻）；
- PPO 损失：clip 后的策略梯度 − β·KL(π_θ‖π_ref)，KL 防偏离 SFT 太远；
- 与 DPO 区别：DPO 用偏好数据直接优化策略（把 RM 用策略比代换），**免 RM、免 RL**，训练成本与稳定性大幅优于 PPO；代价是损失了在线探索与 reward 信号复用。

### Q3：推理时为何要把 Prefill 与 Decode 分离？怎么分离？
- Prefill 计算密集、Decode 访存密集，混部互相拖累；分离后各自独立 batch 调度与扩缩容；
- 实现：prefill 实例只做首轮 KV 生成并写入共享 KV Cache（如分布式 KV 存储），decode 实例按需拉取 KV 流式生成；用 KV 传输/共享机制衔接两阶段。

### Q4：GPTQ 与 AWQ 量化有何区别？各优劣？
- GPTQ 用二阶信息逐层补偿误差，4-bit 通用性强但对校准集敏感、计算重；
- AWQ 仅保留"显著权重"（大激活通道）高精度，其余量化，更轻更稳、适合推理部署；
- 选择：追求极致压缩用 GPTQ，追求部署简便与稳定性用 AWQ；长上下文必做 KV 量化。

### Q5：100 万 token 长上下文的训练/推理瓶颈如何突破？
- 训练：Ring Attention 分块 + Online Softmax，序列维切多卡、K/V 环传递、通信计算重叠，显存线性分摊；
- 推理：分块 Prefix Caching + 注意力 Sink（保首 token）+ 分页 KV（PagedAttention）+ KV 量化；
- 位置编码：RoPE 系需 NTK-aware（YaRN）外推，避免高频混淆。

### Q6：微调时灾难性遗忘怎么解决？
- 架构侧：LoRA/QLoRA 冻结底座只训低秩增量，遗忘极小；
- 数据侧：旧任务回放（replay buffer）+ 多任务混合配比；
- 正则侧：EWC（Fisher 信息加权重要参数）+ KL 约束对齐 SFT；
- 训练侧：低学习率 + Warmup + 指令数据多样性。

## 四、3 个针对性模拟面试题（含参考答案要点）

### 模拟题 1：从零设计一个支持 1M token 上下文的 LLM 推理系统

**参考要点（分层展开）**：
1. **显存拆解**：1M token 的 KV Cache ≈ 2·N·L·d·2Byte（BF16），远超单卡，必须分布式 + 量化。
2. **分块 KV + PagedAttention**：KV 按 block 分页，跨请求共享 Prefix（System Prompt / 长文档前缀），利用率从 ~60%→92%。
3. **Ring Attention（训练/长 prefill）**：序列切多卡，Online Softmax 增量 + K/V 环传递，通信计算重叠。
4. **注意力 Sink**：保留首 token KV（避免长文本早期信息被驱逐导致困惑度飙升）。
5. **位置编码外推**：RoPE + YaRN（NTK-aware）将训练长度外推到 1M，免重训。
6. **调度**：Prefill/Decode 分离；prefill 大 batch 算 KV 落共享存储，decode 流式生成。
**量化目标**：单请求峰值显存 < 单卡 80GB（靠分页+量化+分块达成）；TTFT 随 prefill 批大小可控。

**加分项**：能算 1M token 的 KV 字节数并说明"为何必须量化 + 分页 + 分块三者缺一不可"。

### 模拟题 2：设计一个完整的 RLHF 对齐训练流水线，并说明如何降本

**参考要点（系统 + 量化）**：
1. **标准 RLHF**：SFT → RM(BT 损失) → PPO(4 模型同驻：policy/ref/value/reward)。
2. **成本黑洞**：PPO 需 4 份模型显存 + 高频交互采样，单步成本极高（约 SFT 的 5-10x）。
3. **降本路径**：
   - 用 **DPO/KTO** 替代 PPO：免 RM、免 value、免在线采样，单策略+参考策略即可，成本降一个数量级；
   - **Reward Model 蒸馏**：用强 RM 给无标注数据打分成"伪偏好"扩充训练集；
   - **Rejection Sampling（RAFT）**：先采样多条，只保留高分样本做 SFT，近似 RL 效果但无 RL 开销；
   - **参数高效**：对齐阶段用 LoRA 而非全量，显存 -90%。
4. **质量保障**：保留小批量 PPO 做最终精调 + 在线 A/B 评估（CSAT/任务完成率）。
**权衡**：DPO 省成本但失去在线探索；关键业务用"DPO 粗对齐 + 少量 PPO 精修"混合。

**加分项**：能手写 PPO 与 DPO 损失公式并解释 KL 项作用与 β 取值直觉。

### 模拟题 3：设计一个训练 100B 模型的千卡分布式训练系统

**参考要点（系统 + 容错 + 通信）**：
1. **并行策略组合**：TP（机内 NVLink，切大层）+ PP（切 Stage，1F1B 降气泡）+ DP（跨机，ZeRO-2 切梯度）+ EP（MoE 专家切卡，All-to-All 分发）。
2. **显存预算**：100B BF16 参数 200GB，+ 梯度 200GB + 优化器(AdamW) 1.2TB → 必须 ZeRO-3 + 分片 + 激活重算（activation recomputation，用时间换显存）。
3. **通信优化**：机内 NVLink（900GB/s）走 TP；机间 InfiniBand（400Gbps）走 DP All-Reduce；梯度用 **通信计算重叠（overlap）** + 梯度分桶（bucket）。
4. **故障容错**：Checkpoint 异步落盘（每 N 步）+ 弹性恢复（节点挂掉从最近 ckpt 续训）+ 健康检查（NCCL watchdog）。
5. **稳定性**：Loss Spike 监控（突增 10x 即存 ckpt→查 LR/数据→回滚）；Gradient Clipping(1.0)。
**量化**：千卡（A100 80GB）经 3D 并行 + ZeRO-3 + 激活重算可训 100B；MFU 目标 40-50%（其余耗在通信与空泡）。

**加分项**：能算 3D 并行下的通信量、说明"为何 TP 放机内、DP/PP 跨机"，以及气泡率公式 (p-1)/m。
