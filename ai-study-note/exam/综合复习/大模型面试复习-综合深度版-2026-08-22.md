## 📌 一、项目亮点（Project Highlights）

### 1.1 旗舰示例：Agent Harness（企业级多 Agent 应用框架）

> 前四期已分别补充了六层架构、多模态工具接入等视角。本期补充**LLMOps 可观测与评测闭环**这一生产级视角——这是 Agent 从"能跑"到"敢上生产"的关键分水岭。

**六层架构（速记，全链路插桩贯穿）**：
```
L6 Infra    多集群GPU / K8s / 对象存储 / 向量库
L5 Gateway  限流·熔断·鉴权·灰度·多租户配额·计费埋点
L4 Provider 模型路由·KV复用·投机解码·量化·负载均衡
L3 Exec     工具注册中心·约束解码·依赖DAG·重试兜底
L2 Agent    Planner·Reflector·Memory·RAG·Guardrail
L1 Client   Web/App/API·流式SSE·断点续传
   ↕ 全链路 OpenTelemetry Tracing + Metrics + Online Eval（本期重点）
```

**本期核心新增亮点：LLMOps 可观测与评测闭环（Observability & Evaluation Loop）**

把"评测"和"可观测"当作一等公民内建进框架，而不是上线后补课：

1. **全链路分布式追踪（Tracing）**
   - 每个请求生成一条 Trace，按 `request → planner → {llm_call | tool_call | rag_retrieve}* → reflector` 展开为嵌套 Span；
   - 每个 LLM Span 记录 `model / prompt_version / token_in / token_out / cost / latency / finish_reason / 采样参数`；
   - 每个 Tool Span 记录 `tool_name / args / 返回大小 / 错误码`；RAG Span 记录 `query / 召回top-k / 命中doc_id / 相似度分`；
   - 跨 Span 做 **token 与成本分摊**（按 DAG 节点归属到具体任务），支撑"单次任务成本"精确核算。

2. **在线评测（Online Eval）与回归卡点**
   - **LLM-as-Judge**：用强模型对输出打分（正确性/有用性/安全性），但做了**偏置校正**（见 2.2）；
   - **Golden Set 回归门禁**：每次 prompt / 模型 / 路由变更，自动跑固定黄金集（500+ 条覆盖边界 case），指标回退超阈值则 CI 卡住，禁止发布；
   - **Human-in-the-loop**：低置信度样本（Judge 分数方差大 / 触发 guardrail）自动回流人工标注，标注结果反哺 Judge 校准与训练。

3. **SLI / SLO 体系**
   - 成功率（任务级 `success`）、P99 首 Token 延迟、幻觉率（faithfulness < 阈值占比）、单任务成本（$）四大黄金 SLI；
   - 例：任务成功率 SLO ≥ 89%、P99 TTFT ≤ 0.9s、幻觉率 ≤ 3%、单任务成本 ≤ $0.30。

**量化成果（生产数据，与前四期一致）**：工具调用成功率 55%→92%、端到端任务成功率 61%→89%、推理综合成本 $1.00→$0.29（-71%）、P99 首 Token 2.8s→0.9s；上线后通过 Golden Set 卡点拦截了 3 次会致业务指标下跌的 prompt 回退。

## 📌 二、技术难点（评测与可观测 8 大共性难点 + 解决方案）

### 2.1 离线指标与线上体验的"鸿沟"
**现象**：离线 benchmark（MMLU / GSM8K）刷得高，上线后用户投诉、业务指标却跌。
**根因**：
- 离线集是"考试题"（单轮、静态、分布固定），线上是"真实工作"（多轮、有噪声、分布漂移）；
- 优化目标错位：为刷分过拟合评测集（数据泄漏/题海训练），牺牲通用能力；
- 缺乏**业务代理指标**（如"任务一次解决率""用户重试率"）。
**解决方案**：
- 离线只做**准入**与**回归卡点**，不做终判；线上用 A/B + 业务指标（留存、转化、返工率）做终判；
- 建**线上代理指标**（proxy metrics）：guardrail 触发率、用户编辑/重试次数、负反馈率，作为早期信号；
- 离线集定期**去污染 + 换新**（见 2.6）。

### 2.2 LLM-as-Judge 的偏置（位置/长度/自我/Verbosity）
**现象**：用 GPT-4 给两个回答打分，交换 A/B 顺序后结论反转；长回答、与 Judge 风格相近的答案更易得高分。
**四类偏置**：
- **位置偏置（Position bias）**：倾向给第一个/特定位置的答案打高分；
- **长度偏置（Verbosity/Length bias）**：越长越啰嗦分越高；
- **自我偏好（Self-enhancement bias）**：Judge 给"像自己写的"答案更高分；
- **权威/格式偏置**：带引用、分点、JSON 结构的答案被高估。
**解决方案（工程落地）**：
1. **Pairwise + 顺序交换**：同一对回答跑两次（A→B 与 B→A），仅当两次一致才采信，否则标记低置信；
2. **多次采样取众数 / 置信区间**：对单条评测采样 N=5~10 次，用分数方差衡量不确定性；
3. **Rubric-based 评分**：给定明确 rubric（正确性占 40%、有用性 30%、安全 30%），减少自由发挥；
4. **Judge 校准**：用人工标注集构造校准集，定期算 Judge 与人工的 Cohen's κ / 相关系数，低于阈值则换更强 Judge 或微调 Judge；
5. **Length-controlled win rate**：用参考模型（如 GPT-4 基线）做长度归一，报告 `length-controlled WR`（Llama 2/3 论文做法）。

### 2.3 RAG 评测的"检索-生成"解耦
**现象**：回答错误时，分不清是"没召回到"还是"召回到了但没用好"。
**解决方案（RAGAS 框架）**——把质量拆成可独立归因的三类指标：
- **Context Relevance（上下文相关性）**：召回文档与问题的相关度，`= 被判定相关的句子数 / 总句子数`；
- **Faithfulness（忠实度/无幻觉）**：答案是否仅由上下文支撑，用 NLI 或"陈述句分解+回溯"算 `忠实陈述 / 总陈述`；
- **Answer Relevance（答案相关性）**：答案是否切题，用"以答案为条件生成问题，再看与原问题相似度"的反向方式度量。
> 诊断口诀：**Context 低=检索问题；Faithfulness 低=生成幻觉；Answer 低=指令遵循差**。

### 2.4 幻觉检测（Faithfulness）的落地方法
**核心思路**：衡量"生成内容是否可由检索上下文/已知事实推导"。
- **SelfCheckGPT**：对同一个问题用**同一模型多次采样**得到 K 个回复，若彼此一致则高置信（非幻觉），不一致则疑似幻觉；本质是"一致性即忠实"的代理（无需外部知识库）；
- **FActScore**：把生成文本拆成原子事实（atomic facts），逐条检索证据判"支持/不支持/无解"，`score = 支持数 / 总事实数`；
- **引用归因（Citation Grounding）**：要求模型输出带 `doc_id+span`，自动校验该 span 是否真在原文，未命中即标记；
- **NLI/Cloze 校验**：把"陈述+上下文"送 NLI 判蕴含（entailment），或做完形填空看上下文能否填出该陈述。

### 2.5 可观测性 Trace 的"归因难"
**现象**：一条 30s 的慢请求，不知道慢在 Planner 还是某个 Tool，也不知道成本花在哪。
**解决方案**：
- **Span 标准化**：定义三类核心 Span（`llm` / `tool` / `rag`），统一 attribute 命名（`gen_ai.prompt_tokens` 等遵循 GenAI Semantic Conventions）；
- **成本分摊**：按 DAG 拓扑把总 token/cost 归集到每个节点与"任务标签"，支持"哪个 tool 最烧钱"报表；
- **长链路 Replay & 回放**：保存 prompt + 中间态，出错可一键重放定位；
- **采样策略**：高流量下用头部采样（head-based）+ 尾部采样（tail-based，慢/错请求 100% 采），控成本；
- 工具栈参考：OpenLLMetry（基于 OTel 的 LLM 插桩）、Langfuse（trace+eval 一体）、Phoenix（轨迹可视化）。

### 2.6 评测集污染与数据泄漏
**现象**：模型在训练数据里"见过"评测题，分数虚高，泛化差。
**解决方案**：
- **n-gram 去污染**：用 13-gram 重叠检测训练集与评测集，重叠即剔除；
- **Embedding 相似度去重**：对评测题做语义近邻检索，剔除 paraphrase 复本；
- **留出集（Held-out）+ 私有集**：核心能力用内部私有、不公开评测集，避免被训练吞掉；
- 报告分数时**标注去污染状态**（如 "contamination-controlled"）。

### 2.7 多轮 / Agent 轨迹评测
**现象**：单轮评测无法反映"多步规划是否走对、是否陷入循环、工具是否选错"。
**解决方案**：
- **端到端任务成功率（Task Success Rate）**：给定可验证环境（如代码沙箱、DB 状态），看最终是否达成目标，比逐轮打分更准；
- **Trajectory 正确性**：用"关键决策点" checklist 评（是否在该调工具时调了、是否重复无效动作），可结合 LLM-as-Judge 评中间步骤；
- **成本/步数效率**：同成功率下，步数少、工具调用少者更优（Agent 的"性价比"）。

### 2.8 回归防护（Regression Guardrail）
**现象**：一次 prompt 微调让 A 场景变好、B 场景暴跌，肉眼难发现。
**解决方案**：
- **Golden Set 门禁**：每次变更跑固定黄金集，diff 各指标，回退 > 阈值自动卡 CI；
- **分层评测**：按场景/客户分层报告，避免"平均涨、局部崩"；
- **影子流量（Shadow Mode）**：新版本先接 1% 真实流量做影子对比，不影响用户，验证稳定后再灰度。

## 📌 三、常见问答（10 题，深度版）

**Q1：离线评测和在线评测的区别与联系？为什么 offline leaderboard 高 ≠ 上线好？**
离线是"受控考试"（固定集、单轮、可复现），用于准入与回归；在线是"真实工作"（分布漂移、多轮、有噪声），用 A/B + 业务指标终判。高≠好源于：① 分布错位（考试≠工作）；② 过拟合/数据泄漏刷分；③ 离线缺少业务代理指标（重试率、返工率）。正确姿态：离线做门禁，在线做终判，离线集定期去污染换新。

**Q2：LLM-as-Judge 有哪些偏置？如何缓解？**
四类：位置偏置、长度偏置、自我偏好、格式/权威偏置。缓解：① Pairwise + 顺序交换双跑取一致；② 多次采样取众数并算方差；③ Rubric-based 明确评分维度权重；④ 用人工集做 Judge 校准（κ/相关系数）；⑤ 报告 length-controlled win rate 消除长度干扰。

**Q3：RAGAS 的核心指标与含义？**
三指标解耦质量：Context Relevance（召回相关性）、Faithfulness（忠实无幻觉，=忠实陈述/总陈述）、Answer Relevance（答案切题度，反向生成问题测相似度）。诊断：Context 低→检索问题；Faithfulness 低→生成幻觉；Answer 低→指令遵循差。

**Q4：什么是 Faithfulness / 幻觉检测？SelfCheckGPT 原理？**
Faithfulness = 生成内容是否仅由给定上下文支撑。SelfCheckGPT：对同一问题用同一模型多次采样 K 个回复，彼此一致性高→高置信非幻觉，不一致→疑似幻觉；无需外部知识库，是"一致性即忠实"的代理。另有 FActScore（原子事实逐条检索）、引用归因（doc_id+span 校验）、NLI 蕴含校验。

**Q5：如何设计 LLM 应用的 SLI/SLO？**
SLI 选"用户与业务可感"的指标：① 任务成功率；② P99 首 Token 延迟（TTFT）与总延迟；③ 幻觉率（faithfulness 低于阈值占比）；④ 单任务成本（$）。SLO 设阈值（如成功率≥89%、P99 TTFT≤0.9s、幻觉率≤3%），并配错误预算（Error Budget）与告警；分层（按场景/客户）报告避免平均掩盖局部。

**Q6：可观测性 Trace 的 Span 怎么设计？**
定义三类核心 Span：`llm`（记 model/prompt_version/token_in/out/cost/latency/采样参数）、`tool`（记 tool_name/args/返回大小/错误码）、`rag`（记 query/top-k/doc_id/相似度）。遵循 GenAI Semantic Conventions 统一 attribute；做 token 与成本按 DAG 分摊；高流量用 head+tail 采样；支持长链路 replay 定位。

**Q7：评测集污染如何检测与缓解？**
检测：① n-gram（13-gram）重叠检测；② Embedding 近邻去重（剔除 paraphrase）；③ 留出私有集。缓解：剔除污染样本、用私有不公开集做核心能力评测、报告时标注去污染状态。

**Q8：LLM 场景的 A/B 实验有什么特殊性？**
① **新奇效应（Novelty）**：新模型短期受宠、长期回落，需跑够周期；② **网络/协同效应**：对话类产品改动相互影响，需随机化到用户/会话层级；③ **冷启动方差大**：样本少时置信区间宽，需足够流量与序贯检验；④ **多目标权衡**：准确率↑但延迟↑/成本↑，需 Pareto 而非单一最优；⑤ 用代理指标（guardrail 率、重试率）做早期止损。

**Q9：多 Agent 轨迹如何评测？**
不要逐轮打分。用：① 端到端任务成功率（可验证环境看是否达成目标）；② Trajectory 正确性（关键决策点 checklist + LLM-Judge 评中间步骤）；③ 成本/步数效率（同成功率下步数少者优）。本质是评"走没走对路、有没有循环、工具选没选错"。

**Q10：在线评测去偏（judge debiasing）的具体工程做法？**
① 顺序交换双跑（位置偏置）；② length-controlled win rate（长度偏置）；③ Rubric 化评分 + 多次采样取置信（自我/自由发挥偏置）；④ 定期人工校准集算 κ，低于阈值换/微调 Judge；⑤ 低置信样本（方差大、触发 guardrail）回流 Human-in-the-loop，标注反哺 Judge。

## 📌 四、模拟面试（3 题 + 参考答案要点）

### 模拟题 1：设计生产级 LLM 应用的可观测与评测体系
**考察**：体系化思维（从 trace 到 SLI 到在线评测闭环）。
**参考答案要点**：
- **数据层**：全链路 OTel Trace，三类 Span（llm/tool/rag）统一 attribute，记录 token/cost/latency/错误码；长链路 replay + head+tail 采样。
- **指标层**：四大 SLI（任务成功率、P99 TTFT、幻觉率、单任务成本）+ 业务代理指标（重试率、guardrail 率），分层报告；配 SLO 与错误预算告警。
- **评测层**：离线 Golden Set 回归门禁（每次变更 CI 卡点）；在线 LLM-as-Judge 去偏（顺序交换+多次采样+Rubric+人工校准）；Human-in-the-loop 回流。
- **发布层**：影子流量 1% 验证 → 灰度 → 全量；多目标 Pareto 权衡，不只看单指标。
- **闭环**：评测结果→定位薄弱环节→驱动 prompt/模型/检索优化→再评测。

### 模拟题 2：LLM-as-Judge 打分虚高，实际质量差，你怎么定位与修正？
**考察**：偏置诊断与工程纠偏能力。
**参考答案要点**：
- **定位**：① 交换 A/B 顺序重跑，看结论是否反转（位置偏置）；② 统计"长答案是否系统性高分"（长度偏置）；③ 看"风格相近答案是否高分"（自我偏置）；④ 抽样与人工标注对比算 κ，量化偏置大小。
- **修正**：位置偏置→顺序交换双跑取一致；长度偏置→length-controlled win rate；自我偏置→换更强/更中立 Judge 或微调；自由发挥→Rubric 化 + 多次采样取众数；低置信样本回流人工。
- **兜底**：Judge 只做"粗筛+回归卡点"，终判仍靠在线 A/B + 业务指标，不把 Judge 当真理。

### 模拟题 3：上线一个新 prompt 版本，如何用评测体系避免回归并保证业务指标不跌？
**考察**：回归防护与发布工程。
**参考答案要点**：
- **准入**：新 prompt 先跑 Golden Set 回归门禁，分场景/客户分层 diff 指标，回退超阈值直接卡 CI，禁止发布（曾拦截 3 次回退）。
- **验证**：影子流量（Shadow Mode）接 1% 真实流量做新旧对比，观察 SLI 与代理指标（重试率、guardrail 率），不影响用户。
- **灰度**：小流量灰度（如 5%→20%→100%），配错误预算，超预算自动回滚。
- **终判**：以在线 A/B + 业务指标（留存/转化/返工率）做终判，而非只看离线分；多目标 Pareto 权衡（准确率↑不能靠延迟/成本爆炸换来）。
- **复盘**：回归 case 进 Golden Set，持续补全边界，防同类再犯。
