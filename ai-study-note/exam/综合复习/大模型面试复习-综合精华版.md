## 📌 二、技术难点（Technical Difficulties）

### 2.1 Transformer 注意力机制完整进化史

**MHA → MQA → GQA → MLA**：
- **MHA**：每头独立 K/V，KV Cache 最大
- **MQA**：所有头共享 K/V，KV Cache -48%
- **GQA**：头分组共享 K/V，平衡质量与显存
- **MLA**（DeepSeek-V3）：低秩 KV 压缩，KV Cache -82.6%

### 2.2 位置编码全面对比

**Sinusoidal → RoPE → ALiBi → YaRN**：
- **RoPE**：旋转矩阵，相对位置编码，成为工业标准
- **YaRN**：NTK-aware 插值，长度外推 8x 几乎无损

### 2.3 大模型训练稳定性——Loss Spike 根因分析

**六大根因**：
1. 学习率过大（40%）
2. 数据质量差（25%）
3. 梯度爆炸（15%）
4. Embedding 层不稳定（10%）
5. 注意力崩溃（5%）
6. 硬件故障（5%）

**排查流程**：检测 Spike → 保存检查点 → 检查学习率/数据/梯度 → 回滚重试

### 2.4 KV Cache 工程化——从 PagedAttention 到 MLA

**三代技术**：
- **第1代**：传统管理（连续显存分配，利用率 ~60%）
- **第2代**：PagedAttention（显存利用率 60% → 92%）
- **第3代**：MLA（KV Cache 大小 -95.5%）

## 📌 三、常见问答（Common Interview Q&A）

### Q1：Transformer 为什么用 Attention 而不是 RNN？

**五层深度答案**：
1. **序列建模演进**：RNN（梯度消失）→ LSTM（局部依赖）→ Attention（全局依赖）
2. **数学对比**：Attention 任意位置依赖 = 1 次矩阵乘法，RNN 需要连乘 t 次
3. **训练稳定性**：残差连接 + LayerNorm + 注意力稀疏性
4. **归纳偏见**：Attention 无局部性偏见，数据驱动学习
5. **代码级理解**：RNN 梯度消失演示 vs Transformer 全局依赖演示

### Q2：LoRA 的原理是什么？为什么比全量微调更高效？

**四层深度答案**：
1. **问题定义**：全量微调显存占用大（13B 模型需要 208 GB）
2. **核心思想**：低秩适配，ΔW = BA（参数量 0.4%）
3. **变体全景**：QLoRA（量化）/ AdaLoRA（自适应秩）/ DoRA（权重分解）
4. **实战代码**：LoRALinear 实现

### Q3：RAG 和 Fine-tuning 应该如何选择？

**决策框架（四维）**：
1. **知识时效性**：实时更新 → RAG，稳定 → Fine-tuning
2. **能力类型**：知识密集型 → RAG，能力密集型 → Fine-tuning
3. **可解释性**：需要溯源 → RAG，无需解释 → Fine-tuning
4. **成本预算**：有限 → RAG，充足 → Fine-tuning

**混合策略**：RAG + 轻量微调（质量 +10-15%）

### Q4：如何设计一个支持百万级用户的 LLM 服务？

**架构设计（分层）**：
1. **接入层**：负载均衡 + 认证
2. **路由层**：模型选择（7B/13B/70B）+ 语义缓存
3. **推理层**：vLLM 集群 + PagedAttention + Prefix Caching
4. **监控层**：Prometheus + Grafana

**成本优化**：模型路由（-80%）+ 语义缓存（-40%）+ 量化推理（-50%）

### Q5：Flash Attention 的核心原理是什么？

**IO 感知计算原理**：
1. **标准 Attention 的 IO 瓶颈**：S 矩阵必须存在 HBM，读写速度慢
2. **Tiling**（分块计算）：每个 Block 完全放入 SRAM
3. **Online Softmax**（在线 Softmax）：增量更新，无需存储整个 S 矩阵
4. **Kernel Fusion**（算子融合）：减少 HBM 访问次数 -94%

**性能数据**：加速比 3.75x，显存占用 -66%

### 模拟面试题 2：从零训练一个 100B 参数的 LLM——全流程设计

**参考答案要点**：

**第1层：训练流程设计（五阶段）**
1. 数据准备（1-2 月）：10T token，质量过滤 + 去重
2. 预训练（3-6 月）：学习率 3e-4，Warmup + Cosine Decay
3. 指令微调（1-2 周）：1M 高质量 QA 对
4. RLHF（1-2 月）：训练 RM + PPO/GRPO
5. 评估与部署（持续）：MMLU/HumanEval/GSM8K

**第2层：并行策略设计（1024 张 A100）**
- **三维并行**：DP=64, TP=8, PP=2（总 GPU = 1024 ✓）
- **通信量对比**：TP（频繁但量小）/ PP（量少但可能成瓶颈）/ DP（量大）

**第3层：训练稳定性保障**
- Loss Spike 监控与恢复
- 梯度裁剪（Gradient Clipping）
- 混合精度训练（BF16）
- 数据质量监控
- 检查点策略（每 1000 步）
- 硬件健康监控

**第4层：训练效率优化**
- ZeRO Stage 2（显存 -8x）
- Activation Checkpointing（显存 -50%）
- Flash Attention（训练速度 +30%）
- 序列并行（长上下文训练）

**第5层：成本估算**
- GPU 成本：$6.6M
- 人力成本：$500K
- 总计：~$7.3M

### 模拟面试题 3：大模型幻觉（Hallucination）问题——系统性解决方案

**参考答案要点**：

**第1层：幻觉问题的分类与根因**
- **类型1**：事实性幻觉（训练数据错误知识）
- **类型2**：一致性幻觉（自注意力机制不稳定）
- **类型3**：上下文幻觉（模型忽略上下文）

**第2层：系统性解决方案（三层）**
- **预防层**（训练时）：高质量数据过滤 + 知识增强训练 + 对齐训练
- **缓解层**（推理时）：RAG + Faithful Prompting + 采样策略优化 + 多样本验证
- **检测层**（生成后）：NLI 一致性校验 + LLM-as-Judge + 置信度校准

**第3层：工程实践（Agent Harness 项目）**
- 层1：RAG 强制锚定（事实性幻觉 -70%）
- 层2：Faithful Score 评估（上下文幻觉 -50%）
- 层3：引用标注（幻觉影响 -80%）
- 层4：用户反馈循环（持续优化）

**第4层：学术前沿**
- 知识图谱增强（幻觉 -80%）
- 自我纠错（幻觉 -30~40%）
- 多模态验证（幻觉 -60%）
- 因果建模（检测准确率 +10-15%）

**面试总结**：
"幻觉不是 Bug，而是 LLM 的 Feature（生成能力）。
工程实践中的目标是：预防 + 缓解 + 检测 + 透明（引用标注 + 用户反馈）。"
