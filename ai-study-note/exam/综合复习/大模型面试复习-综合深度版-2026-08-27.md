**亮点 A：布局感知切分 + 父子文档（解决"切太碎丢上下文 / 切太粗噪声多"）**

```python
# 父子文档：父块(大, 用于检索命中) + 子块(小, 用于喂模型)
def build_parent_child(chunks, parent_size=2000, child_size=400, overlap=80):
    parents, children = [], []
    for doc in chunks:
        paras = split_by_layout(doc)              # 按标题/表格/段落结构切
        for p in paras:
            pid = hash(p[:parent_size])
            parents.append({"id": pid, "text": p[:parent_size]})
            for i in range(0, len(p), child_size - overlap):
                seg = p[i:i+child_size]
                children.append({"id": f"{pid}_{i}", "parent": pid, "text": seg})
    return parents, children
# 检索时搜子块→回贴父块→父块进上下文，召回准+上下文全
```

> 面试亮点：纯按 token 滑窗切会把"表头"和"数据行"拆开、把跨段指代切断；布局感知（Markdown/PDF 结构树）保留语义边界，父子文档兼顾"检索粒度"与"生成上下文"。

**亮点 B：混合检索（BM25 稀疏 + Dense 稠密 + RRF 融合）**

```python
def rrf_fusion(rank_lists, k=60):
    """Reciprocal Rank Fusion: 不依赖分值量级, 只信排名"""
    scores = defaultdict(float)
    for rl in rank_lists:                 # rl: 已按相关性排序的 doc 列表
        for rank, doc in enumerate(rl, 1):
            scores[doc["id"]] += 1.0 / (k + rank)
    return sorted(scores.items(), key=lambda x: -x[1])
# BM25 补关键词/专名/编号命中; Dense(BGE-M3)补语义; RRF 融合避免分值不可比
```

## 📌 二、技术难点（RAG 专项六大共性难点 + 解决方案）

### 2.1 切分粒度悖论（chunk size 与语义完整性矛盾）

**现象**：切太小→检索准但生成缺上下文；切太大→噪声多、embedding 被稀释、易超上下文窗。
**根因**：固定滑窗不尊重语义边界（句子/段落/表格被腰斩）。
**方案**：① 布局感知切分（保留标题层级、表格边界）；② 父子文档（小块检索、父块喂入）；③ 动态 chunk（按语义相似度断点，同段相似度>阈值才合并）。经验甜点：检索块 200~400 token，喂入块 1000~2000 token。

### 2.2 召回质量（Embedding + 混合 + 重排三段式）

**根因**：单一稠密向量对"专名/编号/稀有词"不敏感，长尾 query 召回崩。
**方案**：
- **Embedding 选型**：领域适配（用业务语料继续训练/微调 BGE-M3）；多语言用 BGE-M3（100+ 语言 + 稀疏 + 多向量）；Matryoshka（截断维度不丢太多精度）降存储；迟交互 ColBERT（MaxSim，段级对齐，精度高但贵）。
- **混合检索**：BM25 补关键词，Dense 补语义，RRF/k 融合（见亮点 B）。
- **重排**：Cross-Encoder（query-doc 拼接编码，精度高）取 Top-100→Top-10；LLM reranker 仅用于高价值 Top-20→Top-5（成本权衡）。

```python
# ColBERT 迟交互 MaxSim: 每个 query token 取与 doc token 最大相似度再求和
def maxsim(q_emb, d_emb):   # q_emb:[nq,D] d_emb:[nd,D]
    return sum(max(q_emb[i] @ d_emb[j] for j in range(d_emb.shape[0]))
               for i in range(q_emb.shape[0]))
```

### 2.3 检索-生成对齐（检索到了但不相关 / 不充实时）

**现象**：检索 Top-K 看似相关，实则答非所问；或用户问题需要"综合多文档"而非"单文档片段"。
**根因**：检索目标是"相似"而非"能回答问题"；单向量丢掉了 query 意图。
**方案**：① **Query 改写/扩展**（LLM 把口语化问题改写成检索友好 query，多 query 召回再融合）；② **HyDE**（先让 LLM 生成"假设答案"，再用假设答案的 embedding 去检索——绕过 query-doc 词汇鸿沟）；③ **Self-RAG** 的 `is_rel` 判别器，检索后先判相关性再决定用不用。

```python
# HyDE: 用假设文档的 embedding 检索, 弥合 query 与 doc 的词面鸿沟
hypo = llm.generate(f"Q: {query}\n写一个能回答该问题的参考段落:")
hypo_vec = embed(hypo)
docs = vector_db.search(hypo_vec, top_k=5)   # 而非直接用 query 向量
```

### 2.4 长文档 / 多跳 / 全局问答（GraphRAG）

**现象**："公司 2024 各事业部营收趋势对比"这类全局、汇总、多跳问题，常规 RAG 检索片段答不了。
**根因**：向量检索是"局部相似"，缺乏实体关系的全局结构。
**方案**：**GraphRAG**——抽取实体/关系建知识图谱，做社区检测（Leiden）生成社区摘要，全局问答走"社区摘要→层级汇聚"。代价：建图贵、更新难；适合**相对稳定、需全局洞察**的知识域（如企业制度、研报）。实时性高的用 Agentic RAG（多轮检索+工具）替代。

### 2.5 幻觉与引用不可信（grounding/faithfulness）

**根因**：模型会"顺嘴编"检索内容没说的；引用可能挂错/挂空。
**方案（四层堵死，与第45期一致）**：① 工具/检索结果 schema 校验；② **引用约束生成**（事实句必挂 citation，无引用扣分）；③ Guardrail 轻量一致性检查（答案主张 vs 检索片段矛盾即拦截）；④ Online Eval 持续监控 Faithfulness（RAGAS faithfulness + 人工抽检），>阈值自动告警+回滚 Prompt。RAGAS faithfulness 本质用 NLI/LLM 把答案拆成若干陈述，逐条验"能否被检索上下文蕴含"。

### 2.6 延迟与成本（检索链路 100ms 预算）

**现象**：RAG 链路 = query 改写 + 多路检索 + 重排 + 生成，P99 易超 3s。
**根因**：串行调用多、重排/LLM reranker 贵、向量库未预热。
**方案**：① **并行**：BM25/Dense/改写多路并发（asyncio.gather）；② **缓存**：高频 query 结果缓存（命中 ~35%，见成本模型）；③ **重排降级**：默认 Cross-Encoder Top-100→10，长尾才上 LLM reranker；④ **量化索引**：IVF-PQ 压缩 + HNSW 预热，检索 P99 220→35ms；⑤ 上文压缩（LLMLingua 压到 30%）减生成 token。

## 📌 三、常见问答（12 个高频深度问题 + 答案要点）

**Q1：RAG 和 Fine-tuning 怎么选？**
RAG 解决"知识更新/可溯源/防幻觉/长尾事实"，不改模型权重、知识可随时增删；FT 解决"风格/格式/特定能力/低延迟本地推理"，但知识固化、更新贵、易灾难遗忘。经验法则：**先 RAG（知识类），不够再加 LoRA（能力/风格类）；二者正交可叠加**。需"引用出处"必选 RAG。

**Q2：chunk size 怎么定？有公式吗？**
无放之四海皆准公式，按"检索目标长度"定：检索块 200~400 token（embedding 区分度最佳），喂入块 1000~2000（父子文档）。约束：`检索块 ≤ 模型最优上下文窗口的 1/4` 且 `单块 embedding 不被截断`。用 nDCG@10/Recall@10 做网格搜索选甜点。

**Q3：混合检索 RRF 公式与 k 的作用？**
`RRF(d)=Σ_{r∈R} 1/(k+rank_r(d))`，k 通常 60。作用：**不依赖各路分值量纲**（BM25 分数是 0~几十，Dense 是余弦 -1~1，直接加权需归一化；RRF 只信排名，避免病态加权）。k 越大，排名靠前的优势越被稀释，越"民主"。

**Q4：Embedding 模型怎么选？Matryoshka / 迟交互是什么？**
- 通用中文：BGE-M3（稠密+稀疏+多向量三合一，100+ 语言）。
- Matryoshka：同一向量可截断前 d 维仍保精度，省存储/检索（如 1024→256 维丢 <3% 精度）。
- 迟交互（ColBERT）：存 query/doc 每个 token 向量，检索时 MaxSim 段级对齐，精度上限高但存储/QPS 代价大，适合高精度小库。
- 领域强相关：用业务语料继续预训练/微调 embedding（对比学习，难负例挖掘）。

**Q5：Query 改写 / HyDE 是什么？何时用？**
Query 改写：LLM 把模糊口语问题改写成 1~N 个检索友好 query（补术语、拆解多意图），多 query 召回融合。HyDE：先生成"假设答案"再用其 embedding 检索，弥合 query-doc 词面鸿沟（用户问"怎么退货"但文档写"逆向物流流程"）。**HyDE 对语义鸿沟大、文档术语化强的场景提升明显；但假设答案可能引入偏差，需配合重排过滤**。

**Q6：重排 Cross-Encoder vs LLM reranker 怎么取舍？**
Cross-Encoder（query+doc 拼接编码，输出相关性分）：精度高、latency 中（~20ms/对）、便宜，Top-100→Top-10 标配。LLM reranker（让大模型判相关+给理由）：精度上限更高但贵（一次 LLM 调用/批），仅用于高价值 Top-20→Top-5 或争议 query。生产默认 Cross-Encoder，长尾/高价值才上 LLM。

**Q7：GraphRAG 原理与适用场景？**
抽取实体+关系→知识图谱→社区检测(Leiden)→生成社区摘要→全局问答时层级汇聚社区摘要。适用：**全局性、汇总性、多跳**问题（"各事业部趋势对比""本公司合规要点全景"），知识域相对稳定。不适用：高频更新、强实时、简单事实问答（常规 RAG 更省）。代价：建图算力大、增量更新复杂。

**Q8：如何评测 RAG 系统？RAGAS 三指标怎么解耦？**
三层：① 检索层 Recall@k / nDCG@10（用标注相关集）；② 生成层 Faithfulness（答案是否被上下文蕴含）、Answer Relevancy（是否答对）、Context Precision/Recall；③ 端到端用 LLM-as-Judge（去偏见 08-22）。RAGAS 把"检索质量"与"生成质量"解耦：**Context Recall 测检索、Faithfulness 测不胡编、Answer Relevancy 测切题**，三者独立，便于定位是检索还是生成的问题。注意评测集去污染、Judge 偏置校正。

**Q9：如何让模型"引用且忠实"？**
生成时要求结构化输出 `claim + [citation]`，后处理正则校验"事实句必有引用且 citation 指向检索片段"；Guardrail 用 NLI 验"答案陈述 ⊆ 检索上下文"，矛盾句拦截重生成；Online Eval 监控 Faithfulness，掉阈值告警回滚。心法：**幻觉靠"系统堵死编造空间"，不是靠 prompt 让它别编**。

**Q10：生产 RAG 延迟/成本怎么优化到 P99<1.2s？**
并行（改写/BM25/Dense 并发）+ 缓存高频 query（~35% 命中）+ 重排降级（默认 Cross-Encoder，长尾才 LLM）+ 量化索引（IVF-PQ+HNSW 预热，220→35ms）+ 上文压缩（LLMLingua 30%）+ 模型路由（简单问答走 7B）。成本模型：`成本=Σ(路由单价×token)×(1-缓存命中率)`（见第45期）。

**Q11：Self-RAG / Agentic RAG 是什么？**
Self-RAG：训练/提示一个判别器，在生成中自决"是否检索(`is_retrieval`)""检索结果是否相关(`is_rel`)""生成是否支撑(`is_sup`)""是否通顺(`is_use`)"，自适应检索、减少过度/不足检索。Agentic RAG：把检索当工具，Planner 多轮决定"查什么、查几次、查哪类源"，适合多跳/需工具（SQL/API）的复杂问答。二者区别：Self-RAG 是"单模型内自适应"，Agentic RAG 是"多步编排外循环"。

**Q12：RAG 遇到多跳/长文档答不上来怎么办？**
单文档多跳→检索多个片段并在生成时拼接上下文（父子文档+多 query 召回）；跨文档汇总→GraphRAG 社区摘要；需计算/最新数据→Agentic RAG 接 SQL/API 工具；超长文档→分层检索（先章节检索定位、再段落精检）。核心：**问题类型决定检索范式，没有一种 RAG 通吃所有**。

### 🎯 模拟题 1：设计支撑千万级企业文档的 RAG 知识库（端到端）

**题干**：从 0 设计一套支撑千万级企业文档（PDF/Word/表格/网页，中英混排，含专名/编号）的生产级 RAG 知识库，要求召回@10 ≥ 88%、P99 < 1.2s、可溯源、支持"单文档事实问答"与"跨文档汇总问答"两类。给完整链路与关键决策。

**参考答案要点（数据→检索→生成→评测闭环）**：
1. ** ingestion（解析切分）**：版式感知解析（标题树/表格保留）→ 父子文档（检索块 300/喂入块 1500 token）→ 动态合并（同段相似度阈值）。
2. **Embedding**：BGE-M3（稠密+稀疏+多向量）+ 业务语料微调 + Matryoshka 截断省存储；专名/编号靠稀疏向量兜底。
3. **索引**：IVF-PQ（压缩 32×）+ HNSW 二级，预热 + 缓存高频 query（命中 ~35%）。
4. **检索**：BM25 + Dense 并行 → RRF(k=60) 融合 → Cross-Encoder 重排 Top-100→10；长尾/高价值上 LLM reranker Top-20→5。
5. **query 侧**：LLM 改写（多 query 拆解）+ HyDE（弥合词面鸿沟）+ Self-RAG `is_rel` 判相关。
6. **生成**：引用约束生成（claim+citation，无引用扣分）+ Guardrail NLI 一致性拦截。
7. **全局问答**：GraphRAG 社区摘要（Leiden）层级汇聚，应对"各事业部趋势对比"类。
8. **评测**：RAGAS 三指标（Context Recall / Faithfulness / Answer Relevancy）离线 + Online Eval 去偏监控，掉阈值告警回滚。
**加分项**：主动画"延迟预算表"（改写 50ms+检索 35ms+重排 80ms+生成 800ms≈1.1s P99）；并指出"两类问题用两套检索范式，不是一种 RAG 通吃"。

### 🎯 模拟题 2：线上 RAG "答非所问 + 幻觉率 2%→9%" 复合故障 30 分钟止血

**题干**：凌晨告警：RAG 知识库"答非所问"投诉激增，自动评测 Faithfulness 从 95% 跌到 91%、无引用句占比从 2.3% 飙到 9%，P99 从 1.1s 涨到 1.8s。你是 oncall，如何 30 分钟内止血、定位、根治？

**参考答案要点（止血 → 定位 → 根治）**：
- **0–5 min 止血**：开"引用强校验 + 低 Faithfulness 自动拦截重生成"开关；对高投诉业务线切回上一版 Prompt/Embedding（灰度回滚）；保主链路不雪崩。
- **5–15 min 定位（拆因）**：
  - Faithfulness 跌 + 无引用升：多半是**Embedding 模型发版回归**（新版本把专名向量拉开，BM25 权重被冲淡）或**重排 Cross-Encoder 误关**（Top-10 混进不相关）→ 查模型/重排变更时间线。
  - P99 涨：可能**GraphRAG 社区摘要被误触发**（简单问题走了贵的全局链路）或缓存命中率骤降（缓存服务重启）→ 查调用分布。
  - 两者同时：极可能是**一次错误发版**（新 Prompt 弱化引用约束 + 新 Embedding 漂移），对比变更时间线确认即回滚。
- **15–30 min 根因**：三类——① Embedding/重排回归 ② GraphRAG 误触发 ③ 缓存挂。
- **根治 + 防复发**：Embedding 发版强制跑"召回@10 + Faithfulness"回归门禁；重排开关纳入 SLI；引用约束作为不可关的硬护栏；上线"Faithfulness + 无引用率 + P99"三指标联动熔断。
**加分项**：强调"没有 RAGAS 在线监控 + 变更时间线，30 分钟定位不可能"；单指标人人会查，复合故障靠"指标联动假设 + 评测门禁"。

### 🎯 模拟题 3：同一个 RAG，云端 70B 与端侧 7B 如何保证"检索一致 + 引用可信"？

**题干**：公司要求同一套 RAG 既跑云端 70B（强生成/强引用），又跑端侧 7B（低延迟/隐私，数据 0 出端）。请设计工程方案，保证"检索协议互通、引用格式一致、两端 Faithfulness 可比"，从检索协议、生成约束、评测三层展开。

**参考答案要点**：
1. **检索协议层（统一接口，最关键）**：两端共用同一套"检索服务 + 父子文档 + 引用 Schema"，检索走标准 `citation[doc_id, span]` 协议；端侧 7B 必开**约束解码**保证 JSON/引用格式合法（99%+）；端侧只跑"隐私/轻量"检索，重检索/GraphRAG 转云端（端云协同）。即"协议统一、能力按端分流"。
2. **生成约束层**：两端用**同一份引用约束 SFT 数据**蒸馏（70B 教师→7B 学生），保证引用格式与"无引用即拒答"偏好一致；7B 加"拒答类样本"抑制编造；端侧 LoRA 热插拔、云端全量，避免行为漂移。目标：两端 AST 匹配率（引用格式）差距 < 5pp。
3. **评测层（可比）**：统一评测集（单文档事实/多跳/全局/拒答），两端跑同一 benchmark，指标用 Faithfulness + 引用合法率 + Answer Relevancy；Online Eval 监控两端质量差，超阈值自动告警 + 回滚 7B 适配器。
4. **兜底**：端侧低置信/超能力任务自动转云端（端云路由 + 云端兜底），保"体验下限"。
**加分项**：点出"完全一致不必追求"——目标是"协议互通 + 引用格式一致 + Faithfulness 可比 + 云端兜底"，用端云协同把 7B 上限用云端补平。

## 📌 五、今日速记卡（Flashcards）

| 考点 | 一句话答案 |
|------|-----------|
| RAG vs FT | 知识/可溯源/防幻觉→RAG；风格/能力/低延迟→FT；二者正交可叠加 |
| 切分悖论 | 布局感知 + 父子文档：检索块 300、喂入块 1500，不按滑窗腰斩语义 |
| RRF 公式 | `Σ 1/(k+rank)`, k=60, 只信排名不靠分值量纲，避 BM25/Dense 加权病态 |
| Embedding 选型 | 中文 BGE-M3；Matryoshka 省存；ColBERT 迟交互精度高但贵；领域微调 |
| HyDE | 先生成假设答案再嵌检索，弥合 query-doc 词面鸿沟 |
| 重排取舍 | 默认 Cross-Encoder(Top100→10)；长尾/高价值才 LLM reranker |
| GraphRAG | 实体关系图+社区摘要，专治全局/多跳/汇总问答；贵且更新难 |
| RAGAS 三指标 | Context Recall(检索) / Faithfulness(不胡编) / Answer Relevancy(切题) 解耦定位 |
| 引用可信 | 结构化 claim+citation + NLI 蕴含校验 + 无引用扣分 + Online Eval 回滚 |
| 延迟预算 | 并行改写/检索 + 缓存35% + 重排降级 + IVF-PQ+HNSW预热(220→35ms) |
| Self-RAG vs Agentic | 单模型内自适应判别 vs 多步编排外循环(把检索当工具) |
| 云-端 RAG 一致 | 统一检索/引用协议 + 同数据蒸馏 + 统一评测 + 云端兜底 |
