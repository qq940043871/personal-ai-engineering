## 📌 二、技术难点（Technical Difficulties）

### 2.1 PagedAttention 核心原理与代码实现

**问题定义**：
传统 KV Cache 管理方式的缺陷：
1. 连续显存分配：每个请求预分配固定大小（如 2048 token）
2. 显存碎片：短请求浪费显存，长请求 OOM
3. 显存利用率低：~60%（40% 碎片）

**PagedAttention 解决方案**：

**核心数据结构**：
```python
class Page:
    """KV Cache 的一个 Page（默认 16 token）"""
    page_id: int
    ref_count: int          # 引用计数（共享前缀）
    token_ids: List[int]    # 存储的 Token ID
    kv_cache: Tensor        # K Cache + V Cache

class BlockManager:
    """管理所有 Page（类似操作系统内存管理器）"""
    def __init__(self, num_blocks: int, block_size: int = 16):
        self.num_blocks = num_blocks
        self.block_size = block_size
        self.free_blocks = list(range(num_blocks))  # 空闲链表
        self.blocks = [Page(i) for i in range(num_blocks)]

    def allocate(self, num_tokens: int) -> List[int]:
        """为请求分配 Page"""
        num_blocks = (num_tokens + self.block_size - 1) // self.block_size
        if len(self.free_blocks) < num_blocks:
            raise OutOfMemoryError("KV Cache OOM")
        allocated = []
        for _ in range(num_blocks):
            block_id = self.free_blocks.pop()
            self.blocks[block_id].ref_count = 1
            allocated.append(block_id)
        return allocated

    def free(self, block_ids: List[int]):
        """释放 Page（引用计数 = 0 时才真正释放）"""
        for block_id in block_ids:
            self.blocks[block_id].ref_count -= 1
            if self.blocks[block_id].ref_count == 0:
                self.free_blocks.append(block_id)
```

**Attention 计算修改（支持非连续 Page）**：
```python
def paged_attention(
    query: Tensor,      # [batch, num_heads, seq_len, head_dim]
    key_cache: List[Tensor],   # 每个 Page 的 K Cache
    value_cache: List[Tensor], # 每个 Page 的 V Cache
    block_tables: List[List[int]]  # 每个请求的 Page ID 列表
):
    """
    PagedAttention 核心计算（简化版）
    关键：K/V 不再连续，需要通过 block_tables 索引
    """
    batch_size, num_heads, seq_len, head_dim = query.shape
    outputs = []

    for i in range(batch_size):
        # 获取该请求的 KV Cache Page
        block_ids = block_tables[i]
        # 拼接所有 Page 的 K/V（实际实现中会用 Kernel 避免显式拼接）
        keys = torch.cat([key_cache[b] for b in block_ids], dim=0)
        values = torch.cat([value_cache[b] for b in block_ids], dim=0)

        # 标准 Attention 计算
        scores = torch.matmul(query[i], keys.transpose(-1, -2))
        attn_weights = torch.softmax(scores / math.sqrt(head_dim), dim=-1)
        output = torch.matmul(attn_weights, values)
        outputs.append(output)

    return torch.stack(outputs, dim=0)
```

| 方案 | 显存利用率 | 吞吐量（tokens/s/GPU） | 最大并发请求数 |
|------|-----------|----------------------|--------------|
| 连续分配 | 60% | 800 | 8 |
| PagedAttention | 92% | 3200 | 55 |

### 2.2 Continuous Batching 实现原理

**问题定义**：
Static Batching 的缺陷：
- 批次内所有请求必须同步（等待最长请求完成）
- GPU 空闲率高（短请求完成后，批次仍在等待）
- 实际利用率：~40%

**Continuous Batching 解决方案**：

**核心思想**：每个 Decode Step 独立决定批次组成

**实现机制（Fill + Decode 分离）**：
```python
class ContinuousScheduler:
    """Continuous Batching 调度器（简化版）"""
    def __init__(self, max_batch_size: int = 32):
        self.max_batch_size = max_batch_size
        self.waiting_queue = []      # 等待 Fill 的请求
        self.running_requests = []   # 正在 Decode 的请求

    def schedule(self):
        """
        每个 Step 调用一次，返回本 Step 的批次
        关键：Fill 和 Decode 分离（不同 Kernel）
        """
        # Step 1: 选择需要 Fill 的请求（Prefill）
        fill_requests = self._select_fill_requests()

        # Step 2: 选择需要 Decode 的请求
        decode_requests = self._select_decode_requests()

        # Step 3: 合并批次（Fill 优先级更高）
        batch = fill_requests + decode_requests
        if len(batch) > self.max_batch_size:
            batch = batch[:self.max_batch_size]

        return batch

    def _select_fill_requests(self):
        """选择等待中的请求（Prefill 阶段）"""
        selected = []
        for req in self.waiting_queue[:]:
            if req.num_tokens > 0:  # 还有 Token 未处理
                selected.append(req)
                if req.all_tokens_filled():
                    self.waiting_queue.remove(req)
                    self.running_requests.append(req)
        return selected

    def _select_decode_requests(self):
        """选择正在运行的请求（Decode 阶段）"""
        selected = []
        for req in self.running_requests:
            if not req.is_finished():
                selected.append(req)
            else:
                self.running_requests.remove(req)
        return selected
```

**性能对比**：

| 方案 | GPU 利用率 | 吞吐量（tokens/s） | 延迟 P50/P99 |
|------|-----------|-------------------|--------------|
| Static Batching | 40% | 1200 | 200ms / 1200ms |
| Continuous Batching | 85% | 2800 | 150ms / 400ms |

### 2.3 Prefix Caching 实现原理（Radix Tree）

**问题定义**：
多用户共享相同前缀（System Prompt / Few-Shot 示例），导致：
- 重复计算（每个请求都重新计算相同前缀的 KV Cache）
- TTFT 高（Prefix 越长，TTFT 越高）

**Prefix Caching 解决方案**：

**核心数据结构（Radix Tree）**：
```python
class RadixTreeNode:
    """Radix Tree 节点"""
    def __init__(self):
        self.token_ids: List[int] = []       # 该节点存储的 Token ID
        self.children: Dict[int, RadixTreeNode] = {}  # 子节点（按第一个 Token 索引）
        self.block_ids: List[int] = []        # 对应的 KV Cache Page ID
        self.ref_count: int = 0              # 引用计数

class PrefixCache:
    """基于 Radix Tree 的前缀缓存（简化版）"""
    def __init__(self):
        self.root = RadixTreeNode()

    def match(self, token_ids: List[int]) -> Tuple[List[int], int]:
        """
        匹配最长前缀
        返回：(匹配的 Block ID 列表, 匹配长度)
        """
        node = self.root
        matched_blocks = []
        matched_len = 0

        i = 0
        while i < len(token_ids):
            # 在当前节点的 token_ids 中匹配
            matched = 0
            for j in range(min(len(node.token_ids), len(token_ids) - i)):
                if node.token_ids[j] == token_ids[i + j]:
                    matched += 1
                else:
                    break

            if matched == 0:
                break

            # 更新匹配结果
            matched_blocks.extend(node.block_ids)
            matched_len += matched
            i += matched

            # 移动到子节点
            if i < len(token_ids):
                next_token = token_ids[i]
                if next_token in node.children:
                    node = node.children[next_token]
                else:
                    break

        return matched_blocks, matched_len

    def insert(self, token_ids: List[int], block_ids: List[int]):
        """插入新的前缀"""
        # 简化实现：直接插入（实际需要做 Radix Tree 分裂）
        node = self.root
        for block_id in block_ids:
            if len(node.children) == 0:
                new_node = RadixTreeNode()
                new_node.block_ids.append(block_id)
                node.children[token_ids[0]] = new_node
            node = new_node
```

### 2.4 vLLM Tensor Parallelism 实现原理

**问题定义**：
单层模型无法放入单卡显存（如 70B 模型，FP16 需要 140GB > A100 80GB）

**Tensor Parallelism 解决方案**：

**核心原理**：
- Column Parallel（按列切分）：`Y = XW`，W 按列切分，W = [W1, W2], Y = [Y1, Y2]
- Row Parallel（按行切分）：`Y = XW`，W 按行切分，需要 All-Reduce 合并结果

**实现代码（简化版）**：
```python
import torch
import torch.distributed as dist

class ColumnParallelLinear:
    """按列切分的 Linear 层（TP 常用）"""
    def __init__(self, in_features: int, out_features: int, world_size: int):
        self.world_size = world_size
        self.rank = dist.get_rank()
        # 每 GPU 只存储部分权重
        self.weight = torch.nn.Parameter(
            torch.randn(out_features // world_size, in_features)
        )

    def forward(self, x: Tensor) -> Tensor:
        # 每个 GPU 独立计算部分输出
        output_partial = x @ self.weight.T  # [batch, out_features // world_size]
        return output_partial

class RowParallelLinear:
    """按行切分的 Linear 层（需要 All-Reduce）"""
    def __init__(self, in_features: int, out_features: int, world_size: int):
        self.world_size = world_size
        self.rank = dist.get_rank()
        # 每 GPU 只存储部分权重
        self.weight = torch.nn.Parameter(
            torch.randn(out_features, in_features // world_size)
        )

    def forward(self, x: Tensor) -> Tensor:
        # 每个 GPU 计算部分结果
        output_partial = x @ self.weight.T  # [batch, out_features]
        # All-Reduce 合并（求和）
        dist.all_reduce(output_partial, op=dist.ReduceOp.SUM)
        return output_partial

class TPTransformerLayer:
    """Tensor Parallel Transformer Layer（简化版）"""
    def __init__(self, hidden_size: int, world_size: int):
        # Attention 的 Q/K/V 投影：Column Parallel
        self.q_proj = ColumnParallelLinear(hidden_size, hidden_size, world_size)
        self.k_proj = ColumnParallelLinear(hidden_size, hidden_size, world_size)
        self.v_proj = ColumnParallelLinear(hidden_size, hidden_size, world_size)
        self.o_proj = RowParallelLinear(hidden_size, hidden_size, world_size)  # 需要 All-Reduce

        # MLP：Column Parallel（激活函数后） + Row Parallel
        self.gate_proj = ColumnParallelLinear(hidden_size, hidden_size * 4, world_size)
        self.up_proj = ColumnParallelLinear(hidden_size, hidden_size * 4, world_size)
        self.down_proj = RowParallelLinear(hidden_size * 4, hidden_size, world_size)  # 需要 All-Reduce

    def forward(self, x: Tensor) -> Tensor:
        # Attention（简化）
        q = self.q_proj(x)
        k = self.k_proj(x)
        v = self.v_proj(x)
        attn_output = self.o_proj(self.attention(q, k, v))  # o_proj 内含 All-Reduce

        # MLP（简化）
        gate = self.gate_proj(x)
        up = self.up_proj(x)
        mlp_output = self.down_proj(gate * up)  # down_proj 内含 All-Reduce

        return attn_output + mlp_output
```

**通信量分析**：

| 操作 | 通信类型 | 数据量 | 频率 |
|------|---------|--------|------|
| RowParallelLinear | All-Reduce | [batch, out_features] | 每层 2 次（Attention + MLP） |
| 总通信量（28 层） | - | ~10GB（batch=32, hidden=4096） | 每 Forward/Backward 各一次 |

**优化策略**：
- **通信与计算 Overlap**：用 NCCL 异步通信，与计算并行
- **减少 All-Reduce 次数**：连续两层 Row Parallel 可以合并（实际 vLLM 实现）

class ModelRouter:
    """模型路由（简化版）"""
    def __init__(self):
        self.classifier = BertForSequenceClassification.from_pretrained("bert-base")
        self.difficulty_threshold = {
            "easy": 0.7,      # 70% 简单问题用 7B
            "medium": 0.25,   # 25% 复杂问题用 13B
            "hard": 0.05      # 5% 超难问题用 70B
        }

    def route(self, query: str) -> str:
        """路由到合适的模型"""
        score = self.classifier(query)  # [简单, 复杂, 超难]
        if score[0] > 0.8:
            return "7b"
        elif score[1] > 0.6:
            return "13b"
        else:
            return "70b"

**优化2：语义缓存（成本 -40%）**
```python
class SemanticCache:
    """语义缓存（简化版）"""
    def __init__(self, similarity_threshold: float = 0.95):
        self.embedder = SentenceTransformer("bge-large-zh")
        self.cache = {}  # {embedding: response}
        self.similarity_threshold = similarity_threshold

    def get(self, query: str) -> Optional[str]:
        """查询缓存"""
        query_emb = self.embedder.encode(query)
        for cached_emb, response in self.cache.items():
            sim = cosine_similarity(query_emb, cached_emb)
            if sim > self.similarity_threshold:
                return response
        return None

    def set(self, query: str, response: str):
        """写入缓存"""
        query_emb = self.embedder.encode(query)
        self.cache[query_emb] = response
```
