### 1.4 关键模块实现要点（亮点落点）

- **混合检索**：向量负责语义召回，BM25 负责精确词面/编号召回，RRF 无参数融合二者。
- **引用约束生成**：要求模型输出 `[1][2]` 角标，且每个角标必须映射到检索返回的块；后处理校验"无依据陈述"。
- **增量治理**：文档按 `(tenant, doc_id, version)` 管理；更新只重建该文档的块与向量，删除旧 version 倒排/向量。
- **评估闭环**：离线用 RAGAS 风格指标（Faithfulness / Answer Relevancy / Context Recall），在线看"用户采纳率 + 追问率"。

## 📌 二、技术难点（Technical Challenges & Solutions）

### 2.1 文档解析与智能切分 —— "切坏了，后面全废"

**问题**：
1. 企业文档大量是扫描 PDF / 带表格 / 多栏排版，纯文本提取会丢失结构。
2. 固定长度切分（512 token）常把"一个定义"或"一个表格"拦腰切断，破坏语义边界。
3. 切太小 → 检索噪声大；切太大 → 噪声多、超出上下文、召回精度低。

**方案：布局感知切分 + 语义边界检测 + 父子文档（Parent-Child）**
- **布局感知**：用 PDF 解析（如 `pdfplumber` / `unstructured` / 商用版式模型）保留标题层级、表格、页码。
- **语义边界**：在标题/段落边界优先切；再用语义切分（embedding 相似度骤降处作为切分点）。
- **父子文档**：子块（小，~200 token）用于**精准检索**；命中后回链**父块**（大，~1000 token）用于**生成上下文**。兼顾"检索精度"与"上下文完整"。

```python
import re
from typing import List

def layout_aware_split(
    text: str,
    max_chunk: int = 1000,
    min_chunk: int = 200,
    headings: List[str] = None,
) -> List[str]:
    """按标题层级 + 段落边界切分，超长段落再按句子兜底切。
    真实项目里 headings 来自版式模型识别到的 H1/H2/H3。"""
    headings = headings or []
    # 1) 以标题和空行作为强切分点
    blocks = re.split(r'(?=\n#{1,3}\s|^\n{2,})', text, flags=re.M)
    chunks, cur = [], ""
    for b in blocks:
        b = b.strip()
        if not b:
            continue
        if len(cur) + len(b) <= max_chunk:
            cur = (cur + "\n" + b).strip()
        else:
            if cur:
                chunks.append(cur)
            # 超长块按句子切（兜底）
            if len(b) > max_chunk:
                for sent in re.split(r'(?<=[。！？])', b):
                    if len(cur) + len(sent) <= max_chunk:
                        cur = (cur + sent).strip()
                    else:
                        if cur:
                            chunks.append(cur)
                        cur = sent
            else:
                cur = b
    if cur:
        chunks.append(cur)
    return [c for c in chunks if len(c) >= min_chunk * 0.5]
```

### 2.2 Embedding 选型与领域微调 —— "通用向量在垂直领域召回低"

**问题**：通用 BGE/MiniLM 在公开语料上强，但企业里有大量**专有名词、内部缩写、产品编号**，语义被淹没，检索召回低。

**方案**：
1. **先调检索链路**（query rewrite + 混合检索 + 重排），往往能先拿到 10~15pp 提升，成本最低。
2. **再做领域微调**：用对比学习在领域语料上微调 embedding，核心是**难负样本挖掘（hard negative mining）**。

**数学（InfoNCE / 对比损失）**：
$$
\mathcal{L} = -\log \frac{\exp(\text{sim}(q, d^+)/\tau)}{\exp(\text{sim}(q, d^+)/\tau) + \sum_{i=1}^{N}\exp(\text{sim}(q, d_i^-)/\tau)}
$$
其中 $\text{sim}$ 为余弦相似度，$\tau$ 为温度。关键在负样本质量：随机负例太简单，模型学不到边界；**同 batch 内其他正例 / 高分非相关块**作 hard negative 更有效。

```python
import torch, torch.nn.functional as F

def contrastive_loss(q_emb, d_emb, labels, temperature=0.05):
    """q_emb: (B,D)  query; d_emb: (B,D) 对应doc(可含hard neg在batch内)
    返回 InfoNCE 风格对比损失。"""
    q_emb = F.normalize(q_emb, dim=-1)
    d_emb = F.normalize(d_emb, dim=-1)
    sim = q_emb @ d_emb.t() / temperature          # (B,B)
    return F.cross_entropy(sim, labels)            # labels = 对角线正例索引

# 训练技巧：
#  - 用 in-batch negatives + 显式 hard negatives
#  - 温度 τ 从 0.1 调到 0.02，区分度更尖锐
#  - 评估用检索召回率@K，而非 loss 本身
```

### 2.3 混合检索与重排序 —— "召回决定下限，排序决定上限"

**问题**：
1. 纯向量检索对**精确词面**（合同编号 `CT-2024-0091`、错误码 `E_TIMEOUT`）几乎无效。
2. 召回的块很多，但"真正能回答问题的那块"未必排在最前，LLM 被噪声带偏。

**方案**：向量 + BM25 双路召回 → RRF 融合 → Cross-Encoder 重排 → MMR 去冗余。

**RRF（Reciprocal Rank Fusion，无超参、鲁棒）**：
$$
\text{RRF}(d) = \sum_{r \in \{\text{vec},\text{bm25}\}} \frac{1}{k + \text{rank}_r(d)}, \quad k=60
$$

**MMR（Maximal Marginal Relevance，去冗余、保留多样性）**：
$$
\text{MMR} = \arg\max_{d \in R\setminus S}\;\big[\lambda\cdot \text{sim}(d,q) - (1-\lambda)\cdot\max_{d'\in S}\text{sim}(d,d')\big]
$$

```python
from typing import List, Dict

def rrf_fusion(rank_lists: List[List[str]], k: int = 60) -> List[str]:
    """多路召回结果的 RRF 无参融合。rank_lists: 每路按相关性排序的doc_id列表。"""
    scores: Dict[str, float] = {}
    for rl in rank_lists:
        for rank, doc in enumerate(rl):
            scores[doc] = scores.get(doc, 0.0) + 1.0 / (k + rank + 1)
    return sorted(scores, key=scores.get, reverse=True)

def mmr_select(query_emb, cand_embs, cand_ids, lambda_: float = 0.7, top_n: int = 5):
    """用 MMR 从候选里挑 top_n，兼顾相关性与多样性。"""
    selected, remaining = [], list(range(len(cand_ids)))
    while len(selected) < top_n and remaining:
        best, best_score = None, -1e9
        for i in remaining:
            rel = query_emb @ cand_embs[i]                      # 相关性
            red = max((cand_embs[i] @ cand_embs[j] for j in selected), default=0.0)
            score = lambda_ * rel - (1 - lambda_) * red        # 多样性惩罚
            if score > best_score:
                best_score, best = score, i
        selected.append(best); remaining.remove(best)
    return [cand_ids[i] for i in selected]
```

**重排（Cross-Encoder）**：双塔 embedding 召回快但交互弱；Cross-Encoder 把 `(query, doc)` 拼一起过 BERT，精度高、慢，只用于 Top-N（如 Top-50→Top-5）重排，性价比最佳。

### 2.4 幻觉抑制与引用约束生成 —— "RAG 也会编"

**问题**：即便检索正确，LLM 仍可能输出检索内容里**没有**的信息（过度泛化、捏造细节）。

**方案（三层）**：
1. **Prompt 约束**：要求"只基于给定上下文回答，未知就说不知道；用 `[n]` 标注引用来源"。
2. **后处理校验（Citation Grounding）**：正则解析答案中的 `[n]`，确认每个引用 `n` 确实存在于检索块集合；对"无引用支撑的关键陈述"打标或拒答。
3. **置信度拒答**：若答案中无法映射到检索块的比例超阈值，或检索 score 普遍过低 → 走"建议联系人工/补充知识库"分支。

```python
import re

def validate_citations(answer: str, retrieved_ids: set) -> (bool, list):
    """校验答案里的 [n] 是否都来自检索块；返回(是否合规, 问题角标)。"""
    cites = set(int(x) for x in re.findall(r'\[(\d+)\]', answer))
    missing = sorted(cites - retrieved_ids)
    return (len(missing) == 0), missing

def faithfulness_postcheck(answer: str, contexts: List[str]) -> float:
    """极简忠实度检查：把答案拆句，逐句判断能否在上下文找到依据。
    生产环境用 NLI 小模型或 LLM-as-Judge 替代关键词匹配。"""
    sents = re.split(r'(?<=[。！？])', answer)
    hit = 0
    for s in sents:
        s = s.strip()
        if not s:
            continue
        if any(s[:8] in c for c in contexts):   # 简化：前缀命中
            hit += 1
    return hit / max(1, len([s for s in sents if s.strip()]))
```

### 2.5 大规模向量库与性能 —— "千万级向量、低延迟、高召回"

**问题**：知识库上亿块时，暴力检索 O(N) 不可行；HNSW 召回高但内存大；IVF 快但召回波动。

**方案**：
- **IVF-PQ + 量化**：IVF 聚类分桶缩小搜索范围，PQ（Product Quantization）把 768 维向量压成若干 8-bit 子码，内存降 ~32×，精度损失可控。
- **HNSW 用于热数据**：高频访问的小知识库用 HNSW（图检索，召回高、延迟低）。
- **分层缓存**：热门 query 的检索结果缓存（TTL + 版本失效），命中即返回。

> 经验值：1 亿 768 维 FP32 向量 ≈ 300GB；PQ(8×8bit) 后 ≈ 1GB 级，召回仅降 1~3pp。

### 2.6 长文档与多模态问答 —— "表格和图片它看不懂"

**问题**：企业知识大量是**带表格的 PDF、架构图、截图**。普通文本切分会把表格拆烂，图片信息丢失。

**方案**：
- **表格结构化**：用版式模型抽取表格 → 转 Markdown/CSV → 作为独立块入库（表格语义比截图文本强）。
- **多模态检索（ColPali 思路）**：用视觉语言模型把"页面图像"直接编码为向量，检索时图-文对齐，规避 OCR 误差。
- **分块聚合（Map-Reduce）**：长文档先逐块答，再聚合多块答案（适合"这份 200 页合同里所有付款条款"类问题）。

### 2.7 RAG 评估体系 —— "不度量，就无法优化"

**离线核心指标**：
- **Context Recall**：检索到的块是否覆盖了回答所需事实。
- **Faithfulness（忠实度）**：答案是否完全基于检索上下文（用 NLI / LLM-as-Judge）。
- **Answer Relevancy**：答案是否切题。
- **nDCG@k**：检索排序质量（考虑相关性分级）。

$$
\text{nDCG}@k = \frac{\text{DCG}@k}{\text{IDCG}@k},\quad
\text{DCG}@k = \sum_{i=1}^{k}\frac{2^{rel_i}-1}{\log_2(i+1)}
$$

**在线指标**：用户采纳率、追问/修正率、 Session 内重问率、负反馈率。

```python
def dcg_at_k(rels, k):
    return sum((2**r - 1) / (1 + __import__('math').log2(i + 1))
               for i, r in enumerate(rels[:k], 1))

def ndcg_at_k(rels, k):
    dcg, idcg = dcg_at_k(rels, k), dcg_at_k(sorted(rels, reverse=True), k)
    return dcg / idcg if idcg else 0.0
```

## 📌 三、常见问答（Common Q&A）

### Q1：RAG 和 Fine-tuning 怎么选？什么时候该用哪个？
**答（结构化）**：
- **RAG 擅长**：知识**频繁更新**、需要**溯源/可解释**、知识**外部私有**（不希望"写进权重"）、事实正确性要求高。代价是每次推理都要检索、延迟与检索质量耦合。
- **Fine-tuning 擅长**：学习**稳定风格/格式/能力**（如特定语气、结构化抽取、领域术语映射）、压缩"常用知识"降低推理成本、提升指令遵循。代价是训练成本、知识更新慢、易遗忘、不可溯源。
- **实战组合**：先用 RAG 解决"知识外挂"，再用 SFT/LoRA 微调"表达与格式"，必要再 RLHF 调"偏好"。二者不是二选一，而是**RAG 兜底事实 + FT 优化能力**。

### Q2：检索召回率低，怎么系统性排查？
**答（四层漏斗）**：
1. **数据层**：文档是否解析完整（表格/扫描件丢失？）→ 看解析成功率。
2. **索引层**：切块是否破坏语义（太大/太小？标题丢失？）→ 抽样块质量。
3. **查询层**：用户 query 与文档表述差异大（口语 vs 书面）→ 加 Query Rewrite / 同义词 / HyDE（用 LLM 把问题先扩写成"答案风格"再检索）。
4. **检索层**：纯向量漏词面 → 上 BM25 混合；排序差 → 加 Cross-Encoder 重排；冗余 → MMR。
- **关键动作**：先量化"召回率@10"基线，再逐层 A/B，避免拍脑袋。

### Q3：如何控制 RAG 的幻觉？
**答**：从"检索质量 + 生成约束 + 校验拒答"三段治：
- 检索：混合检索 + 重排，保证**喂给模型的是对的**上下文。
- 生成：Prompt 强制"只依据上下文 + 标注引用 + 不知道就说不知道"。
- 校验：Citation Grounding 后处理 + 忠实度打分，超阈值拒答或转人工。
- 数据闭环：把"低 Faithfulness"的 case 回流，做难负样本和评测集。

### Q4：混合检索里向量和 BM25 怎么融合？RRF 和加权求和的区别？
**答**：
- **加权求和**需手动调 `α·vec_score + (1-α)·bm25_score`，且两路分数分布/量纲不同，需各自归一化，超参敏感、易过拟合某路。
- **RRF** 只用**排名**不用分数：`Σ 1/(k+rank)`，无超参、对分数尺度不敏感、鲁棒，工程首选。
- 进阶：用学习排序（LTR）或 Cross-Encoder 直接对融合后 Top-N 重排，上限更高。

### Q5：RAG 系统如何评估？核心指标有哪些？
**答**：分离线 + 在线。离线看 **Context Recall（检索是否够）**、**Faithfulness（答案是否忠于上下文）**、**Answer Relevancy（是否切题）**、**nDCG（排序质量）**；在线看**采纳率、重问率、负反馈率**。重点：Faithfulness 是 RAG 区别于"裸 LLM"的生命线指标，必须持续监控。

### Q6：海量知识库场景下，如何保证检索实时性和成本？
**答**：
- **增量索引**：文档更新只重建对应块，而非全量（2h→30s）。
- **分层缓存**：热门 query 结果缓存（按知识库 version 失效）。
- **向量压缩**：IVF-PQ / 标量量化，内存降数十倍。
- **重排只跑 Top-N**：向量召回 Top-50，Cross-Encoder 只排 Top-50→Top-5。
- **冷热处理**：热库 HNSW、冷库 IVF-PQ，按访问频率分层。

## 📌 四、模拟面试（3 题 + 参考答案要点）

> 面试官视角：这 3 题分别考察**系统设计（广度）**、**故障排查（深度/工程感）**、**技术选型与数据闭环（权衡与落地）**。回答时务必"先给骨架，再填关键技术决策，最后量化收益"。

### 🎯 模拟题 1：从零设计支持 10 亿文档、日活百万的企业级 RAG 知识库问答系统

**考察点**：端到端架构能力、检索/生成/成本/可观测性的权衡。

**参考答案要点**：
1. **分层架构（见 1.3 六层）**：接入层（限流/租户）→ 文档处理层（解析/切分）→ 索引层（向量+倒排）→ 检索层（重写/混合/重排）→ 生成层（引用约束）→ 评估运营层。
2. **文档处理**：版式感知解析 + 父子文档；表格结构化入库；异步流水线（上传即入队，建库与查询解耦）。
3. **索引与检索**：向量(IVF-PQ/HNSW 冷热分层) + BM25 倒排；RRF 融合；Cross-Encoder 重排 Top-N；MMR 去冗余；Query Rewrite/HyDE 提升召回。
4. **生成**：Context 压缩降噪声；引用约束 + 忠实度校验 + 置信度拒答。
5. **规模与成本**：增量索引（30s/文档）、结果缓存、向量压缩（内存 ~32×↓）、重排只跑 Top-N、模型路由（简单问题用小模型）。
6. **可观测与评估**：全链路 Tracing；离线 Faithfulness/Recall 评测集；在线采纳率飞轮；知识库 version 管理保证缓存一致性。
7. **SLA 示例**：首答 P99 < 1.5s，Faithfulness > 95%，单文档更新 < 30s。

### 🎯 模拟题 2：线上 RAG 系统"答对率"突然从 92% 跌到 70%，如何 30 分钟内定位并止血？

**考察点**：故障排查方法论、可观测性、止血优先级。

**参考答案要点**：
1. **先止血（5 分钟）**：看监控三板斧——检索召回率@10、Faithfulness、首答延迟是否同时异常；若有"知识库刚发布/批量导入"，优先**回滚到上一 version**（增量索引支持快速回滚）。
2. **分层定位（15 分钟）**：
   - 检索层：召回率暴跌 → 查**索引是否损坏/刚重建中断**、Embedding 服务是否异常、BM25 倒排是否未刷新。
   - 查询层：Query Rewrite 模型是否上线变更、prompt 是否改动。
   - 生成层：系统 prompt / 模型版本是否切换（小模型答不好）。
   - 数据层：是否刚导入一批**解析失败的乱码文档**污染了检索。
3. **量化验证（10 分钟）**：抽 20 个 bad case，标注"检索错 / 生成错"，定位根因占比。
4. **长期**：把"Faithfulness 跌破阈值"设为告警；建立 bad case → 评测集 → 回归的闭环。
5. **金句**："先回滚、再定位、用 case 说话，不要靠猜。"

---

### 🎯 模拟题 3：如何用最小成本把 RAG 的"可回答率（覆盖率）"从 60% 提升到 90%？

**考察点**：技术选型性价比、数据飞轮、避免盲目堆模型。

**参考答案要点**（按性价比排序）：
1. **先查"答不上"的根因分布**（不花钱）：抽样发现是"检索不到"还是"检索到但答不出"。
2. **检索不到（占多数时）**：上**混合检索（BM25+RRF）** → 召回率往往 +15~20pp，几乎零训练成本；再加 **Query Rewrite/HyDE** 解决表述差异。
3. **索引质量**：修**切分策略**（父子文档/布局感知）→ 块相关性提升；清理**解析失败文档**。
4. **数据飞轮（低成本持续增益）**：把"答不上/低置信"的 query 回流 → 补录知识库 / 做难负样本 → 评测集扩大 → 周级迭代。
5. **必要时才微调 Embedding**：前几步做完若还差一截，再做领域对比微调（hard negative），而非一上来就训模型。
6. **兜底设计**：覆盖率缺口用"转人工 / 引导补充知识"承接，避免硬编。
7. **量化**：混合检索 + 切分优化常可贡献 60%→85%；剩余靠数据飞轮 + 微调补到 90%。

## 📌 速记卡（面试前 5 分钟过一遍）

| 维度 | 一句话 |
|------|--------|
| 项目定位 | 私域知识 + 可溯源 + 控幻觉 + 可度量的 RAG 平台 |
| 召回 | 向量(语义) + BM25(词面) → RRF 融合 → Cross-Encoder 重排 → MMR |
| 切分 | 布局感知 + 父子文档（子检索、父生成） |
| 控幻觉 | Prompt 约束 + Citation Grounding 校验 + 置信度拒答 |
| 增量 | (tenant,doc_id,version) 管理，单文档增量 < 30s |
| 评估 | 离线 Faithfulness/Recall/nDCG + 在线采纳率 |
| 规模 | IVF-PQ 压缩、冷热分层、结果缓存、重排只跑 Top-N |
| 选 RAG vs FT | RAG 兜底事实/更新快/可溯源；FT 优化风格/能力/成本 |

**核心公式**：
- RRF：$\text{RRF}(d)=\sum 1/(k+\text{rank})$，k=60
- MMR：$\max[\lambda\cdot\text{sim}(d,q)-(1-\lambda)\max_{d'\in S}\text{sim}(d,d')]$
- InfoNCE：$\mathcal{L}=-\log\frac{e^{\text{sim}(q,d^+)/\tau}}{e^{\text{sim}(q,d^+)/\tau}+\sum e^{\text{sim}(q,d^-)/\tau}}$
- nDCG：$\text{DCDC}@k=\sum(2^{rel_i}-1)/\log_2(i+1)$
