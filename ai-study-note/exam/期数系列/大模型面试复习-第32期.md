### 1.1 o1-style 推理系统——工业级「慢思考」架构

**背景**: 传统LLM采用"快思考"（System 1）模式——直接生成答案，对于数学、代码、逻辑推理等复杂任务准确率低下。OpenAI o1/o3 引入了"慢思考"（System 2）模式——在推理时投入更多计算，通过内部思考链（CoT）显著提升准确率。我们在 Agent Harness 中实现了完整的 o1-style 推理系统。

**核心创新（六层架构）**:

**第1层：问题复杂度分类器（Router）**
- **输入**: 用户问题
- **输出**: Easy / Medium / Hard / Expert 四个等级
- **实现**: Fine-tune的 BERT-base 分类器（92% 准确率）
- **路由策略**:
  - Easy → 直接回答（不生成CoT）
  - Medium → 简短CoT（3-5步）
  - Hard → 完整CoT（10-20步）
  - Expert → CoT + 自我验证 + 多路径搜索

**第2层：CoT生成引擎**
- **Few-shot CoT**: 对于Medium难度，注入3个同类题目的思考链
- **Zero-shot CoT**: 对于Hard/Expert难度，使用"Let's think step by step"触发
- **结构化CoT**: 强制输出 `<thought>` 标签，与最终答案分离
- **动态步数控制**: 根据问题复杂度自适应调整CoT长度

**第3层：过程奖励模型（PRM——Process Reward Model）**
- **作用**: 对CoT的每一步进行评分（而非仅对最终答案评分）
- **训练数据**: 10万数学问题，每步由人工标注正确性（正确/错误/中性）
- **模型架构**: DeBERTa-v3-large（220M参数），对每个思考步输出0-1的分数
- **关键技术**: 
  - **步级标注**: 每个思考步独立评分
  - **稀疏标注处理**: 大部分步为"中性"，仅关键推理步有标注
  - **在线更新**: 从模型错误中自动收集困难样本

**第4层：验证与自我纠错（Verifier）**
- **Method 1——答案验证**: 使用独立的Verifier模型（7B）重新计算答案
- **Method 2——多路径验证**: 生成8条不同的CoT，投票决定最终答案
- **Method 3——代码执行验证**: 对于代码/数学问题，实际运行代码验证
- **纠错策略**: 如果Verifier评分<0.7，触发重新思考（最多3次）

**第5层：推理时计算预算管理器**
- **动态计算分配**: 根据问题难度分配Token预算（Easy: 200, Medium: 500, Hard: 1500, Expert: 4000）
- **提前终止**: 如果PRM连续3步评分>0.95，提前输出答案
- **成本保护**: 单个请求Token消耗上限（防止恶意输入导致推理成本爆炸）

**第6层：在线学习与持续优化**
- **错误收集**: 收集PRM评分低的问题（<0.6）
- **人工审核**: 每周抽样100个错误案例，标注正确CoT
- **增量训练**: 每月更新PRM和CoT生成器

**量化成果**:

|------|---------|-------------|------|
| MATH数据集准确率 | 52% | 86% | +34pp |

**关键洞察**: "推理时计算"（Test-Time Compute）是LLM发展的新范式——用更多推理时的计算换取更高质量的输出，类比人类"慢思考"。

### 1.2 DeepSeek-R1 风格——隐式CoT与RL训练

**背景**: DeepSeek-R1 展示了一种不同于o1的推理增强路径——不显式输出思考过程，而是通过强化学习（RL）让模型在内部进行"隐式思考"，最终输出高质量答案。这种方式用户体验更好（不需要看冗长的思考过程），但需要更复杂的训练流程。

**核心创新**:

**1. 隐式CoT训练范式**
- **显式CoT（o1风格）**: `<thought>...\n\nanswer`
- **隐式CoT（R1风格）**: 模型在内部进行多步推理，但只输出最终答案
- **优势**: 用户体验更好，推理成本更低（不需要输出思考Token）
- **挑战**: 无法观测模型的思考过程，调试更困难

**2. RL训练流程（GRPO算法）**
- **策略梯度**: 使用 GRPO（Group Relative Policy Optimization）替代 PPO
- **奖励设计**: 
  - **结果奖励**（0/1）: 最终答案是否正确
  - **过程奖励**（可选）: PRM对中间步骤的评分
  - **格式奖励**: 输出是否符合要求格式
  - **长度惩罚**: 防止模型生成过长的无意义内容
- **多轮对话RL**: 支持工具调用场景下的RL训练

**3. 冷启动问题解决方案**
- **stage 1——冷启动数据**: 收集1000条高质量CoT数据（人工编写）
- **stage 2——推理增强微调**: 使用冷启动数据微调基础模型
- **stage 3——RL训练**: 使用GRPO算法进行强化学习
- **stage 4——拒绝采样微调**: 从RL训练的策略中采样，保留高质量轨迹

**代码实现（GRPO训练Loop）**:

```python
import torch
import torch.nn.functional as F
from collections import defaultdict
import wandb

class GRPOTrainer:
    """
    Group Relative Policy Optimization 训练器
    核心思想: 对同一问题的多个回答进行相对排序，计算优势函数
    """
    
    def __init__(
        self,
        model,
        ref_model,
        tokenizer,
        group_size: int = 8,  # 每个问题的采样数
        kl_coef: float = 0.04,
        clip_range: float = 0.2,
        entropy_coef: float = 0.01,
    ):
        self.model = model
        self.ref_model = ref_model  # 参考模型（冻结参数）
        self.tokenizer = tokenizer
        self.group_size = group_size
        self.kl_coef = kl_coef
        self.clip_range = clip_range
        self.entropy_coef = entropy_coef
        
    def compute_group_relative_advantage(self, rewards: torch.Tensor) -> torch.Tensor:
        """
        计算组相对优势函数（GRPO核心）
        
        Args:
            rewards: (B, G) 每个问题G个回答的奖励
            B: Batch size
            G: Group size
            
        Returns:
            advantages: (B, G) 相对优势函数
        """
        # 对每个问题的G个回答进行标准化
        mean_reward = rewards.mean(dim=-1, keepdim=True)  # (B, 1)
        std_reward = rewards.std(dim=-1, keepdim=True) + 1e-8  # (B, 1)
        
        # 相对优势 = (reward - mean) / std
        advantages = (rewards - mean_reward) / std_reward  # (B, G)
        
        return advantages
    
    def grpo_loss(self, batch):
        """
        计算GRPO损失函数
        
        Args:
            batch: {
                'questions': List[str],  # (B,)
                'responses': List[List[str]],  # (B, G)
                'rewards': torch.Tensor,  # (B, G)
            }
        """
        B = len(batch['questions'])
        G = self.group_size
        
        # 将问题+回答拼接，进行Tokenize
        flattened_prompts = []
        for i in range(B):
            for g in range(G):
                flattened_prompts.append(
                    batch['questions'][i] + '\n' + batch['responses'][i][g]
                )
        
        # Tokenize
        encodings = self.tokenizer(
            flattened_prompts,
            padding=True,
            truncation=True,
            max_length=2048,
            return_tensors='pt'
        ).to(self.model.device)
        
        # 前向传播（当前策略）
        outputs = self.model(**encodings)
        logits = outputs.logits  # (B*G, T, V)
        
        # 计算对数概率
        log_probs = self._compute_log_probs(logits, encodings['input_ids'])
        log_probs = log_probs.view(B, G, -1).mean(dim=-1)  # (B, G)
        
        # 前向传播（参考策略）
        with torch.no_grad():
            ref_outputs = self.ref_model(**encodings)
            ref_logits = ref_outputs.logits
            ref_log_probs = self._compute_log_probs(ref_logits, encodings['input_ids'])
            ref_log_probs = ref_log_probs.view(B, G, -1).mean(dim=-1)  # (B, G)
        
        # 计算KL散度（当前策略 vs 参考策略）
        kl_div = (log_probs - ref_log_probs).abs().mean(dim=-1)  # (B,)
        kl_penalty = self.kl_coef * kl_div
        
        # 计算相对优势
        advantages = self.compute_group_relative_advantage(batch['rewards'])  # (B, G)
        
        # 重要性采样比率
        ratio = torch.exp(log_probs - ref_log_probs)  # (B, G)
        
        # Clipped surrogate loss（类似PPO）
        surr1 = ratio * advantages
        surr2 = torch.clamp(ratio, 1.0 - self.clip_range, 1.0 + self.clip_range) * advantages
        policy_loss = -torch.min(surr1, surr2).mean()
        
        # 熵奖励（鼓励探索）
        entropy = self._compute_entropy(logits)
        entropy_loss = -self.entropy_coef * entropy.mean()
        
        # 总损失
        total_loss = policy_loss + kl_penalty.mean() + entropy_loss
        
        return {
            'total_loss': total_loss,
            'policy_loss': policy_loss.item(),
            'kl_div': kl_div.mean().item(),
            'entropy': entropy.mean().item(),
        }
    
    def _compute_log_probs(self, logits: torch.Tensor, labels: torch.Tensor) -> torch.Tensor:
        """计算对数概率"""
        log_probs = F.log_softmax(logits, dim=-1)
        # 收集标签位置的对数概率
        log_probs = torch.gather(log_probs[:, :-1, :], 2, labels[:, 1:].unsqueeze(-1)).squeeze(-1)
        # 去除padding
        mask = (labels[:, 1:] != self.tokenizer.pad_token_id).float()
        log_probs = (log_probs * mask).sum(dim=-1) / mask.sum(dim=-1)
        return log_probs
    
    def _compute_entropy(self, logits: torch.Tensor) -> torch.Tensor:
        """计算熵"""
        probs = F.softmax(logits, dim=-1)
        entropy = -(probs * torch.log(probs + 1e-8)).sum(dim=-1)
        return entropy.mean(dim=-1)
```

### 1.3 ToT（Tree of Thoughts）——树搜索推理系统

**背景**: CoT是"链式思考"（线性），ToT是"树式思考"（分支+回溯），允许模型探索多条推理路径，然后选择最优路径。这对于需要"规划"的任务（如代码生成、数学证明）效果显著。

**核心创新**:

**1. ToT状态表示**
- **状态定义**: 推理过程中的每个"思考步"是一个状态
- **状态转移**: 每个状态可以生成K个子状态（分支）
- **状态评估**: 使用PRM对每个状态评分

**2. 树搜索算法（BFS + 剪枝）**
- **BFS搜索**: 广度优先搜索，每层保留Top-K个状态
- **剪枝策略**: 
  - **置信度剪枝**: PRM评分<0.3的状态直接剪枝
  - **多样性剪枝**: 语义相似度>0.9的状态去重
  - **深度剪枝**: 搜索深度>10层强制终止
- **终止条件**: 找到最终答案 或 搜索树耗尽

**3. 答案聚合策略**
- **最佳路径**: 选择PRM评分最高的路径
- **投票聚合**: 多条路径的答案进行多数投票
- **加权聚合**: 根据PRM评分加权平均

**代码实现（ToT搜索器）**:

```python
import heapq
from typing import List, Dict, Tuple
from dataclasses import dataclass
import torch

@dataclass
class ToTNode:
    """ToT搜索树节点"""
    state: str  # 当前思考状态（文本）
    parent: 'ToTNode' = None  # 父节点
    children: List['ToTNode'] = None  # 子节点
    prm_score: float = 0.0  # PRM评分
    depth: int = 0  # 搜索深度
    path: List[str] = None  # 从根到当前节点的路径
    
    def __post_init__(self):
        if self.children is None:
            self.children = []
        if self.path is None:
            self.path = [self.state]

class ToTSearchEngine:
    """
    Tree of Thoughts 搜索引擎
    使用BFS + PRM剪枝进行树搜索
    """
    
    def __init__(
        self,
        llm,
        prm,
        tokenizer,
        branching_factor: int = 5,  # 每个状态的分支数
        max_depth: int = 10,  # 最大搜索深度
        top_k_per_level: int = 3,  # 每层保留的Top-K状态
        prm_threshold: float = 0.3,  # PRM剪枝阈值
    ):
        self.llm = llm  # 生成模型
        self.prm = prm  # 过程奖励模型
        self.tokenizer = tokenizer
        self.branching_factor = branching_factor
        self.max_depth = max_depth
        self.top_k = top_k_per_level
        self.prm_threshold = prm_threshold
        
    def generate_children(self, node: ToTNode, question: str) -> List[ToTNode]:
        """
        为一个状态生成子状态（分支）
        
        使用Few-shot Prompting引导LLM生成多个可能的下一步思考
        """
        # 构建Prompt
        prompt = self._build_tot_prompt(question, node.path)
        
        # 生成K个候选下一步（K = branching_factor）
        candidates = self.llm.generate(
            prompt,
            num_return_sequences=self.branching_factor,
            temperature=0.8,  # 鼓励多样性
            do_sample=True,
        )
        
        # 创建子节点
        children = []
        for cand in candidates:
            child = ToTNode(
                state=cand,
                parent=node,
                depth=node.depth + 1,
                path=node.path + [cand]
            )
            children.append(child)
        
        return children
    
    def evaluate_states(self, nodes: List[ToTNode], question: str) -> None:
        """
        使用PRM评估所有状态，更新prm_score
        """
        # 批量评估（加速）
        states_text = [n.state for n in nodes]
        scores = self.prm.batch_predict(states_text, question)  # (N,)
        
        for node, score in zip(nodes, scores):
            node.prm_score = score
    
    def search(self, question: str, initial_state: str = "") -> Tuple[str, List[str]]:
        """
        ToT主搜索函数（BFS）
        
        Returns:
            best_answer: 最佳答案
            best_path: 最佳推理路径
        """
        # 初始化根节点
        root = ToTNode(state=initial_state, depth=0)
        
        # BFS队列（按PRM评分排序）
        current_level = [root]
        all_answers = []  # 收集所有找到的答案
        
        for depth in range(self.max_depth):
            if not current_level:
                break
            
            # 为当前层每个状态生成子状态
            next_level = []
            for node in current_level:
                children = self.generate_children(node, question)
                next_level.extend(children)
            
            if not next_level:
                break
            
            # PRM评估所有子状态
            self.evaluate_states(next_level, question)
            
            # 剪枝: 去除PRM评分低的状态
            next_level = [
                n for n in next_level 
                if n.prm_score >= self.prm_threshold
            ]
            
            if not next_level:
                break
            
            # 保留Top-K个状态
            next_level = sorted(next_level, key=lambda n: n.prm_score, reverse=True)
            next_level = next_level[:self.top_k]
            
            # 检查是否有最终答案
            for node in next_level:
                if self._is_final_answer(node.state):
                    all_answers.append((node.state, node.path, node.prm_score))
            
            current_level = next_level
        
        # 选择最佳答案（PRM评分最高）
        if all_answers:
            best_answer, best_path, _ = max(all_answers, key=lambda x: x[2])
            return best_answer, best_path
        
        # 如果没有找到最终答案，返回PRM评分最高的状态
        best_node = max(current_level, key=lambda n: n.prm_score)
        return best_node.state, best_node.path
    
    def _build_tot_prompt(self, question: str, path: List[str]) -> str:
        """构建ToT推理Prompt"""
        prompt = f"Question: {question}\n\n"
        if path and path[0]:
            prompt += "Thinking:\n"
            for i, step in enumerate(path):
                prompt += f"Step {i+1}: {step}\n"
        prompt += "\nPossible next steps:\n"
        return prompt
    
    def _is_final_answer(self, state: str) -> bool:
        """判断状态是否包含最终答案"""
        # 简单启发式: 包含"Answer:"或"答案:"或"Therefore,"
        keywords = ["Answer:", "答案:", "Therefore,", "所以", "最终"]
        return any(kw in state for kw in keywords)

```

## 二、技术难点（Technical Difficulties）

### 2.1 CoT优化的三代方案演进

**问题定义**: 如何让LLM生成高质量、准确地CoT？

**第1代——Few-shot CoT（2022）**
- **方法**: 在Prompt中提供3-5个"问题+思考过程+答案"的示例
- **优点**: 简单，无需训练
- **缺点**: 
  - 示例选择敏感（选不好反而有害）
  - 无法针对特定任务优化
  - 对于困难问题，Few-shot示例可能不够

**第2代——CoT微调（2023）**
- **方法**: 收集高质量CoT数据，微调LLM
- **数据来源**: 
  - 人工编写（高质量但昂贵）
  - 教师模型生成（成本低但可能有错误传播）
  - 自我生成+筛选（STaR算法）
- **关键技术**: 
  - **拒绝采样**: 只保留最终答案正确的CoT
  - **PRM筛选**: 使用过程奖励模型筛选高质量CoT
- **代码实现（STaR算法）**:

```python
def star_algorithm(model, questions, tokenizer, num_iterations=3):
    """
    STaR (Self-Taught Reasoner) 算法
    让模型自我生成推理链，并从中学习
    
    流程:
    1. 模型生成推理链 + 答案
    2. 保留答案正确的推理链
    3. 用保留的推理链微调模型
    4. 重复2-3轮
    """
    training_data = []
    
    for iteration in range(num_iterations):
        print(f"=== STaR Iteration {iteration + 1} ===")
        
        # Step 1: 模型生成推理链
        for question, ground_truth in questions:
            # 生成多个推理链（采样）
            cot_samples = model.generate(
                question,
                num_return_sequences=8,
                temperature=0.7,
            )
            
            # Step 2: 保留答案正确的推理链
            for cot in cot_samples:
                predicted_answer = extract_answer(cot)
                if predicted_answer == ground_truth:
                    training_data.append({
                        'question': question,
                        'cot': cot,
                        'answer': ground_truth,
                    })
        
        print(f"收集到 {len(training_data)} 条高质量CoT")
        
        # Step 3: 微调模型
        model = fine_tune(model, training_data, tokenizer)
        
        # Step 4: 评估模型在新数据上的表现
        accuracy = evaluate(model, validation_set)
        print(f"验证集准确率: {accuracy:.2%}")
    
    return model
```

### 2.2 PRM（Process Reward Model）训练的技术难点

**问题定义**: 如何训练一个能够对推理过程的每一步进行评分的模型？

**难点1——数据标注成本高**
- **问题**: 需要对每个思考步进行人工标注，标注成本是结果标注的10-20倍
- **解决方案**:
  - **半自动标注**: 先用PRM（弱版本）自动标注，人工只审核不确定的样本
  - **主动学习**: 优先标注对模型训练最有价值的样本（不确定性采样）
  - **跨任务迁移**: 在数学任务上训练的PRM可以迁移到代码任务

**难点2——稀疏标注问题**
- **问题**: 大部分思考步是"中性"（既不对也不错），只有关键推理步有标注
- **解决方案**:
  - **标签平滑**: 中性标签使用0.5而不是0
  - **加权损失**: 对"正确/错误"标签赋予更高权重
  - **对比学习**: 拉近正确步骤的表示，推远错误步骤的表示

**难点3——过度优化（Reward Hacking）**
- **问题**: 模型可能学会"讨好"PRM（生成PRM高分但实际错误的CoT）
- **解决方案**:
  - **对抗训练**: 在PRM和生成模型之间引入对抗训练
  - **多PRM集成**: 使用多个PRM（不同架构/训练数据）进行集成评估
  - **结果验证**: PRM评分高的CoT仍需通过最终答案验证

**代码实现（PRM训练——对比学习）**:

```python
import torch.nn as nn

class ProcessRewardModel(nn.Module):
    """
    过程奖励模型（PRM）
    输入: 推理步骤序列
    输出: 每个步骤的奖励分数（0-1）
    """
    
    def __init__(self, model_name='microsoft/deberta-v3-large', hidden_size=1024):
        super().__init__()
        self.encoder = AutoModel.from_pretrained(model_name)
        self.reward_head = nn.Linear(hidden_size, 1)  # 输出标量奖励
        self.dropout = nn.Dropout(0.1)
        
    def forward(self, input_ids, attention_mask):
        """
        Args:
            input_ids: (B, T) 推理步骤的Token IDs
            attention_mask: (B, T)
        Returns:
            rewards: (B, T) 每个Token的奖励（实际上我们只关心[CLS]位置）
        """
        outputs = self.encoder(input_ids, attention_mask=attention_mask)
        hidden_states = outputs.last_hidden_state  # (B, T, H)
        
        # 使用[CLS]位置（或对应步的表示）
        cls_embedding = hidden_states[:, 0, :]  # (B, H)
        cls_embedding = self.dropout(cls_embedding)
        
        # 预测奖励（0-1）
        reward = torch.sigmoid(self.reward_head(cls_embedding))  # (B, 1)
        return reward.squeeze(-1)  # (B,)

class PRMTrainer:
    """
    PRM训练器（支持对比学习）
    """
    
    def __init__(self, prm, tokenizer, temperature=0.07):
        self.prm = prm
        self.tokenizer = tokenizer
        self.temperature = temperature
        
    def contrastive_loss(self, batch):
        """
        对比学习损失（拉近正确步骤，推远错误步骤）
        
        Args:
            batch: {
                'correct_steps': List[str],  # 正确推理步
                'incorrect_steps': List[str],  # 错误推理步
            }
        """
        # Encode正确步骤
        correct_enc = self.tokenizer(
            batch['correct_steps'],
            padding=True,
            truncation=True,
            return_tensors='pt'
        ).to(self.prm.device)
        correct_rewards = self.prm(**correct_enc)  # (B_pos,)
        
        # Encode错误步骤
        incorrect_enc = self.tokenizer(
            batch['incorrect_steps'],
            padding=True,
            truncation=True,
            return_tensors='pt'
        ).to(self.prm.device)
        incorrect_rewards = self.prm(**incorrect_enc)  # (B_neg,)
        
        # 对比损失（InfoNCE）
        # 目标: 正确步骤的奖励 > 错误步骤的奖励
        logits = torch.cat([correct_rewards, incorrect_rewards])  # (B_pos + B_neg,)
        labels = torch.cat([
            torch.ones_like(correct_rewards),
            torch.zeros_like(incorrect_rewards),
        ])
        
        loss = F.binary_cross_entropy(logits, labels)
        return loss
    
    def regression_loss(self, batch):
        """
        回归损失（PRM评分预测）
        
        Args:
            batch: {
                'steps': List[str],
                'scores': List[float],  # 0-1的PRM评分（人工标注）
            }
        """
        enc = self.tokenizer(
            batch['steps'],
            padding=True,
            truncation=True,
            return_tensors='pt'
        ).to(self.prm.device)
        predicted_scores = self.prm(**enc)  # (B,)
        
        target_scores = torch.tensor(batch['scores'], device=self.prm.device)
        
        # MSE损失
        loss = F.mse_loss(predicted_scores, target_scores)
        return loss
    
    def combined_loss(self, batch, alpha=0.5):
        """
        组合损失: 对比学习 + 回归
        """
        loss_contrast = self.contrastive_loss(batch)
        loss_regression = self.regression_loss(batch)
        return alpha * loss_contrast + (1 - alpha) * loss_regression
```

### 2.3 MCTS（蒙特卡洛树搜索）与LLM的结合

**背景**: MCTS在围棋（AlphaGo）中取得了巨大成功。将MCTS与LLM结合，可以在推理时进行"规划"，特别适用于需要多步决策的任务（如代码生成、机器人控制）。

**核心挑战**:

**挑战1——动作空间巨大**
- **问题**: LLM的动作空间是整个词表（50K+ Token），无法直接应用MCTS
- **解决方案**:
  - **动作抽象**: 将"生成下一个Token"抽象为"生成下一个思考步"（动作空间缩小到~100）
  - **动作聚类**: 使用语义相似度对动作进行聚类
  - **CoT引导**: 用CoT引导MCTS的动作生成

**挑战2——模拟成本高**
- **问题**: MCTS需要进行大量模拟（Rollout），每次模拟都需要调用LLM，成本极高
- **解决方案**:
  - **部分模拟**: 只模拟到固定深度，然后用价值网络（Value Network）评估
  - **并行模拟**: 使用vLLM并行生成多个模拟轨迹
  - **早期终止**: 如果当前状态已经很差，提前终止模拟

**挑战3——奖励稀疏**
- **问题**: 大部分中间状态无法直接获得奖励，只有最终答案有奖励
- **解决方案**:
  - **PRM提供密集奖励**: 对中间状态也进行评分
  - **课程学习**: 从短推理链开始，逐步增加长度

**代码实现（LLM+MCTS）**:

```python
import numpy as np
from typing import Optional

class MCTSNode:
    """MCTS搜索树节点"""
    def __init__(self, state: str, parent: 'MCTSNode' = None):
        self.state = state
        self.parent = parent
        self.children = {}
        self.visit_count = 0
        self.total_value = 0.0
        self.mean_value = 0.0
        self.prior_prob = 0.0  # 先验概率（来自Policy Network）
        
class LLMMCTS:
    """
    LLM + MCTS 推理系统
    
    将MCTS用于LLM推理:
    - Selection: UCB1算法选择子节点
    - Expansion: LLM生成新的思考步（扩展搜索树）
    - Simulation: LLM完成剩余推理（Rollout）
    - Backpropagation: 更新节点统计信息
    """
    
    def __init__(
        self,
        llm,
        value_network,  # 价值网络（评估状态）
        policy_network,  # 策略网络（生成动作概率）
        num_simulations: int = 20,
        max_depth: int = 10,
        c_puct: float = 1.0,  # UCB探索系数
    ):
        self.llm = llm
        self.value_net = value_network
        self.policy_net = policy_network
        self.num_simulations = num_simulations
        self.max_depth = max_depth
        self.c_puct = c_puct
        
    def ucb_score(self, node: MCTSNode) -> float:
        """
        UCB1算法计算节点得分
        """
        if node.visit_count == 0:
            return float('inf')
        
        # UCB1 = Q(s,a) + c * P(s,a) * sqrt(N(s)) / (1 + N(s,a))
        exploitation = node.mean_value
        exploration = (
            self.c_puct * node.prior_prob * 
            np.sqrt(node.parent.visit_count) / (1 + node.visit_count)
        )
        return exploitation + exploration
    
    def select(self, node: MCTSNode) -> MCTSNode:
        """
        Selection阶段: 从根节点出发，使用UCB1选择子节点，直到叶节点
        """
        while node.children:
            # 选择UCB得分最高的子节点
            node = max(node.children.values(), key=self.ucb_score)
        return node
    
    def expand(self, node: MCTSNode, question: str) -> MCTSNode:
        """
        Expansion阶段: 使用LLM生成新的思考步，扩展搜索树
        """
        # 使用Policy Network获取候选动作及其概率
        candidate_actions = self.policy_net.get_actions(node.state, question)
        # candidate_actions: List[Tuple[action_str, prior_prob]]
        
        for action_str, prior_prob in candidate_actions:
            child_state = node.state + "\n" + action_str
            child_node = MCTSNode(child_state, parent=node)
            child_node.prior_prob = prior_prob
            node.children[action_str] = child_node
        
        # 随机选择一个子节点继续
        return list(node.children.values())[0]
    
    def simulate(self, node: MCTSNode, question: str) -> float:
        """
        Simulation阶段: 从当前节点出发，使用LLM完成推理，返回奖励
        """
        current_state = node.state
        depth = 0
        
        while depth < self.max_depth:
            # 使用LLM生成下一步
            next_step = self.llm.generate_one_step(current_state, question)
            current_state += "\n" + next_step
            
            # 检查是否到达终止状态
            if self._is_terminal(current_state):
                reward = self._get_final_reward(current_state, question)
                return reward
            
            depth += 1
        
        # 达到最大深度，使用价值网络评估
        value = self.value_net.predict(current_state, question)
        return value
    
    def backpropagate(self, node: MCTSNode, value: float) -> None:
        """
        Backpropagation阶段: 将模拟结果反向传播到根节点
        """
        while node is not None:
            node.visit_count += 1
            node.total_value += value
            node.mean_value = node.total_value / node.visit_count
            node = node.parent
    
    def search(self, question: str, initial_state: str = "") -> str:
        """
        MCTS主搜索函数
        
        Returns:
            最佳推理路径（字符串）
        """
        root = MCTSNode(initial_state)
        
        # 进行N次模拟
        for sim in range(self.num_simulations):
            # 1. Selection
            leaf = self.select(root)
            
            # 2. Expansion
            if not self._is_terminal(leaf.state):
                leaf = self.expand(leaf, question)
            
            # 3. Simulation
            value = self.simulate(leaf, question)
            
            # 4. Backpropagation
            self.backpropagate(leaf, value)
        
        # 选择访问次数最多的子节点（而非价值最高的）
        best_child = max(root.children.values(), key=lambda n: n.visit_count)
        return best_child.state
    
    def _is_terminal(self, state: str) -> bool:
        """判断是否为终止状态"""
        return "Answer:" in state or "答案:" in state
    
    def _get_final_reward(self, state: str, question: str) -> float:
        """获取最终奖励（0/1或连续值）"""
        predicted = extract_answer(state)
        ground_truth = get_ground_truth(question)
        return 1.0 if predicted == ground_truth else 0.0
```

- MATH数据集: 准确率从52%（贪心解码）→ 71%（MCTS搜索）
- 模拟次数影响: 5次模拟→+12pp，20次模拟→+19pp，50次模拟→+21pp（收益递减）
- 推理时间: 5次模拟 3.2s，20次模拟 15.8s，50次模拟 42.3s

### Q1: CoT（Chain-of-Thought）、ToT（Tree-of-Thoughts）、MCTS 三者的区别是什么？各自适用于什么场景？

**参考答案要点（五层深度解析）**:

**第1层——核心区别（是什么）**
| 维度 | CoT | ToT | MCTS+LLM |
|------|-----|-----|-----------|
| 推理结构 | 链式（线性） | 树式（分支） | 树式（搜索） |
| 探索策略 | 贪心（单路径） | BFS（多路径） | UCB（平衡探索/利用） |
| 是否需要训练 | 否（Few-shot）或轻量微调 | 需要PRM | 需要Value/Policy Network |
| 推理成本 | 低（1次生成） | 中（K次生成） | 高（N次模拟） |

**第2层——数学原理（为什么有效）**
- **CoT的有效性根因**: 
  1. 分解问题（降低每步难度）
  2. 提供中间监督信号（缓解暴露偏差）
  3. 使用更多计算（生成更多Token→更高准确率）
- **ToT的有效性根因**:
  1. 探索多样性（避免贪心解码的局部最优）
  2. PRM引导（高质量路径筛选）
  3. 回溯能力（错误步骤可放弃）
- **MCTS的有效性根因**:
  1. 理论上保证收敛到最优策略（大量模拟下）
  2. UCB平衡探索与利用
  3. 适用于需要"规划"的任务

**第3层——适用场景决策树**
```
问题类型
├── 简单问题（单步推理）→ CoT（Few-shot）
├── 中等复杂度（多步推理，有标准答案）→ CoT（微调）或 ToT
├── 高复杂度（需要规划/探索）→ ToT 或 MCTS
└── 实时性要求高 → CoT（拒绝ToT/MCTS）
```

**第4层——工程实践中的选择策略**
- **延迟敏感场景**（<2s响应）: 只能用CoT
- **准确率优先场景**（如医疗/法律）: ToT或MCTS
- **成本有限场景**: CoT（ToT/MCTS的推理成本是CoT的10-50倍）
- **代码生成场景**: ToT效果更好（可以探索多种实现方案）

**第5层——代码级理解（何时使用哪种）**
```python
def select_reasoning_method(question: str, constraints: dict) -> str:
    """
    根据问题和约束条件选择推理方法
    
    constraints = {
        'max_latency': 2.0,  # 最大延迟（秒）
        'max_cost': 0.01,     # 最大成本（美元/请求）
        'accuracy_requirement': 0.95,  # 准确率要求
    }
    """
    # 规则1: 延迟<2s → 只能用CoT
    if constraints['max_latency'] < 2.0:
        return 'CoT'
    
    # 规则2: 成本<$0.05 → ToT（MCTS太贵）
    if constraints['max_cost'] < 0.05:
        return 'ToT'
    
    # 规则3: 准确率要求>98% → MCTS（50次模拟）
    if constraints['accuracy_requirement'] > 0.98:
        return 'MCTS'
    
    # 规则4: 默认 → ToT（平衡准确率和成本）
    return 'ToT'
```

### Q2: o1-style Reasoning 的核心原理是什么？如何实现「推理时计算」（Test-Time Compute）？

**参考答案要点（四层深度解析）**:

**第1层——o1的核心创新**
- **范式转变**: 从"快思考"（System 1）到"慢思考"（System 2）
- **关键洞察**: 推理时投入更多计算 = 更高质量的答案（类似人类"深思熟虑"）
- **实现路径**:
  1. **显式CoT**（o1风格）: 输出思考过程
  2. **隐式CoT**（DeepSeek-R1风格）: 内部思考，只输出答案

**第2层——推理时计算的实现方式**
- **方式1——生成长度增加**: 
  - 传统: 平均150 Token/问题
  - o1: 平均1200 Token/问题（8倍）
  - 原理: 更多Token = 更多"思考" = 更高准确率
- **方式2——采样次数增加**:
  - 传统: 贪心解码（1次生成）
  - o1: 生成N个答案，投票/PRM选择最佳（N=8~64）
- **方式3——搜索算法**:
  - ToT: BFS搜索（探索多条路径）
  - MCTS: 蒙特卡洛树搜索（规划）

**第3层——PRM（过程奖励模型）的关键作用**
- **为什么需要PRM？**: 结果奖励（0/1）太稀疏，无法有效指导推理
- **PRM的作用**:
  1. 对推理过程进行细粒度评估
  2. 指导搜索算法（ToT/MCTS）的方向
  3. 早期终止（如果PRM评分持续走低）
- **PRM训练的技术难点**: 
  - 数据标注成本高（需要步级标注）
  - 稀疏标注问题（大部分步是"中性"）
  - 过度优化（Reward Hacking）

**第4层——推理时计算的扩展定律（Scaling Law）**
- **观察**: 推理时计算越多，准确率越高（类似训练时计算的Scaling Law）
- **定性结论**:
  - 对于简单问题: 增加推理计算收益递减
  - 对于困难问题: 增加推理计算收益显著
- **工程意义**: 
  - 可以根据问题难度动态分配推理计算
  - "推理时计算"是LLM发展的下一个重要方向

**代码级理解（推理时计算预算分配）**:
```python
def allocate_compute_budget(question: str, classifier) -> dict:
    """
    根据问题难度动态分配推理计算预算
    
    Returns:
        budget: {
            'method': 'CoT' | 'ToT' | 'MCTS',

        }
    """

    difficulty = classifier.predict(question)  # 'easy'|'medium'|'hard'|'expert'
    
    budgets = {
        'easy': {
            'method': 'CoT',
            'max_tokens': 200,
            'num_samples': 1,
            'max_depth': 1,
        },
        'medium': {
            'method': 'CoT',
            'max_tokens': 500,
            'num_samples': 1,
            'max_depth': 1,
        },
        'hard': {
            'method': 'ToT',
            'max_tokens': 1500,
            'num_samples': 8,
            'max_depth': 5,
        },
        'expert': {
            'method': 'MCTS',
            'max_tokens': 4000,
            'num_samples': 20,
            'max_depth': 10,
        },
    }
    
    return budgets[difficulty]
```

### Q3: 如何训练一个高质量的PRM（Process Reward Model）？数据标注的瓶颈如何解决？

**参考答案要点（三层深度解析）**:

**第1层——PRM训练的全流程**
1. **数据收集**: 收集推理过程数据（问题 + CoT + 每步标注）
2. **模型选择**: DeBERTa-v3-large（220M参数）或 RoBERTa-large
3. **训练目标**: 回归（预测0-1的连续分数）或 分类（正确/错误/中性）
4. **评估指标**: PRM评分与人工评分的Spearman相关系数

**第2层——数据标注瓶颈的解决方案**
- **方案1——半自动标注Pipeline**:
  ```
  教师模型生成CoT → 弱PRM初步评分 → 人工审核低置信度样本 → 迭代训练PRM
  ```
  - 效率提升: 10倍（人工只需标注10%的样本）
- **方案2——跨任务迁移**:
  - 在数学任务上训练PRM → 迁移到代码任务
  - 方法: 在目标任务上Fine-tune最后两层
  - 效果: 数据量减少70%
- **方案3——合成数据生成**:
  - 使用强模型（GPT-4）生成高质量CoT
  - 注入错误（随机替换某步）→ 获得"错误步骤"标注
  - 成本: $0.01/样本（远低于人工标注的$0.50/样本）

**第3层——PRM训练的高级技巧**
- **技巧1——标签平滑**: 中性标签使用0.5（而非0），缓解稀疏标注问题
- **技巧2——Focal Loss**: 对困难样本（PRM预测错误的样本）加大权重
- **技巧3——多PRM集成**: 使用3-5个不同架构的PRM，集成评估
  - 效果: 评估准确率 +8pp
  - 成本: 推理时间 × 3-5

**代码实现（半自动标注Pipeline）**:
```python
def semi_automated_prm_annotation(
    questions: List[str],
    weak_prm,  # 弱PRM（初版）
    strong_llm,  # 强LLM（用于生成CoT）
    human_annotator,  # 人工标注接口
    confidence_threshold: float = 0.7,
):
    """
    半自动PRM标注Pipeline
    
    流程:
    1. 强LLM生成CoT
    2. 弱PRM评估每步
    3. 低置信度样本 → 人工标注
    4. 高置信度样本 → 自动接受
    5. 用标注数据训练更强PRM
    """
    annotations = []
    
    for question in questions:
        # Step 1: 生成CoT
        cot = strong_llm.generate_cot(question)  # List[str]，每步一个元素
        
        # Step 2: 弱PRM评估
        scores = weak_prm.predict(cot)  # List[float]，每步一个分数
        confidences = weak_prm.predict_confidence(cot)  # List[float]
        
        # Step 3: 决定哪些步骤需要人工标注
        for step, score, conf in zip(cot, scores, confidences):
            if conf < confidence_threshold:
                # 低置信度 → 人工标注
                human_label = human_annotator.annotate(step, question)
                annotations.append({
                    'step': step,
                    'score': human_label,
                    'source': 'human',
                })
            else:
                # 高置信度 → 自动接受
                annotations.append({
                    'step': step,
                    'score': score,
                    'source': 'auto',
                })
    
    # Step 4: 训练更强PRM
    strong_prm = train_prm(annotations)
    return strong_prm
```

```python
def dynamic_compute_allocation(question: str, user_tier: str) -> dict:
    """
    根据问题复杂度和用户等级动态分配推理预算
    
    user_tier: 'free' | 'pro' | 'enterprise'
    """
    difficulty = classifier.predict(question)
    
    # 基础预算
    budgets = {
        'easy': {'max_tokens': 200, 'method': 'direct'},
        'medium': {'max_tokens': 500, 'method': 'cot'},
        'hard': {'max_tokens': 1500, 'method': 'tot', 'num_paths': 5},
        'expert': {'max_tokens': 4000, 'method': 'mcts', 'num_simulations': 20},
    }
    
    budget = budgets[difficulty].copy()
    
    # 根据用户等级调整
    if user_tier == 'free':
        # 免费用户: 限制推理计算
        budget['max_tokens'] = min(budget['max_tokens'], 500)
        budget['method'] = 'cot'  # 不允许ToT/MCTS
    elif user_tier == 'enterprise':
        # 企业用户: 无限制
        pass
    
    return budget
```
