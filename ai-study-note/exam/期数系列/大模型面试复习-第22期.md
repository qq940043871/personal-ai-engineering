### 2.1 RLHF vs DPO——偏好对齐算法的数学本质

**问题定义**：如何让LLM对齐人类偏好？

#### 数学推导（逐层深入）

**第1层：RLHF的目标函数**

RLHF用PPO算法最大化以下目标：
```
J(θ) = E[(r(x,y) - β·KL(π_θ || π_ref))]
```
其中：
- `r(x,y)`：Reward Model给出的奖励
- `KL(π_θ || π_ref)`：当前策略与参考策略的KL散度
- `β`：控制探索与利用的平衡

**第2层：DPO的数学推导**

DPO的核心洞察：**不需要显式训练Reward Model，可以直接优化策略**

从Bradley-Terry偏好模型出发：
```
P(y1 ≻ y2 | x) = σ(r(x,y1) - r(x,y2))
```

代入RLHF的最优策略公式：
```
π*(y|x) ∝ π_ref(y|x) · exp(r(x,y)/β)
```

取对数并整理，得到**DPO损失函数**：
```
L_DPO = -E[log σ(β·log(π_θ(y_w|x)/π_ref(y_w|x)) - β·log(π_θ(y_l|x)/π_ref(y_l|x)))]
```
其中 `y_w` 是偏好回答，`y_l` 是舍去回答。

**第3层：代码实现（DPO Trainer核心逻辑）**

```python
import torch
import torch.nn.functional as F

def dpo_loss(model, ref_model, batch, beta=0.1):
    """
    DPO损失函数实现
    batch: {
        'prompt': [B, L_p],
        'chosen': [B, L_c],   # 偏好回答
        'rejected': [B, L_r]  # 舍去回答
    }
    """
    # 1. 计算当前模型的log概率
    chosen_logps = compute_logps(model, batch['prompt'], batch['chosen'])
    rejected_logps = compute_logps(model, batch['prompt'], batch['rejected'])
    
    # 2. 计算参考模型的log概率（不计算梯度）
    with torch.no_grad():
        ref_chosen_logps = compute_logps(ref_model, batch['prompt'], batch['chosen'])
        ref_rejected_logps = compute_logps(ref_model, batch['prompt'], batch['rejected'])
    
    # 3. 计算偏好对数比
    pi_logratios = chosen_logps - rejected_logps
    ref_logratios = ref_chosen_logps - ref_rejected_logps
    
    # 4. DPO损失
    logits = pi_logratios - ref_logratios
    losses = -F.logsigmoid(beta * logits)
    
    return losses.mean()

def compute_logps(model, prompts, responses):
    """计算序列的log概率（sum of token logprobs）"""
    inputs = torch.cat([prompts, responses], dim=1)
    outputs = model(inputs)
    logits = outputs.logits[:, :-1, :]  # [B, L-1, V]
    labels = inputs[:, 1:]              # [B, L-1]
    
    logprobs = F.log_softmax(logits, dim=-1)
    # 收集标签对应的log概率
    response_logps = torch.gather(logprobs, -1, labels.unsqueeze(-1)).squeeze(-1)
    
    # 只计算response部分的log概率（mask掉prompt）
    response_mask = (labels != tokenizer.pad_token_id)
    response_logps = (response_logps * response_mask).sum(dim=1)
    
    return response_logps
```

**第4层：RLHF vs DPO 性能对比**

| 维度 | RLHF/PPO | DPO | Identity Preference Optimization (IPO) |
|------|-----------|-----|---------------------------------------|
| 训练稳定性 | 低（易collapse） | 高 | 高 |
| 训练速度 | 慢（需Rollout） | 快（+300%） | 快 |
| 样本效率 | 低 | 高 | 高 |
| 理论保证 | 有（收敛到KL约束最优） | 有（隐式奖励匹配） | 有（避免过拟合） |
| 工程复杂度 | 高（4个模型） | 低（2个模型） | 低 |
| 适用场景 | 高质量对齐 | 快速迭代 | 数据量少时 |

**第5层：工程实践中的坑**

1. **参考模型显存占用**：DPO需要同时加载 `model` 和 `ref_model`
   - **解决方案**：LoRA + DPO（只优化LoRA参数，ref_model用全量参数但不计算梯度）
   
2. **长度偏差**：模型倾向于生成更长的回答（因为sum logprob更大）
   - **解决方案**：长度归一化 `logp = logp / len(response)`
   
3. **偏好数据质量**：噪声标签导致训练不稳定
   - **解决方案**：IPA（Identity Preference Alignment）或 偏好强度加权

### 2.2 Speculative Decoding——无损推理加速

**问题定义**：LLM推理是**内存带宽瓶颈**（不是计算瓶颈），如何加速？

#### 算法原理（逐层深入）

**第1层：核心思想**

用**小模型（Draft Model）快速生成K个token** → 用**大模型（Target Model）并行验证这K个token** → 接受所有正确的前缀 → 从第一个错误位置重新采样

**关键洞察**：
- 小模型生成K个token的时间 ≈ 大模型生成1个token的时间（因为小模型参数量少）
- 如果接受率高，等效于**大模型一次生成多个token**

**第2层：数学推导（接受率分析）**

假设：
- 草稿模型分布：`q(x)`
- 目标模型分布：`p(x)`
- 贪心采样时，接受率 = `min(1, p(x)/q(x))`

**定理**：如果 `q(x)` 是 `p(x)` 的good approximation，接受率 ≈ 70-90%

**加速比公式**：
```
加速比 = (K × 接受率 + 1) / (K + 1)
```
例如：K=5，接受率=0.8 → 加速比 = (5×0.8+1)/(5+1) = 4.1/6 ≈ 2.7x

**第3层：代码实现（Speculative Decoding核心逻辑）**

```python
import torch
from typing import List

def speculative_decoding(
    draft_model,
    target_model,
    input_ids: torch.Tensor,
    max_new_tokens: int = 100,
    K: int = 5,  # 草稿token数量
    temperature: float = 1.0
):
    """
    Speculative Decoding 主函数
    
    算法流程：
    1. 用draft_model生成K个token
    2. 用target_model并行验证这K个token
    3. 接受所有正确的前缀
    4. 从第一个错误位置重新采样
    """
    device = input_ids.device
    generated = input_ids.clone()
    
    for step in range(max_new_tokens):
        # === 第1步：草稿生成 ===
        draft_tokens = []
        draft_probs = []
        current_input = generated.clone()
        
        for k in range(K):
            with torch.no_grad():
                draft_logits = draft_model(current_input).logits[:, -1, :] / temperature
                draft_prob = F.softmax(draft_logits, dim=-1)
                draft_token = torch.multinomial(draft_prob, 1)  # [B, 1]
                
                draft_tokens.append(draft_token)
                draft_probs.append(draft_prob)
                current_input = torch.cat([current_input, draft_token], dim=1)
        
        draft_tokens = torch.cat(draft_tokens, dim=1)  # [B, K]
        
        # === 第2步：目标模型验证 ===
        # 将草稿token拼接到输入，一次性前向传播
        verify_input = torch.cat([generated, draft_tokens], dim=1)  # [B, L+K]
        
        with torch.no_grad():
            target_logits = target_model(verify_input).logits[:, -K-1:, :]  # [B, K+1, V]
        
        # 计算每个位置的target概率
        target_probs = F.softmax(target_logits / temperature, dim=-1)
        
        # === 第3步：逐位置验证 ===
        accepted_tokens = []
        for k in range(K):
            # 草稿模型在位置k的采样结果
            draft_token = draft_tokens[:, k]  # [B]
            draft_prob = draft_probs[k].gather(-1, draft_token.unsqueeze(-1)).squeeze(-1)  # [B]
            
            # 目标模型在位置k的真实概率
            target_prob = target_probs[:, k, :].gather(-1, draft_token.unsqueeze(-1)).squeeze(-1)  # [B]
            
            # 接受概率
            accept_prob = torch.min(torch.ones_like(draft_prob), target_prob / draft_prob)
            accept_mask = torch.rand_like(accept_prob) < accept_prob  # [B]
            
            if accept_mask.all():
                accepted_tokens.append(draft_token.unsqueeze(1))
            else:
                # 从第k个位置重新采样
                corrected_dist = F.softmax(
                    (target_logits[:, k, :] - draft_logits[:, :]).clamp(max=0) / temperature,
                    dim=-1
                )
                new_token = torch.multinomial(corrected_dist, 1)
                accepted_tokens.append(new_token)
                break
        
        # === 第4步：拼接已接受的token ===
        if accepted_tokens:
            accepted_tokens = torch.cat(accepted_tokens, dim=1)
            generated = torch.cat([generated, accepted_tokens], dim=1)
        
        # 检查是否生成EOS
        if (generated[:, -1] == eos_token_id).all():
            break
    
    return generated
```

**第4层：工程优化技巧**

1. **KV Cache复用**：
   - 草稿阶段和验证阶段共享KV Cache
   - 实现：验证阶段只计算新增的token的KV

2. **Tree-based验证**（不确定时探索多个分支）：
   - 如果草稿模型的top-2概率接近，同时验证两个分支
   - 接受率提升 10-15%

3. **自适应K值选择**：
   - 简单token（高频词）：K=5-10
   - 复杂token（低频词、数字、代码）：K=2-3

| GPT-2 Small → GPT-2 XL | 117M | 1.5B | 2.7x | 78% |

### 2.3 长度控制——让LLM生成"恰到好处"的回答

**问题定义**：LLM倾向于生成冗长、重复的回答，如何控制生成长度？

#### 技术方案（逐层深入）

**第1层：问题根因分析**

1. **训练数据偏差**：SFT数据中长回答占比高（因为"详细回答"被标记为高质量）
2. **RLHF奖励黑客**：模型发现"生成长回答"可以获得更高的Reward（因为sum logprob更大）
3. **解码策略问题**：贪心解码倾向于重复，采样温度高时倾向于发散

**第2层：Length-Controlled Decoding（推理时控制）**

**核心思想**：在生成时，对"过长"的候选token施加惩罚

**算法流程**：
1. 生成N个候选回答（Beam Search或采样）
2. 计算每个候选的"长度归一化得分"：
   ```
   score = logp(response) / len(response) + α·length_penalty(len)
   ```
3. 选择得分最高的回答

**代码实现**：
```python
def length_controlled_generate(
    model,
    input_ids,
    max_length: int = 512,
    num_return_sequences: int = 5,
    length_penalty: float = 1.0
):
    """
    Length-Controlled Decoding
    生成多个候选，按长度归一化得分排序
    """
    # 1. 生成N个候选（Beam Search）
    outputs = model.generate(
        input_ids,
        max_length=max_length,
        num_return_sequences=num_return_sequences,
        do_sample=True,
        top_p=0.95,
        num_beams=num_return_sequences
    )
    
    # 2. 计算每个候选的得分
    scores = []
    for seq in outputs:
        logp = compute_sequence_logp(model, input_ids, seq)
        length = len(seq) - len(input_ids)
        # 长度归一化 + 长度惩罚
        normalized_score = logp / length - length_penalty * (length / max_length)
        scores.append(normalized_score)
    
    # 3. 选择得分最高的
    best_idx = torch.argmax(torch.tensor(scores))
    return outputs[best_idx]
```

**第3层：RL微调 + 长度惩罚（训练时控制）**

**核心思想**：在RL目标函数中加入长度惩罚项

**改进的GRPO目标函数**：
```
J(θ) = E[reward(x,y) - β·KL(π_θ||π_ref) - γ·len(y)/len_max]
```
其中 `γ` 是长度惩罚系数（通常取 0.01-0.1）

**代码实现（GRPO Trainer）**：
```python
def grpo_loss_with_length_penalty(
    model,
    ref_model,
    batch,
    beta: float = 0.1,
    gamma: float = 0.05  # 长度惩罚系数
):
    """
    GRPO损失函数 + 长度惩罚
    """
    prompts = batch['prompt']  # [B, L_p]
    responses = batch['response']  # [B, L_r]
    
    # 1. 计算当前模型的log概率
    logps = compute_logps(model, prompts, responses)  # [B]
    
    # 2. 计算参考模型的log概率
    with torch.no_grad():
        ref_logps = compute_logps(ref_model, prompts, responses)  # [B]
    
    # 3. 计算KL散度
    kl = logps - ref_logps  # [B]
    
    # 4. 计算长度惩罚
    lengths = (responses != tokenizer.pad_token_id).sum(dim=1)  # [B]
    length_penalty = gamma * lengths / 512  # 假设max_length=512
    
    # 5. GRPO损失 + 长度惩罚
    advantages = batch['reward'] - beta * kl - length_penalty
    loss = - (logps * advantages.detach()).mean()
    
    return loss
```

|------|---------|-----------------|---------|
| Baseline（无控制） | 512 tokens | 7.8/10 | - |
| Prompt工程 | 310 tokens (-39%) | 7.5/10 (-0.3) | 0 |
| Length-Controlled Decoding | 280 tokens (-45%) | 7.6/10 (-0.2) | 推理时 +20% |
| GRPO + 长度惩罚 | 190 tokens (-63%) | 7.7/10 (-0.1) | 训练时 +50% |

**结论**：GRPO + 长度惩罚 是最佳方案（长度 -63%，质量损失仅 -0.1）

## 📌 三、常见问答（Common Interview Q&A）

### Q1：DPO和RLHF的核心区别是什么？为什么DPO训练更稳定？

**五层深度答案**：

**第1层：算法流程对比**

| 步骤 | RLHF/PPO | DPO |
|------|-----------|-----|
| 1. 训练Reward Model | ✅ 需要 | ❌ 不需要 |
| 2. Rollout生成样本 | ✅ 需要 | ❌ 不需要 |
| 3. 计算Reward | ✅ 需要 | ❌ 不需要 |
| 4. PPO策略优化 | ✅ 需要 | ❌ 不需要 |
| 5. 直接优化策略 | ❌ | ✅ |

**第2层：数学本质**

- **RLHF**：显式训练Reward Model `r(x,y)`，然后用PPO最大化 `E[r(x,y)]`
- **DPO**：隐式定义Reward `r(x,y) = β·log(π(y|x)/π_ref(y|x))`，直接优化策略

**第3层：为什么DPO更稳定？**

1. **没有Reward Model的误差传播**：RLHF中Reward Model的错误会被PPO放大
2. **没有Rollout的不稳定性**：RLHF需要在线生成样本，可能导致分布偏移
3. **单阶段训练**：DPO是简单的分类损失，梯度稳定

**第4层：代码级对比**

```python
# RLHF/PPO：需要4个模型
actor = model          # 策略模型（需要优化）
critic = ValueHead()   # 价值模型（需要优化）
reward_model = RM()    # 奖励模型（固定）
ref_model = copy(actor) # 参考模型（固定）

# DPO：只需要2个模型
model = model          # 策略模型（需要优化）
ref_model = copy(model) # 参考模型（固定）
```

**第5层：工程实践建议**

- **快速迭代**：用DPO（训练速度快，稳定性高）
- **极致质量**：用RLHF（理论上限更高，但调参难度更大）
- **混合策略**：先用DPO做初步对齐，再用RLHF微调

### Q2：Speculative Decoding的接受率上限是多少？如何进一步提升接受率？

**四层深度答案**：

**第1层：理论上限**

假设草稿模型 `q(x)` 和目标模型 `p(x)` 完全相同，接受率 = 100%（因为 `p(x)/q(x) = 1`）

但实际中 `q(x) ≠ p(x)`，接受率上限由**两个分布的总变分距离（Total Variation Distance）**决定：
```
接受率 ≤ 1 - TV(q||p) / 2
```

**第2层：影响接受率的因素**

1. **草稿模型质量**：草稿模型越接近目标模型，接受率越高
2. **生成温度**：温度越高，分布越平滑，接受率越低
3. **token难度**：高频词接受率高，低频词接受率低

**第3层：提升接受率的方法**

1. **Self-Speculative（DeepSeek-V3）**：
   - 不用独立草稿模型，而是用目标模型的前几层作为草稿模型
   - 接受率：78% → 85%

2. **Tree-based验证**：
   - 同时验证多个候选分支
   - 接受率：+10-15%

3. **自适应草稿数量K**：
   - 简单token：K=5-10
   - 复杂token：K=2-3
   - 平均接受率：+5-10%

**代码实现**：
```python
def length_controlled_generate(model, prompt, max_len=512, num_candidates=5):
    # 1. 生成多个候选
    candidates = [model.generate(prompt) for _ in range(num_candidates)]
    
    # 2. 计算长度归一化得分
    scores = [logp(c) / len(c) - 0.05*len(c)/max_len for c in candidates]
    
    # 3. 选择得分最高的
    return candidates[argmax(scores)]
```

**第3层：训练时控制方案（25分钟）**

```
J(θ) = E[reward - β·KL - γ·len/len_max]
```

```python
def grpo_loss_with_length_penalty(model, batch, gamma=0.05):
    logps = compute_logps(model, batch)

    length_penalty = gamma * lengths / 512
    
    # GRPO损失 + 长度惩罚
    loss = - (logps * (batch['advantage'] - length_penalty)).mean()
    return loss
```
