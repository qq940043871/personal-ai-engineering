### 1.3 稀疏注意力系统——突破二次复杂度

**问题背景**：标准Attention的O(n²)复杂度，128K Token上下文需要 ~137亿次计算（不可接受）

**核心方案**：稀疏注意力模式
```
标准Attention（稠密）：
  计算：O(n²) = O(131072²) ≈ 1.7×10¹⁰ FLOPs（128K上下文）
  显存：O(n²) ≈ 68GB（FP16，仅Attention矩阵）

稀疏Attention（稀疏）：
  计算：O(n·√n) 或 O(n·log n) ≈ 10⁸ FLOPs（压缩100x）
  显存：O(n) ≈ 1GB
```

**四种稀疏模式对比**：
1. **固定模式**（Longformer）：局部窗口 + 全局Token，实现简单，压缩比 100x
2. **自适应模式**（BigBird）：随机连接 + 局部窗口 + 全局Token，理论证明有效
3. **可学习模式**（Routing Transformer）：用路由网络学习稀疏连接，质量更优但训练复杂
4. **环形模式**（Ring Attention）：序列维度分片 + 分布式计算，支持超长上下文（1M+）

## 📌 二、技术难点（Technical Difficulties）

### 2.1 长度外推的数学原理——RoPE 频率缩放

#### 第1层：RoPE 回顾（必备基础）

**RoPE（旋转位置编码）核心公式**：
```
对位置 m 的 Query 向量 q，其第 i 对维度（2i, 2i+1）应用旋转：

RoPE(q, m) = [ q₁cos(mθ₁) - q₂sin(mθ₁),
                 q₁sin(mθ₁) + q₂cos(mθ₁),
                 q₃cos(mθ₂) - q₄sin(mθ₂),
                 ... ]

其中 θᵢ = 1/(base^(2i/d)), base=10000（LLaMA）
```

**关键性质**：RoPE 是相对位置编码
```
<RoPE(q, m), RoPE(k, n)> = <RoPE(q, 0), RoPE(k, n-m)>
```
即：Query在位置m、Key在位置n的内积，只依赖于相对位置(n-m)

#### 第2层：长度外推的根本问题

**问题形式化**：
```
训练长度：L_train = 4096
测试长度：L_test  = 32768（8倍）

RoPE频率：θᵢ = 1/(10000^(2i/d))

当位置 m > L_train 时：
  m·θᵢ 可能超出 [-π, π] 范围
  → 旋转矩阵"绕回"（aliasing）
  → 模型无法区分位置 m 和位置 m mod (2π/θᵢ)
```

**可视化理解**：
```
假设 θ=0.01，则周期 T=2π/θ≈628
位置 0, 628, 1256, ... 的旋转矩阵完全相同
→ 模型认为这些位置"相同"（位置混淆）
```

#### 第3层：Position Interpolation（线性缩放）

**核心思想**：将位置索引从 [0, L_test-1] 线性缩放到 [0, L_train-1]

```python
def position_interpolation(positions, L_train=4096, L_test=32768):
    """
    Position Interpolation：线性缩放位置索引
    """
    # 原始RoPE：位置 m 的旋转角度 = m·θ
    # 插值后：位置 m 的旋转角度 = (m · L_train / L_test) · θ
    
    scale_factor = L_train / L_test  # 4096/32768 = 0.125
    
    # 等价于：保持位置不变，缩放RoPE的base
    # base_new = base^(1/scale_factor) = 10000^(8) = 10^32（太大！）
    # 实际实现：直接缩放位置索引
    
    scaled_positions = positions * scale_factor
    return apply_rope(q, scaled_positions, base=10000)

# 问题：线性缩放导致高频信息丢失
# 原因：缩放后，相邻位置的旋转角度差变小 → 位置区分度下降
# 表现：32K上下文时，相邻Token的位置编码几乎相同
```

#### 第4层：NTK-aware 插值（非线性缩放）

**核心改进**：不同频率维度使用不同的缩放因子（高频少缩放，低频多缩放）

```python
def ntk_aware_interpolation(q, positions, L_train=4096, L_test=32768, base=10000):
    """
    NTK-aware插值：为每对维度(2i,2i+1)计算独立的缩放因子
    NTK理论：高频需要更精细的插值（保留更多信息）
    """
    d = q.shape[-1]
    num_heads = d // 64  # 假设head_dim=64
    
    # 为每对维度计算缩放因子
    scale_factors = []
    for i in range(d // 2):
        # 高频（小i）：缩放因子接近1（几乎不缩放）
        # 低频（大i）：缩放因子 = L_test / L_train（大幅缩放）
        freq = 1 / (base ** (2 * i / d))
        
        # NTK-aware核心：高频用小缩放，低频用大缩放
        # 简单启发式：scale = (L_test / L_train) ^ (2i/d)
        scale = (L_test / L_train) ** (2 * i / d)
        scale_factors.append(scale)
    
    # 应用缩放（修改RoPE的base）
    # 等价实现：base_new = base * scale_factor_for_each_dim
    # 实际实现：直接修改频率计算
    new_base = base * (L_test / L_train)  # 简化版：统一缩放base
    
    return apply_rope(q, positions, base=new_base)

# NTK-aware效果（Meta报告）：
#  · 8K扩展：性能损失 <3%（Position Interpolation: 8%）
#  · 16K扩展：性能损失 <5%（Position Interpolation: 15%）
```

#### 第5层：YaRN（Yet another RoPE extensioN）

**核心创新1：分段NTK缩放**
```python
def yarn_scaling(L_train=4096, L_test=32768, d=128, base=10000):
    """
    YaRN：分段缩放 + 注意力温度调节
    """
    scale = L_test / L_train  # 8x
    
    # 分段缩放：低频大幅缩放，高频小幅缩放
    # 使用平滑过渡（避免分段边界突变）
    alpha = 0.1  # 高频缩放因子（接近1）
    beta = scale  # 低频缩放因子（等于长度扩展比）
    
    scales = []
    for i in range(d // 2):
        # 插值函数：从alpha平滑过渡到beta
        t = i / (d // 2)  # 归一化频率索引 [0, 1]
        s = alpha + (beta - alpha) * t
        scales.append(s)
    
    return scales

# YaRN效果（Peng等人，2023）：
#  · 64K扩展（LLaMA-2-7B）：Passkey Retrieval准确率 99.2%
#  · 128K扩展：LongBench平均性能损失 <3%
```

**核心创新2：注意力温度缩放**
```python
def yarn_attention_with_temperature(q, k, v, L_test, L_train):
    """
    YaRN的注意力温度缩放：补偿长度外推后的注意力分布变化
    """
    # 问题：长度扩展后，注意力的logits幅度会变化
    # 解决：对Attention logits应用温度缩放
    
    scale = L_test / L_train
    temperature = 1.0 / math.sqrt(scale)  # 温度 = 1/√(扩展比)
    
    # 计算注意力
    logits = (q @ k.T) / math.sqrt(q.shape[-1])
    logits = logits * temperature  # 温度缩放
    attn = F.softmax(logits, dim=-1)
    
    return attn @ v

# 物理直觉：
#  长度扩展后，Key的数量增加 → 注意力分布更"平坦"（熵增加）
#  温度缩放：降低温度 → 注意力分布更"尖锐"（恢复训练时的分布）
```

**完整YaRN实现**：
```python
import torch
import torch.nn.functional as F
import math

def yarn_rope(pos, dim, base=10000, L_train=4096, L_test=32768):
    """
    YaRN的完整RoPE实现（支持任意长度扩展）
    """
    scale = L_test / L_train
    
    # 1. 计算频率（分段缩放）
    inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
    
    # 2. 应用YaRN缩放（高频alpha，低频beta）
    alpha = 0.1
    beta = scale
    
    # 平滑插值
    t = torch.arange(0, dim // 2).float() / (dim // 2)
    scales = alpha + (beta - alpha) * t
    inv_freq = inv_freq / scales  # 缩放频率（等价于缩放base）
    
    # 3. 应用RoPE
    t = torch.arange(pos, pos + 1).type_as(inv_freq)
    freqs = torch.einsum('i,j->ij', t, inv_freq)
    emb = torch.cat((freqs, freqs), dim=-1)
    
    return emb.cos(), emb.sin()

def apply_yarn_rope(q, k, positions, L_train=4096, L_test=32768):
    """
    应用YaRN RoPE到Q和K
    """
    cos, sin = yarn_rope(positions, q.shape[-1], L_train=L_train, L_test=L_test)
    
    # RoPE应用：旋转
    q_out = (q * cos) + (rotate_half(q) * sin)
    k_out = (k * cos) + (rotate_half(k) * sin)
    
    return q_out, k_out

def rotate_half(x):
    """旋转一半维度"""
    x1, x2 = x.chunk(2, dim=-1)
    return torch.cat((-x2, x1), dim=-1)

# 使用YaRN后的效果：
#  LLaMA-2-7B，训练长度4096，扩展至32768（8x）
#  LongBench平均准确率：
#    - 无扩展（截断）：52.3%
#    - Position Interpolation：68.7%
#    - NTK-aware：74.2%
#    - YaRN：78.6%（SOTA）
```

### 2.2 稀疏注意力代码实现——从 Longformer 到 Ring Attention

#### 第1层：Longformer 稀疏注意力（局部窗口 + 全局Token）

**核心思想**：
```
标准Attention：每个Tokenattend到所有Token（O(n²)）
Longformer：每个Token只attend到：
  1. 局部窗口（前后各w个Token）→ O(n·w)
  2. 全局Token（如[CLS]）→ O(n·g)

总复杂度：O(n·(w+g))，其中w=512, g=8（典型值）
```

**代码实现**：
```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class LongformerAttention(nn.Module):
    """
    Longformer稀疏注意力实现
    支持：局部窗口 + 全局Token + 任务特定全局位置
    """
    def __init__(self, dim, num_heads, window_size=512, global_tokens=8):
        super().__init__()
        self.dim = dim
        self.num_heads = num_heads
        self.head_dim = dim // num_heads
        self.window_size = window_size  # 局部窗口大小
        self.global_tokens = global_tokens  # 全局Token数量
        
        self.q_proj = nn.Linear(dim, dim)
        self.k_proj = nn.Linear(dim, dim)
        self.v_proj = nn.Linear(dim, dim)
        self.out_proj = nn.Linear(dim, dim)
        
    def forward(self, x, global_mask=None):
        """
        x: [batch, seq_len, dim]
        global_mask: [batch, seq_len]，标记哪些位置是全局Token
        """
        B, N, C = x.shape
        q = self.q_proj(x).reshape(B, N, self.num_heads, self.head_dim).permute(0, 2, 1, 3)
        k = self.k_proj(x).reshape(B, N, self.num_heads, self.head_dim).permute(0, 2, 1, 3)
        v = self.v_proj(x).reshape(B, N, self.num_heads, self.head_dim).permute(0, 2, 1, 3)
        
        # 构建稀疏注意力Mask
        attn_mask = self._build_sparse_mask(N, global_mask)  # [N, N]
        
        # 计算注意力（支持变长序列）
        scores = (q @ k.transpose(-2, -1)) / math.sqrt(self.head_dim)  # [B, H, N, N]
        scores = scores + attn_mask.unsqueeze(0).unsqueeze(0)  # 加入Mask
        
        attn = F.softmax(scores, dim=-1)
        out = (attn @ v).permute(0, 2, 1, 3).reshape(B, N, C)
        
        return self.out_proj(out)
    
    def _build_sparse_mask(self, seq_len, global_mask):
        """
        构建Longformer稀疏Mask
        返回：attention_mask [seq_len, seq_len]
              - 允许attend的位置：0
              - 禁止attend的位置：-inf
        """
        # 初始化：所有位置都禁止
        mask = torch.ones(seq_len, seq_len) * -float('inf')
        
        for i in range(seq_len):
            # 1. 局部窗口：位置i可以attend到 [i-w, i+w]
            start = max(0, i - self.window_size // 2)
            end = min(seq_len, i + self.window_size // 2 + 1)
            mask[i, start:end] = 0
            
            # 2. 全局Token：所有位置都可以attend到全局Token
            if global_mask is not None:
                global_positions = (global_mask[0] == 1).nonzero(as_tuple=True)[0]
                mask[i, global_positions] = 0
                
                # 全局Token也可以attend到所有位置
                mask[global_positions, i] = 0
        
        return mask

# 复杂度对比：
#  标准Attention（N=131072/128K）：O(N²) = 1.7×10¹⁰ FLOPs
#  Longformer（w=512, g=8）：O(N×(w+g)) = 6.7×10⁷ FLOPs（压缩250x）
```

#### 第2层：Ring Attention（序列维度分布式计算）

**核心思想**：将超长序列切分到多个GPU，每个GPU只计算局部Attention，通过环形通信传递KV

**算法流程**：
```
假设：序列长度N=1M，8个GPU
每个GPU负责：N/8 = 125K Token

Ring Attention流程：
  第1步：每个GPU计算局部QK^T（自己负责的Token）
  第2步：环形传递KV块（每个GPU向下一个GPU发送自己的KV）
  第3步：重复N/GPU_count次，每个GPU都能"看到"完整序列的KV
  
总通信量：O(N)（每个KV块传递GPU_count次）
总计算量：O(N²/GPU_count)（每个GPU只计算部分Attention）
```

**代码实现（简化版）**：

    Ring Attention：序列维度分布式Attention

    """
    seq_len = q.shape[1]

### 2.3 上下文压缩——从 LLMLingua 到 AutoCompressor

#### 第1层：LLMLingua（文本级压缩）

**核心思想**：用一个小模型（如GPT-2）预测每个Token的重要性，删除不重要Token

**算法流程**：
```
输入：长文档 D = [t₁, t₂, ..., tₙ]（n=10000 Token）
目标：压缩到 m=2500 Token（压缩比 4:1）

步骤1：用重要性预测模型计算每个Token的保留概率
  p_i = P(retain | t_i, D)  （用小模型预测）

步骤2：按重要性排序，保留Top-m个Token
  D_compressed = [t_i for i in top_m_indices]

步骤3：微调大模型，使其在压缩后的文档上表现接近原始文档
  Loss = L(orig) - L(compressed)  （KL散度）
```

**代码实现**：
```python
def llmlingua_compress(document, target_ratio=0.25, importance_model='gpt2'):
    """
    LLMLingua文本压缩
    """
    tokens = tokenize(document)  # [n]
    
    # 1. 计算每个Token的重要性（用小模型）
    importance_scores = []
    for i, token in enumerate(tokens):
        # 方法1：Perplexity增益（删除该Token后PPL增加越多 = 越重要）
        ppl_with = compute_perplexity(tokens, importance_model)
        ppl_without = compute_perplexity(tokens[:i] + tokens[i+1:], importance_model)
        importance = ppl_without - ppl_with
        importance_scores.append(importance)
    
    # 2. 按重要性排序，保留Top-(n*target_ratio)个Token
    num_retain = int(len(tokens) * target_ratio)
    top_indices = sorted(range(len(tokens)), key=lambda i: importance_scores[i], reverse=True)[:num_retain]
    top_indices.sort()  # 保持原始顺序
    
    compressed_tokens = [tokens[i] for i in top_indices]
    
    # 3. 微调（可选）：让大模型适应压缩后的文本
    # finetune_llm(compressed_tokens, original_outputs)
    
    return detokenize(compressed_tokens)

#  · 信息损失：<3%（LongBench QA任务）
#  · 压缩速度：50 tokens/s（GPT-2重要性模型）
```

#### 第2层：AutoCompressor（向量级压缩）

**核心思想**：用Transformer编码器将多个Token压缩成一个"摘要向量"，减少KV Cache大小

**算法流程**：
```
输入：Token序列 [t₁, ..., tₙ]，压缩比 r=4
目标：将每r个Token压缩成1个向量

步骤1：用编码器处理滑动窗口
  Window₁ = [t₁, t₂, t₃, t₄] → 压缩向量 c₁
  Window₂ = [t₅, t₆, t₇, t₈] → 压缩向量 c₂
  ...

步骤2：压缩向量作为新的KV Cache
  Original KV Cache: [k₁, v₁, k₂, v₂, ..., kₙ, vₙ]  (n×2 个向量)
  Compressed KV Cache: [c₁, c₂, ..., c_{n/r}]  (n/r 个向量)

步骤3：推理时，用压缩向量替代原始KV
  计算量：O((n/r)²) 而非 O(n²)
```

**代码实现**：
```python
class AutoCompressor(nn.Module):
    """
    自动上下文压缩器：将多个Token压缩成摘要向量
    """
    def __init__(self, dim, compression_ratio=4):
        super().__init__()
        self.compression_ratio = compression_ratio
        self.encoder = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(dim, nhead=8),
            num_layers=2
        )
        self.compress_proj = nn.Linear(dim * compression_ratio, dim)
        
    def forward(self, hidden_states):
        """
        hidden_states: [batch, seq_len, dim]
        返回：compressed: [batch, seq_len/ratio, dim]
        """
        batch, seq_len, dim = hidden_states.shape
        
        # 1. 按compression_ratio分组
        # [batch, seq_len/ratio, ratio, dim]
        grouped = hidden_states.reshape(batch, seq_len // self.compression_ratio, self.compression_ratio, dim)
        
        # 2. 用Transformer编码器压缩每组
        compressed = []
        for i in range(grouped.shape[1]):
            group = grouped[:, i, :, :]  # [batch, ratio, dim]
            encoded = self.encoder(group)  # [batch, ratio, dim]
            # 用[CLS]位置的输出作为压缩向量（或平均池化）
            compressed_vec = encoded[:, 0, :]  # [batch, dim]
            compressed.append(compressed_vec)
        
        compressed = torch.stack(compressed, dim=1)  # [batch, seq_len/ratio, dim]
        
        return compressed

# AutoCompressor效果（Stanford）：
#  · KV Cache压缩比：4:1
#  · 推理速度：+80%（128K上下文）
#  · 准确率损失：LongBench -2.1%（可接受）
```

### 2.4 KV Cache 显存优化——1M Token 上下文的工程挑战

#### 显存占用计算

```
假设：
  · 模型：LLaMA-3-70B
  · 上下文长度：1M Token
  · 层数：80层
  · 头数：64头
  · 头维度：128
  · 精度：FP16（2字节）

每层KV Cache大小：
  K: [batch, num_heads, seq_len, head_dim] = [1, 64, 1M, 128]
  V: [batch, num_heads, seq_len, head_dim] = [1, 64, 1M, 128]
  
  单层KV Cache = 2 × 64 × 1M × 128 × 2字节 = 32GB
  80层总KV Cache = 80 × 32GB = 2560GB（！）

优化后（分组查询 + INT4 + 分层压缩）：
  · GQA（8组）：KV Cache -87.5% → 320GB
  · INT4量化：-50% → 160GB
  · 分层压缩（后40层压缩4:1）：-35% → 104GB
  · PagedAttention（共享前缀）：-20% → 83GB
  
仍然无法在单卡（80GB A100）放下 → 需要多卡或丢弃历史
```

#### 多卡KV Cache分片策略

```python
def distribute_kv_cache(kv_cache, num_gpus):
    """
    将KV Cache分布到多个GPU
    """
    # 策略1：层间分片（Pipeline Parallelism风格）
    #   GPU 0: 层 0-19
    #   GPU 1: 层 20-39
    #   ...
    # 优点：每层完整序列，实现简单
    # 缺点：需要频繁GPU间通信（每层的KV要传给下一层）
    
    # 策略2：序列分片（Sequence Parallelism风格）
    #   GPU 0: Token 0-249999（前250K）
    #   GPU 1: Token 250000-499999
    #   ...
    # 优点：通信量少（只在边界Token需要通信）
    # 缺点：需要实现序列并行的Attention
    
    # 策略3：混合分片（推荐）
    #   层间分片（4个GPU） × 序列分片（2个GPU）= 8 GPU
    #   总显存需求：83GB / 8 = 10.4GB/GPU（可行！）
    
    layers_per_gpu = kv_cache.shape[0] // num_gpus
    sharded_kv = []
    for i in range(num_gpus):
        shard = kv_cache[i*layers_per_gpu:(i+1)*layers_per_gpu]
        sharded_kv.append(shard)
    
    return sharded_kv
```

## 📌 三、常见问答（Common Interview Q&A）

### Q1：RoPE 为什么能有效支持长度外推？YaRN 相比 NTK-aware 插值的本质改进是什么？

**五层深度答案**：

#### 第1层：RoPE 的长度外推问题根因

```
问题1：高频混淆（Aliasing）
  RoPE频率：θᵢ = 1/(base^(2i/d))
  
  当位置 m 增大到：m·θᵢ > 2π
  → 旋转矩阵"绕回"（cos/sin的周期性）
  → 模型无法区分位置 m 和 m + 2π/θᵢ

问题2：注意力熵偏移
  长度扩展后，Key的数量增加
  → 注意力的logits幅度不变，但softmax后分布更"平"（熵增加）
  → 模型变得"不确定"（注意力分散到更多Token）

问题3：位置索引分布偏移
  训练时位置索引范围：[0, 4095]
  测试时位置索引范围：[0, 32767]
  → 位置索引的均值和方差都变化
  → 模型的位置感知层（如ALiBi的偏置）失效
```

#### 第2层：Position Interpolation 为什么效果差？

```
核心问题：线性缩放对所有频率维度"一视同仁"

高频维度（小i，如i=0）：
  · 原始周期：T = 2π/θ₀ ≈ 6.28（几乎每个位置都不同）
  · 线性缩放后：T' = T / 0.125 = 50.24（相邻位置开始"相似"）
  · 结果：高频信息（精确位置）丢失

低频维度（大i，如i=63）：
  · 原始周期：T = 2π/θ₆₃ ≈ 628（已经很"粗糙"）
  · 线性缩放后：T' = 5024（更粗糙，但原本就需要扩展）
  · 结果：低频信息保留较好

结论：线性缩放"误杀"高频信息 → 位置区分度下降 → 性能损失5-10%
```

#### 第3层：NTK-aware 插值的本质改进

```
核心洞察： Neural Tangent Kernel（NTK）理论
  · 高频维度对应"高频函数"（快速变化）
  · 低频维度对应"低频函数"（缓慢变化）
  · 长度外推时，高频函数需要更精细的插值（保留更多高频信息）

NTK-aware实现：
  · 高频维度（小i）：缩放因子接近1（几乎不缩放）
  · 低频维度（大i）：缩放因子 = L_test/L_train（大幅缩放）
  · 过渡：平滑插值（避免边界突变）

数学形式：
  scale(i) = (L_test/L_train) ^ (2i/d)
  
  当 i=0（最高频）：scale = 1（不缩放）
  当 i=d/2（最低频）：scale = L_test/L_train（全缩放）

效果：
  · 高频信息保留：位置区分度不下降
  · 低频信息扩展：长度成功外推
  · 性能损失：从10% → 3-5%
```

#### 第4层：YaRN 的两个核心改进

**改进1：分段缩放 + 注意力温度调节**
```python
# YaRN = NTK-aware + 温度缩放 + 分段优化

# 1. 分段缩放（比NTK-aware更精细）
def yarn_scale(i, d, scale):
    """
    YaRN的分段缩放函数
    """
    # NTK-aware：scale(i) = scale^(2i/d)  （指数过渡）
    # YaRN：使用更平滑的过渡函数（避免指数爆炸）
    
    t = i / (d // 2)
    # 使用多项式过渡（而非指数）
    alpha = 0.1
    beta = scale
    yarn_scale = alpha + (beta - alpha) * (t ** 2)  # 二次项过渡
    
    return yarn_scale

# 2. 注意力温度缩放（YaRN的关键创新）
def yarn_temperature scaled_attention(q, k, attn_temperature):
    """
    对注意力logits应用温度缩放
    """
    logits = (q @ k.T) / math.sqrt(q.shape[-1])
    logits = logits / attn_temperature  # 温度缩放
    # 注意：这里是"除以温度"（与通常的softmax温度相反）
    # 目的：恢复长度扩展后的注意力分布（使其接近训练时的分布）
    
    attn = F.softmax(logits, dim=-1)
    return attn

# 温度的选择（经验公式）：
#  attn_temperature = 0.1 * log2(L_test / L_train) + 1.0
#  L_test/L_train=8 → temperature=1.3
#  L_test/L_train=32 → temperature=1.6
```

**改进2：实证调优的超参数**

| 扩展倍数 | NTK-scale | YaRN-temperature | LongBench性能 |
|----------|-----------|-----------------|---------------|
| 2x（8K） | 2.0 | 1.1 | 98.5% |
| 4x（16K） | 4.0 | 1.3 | 96.2% |
| 8x（32K） | 8.0 | 1.6 | 93.8% |
| 16x（64K） | 16.0 | 1.9 | 89.4% |
| 32x（128K） | 32.0 | 2.3 | 81.7% |

#### 第5层：代码级理解（完整YaRN实现）

```python
import torch
import torch.nn.functional as F
import math

class YaRNRoPE:
    """
    YaRN RoPE完整实现（可直接用于LLaMA微调）
    """
    def __init__(self, dim, max_seq_len=32768, original_max_len=4096, base=10000):
        self.dim = dim
        self.max_seq_len = max_seq_len
        self.original_max_len = original_max_len
        self.base = base
        
        # 计算YaRN缩放因子
        self.scale = max_seq_len / original_max_len
        self.temperature = 0.1 * math.log2(self.scale) + 1.0
        
        # 预计算频率（分段缩放）
        inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
        
        # YaRN分段缩放
        t = torch.arange(0, dim // 2).float() / (dim // 2)
        yarn_scales = 0.1 + (self.scale - 0.1) * (t ** 2)  # 二次项过渡
        inv_freq = inv_freq / yarn_scales
        
        self.register_buffer("inv_freq", inv_freq)
    
    def forward(self, x, seq_len):
        """
        x: [batch, num_heads, seq_len, head_dim]
        """
        t = torch.arange(seq_len, device=x.device).type_as(self.inv_freq)
        freqs = torch.einsum('i,j->ij', t, self.inv_freq)
        emb = torch.cat((freqs, freqs), dim=-1)
        
        cos = emb.cos().unsqueeze(0).unsqueeze(0)  # [1, 1, seq_len, dim]
        sin = emb.sin().unsqueeze(0).unsqueeze(0)
        
        # 应用RoPE
        x_cos = x * cos
        x_sin = self._rotate_half(x) * sin
        x_out = x_cos + x_sin
        
        return x_out
    
    def _rotate_half(self, x):
        x1, x2 = x.chunk(2, dim=-1)
        return torch.cat((-x2, x1), dim=-1)
    
    def apply_temperature(self, attn_logits):
        """
        应用YaRN的注意力温度缩放
        """
        return attn_logits / self.temperature

# 使用方法：
#  1. 替换LLaMA的RoPE为YaRNRoPE
#  2. 在Attention计算时应用温度缩放
#  3. 继续微调（学习率 1e-5，数据量 100M Token）
#  4. 结果：128K上下文，LongBench性能损失 <5%
```

### Q2：稀疏注意力有哪些主流方案？Ring Attention 如何实现 1M+ Token 的上下文？

**四层深度答案**：

#### 第1层：稀疏注意力方案全景对比

```
方案分类：

1. 固定模式（Fixed Pattern）
   · Longformer：局部窗口 + 全局Token
   · BigBird：局部窗口 + 全局Token + 随机连接
   · 优点：实现简单，训练稳定
   · 缺点：稀疏模式固定，无法适应数据
   · 适用：128K上下文（LLaMA-3-128K使用类似方案）

2. 自适应模式（Adaptive Pattern）
   · Routing Transformer：用路由网络学习稀疏连接
   · Reformer：用LSH（局部敏感哈希）分组Token
   · 优点：数据驱动，质量更优
   · 缺点：训练复杂，路由可能不稳定
   · 适用：研究原型

3. 近似模式（Approximate Pattern）
   · Linformer：用低秩近似Attention矩阵
   · Performer：用随机特征近似Attention
   · 优点：理论保证，计算量 O(n) 
   · 缺点：近似误差，实际效果不如稀疏Attention
   · 适用：超长序列（1M+）的"快速原型"

4. 分布式模式（Distributed Pattern）
   · Ring Attention：序列维度分片 + 环形通信
   · Sequence Parallelism：序列维度模型并行
   · 优点：支持1M+ Token，可扩展性好
   · 缺点：需要实现分布式训练框架
   · 适用：1M+ 上下文（目前唯一可行方案）
```

#### 第2层：Ring Attention 核心原理

```
问题：1M Token上下文，单卡显存放不下
  KV Cache大小（LLaMA-3-70B，1M Token）：~2560GB

Ring Attention解决方案：序列维度分片
  · 8个GPU，每个GPU负责 125K Token
  · 每个GPU只存储自己负责的KV Cache：2560GB / 8 = 320GB/GPU
  · 仍然太大 → 需要进一步优化（GQA + INT4 + 分层压缩）

Ring Attention计算流程：
  假设序列被分为8个块：B₁, B₂, ..., B₈
  每个GPU初始持有1个块

  第1步（局部计算）：
    GPU 0 用 B₁ 的Q 和 B₁ 的KV 计算局部Attention
    GPU 1 用 B₂ 的Q 和 B₂ 的KV 计算局部Attention
    ...

  第2步（环形传递KV）：
    GPU 0 把 B₁ 的KV 发送给 GPU 1
    GPU 1 把 B₂ 的KV 发送给 GPU 2
    ...
    GPU 7 把 B₈ 的KV 发送给 GPU 0

  第3步（累积Attention）：
    GPU 0 现在有用 B₁ 的Q 和 B₂ 的KV（来自GPU 1）
    计算跨块Attention，累加到输出

  重复8次（环形传递一圈）：
    每个GPU都能"看到"所有块的KV
    最终输出 = 所有块Attention的加权和

总通信量：O(N)（每个KV块传递8次）
总计算量：O(N²/8)（每个GPU计算1/8的Attention）
```

#### 第3层：Ring Attention 代码实现（简化版）

```python
import torch
import torch.distributed as dist

def ring_attention_forward(q, k, v, world_size, rank):
    """
    Ring Attention的前向传播（简化版，省略了Mask等细节）
    q, k, v: [batch, seq_len_per_gpu, num_heads, head_dim]
    
    返回：
      out: [batch, seq_len_per_gpu, num_heads, head_dim]
    """
    seq_len = q.shape[1]
    
    # 初始化输出（全零）
    out = torch.zeros_like(q)
    
    # 环形计算（共world_size步）
    for step in range(world_size):
        # 当前步：用本地的Q和（本地或接收到的）KV计算Attention
        attn_logits = torch.matmul(q, k.transpose(-2, -1)) / math.sqrt(q.shape[-1])
        attn_weights = F.softmax(attn_logits, dim=-1)
        out_local = torch.matmul(attn_weights, v)
        
        # 累积到输出（平均或加权）
        out = out + out_local / world_size
        
        # 如果不是最后一步，传递KV到下一个GPU
        if step < world_size - 1:
            # 发送当前KV到rank+1
            send_k = k.contiguous()
            send_v = v.contiguous()
            
            # 从rank-1接收新的KV
            recv_k = torch.empty_like(k)
            recv_v = torch.empty_like(v)
            
            # 使用NCCL进行环形通信
            ops = []
            # Send k to (rank+1)%world_size
            ops.append(dist.P2POp('isend', send_k, (rank + 1) % world_size))
            # Recv k from (rank-1+world_size)%world_size
            ops.append(dist.P2POp('irecv', recv_k, (rank - 1 + world_size) % world_size))
            
            reqs = dist.batch_isend_irecv(ops)
            for req in reqs:
                req.wait()
            
            # 同样处理v
            # ...
            
            k = recv_k
            v = recv_v
    
    return out

# 实际使用（需要分布式训练框架支持）：
#  1. 初始化NCCL通信组
#  2. 将序列分片到8个GPU
#  3. 每个GPU运行ring_attention_forward
#  4. 反向传播需要实Save/Restore中间激活（显存优化）
```

#### 第4层：1M Token 上下文的系统设计

```
需求：支持1M Token上下文的LLM推理服务

系统设计（分层）：

第1层：模型优化
  · 使用GQA（分组查询注意力）：KV Cache -87.5%
  · 使用INT4量化KV Cache：-50%
  · 使用YaRN RoPE：支持长度外推 256x

第2层：稀疏注意力
  · 前32K Token：稠密Attention（保留局部依赖）
  · 32K-128K Token：Longformer稀疏（局部窗口512 + 全局Token 8）
  · 128K-1M Token：Ring Attention（分布式计算）

第3层：KV Cache管理
  · 分层存储：
    - 热层（前16层）：全精度FP16，存储在GPU显存
    - 温层（中32层）：INT8量化，存储在GPU显存
    - 冷层（后32层）：INT4量化，存储在CPU内存（需要时取回）
  · 驱逐策略：LRU（最近最少使用）
    - 如果显存不足，将最旧的KV块换出到CPU

第4层：分布式推理

量化效果：

#### 第2层：LLMLingua-2 的代码实现与优化

```python
class LLMLingua2:
    """
    LLMLingua-2：改进的文本级压缩（训练一个小型重要性预测模型）
    """
    def __init__(self, importance_model='gpt2-medium', target_ratio=0.25):
        self.model = AutoModelForCausalLM.from_pretrained(importance_model)
        self.tokenizer = AutoTokenizer.from_pretrained(importance_model)
        self.target_ratio = target_ratio
        
    def compute_importance(self, text):
        """
        计算每个Token的重要性分数
        方法：删除该Token后，Perplexity的增加量
        """
        tokens = self.tokenizer.encode(text)
        n = len(tokens)
        
        importance = []
        for i in range(n):
            # 原始Perplexity
            ppl_orig = self.compute_perplexity(tokens)
            
            # 删除第i个Token后的Perplexity
            tokens_without_i = tokens[:i] + tokens[i+1:]
            ppl_without = self.compute_perplexity(tokens_without_i)
            
            # 重要性 = PPL增加量（增加越多 = 越重要）
            imp = ppl_without - ppl_orig
            importance.append(imp)
        
        return importance
    
    def compress(self, text):
        """
        压缩文本到target_ratio
        """
        importance = self.compute_importance(text)
        
        # 选择最重要的Top-(n*target_ratio)个Token
        n = len(importance)
        k = int(n * self.target_ratio)
        
        top_indices = sorted(range(n), key=lambda i: importance[i], reverse=True)[:k]
        top_indices.sort()  # 保持原始顺序
        
        # 提取选中的Token
        compressed_tokens = [self.tokenizer.decode([tokens[i]]) for i in top_indices]
        compressed_text = ''.join(compressed_tokens)
        
        return compressed_text
    
    def finetune_for_compression(self, original_texts, compressed_texts):
        """
        微调大模型，使其在压缩后的文本上表现接近原始文本
        """
        # 用KL散度损失：让模型在压缩文本上的输出分布接近原始文本
        for orig, comp in zip(original_texts, compressed_texts):
            logits_orig = self.llm(orig)
            logits_comp = self.llm(comp)
            
            loss = F.kl_div(
                F.log_softmax(logits_comp, dim=-1),
                F.softmax(logits_orig, dim=-1),
                reduction='batchmean'
            )
            
            loss.backward()
            optimizer.step()
        
        # 微调后：压缩文本的性能损失从 5-10% → 2-3%

# LLMLingua-2效果（Microsoft Research，2024）：
#  · 压缩比：4:1

#  · 微调成本：100万Token，8×A100，12小时
