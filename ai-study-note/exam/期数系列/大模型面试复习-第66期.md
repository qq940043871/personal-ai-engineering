### 1.4 核心亮点 1：KGW Green-List 注入（工业界主流算法）

这是 2023 年 Kirchenbauer 提出的 **KGW（Green List）** 方法，也是 OpenAI / Google / Meta 水印方案的学术原型。本质是**用密钥把词表分红绿两份，在绿表 token 的 logit 上加偏置 δ，使带水印文本中绿 token 占比显著偏高**，检测时做二项检验即可。

```python
import hashlib, numpy as np
from scipy.stats import norm

class KGWWatermark:
    def __init__(self, vocab_size, gamma=0.5, delta=2.0, key=b"tenant-secret"):
        self.V, self.gamma, self.delta, self.key = vocab_size, gamma, delta, key

    def _green_list(self, prev_tid):
        # 用「上一 token id + 密钥」派生伪随机种子 → 把词表洗牌后取前 γ 比例作绿表
        h = hashlib.sha256(self.key + str(prev_tid).encode()).digest()
        rng = np.random.RandomState(int.from_bytes(h[:4], 'big'))
        perm = rng.permutation(self.V)
        g = int(self.gamma * self.V)
        return set(perm[:g].tolist())

    def bias_logits(self, logits, prev_tid):
        green = self._green_list(prev_tid)
        bias = np.zeros(self.V)
        for t in green:
            bias[t] = self.delta          # 绿 token logit +δ，提高被采样概率
        return logits + bias

    def detect(self, tokens):
        # 统计序列中绿 token 占比，做二项 / z 检验
        N = len(tokens) - 1
        g = sum(1 for i in range(N) if tokens[i+1] in self._green_list(tokens[i]))
        z = (g - self.gamma * N) / np.sqrt(self.gamma * (1 - self.gamma) * N)
        return {"green_frac": g / N, "z": z, "p_value": 1 - norm.cdf(z)}
```

**面试亮点**：能讲清三个数学事实——①H0（人类文本，无偏置）下绿 token 数 `g ~ Binomial(N, γ)`，期望 `γN`、方差 `γ(1-γ)N`；②z 值随序列长度 `√N` 增长，所以**越长越易检测**（100 token 时 z 约 4.5，p<1e-5）；③δ 越大 z 越高但生成质量越差，存在**强度-失真权衡**。

### 1.5 核心亮点 2：无偏 / 失真自由水印（Gumbel 与 Unigram）

KGW 的 `logit + δ` 会系统性改变输出分布（文本略机械、perplexity 上升），在**高风险合规场景**不可接受。我们同时上线两类**理论失真=0**的水印：

```python
import numpy as np, hashlib

def gumbel_noise(key, position, token_id, T=1.0):
    h = hashlib.sha256(f"{key}-{position}-{token_id}".encode()).digest()
    u = int.from_bytes(h[:8], 'big') / 2**64
    return -np.log(-np.log(u + 1e-12)) * T   # 标准 Gumbel(0,1) 噪声

def gumbel_sample(logits, key, position, T=1.0):
    z = logits / T
    for tid in range(len(z)):
        z[tid] += gumbel_noise(key, position, tid, T)   # 注入密钥噪声后取 argmax
    return int(np.argmax(z))

# 检测：持有密钥者可恢复噪声，验证「logit_i + g_i 是否最大」→ 不改分布的「不可检测水印」
```

- **Gumbel 水印（Aaronson & Kirchenbauer 2024）**：给每个 logit 加一把**密钥派生的秘密 Gumbel 噪声**，仍按 `argmax` 采样；因为噪声是确定性密钥函数，持有密钥者能验证"某 token 确实是在加了正确噪声后胜出"。已证明为**不可检测（provably undetectable）**——任何统计检验都无法区分带水印与不带水印分布。
- **Unigram 水印（Aaronson）**：给每个词表 token 固定一个秘密分数 `r_i = PRF(key, i) ∈ [0,1]`，用**拒绝采样**（分数 > τ 才接受，否则重采样）注入，完全不改模型 logits。τ 选得当时理论失真=0。

### 1.6 核心亮点 3：对抗鲁棒层（抗改写 / 翻译 / 裁剪）

KGW 最大的软肋是 **paraphrase 攻击**（用 LLM 改写后绿 token 被打散，检测失效）。我们落地 **Kirchenbauer Robust Watermark**：绿表只从**当前步 top-k 高概率 token** 中取，而非整表——因为改写通常保留原本高概率词，绿信号得以保留。

```python
def robust_green_list(logits, prev_tid, key, k_frac=0.5, gamma=0.5):
    k = max(1, int(k_frac * len(logits)))
    topk = set(np.argsort(logits)[-k:].tolist())      # 只在 top-k 高概率 token 内打标
    h = hashlib.sha256(key + str(prev_tid).encode()).digest()
    rng = np.random.RandomState(int.from_bytes(h[:4], 'big'))
    perm = rng.permutation(list(topk))
    return set(perm[:int(gamma * len(perm))].tolist()) # 绿表 ⊂ top-k → 改写后残留
```

**面试亮点**：能讲清鲁棒性的**三重权衡三角形**——`检测强度 ↔ 失真度 ↔ 抗攻击性` 不可能同时拉满：KGW(δ大) 强检测但怕改写；robust-KGW 抗改写但单文档信号弱；Gumbel 不可检测但需持有密钥且对 token 级替换敏感。平台按租户风险等级**分级选型**。

## 🔧 二、技术难点（Key Technical Difficulties）

### 难点 1：强度-失真权衡（Strength–Distortion Tradeoff）

**根因**：KGW 的 δ 偏置等价于把生成分布向绿表"推"了一点，δ↑ → 绿占比↑ → z↑ → 易检测，但同时 KL(真实‖带水印)↑ → 文本流畅度/指令遵循下降。`δ=0` 无信号，`δ=4` 文字明显僵硬。

**方案**：做**离线网格搜索 + 在线 β 监控**。固定 γ=0.5，扫描 δ∈{1,1.5,2,2.5,3}，在 10k 测试集上量 `检测AUC` 与 `质量掉点(PPL/MT-Bench)`，取 Pareto 点（我们取 δ=2.0，AUC 0.99、质量掉 <0.5%）。高敏感租户（如新闻稿）用 Gumbel 无偏替代。

### 难点 2：假阳性率（FPR）控制 —— 人类文本误判

**根因**：这是水印**最致命的产业雷区**。若把真人写的作文/代码误判为"AI 生成"，会引发申诉、信任崩塌、合规反诉。单文档检验水平 α=0.01 看似安全，但**平台每天扫描千万文档，多重比较会把 FPR 放大成天文数字**。

**方案 + 代码**：
```python
def multi_compare_correct(p_values, method="bonferroni", alpha=0.01):
    m = len(p_values)
    if method == "bonferroni":
        return [p <= alpha / m for p in p_values]          # 最严：α_eff = α/m
    # Benjamini-Hochberg（在允许部分误报时更省检出力）
    order = sorted(range(m), key=lambda i: p_values[i])
    thr = [i * alpha / m for i in range(1, m + 1)]
    flags = [False] * m
    for rank, i in enumerate(order):
        if p_values[i] <= thr[rank]:
            flags[i] = True
    return flags
```
- 人类文本在 KGW 下绿占比仍 ~γ，z≈0、p≈1，**单测 FPR 天然≈α**。关键是**平台级多重比较修正**（Bonferroni / BH）与**阈值按文档量动态校准**。
- 上线实测：12B token 人类语料上 FPR 0.9% → 经校准降到 **0.3%**，远优于监管 1% 红线。

### 难点 3：无偏 / 失真自由水印的实现与可验证性

**根因**：Gumbel 水印"不可检测"的数学保证依赖**密钥噪声与位置/词表严格绑定**且采样是 argmax（非随机采样），一旦用了 temperature sampling 或 beam search，保证失效。

**方案**：Gumbel 路径强制 `temperature` 映射进噪声、采样退化为 argmax+噪声（等价于秘密扰动后的贪心）；Unigram 路径用拒绝采样。二者都要求**密钥服务端保管、绝不下发客户端**，否则攻击者可反推绿表。检测 API 走私钥验签，与生成解耦。

### 难点 4：对抗鲁棒性 —— 改写 / 翻译 / 裁剪攻击

**根因**：paraphrase、翻译、同义词替换、随机删除都能破坏绿表统计结构；尤其**翻译**会把 token 级绿信号彻底打乱。

**方案**：
- 文本：robust-KGW（top-k 绿表，见 1.6）+ 句子级聚合（用多个 token 共同决定，而非逐 token）。
- 跨语言：在**语义向量空间**打隐式水印（给 embedding 加密钥驱动的微小方向扰动，翻译后语义不变则信号留存）。
- 图像/视频：频域 DCT 水印（不可见、抗压缩裁剪）、与 C2PA 内容凭证结合。
- 红队：内置 paraphrase/translation 攻击回灌，定期测"改写后 AUC"，跌破 0.85 自动告警。

### 难点 5：多模型 / 多框架适配与低延迟注入

**根因**：水印要嵌进 vLLM / TGI / SGLang / HF Transformers 不同采样栈，且注入额外时延必须 <5ms（否则影响 P99）。

**方案**：抽象成 `LogitsProcessor` 接口，各框架挂载各自的 hook（HF 原生支持；vLLM 用 `LogitsProcessor` in sampling params；TGI 用 custom stopping/transform）。密钥与策略在**推理前一次性下发**到 worker，热路径只做"算绿表 + 加偏置"，纯 NumPy/向量化，单 token <0.05ms。

```python
from transformers import LogitsProcessor
class WatermarkProcessor(LogitsProcessor):
    def __init__(self, wm: KGWWatermark):
        self.wm = wm; self.last_tid = 0
    def __call__(self, input_ids, scores):
        scores = self.wm.bias_logits(scores[0].numpy(), self.last_tid)
        self.last_tid = int(np.argmax(scores))
        return scores[None, :]
```

### 难点 6：密钥安全、租户隔离与合规上报

**根因**：水印的"可验证性"同时意味着"可被伪造"——若密钥泄露，攻击者可给任意文本打上本平台水印嫁祸。**多租户**还须保证 A 租户的水印不能被 B 租户的检测逻辑误读。

**方案**：
- 密钥经 **HKDF(密钥 + tenant_id + 模型 + 版本)** 派生，**每租户每模型独立子密钥**，按日轮换（旧密钥留 30 天用于存量验证）。
- 服务端**只存私钥哈希**，生成/检测都走内网签名 API，绝不下发明文密钥。
- 合规层：生成即落 `模型/租户/时间/强度` 的不可篡改审计日志，对接 **C2PA / EU AI Act Art.50 / 中国 AIGC 办法**，监管可一键导出溯源报告。

## ❓ 三、常见问答（6 道深度问题）

**Q1. KGW 水印的原理是什么？绿表怎么生成？为什么能检测？**
> 用密钥 + 上一 token 洗牌词表取前 γ 比例作"绿表"，生成时对绿 token 的 logit 加 δ 偏置，使带水印文本绿占比显著高于随机的 γ。检测时统计绿 token 数 `g`，在 H0（无偏置，g~Binomial(N,γ)）下算 z 值 `z=(g-γN)/√(γ(1-γ)N)`，p<阈值即判为 AI 生成。z 随 √N 增长，越长的文本越易检。

**Q2. 水印会影响生成质量吗？δ 怎么选？**
> 会。δ 偏置等价于把分布在绿表方向推偏，δ↑ → 检测强但 KL 散度↑ → 流畅度/指令遵循下降。选法是离线扫 δ∈{1..3}，在测试集上量 AUC 与质量掉点取 Pareto 点（我们 δ=2.0，AUC 0.99、质量掉<0.5%）。高敏场景改用 Gumbel/Unigram 无偏水印。

**Q3. 假阳性率怎么控制？真人文章被误判怎么办？**
> 人类文本在 KGW 下绿占比仍≈γ，单测 FPR≈α。真正风险在**多重比较**：扫描 m 文档用 Bonferroni/BH 把 α_eff 降到 α/m。再叠加阈值按文档量动态校准 + 人类语料回测。我们实测 12B token 人类语料 FPR 0.3%，优于监管 1% 红线。

**Q4. 无偏 / 失真自由水印（Gumbel / Unigram）为什么"无偏"？和 KGW 区别？**
> KGW 改 logits 故分布偏移。Gumbel 给每个 logit 加**密钥派生的秘密 Gumbel 噪声**后仍 argmax，噪声是确定性密钥函数，故整体分布 = 原 argmax 分布（不可检测）；Unigram 用**拒绝采样**不改 logits。二者理论失真=0，但代价是：须持有密钥检测、对 token 级替换敏感、工程更重。

**Q5. 改写（paraphrase）/ 翻译攻击怎么破？鲁棒水印怎么做？**
> 普通 KGW 绿 token 被改写打散即失效。鲁棒做法：绿表只取**当前步 top-k 高概率 token**（改写多保留高概率词），并做句子级聚合。跨语言用**语义向量空间隐式水印**（embedding 加密钥微扰，翻译后语义不变信号留存）。三难权衡：检测强 / 失真低 / 抗攻击 不可同时拉满，须分级选型。

**Q6. 水印在产业落地面临的真实问题是什么？**
> ①合规：EU AI Act / 中国 AIGC 办法要求 AI 内容标识，但跨国标准不一；②误杀：FPR 控制是生命线（见 Q3）；③密钥：泄露即可被伪造嫁祸，须 HKDF 派生 + 服务端保管 + 轮换；④对抗：paraphrase/翻译持续进化，需红队回灌；⑤多模态：文本水印成熟但图像/视频鲁棒水印仍是工程难点。落地须"水印 + C2PA + 审计"三位一体。

## 🎯 四、模拟面试（3 道深度题 + 参考答案要点）

### 模拟题 1：千万级 AIGC 平台的水印与溯源系统端到端设计

> **题目**：你负责一家日产 10 亿条 AIGC 内容（文本/图像/视频/音频）的平台，监管要求"任何内容可验证是否本平台生成、误杀真人内容1% 以下、改写后仍可溯源"。请设计系统架构、核心算法、FPR 控制与对抗鲁棒方案。

**参考答案要点（结构化作答框架）**：
- **架构分层**（呼应 L1–L6）：注入层（logit-bias / Gumbel / 频域图水印）→ 密钥策略层（HKDF 租户派生 + 按日轮换）→ 适配层（vLLM/TGI/SDXL 各自 hook）→ 检测层（z 检验 + 多算法融合 + FPR 修正）→ 鲁棒层（top-k 绿表 + 语义向量水印 + 红队回灌）→ 应用层（溯源查询 + 合规上报 + C2PA）。
- **文本算法**：默认 KGW(γ=0.5,δ=2.0)，高敏租户切 Gumbel 无偏；跨语言走 embedding 微扰。
- **FPR 控制**：单测 α=0.01 + 平台级 BH 多重比较修正 + 人类语料回测校准阈值，目标 FPR<0.3%。
- **对抗鲁棒**：robust-KGW(top-k 绿表) + 句子级聚合；图像 DCT 频域 + C2PA；红队 paraphrase/translation 每日回灌，改写后 AUC<0.85 自动告警。
- **密钥安全**：私钥服务端签名 API，只下发子密钥哈希；按 tenant+model+version+日期 派生；旧密钥留 30 天。
- **量化指标**：文本 AUC 0.99、改写字保留 0.91、注入 +3ms、四模态覆盖。
> 加分：点出"三难权衡（检测/失真/抗攻击）不可同时最优，按租户风险分级"；点出"水印不可单独扛合规，须 +C2PA + 审计"。

### 模拟题 2：线上"AI 误判率"从 1% 以下 暴涨到 18% 的 30 分钟止血复盘

> **题目**：运营报警：过去 1 小时"真人内容被标为 AI 生成"的申诉率从 0.3% 飙到 18%。你是值班 SRE，请按 30 分钟 SOP 定位止血。

**参考答案要点（止血 SOP）**：
- **0–5 min 止血优先**：立刻把"强水印检测"降级为"疑似标记 + 人工复核队列"，暂停自动打标裁决，先止住误杀扩散；同时回滚最近一次上线（密钥轮换 / 模型升级 / 阈值变更任一）。
- **5–15 min 定位**：三方向并行——
  1. **密钥/参数漂移**：是否刚做了密钥轮换，旧内容用新密钥检测导致绿表错位 → 查轮换日志；
  2. **模型升级未对齐**：新模型 vocab 变化但 γ/δ 沿用旧值，人类文本 z 值虚高 → 比对模型版本与绿表生成参数；
  3. **阈值漂移/标定过期**：扫描文档量暴涨（活动引流）触发多重比较未修正 → 查当日流量与 BH 修正是否生效。
- **15–25 min 验证**：取申诉样本做 A/B：旧参数 vs 新参数重检，确认真凶（本例多为"模型升级 + 阈值未重标"组合）。
- **25–30 min 闭环**：回滚模型参数 + 重跑阈值校准 + 补发"误杀补偿"；事后把"密钥/模型变更必须联动重标"写成上线卡点。
> 加分：能用数字说话（z=(g-γN)/√(γ(1-γ)N) 在 N 暴增时若 γ 错配会系统性虚高）；提到"检测阈值须随扫描量动态校准"这一最易被忽略的点。

### 模拟题 3：开放 7B 模型，如何做到水印"抗改写 + 可检测 + 误杀1% 以下"一体

> **题目**：给你一个开源 7B 模型（权重公开、无法改训练），要求部署其生成服务时打上"抗改写且不可被轻易移除、仍可检测、误杀1% 以下"的水印。给出训练 + 推理一体方案。

**参考答案要点**：
- **推理侧（无需训练）**：Gumbel 无偏水印（密钥噪声 argmax，不可检测、零失真）+ robust-KGW(δ 调小、top-k 绿表) 双轨——Gumbel 保"不可移除"，robust-KGW 保"强可检"，二者融合检测分数。
- **训练侧增强（若允许轻量微调）**：对 7B 做 **LoRA 蒸馏**，让它"自然偏向生成带绿表偏置风格的文本"（即水印成为模型习惯而非外挂），这样即便攻击者移除注入层，模型本身仍残留统计信号；同时用**对抗训练**喂 paraphrase 样本，逼模型在改写后仍保持绿占比。
- **误杀控制**：密钥派生 + BH 多重比较 + 人类语料回测，把 FPR 压到 0.3%。
- **抗移除**：密钥服务端保管 + 模型习惯化（双重保险），攻击者即便做 logit 重归一或随机替换也难以抹除。
> 加分：指出"纯推理无偏水印（Gumbel）对抗 token 级替换弱，需 + 模型习惯化 + 鲁棒绿表"才能真抗改写；点出"开源权重无法阻止本地移除，但云端服务可通过协议层强制水印"。

## 📌 五、今日速记卡（Flashcards）

| 考点 | 一句话答案 |
|------|-----------|
| KGW 原理 | 密钥+prev洗牌词表取绿表，绿token logit+δ，检测做二项/z检验 |
| z 公式 | z=(g-γN)/√(γ(1-γ)N)，随√N增长，越长越易检 |
| 强度-失真权衡 | δ↑→检测强但KL↑质量降，取Pareto点(δ=2.0) |
| 无偏水印 | Gumbel(密钥噪声argmax,不可检测)/Unigram(拒绝采样)，理论失真=0 |
| FPR 控制 | 单测≈α，平台级BH/Bonferroni多重比较修正+人类回测校准 |
| 抗改写 | robust-KGW(top-k绿表)+句子聚合+语义向量水印，三难不可同优 |
| 密钥安全 | HKDF租户派生+服务端保管+按日轮换+旧密钥留30天 |
| 合规落地 | 水印+C2PA+审计三位一体，对接EU AI Act/中国AIGC办法 |
| KGW vs Gumbel | 前者改logits可检测但失真，后者不可检测零失真但需持密钥 |
| 误杀止血 | 先降级人工复核→回滚变更→查密钥/模型/阈值漂移→重标校准 |
