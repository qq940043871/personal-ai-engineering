## 📌 一、项目亮点（Project Highlights）

### 1.1 RAG 系统全链路工程化

#### **从"能跑"到"好用"——RAG 生产级架构演进**

我们搭建了完整的 RAG（Retrieval-Augmented Generation）系统，经历了三代架构演进：

```
V1（原型）: 简单检索 + LLM 回答
  问题：检索不准、上下文截断、答案质量不稳定

V2（优化）: 混合检索 + 重排序 + 上下文窗口管理
  问题：延迟较高、多轮对话上下文丢失

V3（生产）: Query Rewrite + 混合检索 + Multi-stage Rerank + 对话记忆
  核心：端到端延迟 < 2s，准确率提升 40%
```

#### **关键技术亮点**

| 模块 | 技术 | 解决的问题 |
|------|------|-----------|
| **Query Rewrite** | HyDE + Multi-Query | 用户问题模糊、口语化 |
| **混合检索** | BM25 + Vector Search (Reciprocal Rank Fusion) | 精确匹配 + 语义匹配互补 |
| **重排序** | Cross-Encoder Reranker | Top-K 检索结果不够精准 |
| **上下文压缩** | LLMLingua / 摘要压缩 | 有效信息被噪声稀释 |
| **评估体系** | RAGAS 框架 | 无法量化 RAG 效果 |

**面试表达**：
> "我们的 RAG 系统不是简单地调一次向量搜索然后拼接 Prompt，而是做了完整的 Query 预处理、混合检索、两阶段重排序和上下文压缩。用 RAGAS 框架做端到端评估，Faithfulness 从 0.72 提升到 0.91。"

```python
# 3. 语义缓存（相似问题命中缓存）
async def semantic_cache(query: str, threshold: float = 0.95) -> str:
    """用 Embedding 做语义缓存，相似问题直接返回"""
    query_vec = await embed(query)

    # 搜索最相似的历史 Query
    cached = await vector_db.search(query_vec, top_k=1)

    if cached and cached[0].score >= threshold:
        return cached[0].cached_response
```

**面试要点**：

- **本地部署必要性**：数据安全要求高时，选择 bge 等开源模型本地部署

### 1.4 多模态 Agent 实战

#### **多模态理解 pipeline**

```
用户输入（文本 + 图片 + 文件）
    ↓
[输入解析层] 识别输入类型 → 路由到不同的处理 pipeline
    ↓
[文本处理]   → LLM 直接处理
[图片处理]   → Vision Model 提取描述 → 送入 LLM
[文档处理]   → OCR/PDF Parser → 分块 → RAG
[音频处理]   → ASR 语音转文字 → 送入 LLM
    ↓
[多模态融合] 将所有信息汇总，统一 Prompt 结构
    ↓
[LLM 生成]   结合所有上下文生成最终回答
```

#### **多模态 RAG 实现**

```python
from typing import List, Union
from PIL import Image

class MultimodalRAG:
    """支持图片+文本的 RAG 系统"""

    def __init__(self):
        self.text_retriever = VectorDB(collection="text_knowledge")
        self.image_retriever = VectorDB(collection="image_knowledge")

    async def retrieve(self, query: str, top_k: int = 5) -> List[dict]:
        """多模态检索：同时搜索文本和图片"""

        # 1. 文本检索
        text_results = await self.text_retriever.search(query, top_k=top_k)

        # 2. 图片检索（用 CLIP 模型做图文匹配）
        image_results = await self.image_retriever.search(query, top_k=top_k // 2)

        # 3. 融合排序（Reciprocal Rank Fusion）
        all_results = text_results + image_results
        fused = self.reciprocal_rank_fusion(all_results)

        return fused[:top_k]

    async def answer(self, query: str, uploaded_image: Image.Image = None):
        """完整的多模态问答"""

        # 1. 如果用户上传了图片，先用 Vision Model 分析
        context_parts = []
        if uploaded_image:
            image_desc = await self.vision_model.analyze(
                uploaded_image,
                prompt="详细描述这张图片的内容，包括文字、数字、图表信息"
            )
            context_parts.append(f"用户上传的图片描述：{image_desc}")

        # 2. RAG 检索
        retrieved = await self.retrieve(query)
        for r in retrieved:
            if r["type"] == "text":
                context_parts.append(r["content"])
            else:
                # 图片检索结果，需要将图片描述作为上下文
                context_parts.append(f"[参考图片] {r['description']}")

        # 3. 构造 Prompt
        prompt = f"""
        根据以下参考资料回答用户问题。

        参考资料：
        {"\\n".join(context_parts)}

        用户问题：{query}

        要求：
        1. 优先使用参考资料中的信息
        2. 如果参考资料不够，可以结合常识推理
        3. 如果用户上传了图片，结合图片信息回答
        """

        return await self.llm.chat(prompt)

    @staticmethod
    def reciprocal_rank_fusion(results: List[dict], k: int = 60) -> List[dict]:
        """RRF 融合排序算法"""
        scores = {}
        for rank, result in enumerate(results):
            doc_id = result["id"]
            scores[doc_id] = scores.get(doc_id, 0) + 1.0 / (k + rank + 1)

        return sorted(
            results,
            key=lambda x: scores.get(x["id"], 0),
            reverse=True
        )
```

**面试表达**：
> "我们实现了多模态 RAG，用户可以同时上传图片和文本提问。文本走标准的向量检索，图片用 CLIP 模型做图文匹配。最终用 RRF（Reciprocal Rank Fusion）融合排序，保证相关结果优先展示。"

### 2.1 RAG 中的"检索不准"问题

#### **根因分析**

| 原因 | 占比 | 解决方案 |
|------|------|---------|
| **Query 表达不清晰** | 35% | Query Rewrite（HyDE / Multi-Query） |
| **文档分块不合理** | 25% | 语义分块 + 重叠窗口 |
| **Embedding 模型不匹配** | 20% | Fine-tune Embedding |
| **检索数量不够** | 15% | 扩大 Top-K + 重排序 |
| **知识缺失** | 5% | 补充知识库 |

#### **HyDE（Hypothetical Document Embedding）详解**

```python
async def hyde_search(query: str, vector_db, llm) -> List[dict]:
    """
    HyDE 核心思路：
    1. 让 LLM 假装回答问题，生成一段"假答案"（Hypothetical Document）
    2. 用这段假答案的 Embedding 去检索
    3. 假答案比原始 Query 更接近真实文档的语义空间

    示例：
    Query: "Vue3 和 React 哪个性能更好？"
    HyDE 生成的假答案: "Vue3 和 React 在性能方面各有优势。
      Vue3 使用 Proxy 实现响应式... React 使用 Virtual DOM..."
    → 用这段话去检索，比直接用 Query 检索效果好得多
    """

    # Step 1: 生成假设性文档
    hyde_prompt = f"""
    请回答以下问题，即使你不确定也请给出尽可能合理的回答：
    {query}
    """
    hypothetical_doc = await llm.chat(hyde_prompt)

    # Step 2: 用假设性文档的 Embedding 检索
    query_embedding = embed(hypothetical_doc)
    results = await vector_db.search(query_embedding, top_k=5)

    return results
```

#### **语义分块 vs 固定长度分块**

```python
# ❌ 固定长度分块（简单但容易截断语义）
def naive_chunk(text: str, chunk_size: int = 500) -> List[str]:
    return [text[i:i+chunk_size] for i in range(0, len(text), chunk_size)]

# ✅ 语义分块（保持段落/章节完整性）
def semantic_chunk(text: str, model) -> List[str]:
    """
    原理：计算相邻句子的 Embedding 相似度
    相似度骤降的位置 → 语义断点 → 在此分块
    """
    sentences = split_sentences(text)
    embeddings = [embed(s) for s in sentences]

    chunks = []
    current_chunk = [sentences[0]]

    for i in range(1, len(sentences)):
        # 计算与上一句的相似度
        sim = cosine_similarity(embeddings[i], embeddings[i-1])

        if sim < 0.5:  # 相似度骤降 → 新分块
            chunks.append(" ".join(current_chunk))
            current_chunk = [sentences[i]]
        else:
            current_chunk.append(sentences[i])

    if current_chunk:
        chunks.append(" ".join(current_chunk))

    return chunks
```

```python
# 方案 1：Structured Output（OpenAI JSON Mode / Function Calling）

import re

def robust_parse(llm_output: str) -> dict:
    """多层兜底解析"""
    try:
        return json.loads(llm_output)
    except json.JSONDecodeError:
        pass

    # 尝试提取 JSON 块
    json_match = re.search(r'```json\s*(.*?)\s*```', llm_output, re.DOTALL)
    if json_match:
        try:
            return json.loads(json_match.group(1))
        except json.JSONDecodeError:
            pass

    # 尝试提取 { } 块
    brace_match = re.search(r'\{.*\}', llm_output, re.DOTALL)
    if brace_match:
        try:
            return json.loads(brace_match.group())
        except json.JSONDecodeError:
            pass

    # 最后兜底：让 LLM 重新格式化
    return {"raw_output": llm_output, "parse_failed": True}
```

### 2.3 Agent 编排模式（Orchestration Patterns）

#### **四种主流编排模式对比**

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  1. Sequential Chain（串行链）                                   │
│     A → B → C → D                                              │
│     场景：固定流程（数据清洗→分析→生成报告）                        │
│                                                                 │
│  2. Router（路由器）                                              │
│     Input → [Router] → Branch A / Branch B / Branch C            │
│     场景：多意图分类（客服分流、内容审核）                           │
│                                                                 │
│  3. ReAct Loop（推理-行动循环）                                    │
│     Think → Act → Observe → Think → Act → ... → Final Answer     │
│     场景：需要多步推理（代码助手、数据分析）                         │
│                                                                 │
│  4. Multi-Agent Collaboration（多 Agent 协作）                     │
│     Planner → [Agent1, Agent2, Agent3] → Reviewer → Output        │
│     场景：复杂任务分解（软件开发、科研分析）                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### **生产级 Multi-Agent 编排实现**

```python
from enum import Enum
from typing import Optional
from dataclasses import dataclass

class AgentRole(Enum):
    PLANNER = "planner"
    CODER = "coder"
    REVIEWER = "reviewer"
    TESTER = "tester"

@dataclass
class Task:
    id: str
    description: str
    assignee: AgentRole
    dependencies: list[str] = None  # 依赖的任务ID
    status: str = "pending"
    result: str = ""

class AgentOrchestrator:
    """多 Agent 编排器"""

    def __init__(self):
        self.agents = {
            AgentRole.PLANNER: LLMAgent(
                role="产品经理",
                system_prompt="你负责将用户需求分解为具体的技术任务...",
            ),
            AgentRole.CODER: LLMAgent(
                role="高级开发者",
                system_prompt="你负责编写高质量的代码...",
            ),
            AgentRole.REVIEWER: LLMAgent(
                role="代码审查专家",
                system_prompt="你负责审查代码质量，检查 Bug 和安全隐患...",
            ),
            AgentRole.TESTER: LLMAgent(
                role="测试工程师",
                system_prompt="你负责编写测试用例并验证功能...",
            ),
        }
        self.task_queue = []
        self.completed = {}

    async def execute(self, user_requirement: str) -> str:
        """完整的编排流程"""

        # Phase 1: 任务分解
        plan = await self.agents[AgentRole.PLANNER].chat(
            f"将以下需求分解为具体的开发任务：\n{user_requirement}\n"
            f"输出 JSON 格式的任务列表，每个任务包含 id、description、assignee"
        )
        tasks = self._parse_tasks(plan)

        # Phase 2: 任务执行（按依赖关系）
        results = {}
        for task in tasks:
            # 检查依赖是否完成
            if not all(dep in results for dep in (task.dependencies or [])):
                continue

            agent = self.agents[task.assignee]
            context = self._build_context(task, results)

            result = await agent.chat(context)
            results[task.id] = result

        # Phase 3: 结果审核
        review = await self.agents[AgentRole.REVIEWER].chat(
            f"审核以下开发成果：\n{json.dumps(results, ensure_ascii=False)}\n"
            f"指出需要修改的地方。如果全部通过，回复 APPROVED。"
        )

        if "APPROVED" not in review:
            # 不通过，将修改意见反馈给执行者，最多迭代 2 次
            for task in tasks:
                agent = self.agents[task.assignee]
                results[task.id] = await agent.chat(
                    f"原始任务：{task.description}\n"
                    f"你的实现：{results[task.id]}\n"
                    f"审查意见：{review}\n请根据审查意见修改。"
                )

        return json.dumps(results, ensure_ascii=False, indent=2)

    def _build_context(self, task: Task, results: dict) -> str:
        """构建任务上下文（包含依赖任务的输出）"""
        context = f"你的任务：{task.description}\n\n"
        for dep_id in (task.dependencies or []):
            if dep_id in results:
                context += f"依赖任务 {dep_id} 的输出：\n{results[dep_id]}\n\n"
        return context
```

**面试表达**：
> "我们的 Agent 编排器支持四种模式：串行链适合固定流程，路由器适合意图分类，ReAct 循环适合需要多步推理的场景，Multi-Agent 协作适合复杂任务。在 Multi-Agent 模式下，我们有 Planner 分解任务、Coder 执行、Reviewer 审核、Tester 验证，通过任务依赖关系图控制执行顺序。"

### 2.4 长上下文处理策略

#### **问题场景**
- GPT-4 Turbo 上下文窗口 128K tokens
- 但长上下文 ≠ 高质量，中间信息容易被"遗忘"（Lost in the Middle）

#### **解决方案**

```python
class LongContextManager:
    """长上下文管理器"""

    # 策略 1: 上下文窗口分级
    CONTEXT_LEVELS = {
        "fast": {"model": "gpt-4o-mini", "max_tokens": 8000},   # 便宜快速
        "standard": {"model": "gpt-4o", "max_tokens": 32000},   # 平衡
        "extended": {"model": "gpt-4-turbo", "max_tokens": 128000},  # 长文档
    }

    async def route(self, messages: list) -> str:
        """根据输入长度自动选择模型"""
        total_tokens = sum(count_tokens(m["content"]) for m in messages)

        for level, config in reversed(self.CONTEXT_LEVELS.items()):
            if total_tokens <= config["max_tokens"]:
                return await self.call_model(config["model"], messages)

        # 超出最大上下文，需要压缩
        compressed = await self.compress_context(messages)
        return await self.call_model("gpt-4-turbo", compressed)

    # 策略 2: Map-Reduce 分块处理
    async def map_reduce(self, long_document: str, question: str) -> str:
        """将长文档分块，分别处理，再合并结果"""
        chunks = self.semantic_chunk(long_document)

        # Map: 每个 chunk 独立回答
        map_results = []
        for chunk in chunks:
            result = await self.llm.chat(
                f"根据以下文档片段回答问题：\n{chunk}\n问题：{question}"
            )
            map_results.append(result)

        # Reduce: 合并所有回答
        final_answer = await self.llm.chat(
            f"根据以下多个来源的回答，给出最终的综合答案：\n"
            + "\n".join(f"来源{i+1}: {r}" for i, r in enumerate(map_results))
            + f"\n原始问题：{question}"
        )
        return final_answer

    # 策略 3: Lost in the Middle 缓解
    @staticmethod
    def reorder_context(documents: list, query: str) -> list:
        """
        将最相关的文档放在开头和结尾
        （研究表明 LLM 对开头和结尾的信息更敏感）
        """
        # 按相关性排序
        ranked = sorted(documents, key=lambda d: d["score"], reverse=True)

        # 重排：最相关的放头尾，中间的放中间
        reordered = []
        for i, doc in enumerate(ranked):
            if i % 2 == 0:
                reordered.insert(0, doc)    # 偶数位：从头部插入
            else:
                reordered.append(doc)       # 奇数位：从尾部插入

        return reordered
```

### Q1: RAG 和 Fine-tuning 如何选择？

**面试高频题，必须掌握**

| 维度 | RAG | Fine-tuning |
|------|-----|-------------|
| **适用场景** | 需要外部知识（文档、数据库） | 需要特定风格/格式/能力 |
| **知识更新** | 实时（更新文档即可） | 需要重新训练 |
| **幻觉控制** | 好（有来源约束） | 一般 |
| **成本** | 中等（检索+生成） | 高（训练成本） |
| **部署复杂度** | 中等 | 高 |
| **效果上限** | 取决于知识库质量 | 取决于训练数据 |

**最佳实践：RAG + Fine-tuning 结合**
> "我们的经验是先用 RAG 解决知识问题，如果 LLM 的输出格式、风格不达标，再用 Fine-tuning 调优。两者不是替代关系，而是互补关系。"

### Q2: 如何评估 RAG 系统的效果？

**使用 RAGAS 框架**

```python
# RAGAS 评估四大核心指标
ragas_metrics = {
    # 1. Faithfulness（忠实度）：答案是否忠实于检索到的上下文
    #    值域 0-1，越高越好
    "faithfulness": 0.91,

    # 2. Answer Relevancy（答案相关性）：答案是否切题
    #    值域 0-1，越高越好
    "answer_relevancy": 0.88,

    # 3. Context Precision（上下文精度）：检索到的文档中有多少是相关的
    #    值域 0-1，越高越好
    "context_precision": 0.75,

    # 4. Context Recall（上下文召回）：相关信息是否都被检索到了
    #    值域 0-1，越高越好
    "context_recall": 0.82,
}
```

**优化路径**：
- Faithfulness 低 → 加强 Prompt 约束（"只根据参考资料回答"）
- Answer Relevancy 低 → 优化 Query Rewrite
- Context Precision 低 → 调优 Embedding 模型 / 增加重排序
- Context Recall 低 → 扩大 Top-K / 改进分块策略

### Q4: 如何处理大文档（超过 100 页）的 RAG？

**挑战**：
- 分块太多 → 检索噪声大
- 分块太大 → 上下文窗口不够用
- 文档结构复杂（目录、图表、附录）→ 简单分块会破坏语义

**解决方案：层级化 RAG**

```python
class HierarchicalRAG:
    """层级化 RAG：先定位章节，再检索段落"""

    def __init__(self):
        # 两级索引
        self.chapter_index = VectorDB("chapters")   # 章节级（粗检索）
        self.chunk_index = VectorDB("chunks")       # 段落级（细检索）

    async def build_index(self, document: str):
        """构建层级索引"""
        # 1. 提取文档结构（目录/标题）
        chapters = extract_chapters(document)

        for chapter in chapters:
            # 2. 章节级索引
            chapter_embedding = embed(chapter["title"] + " " + chapter["summary"])
            await self.chapter_index.add(
                id=chapter["id"],
                embedding=chapter_embedding,
                text=chapter["summary"],
                metadata={"chapter_id": chapter["id"], "page_range": chapter["pages"]}
            )

            # 3. 段落级索引（关联到章节）
            chunks = semantic_chunk(chapter["content"])
            for chunk in chunks:
                chunk_embedding = embed(chunk)
                await self.chunk_index.add(
                    id=chunk["id"],
                    embedding=chunk_embedding,
                    text=chunk["content"],
                    metadata={"chapter_id": chapter["id"]}
                )

    async def search(self, query: str) -> list:
        """两阶段检索"""
        # Phase 1: 粗检索（定位章节）
        chapters = await self.chapter_index.search(query, top_k=2)
        target_chapter_ids = [c["metadata"]["chapter_id"] for c in chapters]

        # Phase 2: 细检索（在目标章节内搜索段落）
        chunks = []
        for cid in target_chapter_ids:
            results = await self.chunk_index.search(
                query,
                top_k=5,
                filter={"chapter_id": cid}  # 只在目标章节内搜索
            )
            chunks.extend(results)

        return sorted(chunks, key=lambda x: x["score"], reverse=True)[:5]
```

### Q5: LLM Agent 和传统 Rule-based 系统如何结合？

**核心思路：LLM 负责"判断"，Rule Engine 负责"执行"**

```python
class HybridAgent:
    """LLM + Rule Engine 混合架构"""

    def __init__(self):
        self.llm = LLMClient()
        self.rule_engine = RuleEngine()

        # 预定义规则（高置信度场景直接走规则，不需要 LLM）
        self.rules = {
            "退款查询": self._rule_refund_query,
            "订单状态": self._rule_order_status,
            "常见问题": self._rule_faq,
        }

    async def handle(self, user_input: str) -> str:
        """混合处理"""

        # Step 1: LLM 意图识别
        intent = await self.llm.classify(
            user_input,
            categories=list(self.rules.keys()) + ["其他"]
        )

        # Step 2: 高置信度 → 直接走规则
        if intent.confidence > 0.9 and intent.label in self.rules:
            return self.rules[intent.label](user_input)

        # Step 3: 低置信度 → LLM 生成回答
        response = await self.llm.chat(user_input)

        # Step 4: 事后审核（规则引擎检查 LLM 输出）
        if self.rule_engine.contains_sensitive_info(response):
            return "抱歉，我无法提供该信息。"

        return response

    def _rule_refund_query(self, query: str) -> str:
        """规则：退款查询"""
        order_id = extract_order_id(query)
        return self.rule_engine.query_database(
            "SELECT refund_status FROM orders WHERE id = ?",
            [order_id]
        )
```

**面试表达**：
> "我们的策略是'规则兜底 + LLM 增强'。高频、标准化的场景（退款查询、订单状态）走规则引擎，响应快、成本零、100% 准确。复杂的、长尾的场景走 LLM。同时 LLM 的输出会经过规则引擎的事后审核，防止错误信息泄露。"

```python
class IncrementalIndexer:
    """文档增量更新"""

    async def on_document_change(self, event: dict):
        """文档变更事件回调"""
        doc_id = event["doc_id"]
        action = event["action"]  # create / update / delete

        if action == "delete":
            # 删除旧索引
            await milvus.delete(f"doc_id == '{doc_id}'")
            await pg.delete("DELETE FROM documents WHERE id = ?", [doc_id])

        elif action in ("create", "update"):
            # 解析文档
            doc = await self.parse_document(doc_id)

            # 重新分块 + 向量化
            chunks = semantic_chunk(doc["content"])
            embeddings = embed_batch([c["text"] for c in chunks])

            # 删除旧索引 + 插入新索引（事务性）
            async with transaction():
                await milvus.delete(f"doc_id == '{doc_id}'")
                await milvus.insert(embeddings, metadata=[{"doc_id": doc_id} for _ in chunks])
```

```python
class LearningAgent:
    """能自主学习的 Agent"""

    def __init__(self):
        self.llm = LLMClient()
        self.experience_db = VectorDB("agent_experiences")  # 经验库
        self.success_patterns = []                          # 成功模式

    async def solve(self, task: str) -> str:
        """解决问题（带学习闭环）"""

        # Step 1: 检索相关经验
        experiences = await self.experience_db.search(task, top_k=5)
        experience_context = self._format_experiences(experiences)

        # Step 2: 结合经验执行任务
        prompt = f"""
        任务：{task}

        以下是从过去经验中学到的知识：
        {experience_context}

        请参考这些经验完成任务。
        """
        solution = await self.llm.chat(prompt)

        # Step 3: 获取用户反馈
        feedback = await self.collect_feedback(solution)

        # Step 4: 根据反馈学习
        await self.learn_from_feedback(task, solution, feedback)

        return solution

    async def learn_from_feedback(self, task: str, solution: str, feedback: dict):
        """从反馈中学习"""

        if feedback["rating"] == "positive":
            # 正面反馈 → 提炼成功模式
            pattern = await self.llm.chat(f"""
                从以下成功的任务解决过程中提炼可复用的经验：
                任务：{task}
                解决方案：{solution}

                用 1-2 句话总结经验教训，供将来参考。
            """)

            # 存入经验库
            await self.experience_db.add(
                text=pattern,
                metadata={
                    "task_type": classify_task(task),
                    "success": True,
                    "timestamp": time.time()
                }
            )

        else:
            # 负面反馈 → 提炼失败原因
            failure_lesson = await self.llm.chat(f"""
                以下方案未满足用户需求：
                任务：{task}
                方案：{solution}
                用户反馈：{feedback['comment']}

                分析失败原因，并给出改进建议（1-2 句话）。
            """)

            # 存入经验库（标记为失败教训）
            await self.experience_db.add(
                text=f"避免：{failure_lesson}",
                metadata={
                    "task_type": classify_task(task),
                    "success": False,
                    "timestamp": time.time()
                }
            )

    def _format_experiences(self, experiences: list) -> str:
        """格式化经验上下文"""
        result = []
        for exp in experiences:
            if exp["metadata"]["success"]:
                result.append(f"✅ 成功经验：{exp['text']}")
            else:
                result.append(f"❌ 失败教训：{exp['text']}")
        return "\n".join(result)
```

```
└── 用户满意度：首周满意度 > 3.5/5.0
```

**面试表达**：
> "冷启动的关键是'先能用，再好用'。第一天导入所有已有数据源（Wiki、工单、聊天记录），用 Few-shot Prompt 让 LLM 有基本的表现。第一周收集真实用户反馈，用 LLM 自己标注数据构建训练集。一个月后知识库和 Prompt 都经过了真实场景打磨，效果会有质的提升。"
