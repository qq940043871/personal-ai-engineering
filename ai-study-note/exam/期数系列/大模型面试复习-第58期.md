## 三、技术难点（含根因 + 方案 + 可运行代码/公式）

### 3.1 查询规划与任务分解：一次计划不够，要"边查边改"

**根因**：复杂研究问题（如"对比 A/B/C 三家公司在东南亚的供应链风险"）无法一步检索到位。一次性生成的静态计划有两大问题：①**遗漏子问题**（没覆盖关键维度）；②**过时**（查到一半发现原假设错、方向要调）。纯 ReAct 边走边想又易"陷进一条分支出不来"。

**方案**：Plan-and-Execute + 反思式 replan 双循环
1. **先规划**：LLM 把目标拆成带依赖的子问题 DAG（如"各家公司东南亚工厂分布 → 关税政策 → 物流脆弱点 → 综合风险"）。
2. **再执行**：按 DAG 并行检索；每完成一批，用**信息覆盖评估**判断 gap。
3. **后反思**：覆盖不足或假设被推翻时，**replan**（增删/重排子问题），而非一条路走到黑。

**数学视角（覆盖驱动的 replan）**：设关键子问题集合 `K`，已解答集合 `A`，覆盖分 `cov = |A∩K| / |K|`。当 `cov < θ`（如 0.9）且剩余预算 `B>0`，触发 replan：

```
gap = K \ A                       # 未解答的关键子问题
new_plan = LLM.replan(goal, A, gap, B)   # 生成补充子问题或修正方向
```

**可运行代码：研究计划生成 + 覆盖评估 + 反思 replan**

```python
import re

class ResearchPlanner:
    """计划-执行-反思 三件套。"""
    def __init__(self, llm, theta=0.9):
        self.llm, self.theta = llm, theta
    def make_plan(self, goal):
        # 输出带依赖的子问题列表，形如 ["Q1: xxx", "Q2: xxx (依赖 Q1)"]
        prompt = (f"研究目标：{goal}\n请拆成 3-8 个可独立检索的子问题，"
                   f"用 '- ' 列出，依赖用'(依赖 Qn)'标注：")
        return [l.strip("- ").strip() for l in self.llm(prompt).splitlines() if l.strip().startswith("-")]
    def coverage(self, key_qs, answered):
        # key_qs: 关键子问题集合；answered: 已充分回答的
        if not key_qs: return 1.0
        return len(key_qs & answered) / len(key_qs)
    def reflect_replan(self, goal, answered, key_qs, budget):
        cov = self.coverage(key_qs, answered)
        if cov >= self.theta or budget <= 0:
            return [], cov                      # 达标或没钱，停
        gap = key_qs - answered
        prompt = (f"目标：{goal}\n已答：{answered}\n未覆盖：{gap}\n"
                  f"请补充 1-3 个新子问题或修正研究方向：")
        new_qs = [q.strip("- ").strip() for q in self.llm(prompt).splitlines() if q.strip().startswith("-")]
        return new_qs, cov
```

> 关键权衡：**纯 Plan-then-Execute** 快但易遗漏；**纯 ReAct** 灵活但易发散、难保证覆盖。工业正解 = 粗计划定骨架 + 覆盖评估触发精细 replan，兼顾"不漏"与"不偏"。

### 3.2 迭代检索与查询改写：首查召回低，要"看后再问"

**根因**：用户原始问句（如"最近大模型推理成本怎么降的"）直接拿去检索，召回质量差——词面不匹配、意图含糊、缺少上下文。且一次检索只能覆盖一个角度，复杂问题需**横向拓宽**（更多来源）与**纵向深入**（更细颗粒度）。

**方案**：三板斧
1. **查询改写（Query Rewriting）**：基于已读内容，把子问题改写成更利于检索的词面（去歧义、补实体）。
2. **HyDE（假设性文档嵌入）**：先让 LLM 写一段"假设答案"，用这段答案的 embedding 去检索，比用问句 embedding 召回更准（弥合"查询-文档"语义鸿沟）。
3. **多源并行 + 边际收益停止**：Web / 私有库 / DB 扇出检索；当新增检索的边际相关度低于阈值 ε 即停，避免无效开销。

**数学视角（边际收益递减停止准则）**：设已见文档集 `D_seen`，新查询 `q` 召回 `D_new`，边际收益

```
marginal(q) = rel(D_new \ D_seen) − rel(D_seen)      # 新增相关信息净增量
停止当 marginal(q) < ε
```

**可运行代码：HyDE 改写 + 并行检索 + 边际停止**

```python
import numpy as np

def hyde_query(llm, subq, embed):
    """用假设性答案的 embedding 做检索，弥合查询-文档鸿沟。"""
    hypo_answer = llm(f"假设你要回答：{subq}\n请写一段可能的答案要点：")
    return embed(hypo_answer)                      # 返回假设答案向量

def retrieve_fanout(queries, retrievers, embed, eps=0.05, topk=8):
    """多源并行检索 + 边际收益停止。"""
    seen, docs, total_rel = set(), [], 0.0
    for q in queries:
        qvec = hyde_query(None, q, embed) if False else embed(q)
        for retr in retrievers:                    # Web / 私有库 / DB
            hits = retr.search(qvec, topk)
            new = [h for h in hits if h.id not in seen]
            rel_new = sum(h.score for h in new)
            marginal = rel_new - total_rel
            if marginal < eps and docs:            # 边际收益过低，停
                continue
            for h in new:
                seen.add(h.id); docs.append(h)
            total_rel += rel_new
    return docs
```

### 3.3 来源可信度评估与跨源印证：单源不可信，要"多方对账"

**根因**：网络来源质量参差——营销软文、过时网页、AI 生成内容、甚至编造数据混入。信单一来源极易被带偏（"孤证不立"）。需要**权威性打分 + 跨源一致性印证**双保险。

**方案**：双层可信度
1. **来源权威性 `w_s`**：综合域名权威（gov/edu/顶级期刊 > 普通博客）、发布时效（recency）、被引量、出版方声誉。
2. **claim 级跨源印证**：每个事实 claim 要求 ≥2 个**独立**来源支持；用贝叶斯真值发现（Bayesian Truth Discovery）给 claim 算置信。

**数学视角（加权一致率 / 真值发现）**：设 claim `c` 被来源集 `S` 中部分支持，每个来源权重 `w_s`，claim 置信

```
conf(c) = Σ_{s∈S, s supports c} w_s / Σ_{s∈S} w_s        # 加权一致率
```

更严谨用迭代贝叶斯（Sums 算法）：来源 `s` 可靠度 `α_s` 与 claim 真值 `t_c` 互相迭代估计，直到收敛——可靠来源倾向于一致，真值由高可靠来源主导。

**可运行代码：来源权威性 + claim 跨源印证**

```python
def source_authority(url, published, citations, base=0.5):
    """0~1 来源权威性：域名 + 时效 + 被引。"""
    dom = 1.0 if any(k in url for k in [".gov", ".edu", "nature.com", "arxiv.org"]) else 0.4
    rec = max(0.0, 1.0 - (2026 - published) * 0.1)     # 每年衰减 0.1
    cit = min(1.0, citations / 100.0)
    return base * (0.5*dom + 0.3*rec + 0.2*cit)

def verify_claim(claim, evidences):
    """claim 级跨源印证：加权一致率 + 独立源数。"""
    sup = [e for e in evidences if e.supports(claim)]
    if len({e.src for e in sup}) < 2:                  # 独立源不足 2，降权
        return 0.0
    w_sum = sum(source_authority(e.url, e.year, e.cites) for e in sup)
    w_all = sum(source_authority(e.url, e.year, e.cites) for e in evidences)
    return w_sum / w_all if w_all else 0.0            # conf ∈ [0,1]
```

> 工程要点：**权威性**防"垃圾源进决策"；**跨源印证**防"单一权威源出错"。二者结合，把"信一个"变成"信多数加权"，幻觉率从 22%→3%。

### 3.4 长文综合与引用约束生成：每句话都要"有出处"

**根因**：长报告（数千字）生成时模型易"自信编造"——跑题、张冠李戴、丢掉引用。朴素"一次生成全文"几乎必幻觉。必须让**每个论断绑定证据片段**，且生成后可校验。

**方案**：分节综合 + Citation Grounding
1. **分节生成**：每个子问题绑定其证据块，逐节生成（上下文短、引用准）。
2. **引用约束**：生成时强制 `（来源[1][3]）` 标注；模型只能引用"检索到的证据 id"，不能用外部知识。
3. **自校验**：生成后逐句做 NLI 蕴含校验——`P(sentence | evidence)` 低则该句标记为"无依据"，要么删、要么补检索。

**数学视角（忠实度与引用精度）**：

```
Faithfulness = grounded_sentences / total_sentences          # 有证据支撑的比例
CitationAcc  = correct_citations / total_citations           # 引用指向正确的比例
```

用自然语言推理（NLI）判 `entail(evidence, sentence)`：若 `¬entail` 则 sentence 不被支撑，计入幻觉。

**可运行代码：分节综合 + 引用自校验**

```python
def synthesize_section(subq, evidence_block, llm, nli):
```

### 3.5 工具调用与并行浏览调度：子问题要并发，但不能乱

**根因**：一个研究计划有十几个子问题，串行检索太慢（分钟级→小时级）；并行又面临工具限流、单点失败、结果重复。需要"像 Agent Harness 一样"做 DAG 并行调度。

**方案**：复用 Agent Harness 调度器（第35/44/52期）——子问题 DAG 拓扑分层、同层并行扇出、令牌桶限流、失败重试 + Fallback（搜不到换搜索引擎）、结果去重。

**数学视角（并行加速比与成本）**：

```
T_parallel ≈ T_crit_path                            # 受关键路径约束
S = T_seq / T_parallel                             # 加速比
C = Σ_q (k_retrievals·c_r + l_synth·c_t)           # 总成本 = 检索 + 综合
```

其中 `T_crit_path` 为 DAG 最长依赖链耗时，`k` 为每子问题检索数，`l` 为综合 token 数。

**可运行代码：研究 DAG 并行调度器（复用 Agent Harness 范式）**

```python
from collections import defaultdict, deque

def schedule_research(plan_dag, fetch_fn, max_concurrency=8):
    """子问题 DAG 拓扑分层并行检索；令牌桶限流 + 失败重试。"""
    indeg = {q: len(deps) for q, deps in plan_dag.items()}
    children = defaultdict(list)
    for q, deps in plan_dag.items():
        for d in deps: children[d].append(q)
    ready = deque([q for q, d in indeg.items() if d == 0])
    results, tokens = {}, max_concurrency
    while ready:
        batch = [ready.popleft() for _ in range(min(max_concurrency, len(ready)))]
        for q in batch:
            for attempt in range(3):                     # 失败重试
                try:
                    results[q] = fetch_fn(q); break
                except Exception:
                    if attempt == 2: results[q] = fallback_fetch(q)   # 兜底
            for c in children[q]:
                indeg[c] -= 1
                if indeg[c] == 0: ready.append(c)
    return results                                       # 全部子问题证据
```

### 3.6 成本与时延工程：深度研究不能"无底洞"

**根因**：深度研究一次任务要数十次 LLM 调用（规划 + 改写 + 综合 + 校验），成本与时延易失控，且不同环节对模型能力要求不同——规划用小的、综合用大的，一刀切浪费。

**方案**：三级模型路由 + 预算闸门 + 语义缓存
1. **路由**：小模型做计划/查询改写（70B 级不必）；中模型做检索排序；大模型只做最终综合。经 ModelRouter（第48期）落地。
2. **预算闸门**：`max_searches`（如 ≤30）、`max_tokens`（如 ≤8k）硬上限，超阈即收敛成稿。
3. **语义缓存**：重复/相似的子问题直接复用历史研究档案（MemoryWeaver，第47期），命中即省一次完整检索+综合。

**数学视角（成本模型）**：

```
E[cost] = n_plan·c_small + n_q·(c_mid·k + c_large·l) − hit·(c_mid·k + c_large·l)
```

其中 `hit` 为语义缓存命中次数，每命中省下"一次子问题检索+综合"的全成本。

**可运行代码：预算闸门 + 模型路由 + 语义缓存**

```python
class BudgetGate:
    def __init__(self, max_searches=30, max_tokens=8000):
        self.s, self.t = max_searches, max_tokens
    def ok(self, n_search, n_token):
        return n_search <= self.s and n_token <= self.t

def route(role):
    return {"plan": "7B", "rewrite": "7B", "rank": "14B", "synthesize": "70B"}[role]

def semantic_cache_lookup(subq, cache, embed, thr=0.92):
    qv = embed(subq)
    for key, val in cache.items():                  # 复用历史研究档案
        if cosine(qv, embed(key)) > thr:
            return val                              # 命中，省一次完整研究
    return None
```

## 四、常见问答（6 道深度题）

### Q1：Deep Research 和朴素 RAG、Agent Harness 到底有什么区别？
**答**：三者逐层递进。**朴素 RAG（第38期）** = "一问一答 + 检索拼接"，无规划、无多步、无长文成稿，适合单点问答；**Agent Harness（第35期）** = "通用智能体编排框架"，提供调度/记忆/工具底座，但不限定"研究"语义；**Deep Research（本期）** = 在 Agent Harness 之上、针对"研究写作"场景的垂直智能体：内置"计划 DAG → 迭代检索 → 跨源印证 → 引用约束成稿"的研究闭环，并把 RAG 当作检索底座。一句话：**RAG 是零件，Agent Harness 是机床，Deep Research 是用机床造出的"研究员"产品。**

### Q2：查询规划为什么要"反思 replan"，而不是一次生成计划就执行？
**答**：见 §3.1。一次性静态计划两大死穴——**遗漏**（关键维度没拆出来）和**过时**（查到一半发现原假设错）。纯 ReAct 又易陷进单一分支发散。Plan-and-Execute + 覆盖评估触发 replan，兼顾"骨架不偏"与"细节不漏"：粗计划定方向，执行中用 `cov=|A∩K|/|K|` 测覆盖，低于阈值 θ 就补子问题/改方向。这是"计划稳定性"与"执行适应性"的折中。

### Q3：来源可信度怎么量化？只信一个大权威源够吗？
**答**：不够，见 §3.3 "孤证不立"。两层：①**权威性 `w_s`**——域名(.gov/.edu/顶刊)/时效/被引加权，防垃圾源进决策；②**跨源印证**——每个 claim 需 ≥2 独立源，用加权一致率 `conf=Σw_s·I(支持)/Σw_s` 或迭代贝叶斯真值发现，防单一权威源出错。两者结合把"信一个"变成"信多数加权"，是幻觉率 22%→3% 的核心杠杆。

### Q4：长报告怎么抑制幻觉、保证引用可追溯？
**答**：见 §3.4。三招：①**分节综合**——每节绑定自己的证据块，上下文短、引用准，避免"全文一次生成"必然跑题；②**引用约束**——生成时强制标注 `（来源[n]）`，模型只能引用检索到的证据 id，禁外部知识；③**自校验**——逐句 NLI 蕴含校验 `P(sentence|evidence)`，不支撑的句标"无依据"后删/补检索。用 Faithfulness（有依据句占比）和 CitationAcc（引用正确率）两个指标量化。

### Q5：深度研究检索成本/时延高，怎么优化？
**答**：见 §3.2、§3.5、§3.6 三处合力：①**检索侧**——HyDE 改写提升首查召回，边际收益停止准则避免无效检索；②**调度侧**——子问题 DAG 并行扇出（加速比 `S=T_seq/T_parallel`），令牌桶限流 + 失败兜底；③**成本侧**——三级模型路由（小模型规划/中模型排序/大模型综合）+ 预算闸门（max_searches/tokens 硬上限）+ 语义缓存复用历史档案。综合成本 −81%、耗时 −87%。

### Q6：深度研究系统怎么评测？不能只靠"感觉写得好"吧？
**答**：四维可量化：①**覆盖率 Coverage**——关键子问题命中比例（信息全不全）；②**忠实度 Faithfulness**——有证据支撑句占比（幻不幻觉）；③**引用精度 CitationAcc**——引用指向正确率（追不追溯得到）；④**人类一致性 Human-Agreement**——专家对"结论正确性/可用性"的评分（金标准）。工业上还加**端到端时延/成本**与**LLM-as-Judge 在线评测**（第28/39期）。这四个指标直接对应 §2.2 的量化成果（54%→91% / 22%→3% / 76%→97%）。

## 五、模拟面试（3 道深度题，均为本期专属角度，不与历史 85 题重复）

### 面试题 1：设计支持千万用户、日百万研究的深度研究平台（ResearchWeaver）端到端架构
**考点**：把"规划—检索—印证—综合—成稿"做成可规模化的生产闭环，而非单机 demo。
**参考答案要点**：
- **接入层（L0）**：ModelRouter（第48期）做三级路由（计划用 7B/排序 14B/综合 70B）+ 预算闸门（max_searches/tokens）+ 语义缓存命中复用历史档案。
- **规划层（L4）**：研究计划 DAG 生成 → 覆盖评估 → 反思 replan（§3.1）；子问题 DAG 交调度器并行扇出（§3.5，复用 Agent Harness 调度器）。
- **检索层（L3）**：HyDE 改写 + 多源并行（Web/私有库/DB）+ 边际停止（§3.2）；RAG/GraphRAG（第38/46期）作检索底座。
- **印证与综合层（L3/L5）**：来源权威性打分 + claim 跨源印证（§3.3）→ 分节综合 + Citation Grounding 自校验（§3.4）。
- **数据与可观测（L1/L6）**：MemoryWeaver（第47期）存历史研究档案供缓存复用；LLMOps（第39期）全链路 Trace + 四维在线评测（覆盖/忠实/引用/人类一致）。
- **规模化**：影子模式（新研究策略先仿真跑、达标再放量）+ A/B 灰度 + 故障自动回滚（沿用第39期机制）；成本闸门防单任务失控。

### 面试题 2：线上"引用出错率"从 3% 突然涨到 25%，30 分钟止血复盘
**考点**：复合故障的分钟级定位 SOP（检索/印证/生成/数据四路排查）。
**参考答案要点**：
- **0–5min 止血**：先切影子/回退版本（最坏回退到"仅返回检索原文 + 人工判读"兜底），止住业务损失；拉 LLMOps Trace（第39期）看出错分布（哪个环节/哪类来源）。
- **5–15min 定位**：①**检索层**——新接入的搜索引擎返回格式变了？HyDE embedding 版本漂移导致召回错乱？②**印证层**——来源权威性权重配置被误改？跨源印证阈值 `θ` 被调低导致孤证放行？③**生成层**——综合模型升级后"编造引用 id"？Citation Grounding 自校验 NLI 阈值被调高放行无依据句？④**数据层**——索引库被污染/部分源失效？
- **15–30min 修复**：检索→回退 embedding/修解析；印证→复原权重与阈值；生成→回退模型 + 收紧 NLI 阈值；数据→剔除污染源。灰度放量验证引用准确率回到 >95%。

### 面试题 3：7B 经"检索增强 + 规划"追平 70B 深度研究质量（成本 −85%）
**考点**：小模型如何在"研究"域以低成本追平大模型（检索增强 + 规划蒸馏 + 缓存）。
**参考答案要点**：
- **检索增强补短板**：7B 参数记忆有限，但研究靠"查"不靠"背"——HyDE + 多源检索（§3.2）把外部知识拉到上下文，弥补参数知识不足；跨源印证（§3.3）用"多数加权"替代模型自身判断力。
- **规划蒸馏**：70B 教师产出高质量研究计划 DAG + 子问题分解，7B 学生用 KL 蒸馏学"怎么拆问题"；教师只在云端训，学生端侧/廉价跑。
- **引用约束兜底**：分节综合 + Citation Grounding（§3.4）强制每句绑定证据，把"模型可能编"变成"必须引证据"，幻觉率压到 3% 水平。
- **语义缓存复用**：MemoryWeaver（第47期）存历史档案，重复子问题直接命中，省检索+综合。
- **量化预期**：信息覆盖 54%→90%、引用准确率 76%→96%、单份成本 ¥3.2→¥0.5（−85%），时延满足分钟级交付。
