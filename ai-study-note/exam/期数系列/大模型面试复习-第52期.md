#### 亮点 A：生产级 DAG 动态调度器（环检测 + 分层并行 + 指数退避 + 熔断）

```python
from collections import defaultdict, deque
import asyncio, json

class DAGScheduler:
    def __init__(self):
        self.nodes = {}; self.deps = defaultdict(set)
        self.status = {}; self.max_retry = 3; self.circuit_open = set()
        self.budget = {}   # 每节点 token/时延预算闸门

    def add(self, name, fn, depends_on=None, fallback=None, token_budget=None):
        self.nodes[name] = (fn, fallback); self.deps[name] = set(depends_on or [])
        self.budget[name] = token_budget

    def _detect_cycle(self):                      # 入度法 O(V+E)
        indeg = {n: len(self.deps[n]) for n in self.nodes}
        q = deque([n for n in self.nodes if indeg[n] == 0]); seen = 0
        adj = defaultdict(list)
        for n, ds in self.deps.items():
            for d in ds: adj[d].append(n)
        while q:
            u = q.popleft(); seen += 1
            for v in adj[u]:
                indeg[v] -= 1
                if indeg[v] == 0: q.append(v)
        if seen != len(self.nodes): raise RuntimeError("DAG 存在环，拒绝调度")

    async def _run_node(self, name):
        if name in self.circuit_open:             # 熔断：持续故障直接降级
            return await self._fallback(name)
        fn, fallback = self.nodes[name]
        for attempt in range(self.max_retry + 1):
            try:
                self.status[name] = 'running'
                return await asyncio.wait_for(fn(), timeout=self.budget.get(name, 30))
            except Exception:
                if attempt == self.max_retry:
                    if fallback: return await self._fallback(name)
                    self.circuit_open.add(name); self.status[name] = 'failed'; raise
                await asyncio.sleep(2 ** attempt)  # 指数退避治瞬时抖动

    async def run(self):
        self._detect_cycle()
        indeg = {n: len(self.deps[n]) for n in self.nodes}
        ready = deque([n for n in self.nodes if indeg[n] == 0])
        # 分层并行：同一层可并发，整体时延≈最长链而非链和
        while ready:
            batch = list(ready); ready.clear()
            await asyncio.gather(*(self._run_node(n) for n in batch))
            for n in batch:
                for m, ds in self.deps.items():
                    if n in ds:
                        indeg[m] -= 1
                        if indeg[m] == 0: ready.append(m)
```

> **面试话术**：① 环检测防 Planner 自引用死循环（白灰黑三色或入度法）；② 分层并行使整体时延≈最长关键路径，而非所有节点之和；③ **重试治瞬时故障（网络抖动），熔断治持续故障（下游雪崩），二者分工不能混**；④ `wait_for` 预算闸门防止单节点拖垮整条 DAG。

#### 亮点 C（本期新增）：工具调用可靠性三板斧

```python
import json, re

def robust_json_parse(raw: str, schema: dict):
    """三板斧：约束解码优先 → 自愈修复 → 结构化兜底"""
    # ① 优先信任约束解码（Grammar-Constrained Decoding）的合法输出
    try:
        return json.loads(raw)
    except Exception:
        pass
    # ② 自愈：抽取首个 {...} 平衡括号 + 修常见转义
    s = extract_balanced_braces(raw)
    s = s.replace("'", '"').replace('\\"', '"')
    try:
        return json.loads(s)
    except Exception:
        pass
    # ③ 兜底：调用 Fallback 工具或返回结构化错误，绝不让 Agent 崩溃
    return {"__parse_error__": True, "raw": raw[:200]}

def extract_balanced_braces(text: str) -> str:
    start = text.find("{")
    if start == -1: return ""
    depth = 0
    for i in range(start, len(text)):
        if text[i] == "{": depth += 1
        elif text[i] == "}":
            depth -= 1
            if depth == 0: return text[start:i+1]
    return text[start:]
```

> **量化**：首次成功率 55% → 82%（约束解码）→ 92%（自愈+兜底）。**面试金句**："合法 JSON 不是靠 prompt 求来的，是靠 Grammar-Constrained Decoding 强制出来的；解析失败是常态不是异常，必须有自愈和兜底。"

```python
class BudgetGate:
    def __init__(self, base=2000, per_step=800, hard_cap=32000):
        self.base, self.per_step, self.hard_cap = base, per_step, hard_cap
    def allow(self, step: int, used: int) -> bool:
        cap = min(self.base + step * self.per_step, self.hard_cap)
        return used < cap          # 超 cap → 触发记忆压缩/降级
```

## 🔧 二、技术难点：跨项目六大共性难点（深度总纲）

> 这六个难点是 13 个项目反复出现的"命门"，面试几乎必问其一。每个都给 **根因 → 方案 → 代码/公式**。

### 难点 1：多 Agent 循环发散（死循环 / 无限调用）

**根因**：Planner 缺乏终止条件 + 工具返回不明确 + 无预算闸门，导致"A→B→A"自引用。
**方案**：① DAG 环检测（见亮点 A）；② `max_iter` 硬上限；③ 自检器（反思"目标是否达成"）；④ token/步数预算闸门。
```python
if step >= max_iter or not planner.should_continue(state):
    return finalize(state)   # 强制收口
```

### 难点 2：KV Cache 显存墙

**显存公式**（每请求每层）：
```
KV_bytes = 2 (K,V) × L(层数) × n_kv(缓存序列数) × T(长度) × hd(头维) × 2(BF16)
```
7B 模型、1M 上下文、批量 32：`2×32×32×1e6×128×2 ≈ 5.2 TB` —— 必须优化。
**方案**：① PagedAttention（KV 分块按需分配，消除碎片）；② GQA/MQA 减少 `n_kv`；③ KV 量化（K INT8 / V INT4）；④ 前缀缓存（Radix Tree 复用系统提示）。

### 难点 3：工具调用可靠性

**根因**：自回归生成 JSON 有概率非法；参数类型不匹配；下游超时。
**方案**：约束解码（Grammar-Constrained）+ 自愈解析（亮点 C）+ Fallback + 双模式（JSON Mode 优先，失败回 Function Calling）。**量化**：55% → 92%。

### 难点 4：长上下文记忆污染 / 遗忘

**根因**：全量塞进上下文 → 注意力稀释 + 噪声淹没关键事实。
**方案**：三层记忆（B 亮点）+ 重要性过滤（imp<0.3 丢弃）+ 压缩摘要 + Ebbinghaus 遗忘淘汰（低频记忆降权）。
```
retain_score = imp × recency_decay(t) × access_freq
# recency_decay(t) = exp(-t/τ)，τ 按业务设定
```

### 难点 5：幻觉可控性

**根因**：模型"自信地编造" + 缺乏事实锚点。
**方案**：① Citation Grounding（每个论断回指检索片段，无引用即拒答）；② 置信度门控（低于阈值触发 RAG 复核）；③ 自洽投票（Self-Consistency，多采样取多数）。
```python
if not has_citation(claim) or confidence(claim) < 0.7:
    claim = rag_verify(claim)   # 强制落地到证据
```

### 难点 6：规模化多租户 SRE

**根因**：单租户尖峰拖垮全局；故障扩散；配额超卖。
**方案**：① 隔离（一致性哈希分片）；② 双层令牌桶限流；③ 熔断降级链；④ 混沌工程常态化。
```python
class TokenBucket:
    def __init__(self, rate, cap): self.rate, self.cap = rate, cap; self.tok = cap; self.ts = time()
    def allow(self, n=1):
        now = time(); self.tok = min(self.cap, self.tok + (now-self.ts)*self.rate); self.ts = now
        if self.tok >= n: self.tok -= n; return True
        return False   # 拒绝 → 触发降级/排队
```

## ❓ 三、常见问答（12 道高频深度问答）

**Q1：Agent 和 RPA 的本质区别？**
A：RPA 是**确定性的规则脚本**（if-then，流程固定），适合结构化、稳定的后台操作；Agent 是**基于 LLM 的目标驱动系统**（Planner 动态决策、能处理非结构化输入、有工具调用与反思）。RPA 不会"理解"，Agent 有一定泛化与容错。面试延伸：生产里常"Agent 编排 + RPA 执行"混合——Agent 做决策，RPA 做高可靠的动作。

**Q2：如何保证 LLM 输出 100% 合法 JSON？**
A：三层——① **Grammar-Constrained Decoding**（在采样时用语法制约，只允许合法 token 序列，根本不会生成非法 JSON）；② 双模式（JSON Mode 优先）；③ 自愈解析 + 结构化兜底（见亮点 C）。Prompt 说"请输出 JSON"只是软约束，不可靠。

**Q3：PagedAttention 为什么比传统 KV Cache 管理省显存？**
A：传统方案为每个序列预分配连续最大长度 KV，产生大量**内部碎片**（实际用 2k 但分配 8k）；PagedAttention 把 KV 切成固定 Block（如 16 token），**按需分配、块间不要求连续**，配合 Copy-on-Write 共享前缀，显存利用率从 ~20% 提升到 ~92%，从而支持更大批量 → 吞吐 +300%。

**Q4：RAG 召回率低怎么排查？**
A：分四层——① **切块**：是否过碎/过粗（布局感知 + 父子文档）；② **Embedding**：领域漂移→领域微调（InfoNCE + hard negative）；③ **检索策略**：纯向量漏召回→改混合检索（BM25 + 向量 + RRF 重排）；④ **索引**：IVF-PQ 聚类数是否合理、是否增量更新。召回@10 从 68%→89% 的实战路径。

**Q5：如何把 LLM 推理成本压下来（"成本 -71%" 怎么来的）？**
A：四杠杆——路由（简单任务走小模型）、语义缓存（命中 41%）、投机解码（接受率 ~80%）、量化+调度（INT4 + PagedAttention + Continuous Batching）。详见 1.1 亮点 D 表格。

**Q6：多 Agent 怎么防循环 / 无限调用？**
A：DAG 环检测 + `max_iter` + 自检器 + 预算闸门（难点 1）。**关键认知**：重试治瞬时故障、熔断治持续故障，二者必须分工。

**Q7：Agent 幻觉怎么压到可控范围？**
A：Citation Grounding（无引用拒答）+ 置信度门控 + 自洽投票（难点 5）。Faithfulness 可从 82%→95%。

**Q8：GQA / MQA / MHA 怎么选？**
A：MHA 每头独立 KV（显存大、质量高）；MQA 所有头共享 1 组 KV（显存最小、质量略降）；GQA 分组共享（折中，Llama2/3、DeepSeek 采用）。**端侧/长上下文必选 GQA**——KV 显存 ∝ n_kv，GQA 把 n_kv 从 32 降到 8，KV 直接 -75%。

**Q9：端云协同路由如何防质量崩？**
A：RouteLLM 思路——用偏好模型给"query 难度"打分，简单 query 走端侧小模型，复杂走云端 70B；质量阈值兜底（端侧置信度 < 阈值即回云端）。成本 -83% 且质量损 < 2%。

**Q10：ReAct 和 Function Calling 怎么选？**
A：ReAct 是"思考-行动-观察"的 prompt 范式，天然可解释但 token 贵、易发散；Function Calling 是模型原生结构化调用，首次成功率高（55%→92%）、延迟低。生产倾向 FC 做执行底座，ReAct 做复杂规划外层。

**Q11：MoE 负载均衡怎么解决？**
A：Auxiliary-Loss（负载均衡损失）+ 最新 Auxiliary-Loss-Free（DeepSeek-V3，用 bias 项动态调路由，不引入额外梯度噪声）。不均会导致部分专家过载、显存倾斜、训练震荡。

**Q12：大规模预训练 100B+ 模型怎么通信？**
A：3D 并行（数据 + 张量 + 流水线）+ Zero Redundancy Optimizer（切分优化器状态/梯度/参数）+ 通信计算重叠（用 NVLink/IB 拓扑感知的 ring/Tree All-Reduce）。反向时梯度 All-Reduce 与前向计算重叠，掩盖通信开销。

## 🎯 四、模拟面试（3 道全新综合题 · 不与历史 67 题重复）

> 选题说明：历史模拟题多为"单项目单点设计 / 单指标故障复盘"。本期三题均为**跨项目综合级 + 新维度**（分布式一致性 / 三重复合故障 / 7B 追平旗舰），确保全新。

### 模拟题 1：设计支持「千万级并发 Agent + 强一致分布式记忆 + 跨 Region 容灾」的生产平台

**场景**：你的 Agent Harness 要从单 Region 支撑百万用户，升级到多 Region、千万并发，且要求记忆跨 Region 强一致、故障 RTO<30s、RPO≈0。

**参考要点**：
1. **记忆一致性协议选型**：跨 Region 强一致不能上 2PC（延迟高、锁冲突），用 **CRDT（无冲突复制数据类型）** 或 **最后写入胜出(LWW)+向量时钟**；会话内强一致用 Raft 选主。给出"会话级 Raft + 全局 CRDT"双层设计。
2. **数据分片**：一致性哈希按 `tenant_id` 分片，每分片独立 Raft 组；热点租户再按 `user_id` 二次分片。
3. **故障转移**：Region 级健康探测（主动探活 + 被动熔断）→ 流量 30s 内切到备 Region；记忆异步复制 + 崩溃恢复重放 WAL 保证 RPO≈0。
4. **与 ModelRouter 联动**：备 Region 自动降级到本地缓存的路由策略，避免跨 Region 回源放大延迟。
5. **量化目标**：P99 首 token < 1.2s（跨 Region +0.3s 预算）、记忆冲突率 < 0.1%、容灾演练 RTO 验证 < 30s。

### 模拟题 2：线上突发「Agent 自建循环耗尽配额 + P99 翻倍 + 工具成功率暴跌」三重复合故障，30 分钟止血

**场景**：早高峰某业务线告警——① 推理成本 30 分钟内 ×3（Agent 疯狂自调用）；② P99 首 token 0.9s→4s；③ 工具调用成功率 92%→28%。你如何在 30 分钟内止血？

**参考要点（黄金信号 → 下钻 → 假设验证 SOP）**：
1. **0~5min 止血（保命）**：查可观测面板三黄金信号——QPS/成本/成功率。先 **全局降级**：对该业务线开启 `max_iter=5` 硬闸 + 预算熔断（亮点 D），成本立刻止涨；临时把该线路由到高可靠 Fallback 工具，成功率回升。
2. **5~15min 定位**：Trace 下钻发现某 Planner 提示词更新后产生"A→B→A"环（无环检测兜底）→ 回滚提示词版本（Prompt 灰度回滚，见 LLMOps 39）；P99 高因 KV 显存 OOM 触发频繁淘汰 → 临时扩容 + 开 KV 量化。
3. **15~30min 根因**：工具成功率暴跌是下游第三方 API 限流（双层令牌桶在租户级被单用户打爆）→ 拉黑异常租户 + 全局令牌桶收紧。
4. **事后预防**：混沌工程常态化（注入"工具超时/限流"验证熔断）、DAG 环检测强制开启、成本异常自动熔断。

### 模拟题 3：让自研 7B Agent 在「工具调用 / 长程规划 / 多模态 / 成本」四维追平 GPT-4o

**场景**：老板要求用自研 7B 替代 GPT-4o 跑 Agent，目标：工具调用准确率 ≥ 95%、可稳定规划 >10 步、能看懂图表/截图、单会话成本 < 1/10。给出训练+推理+评测一体化方案。

**参考要点**：
1. **训练（DataFoundry 50 + Reasoning-RL 37 + FuncHub 41）**：① 用 GPT-4o 蒸馏 + Self-Instruct/Evol 合成 工具调用轨迹；② 拒绝采样保留高准确率样本；③ GRPO + 过程奖励（PRM）训长程规划，AIME 式逐步 reward；④ 多模态用 SigLIP 对齐 + 三阶段训练（VisionLLM 40）。
2. **推理（FuncHub + ModelRouter + EdgeLLM）**：7B 为主，复杂子任务经 ModelRouter 路由到云端 70B（仅 10%~20% 流量）；工具调用走 Grammar-Constrained Decoding 保 99.6% 合法；端侧能跑则端侧（EdgeLLM）。
3. **评测（LLMOps 39）**：可执行评测（pass@k / SWE-bench resolve）+ 过程级 PRM 打分 + 在线 LLM-as-Judge 去偏采样。量化目标：工具准确率 95%、10 步规划成功率 > 80%、多模态 DocVQA > 85%、成本 -90%。
