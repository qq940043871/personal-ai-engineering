3. **Eval 与 Serve 闭环** → 评估不通过禁止上线，线上指标回落触发自动回滚 + 数据飞轮补数据。

## 📌 二、技术难点（Technical Challenges & Solutions）

### 2.1 LoRA 数学原理与实现

**核心思想**：预训练权重 $W_0 \in \mathbb{R}^{d\times k}$ 在适配时变化量是**低秩**的。我们不直接更新 $W_0$，而是学一个低秩分解：

$$W = W_0 + \Delta W = W_0 + B A, \quad B \in \mathbb{R}^{d\times r},\ A \in \mathbb{R}^{r\times k},\ r \ll \min(d,k)$$

前向计算：

$$h = W_0 x + \Delta W x = W_0 x + B A x$$

- 训练时 **只优化 $A, B$**（参数量从 $d\times k$ 降到 $r(d+k)$），例如 $d=k=4096, r=8$ → 可训参数占比仅 $\frac{8\times(4096+4096)}{4096\times4096} \approx 0.39\%$。
- 反向传播时梯度只流向 $A,B$，$\Delta W$ 的秩 $\le r$。
- 推理时可把 $BA$ 加回 $W_0$ 做**权重合并**（无额外延迟），或保持分离做**多适配器热插拔**。

```python
import torch, torch.nn as nn

class LoRALinear(nn.Module):
    def __init__(self, base: nn.Linear, r: int = 8, alpha: int = 16, dropout: float = 0.05):
        super().__init__()
        self.base = base
        self.base.weight.requires_grad_(False)      # 冻结基座
        if base.bias is not None:
            base.bias.requires_grad_(False)
        d_out, d_in = base.weight.shape
        self.r, self.alpha, self.scaling = r, alpha, alpha / r
        self.lora_a = nn.Parameter(torch.randn(r, d_in) * 0.01)   # A: r×in
        self.lora_b = nn.Parameter(torch.zeros(d_out, r))         # B: out×r (零初始化→初始ΔW=0)
        self.drop = nn.Dropout(dropout)

    def forward(self, x):
        base_out = self.base(x)
        lora_out = (self.drop(x) @ self.lora_a.T @ self.lora_b.T) * self.scaling
        return base_out + lora_out

    def merge(self):
        """推理前合并回基座，零额外延迟"""
        with torch.no_grad():
            self.base.weight += (self.lora_b @ self.lora_a) * self.scaling
        return self.base
```

**面试追问**：
- *为什么 $B$ 零初始化、$A$ 随机初始化？* → 保证训练开始时 $\Delta W=0$，模型等价于原基座，训练稳定、不破坏预训练知识。
- *$\alpha$ 是什么？* → 缩放因子，实际更新幅度 $= \frac{\alpha}{r} BA$。$\alpha>r$ 时放大 LoRA 贡献。
- *秩 $r$ 怎么选？* → 任务越复杂、$W$ 变换越"满秩"，$r$ 越大；一般 8/16/32/64 做网格搜索，观察验证集。

### 2.2 QLoRA：4-bit NF4 量化训练

**为什么需要 QLoRA**：全量/普通 LoRA 训 70B 仍需多卡。QLoRA 把**基座权重压到 4-bit**，单张 48GB 卡即可训 70B。

**三大技术**：
1. **NF4（NormalFloat 4-bit）**：对"标准正态分布权重"信息论最优的 4-bit 数据类型（分位点量化）。
2. **双重量化（Double Quantization）**：量化常数本身也量化（2-bit），再省约 0.37 bit/参数。
3. **分页优化器（Paged Optimizers）**：用 CUDA 分页，显存尖峰时把优化器状态暂存 CPU，避免 OOM。

量化映射（仿射）：

$$\text{dequant}(q) = q.\text{to}(\text{float}) \times \text{scale} + \text{zero\_point},\quad \text{scale} = \frac{\max-\min}{2^{\text{bits}}-1}$$

```python
# 伪代码：QLoRA 训练核心（基于 bitsandbytes + PEFT）
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
import torch

bnb_cfg = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",              # NF4 数据类型
    bnb_4bit_compute_dtype=torch.bfloat16,  # 计算用 bf16 保精度
    bnb_4bit_use_double_quant=True,         # 双重量化
)
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3-70B",
    quantization_config=bnb_cfg, device_map="auto",
)
# 仅 LoRA 参数可训；前向用 4bit 权重，反传梯度经 dequant 流回 LoRA
```

**面试追问**：
- *4-bit 训练会掉点吗？* → NF4 + 双重量化下，70B 上相对 fp16 全量 LoRA 通常仅掉 1~2pp，但显存从 ~140GB 降到 <48GB。
- *梯度怎么传？* → 前向用量化权重，反向时通过**伪量化（straight-through）**把梯度近似传给 LoRA 参数。

### 2.3 灾难性遗忘（Catastrophic Forgetting）

**本质**：神经网络容量有限，学习新任务时梯度会覆盖对旧任务重要的权重，导致旧能力"被抹掉"。全量微调最严重，PEFT（LoRA）天然缓解但仍存在。

**系统性缓解方案**（面试要能列 4 种以上）：

| 方法 | 原理 | 代价 |
|------|------|------|
| 参数高效（LoRA/Adapter） | 只动少量参数，旧权重不动 | 表达力略受限 |
| 正则化（EWC / L2-SP） | 约束重要权重别乱动 | 需算 Fisher |
| 回放（Replay） | 混入旧任务样本一起训 | 需存旧数据 |
| 参数冻结/切片 | 冻结底层、只训顶层 | 灵活性低 |
| 模型融合（Model Merging） | 训新适配器后与原模型加权融合 | 需合并策略 |

**EWC（弹性权重固化）损失**：

$$\mathcal{L}(\theta) = \mathcal{L}_{\text{task}}(\theta) + \frac{\lambda}{2} \sum_i F_i (\theta_i - \theta^*_i)^2$$

- $F_i$：对角 Fisher 信息矩阵，衡量参数 $i$ 对旧任务的重要性。
- $\theta^*_i$：旧任务收敛的参数。重要性高的参数被"钉住"，不能大幅移动。

```python
def ewc_loss(task_loss, theta, theta_star, fisher, lam=0.4):
    """EWC 正则项：惩罚偏离旧任务重要参数的更新"""
    reg = 0.0
    for name in theta:
        reg += (fisher[name] * (theta[name] - theta_star[name]) ** 2).sum()
    return task_loss + (lam / 2) * reg
```

**面试追问**：
- *LoRA 为什么比全量微调遗忘轻？* → 基座 $W_0$ 完全冻结，只有低秩增量 $\Delta W$ 变化；旧能力仍完整保存在 $W_0$ 中。
- *怎么量化"遗忘了多少"？* → 保留一份**通用能力回测集**（如 MMLU 子集），每次微调后跑一遍，对比旧模型掉点。

### 2.4 SFT 数据质量与配比

**难点**：数据决定了微调上限。常见问题：
- **数据污染**：训练集混入测试题 → 指标虚高。解法：对训练/测试做 n-gram + 语义去重。
- **格式噪声**：多源数据 schema 不一。解法：统一为 `(system, instruction, input, output)` 并做 JSON Schema 校验。
- **分布失衡**：某类样本过多导致过拟合。解法：按任务做配比 + 难例上采样。
- **合成数据退化**：Self-Instruct 易生成同质样本。解法：用强模型蒸馏 + 多样性惩罚 + 奖励模型质检。

```python
def dedup_by_ngram(samples, n=5, threshold=0.8):
    """n-gram 重叠率去重，防数据污染"""
    seen, kept = set(), []
    for s in samples:
        grams = set(zip(*[s.split()[i:] for i in range(n)]))
        if not any(len(grams & g) / len(grams | g) > threshold for g in seen):
            seen.add(grams); kept.append(s)
    return kept
```

### 2.5 长序列微调

**难点**：领域文档常超 4K/8K（合同、论文、代码库）。

- **RoPE 长度外推**：继续预训练阶段用 NTK-aware / YaRN 扩展位置编码到目标长度。
- **序列并行（Sequence Parallelism）**：把长序列切到多卡，激活显存按卡分摊。
- **FlashAttention + 梯度检查点**：降低显存峰值。

**面试追问**：*长序列微调为什么显存更贵？* → 注意力是 $O(n^2)$ 激活；序列翻倍，激活显存约 4 倍，需序列并行 + 检查点抵消。

### 2.6 训练稳定性

**常见故障与对策**：

| 现象 | 根因 | 解法 |
|------|------|------|
| loss spike | 个别样本/学习率过高 | warmup + 梯度裁剪(clip=1.0) + 异常样本过滤 |
| loss=NaN | fp16 溢出/除零 | 切 bf16、检查归一化、降 lr |
| 训不动/欠拟合 | lr 太小/数据太少 | 调 lr、加数据、解冻更多层 |
| 过拟合 | 数据少/轮数多 | 早停、加正则、数据增强 |

## 📌 三、常见问答（Common Q&A，3 个深度问题）

### Q1：LoRA 为什么有效？秩 $r$ 怎么选？与全量微调的 trade-off 是什么？

**深度参考答案**：
1. **为什么有效**：①预训练权重已编码海量通用知识，微调只需"小幅修正"而非"重学"，低秩 $\Delta W$ 恰好捕捉这种小幅、任务特定的修正方向；②预训练模型的权重更新矩阵天然近似低秩（Aghajanyan et al. 证明语言模型内在维度低）；③冻结基座保留通用能力，规避灾难性遗忘。
2. **$r$ 怎么选**：从经验值（8/16/32）做网格搜索，看验证集。规律——任务越复杂、越"偏离"预训练分布（如强领域/新格式），$r$ 越大；简单风格适配 $r=8$ 即可。也可用**秩自适应（AdaLoRA / DoRA）**自动分配每层的有效秩。
3. **trade-off**：全量微调表达力上限高、能学最难的领域偏移，但显存贵、易遗忘、易过拟合小数据；LoRA 省显存、抗遗忘、可多适配器热插拔，但在"领域分布与预训练差异极大"时可能欠拟合。工业界默认 LoRA/QLoRA，仅在数据极多且效果不满足时上全量。

### Q2：灾难性遗忘的本质是什么？如何系统性缓解？

**深度参考答案**：
1. **本质**：神经网络共享参数，新任务梯度会覆盖旧任务依赖的权重子空间；当新旧任务激活不同特征方向时，旧能力被"冲刷"。本质是**参数空间冲突 + 容量有限**。
2. **四层缓解体系**：
   - 架构层：PEFT（LoRA/Adapter）只动少量参数，旧权重原样保留——最省心。
   - 算法层：正则（EWC/L2-SP 钉住重要参数）、回放（Replay 混入旧数据）、知识蒸馏（对齐旧模型输出）。
   - 数据层：持续预训练时做数据混合（旧 domain + 新 domain），控制学习率。
   - 评估层：保留**通用能力回测集**，每次微调后量化掉点，掉太多则回滚或重训。
3. **工程判断**：先上 LoRA（天然抗遗忘），若仍掉点再加 Replay + 通用回测门禁。

### Q3：SFT、指令微调、RLHF/DPO、持续预训练的区别与适用场景？

**深度参考答案**：
| 阶段 | 目标 | 数据 | 损失 | 适用 |
|------|------|------|------|------|
| 持续/领域预训练 | 注入领域知识 | 无标注领域语料(CLM) | 交叉熵 | 领域词/知识缺失 |
| SFT（监督微调） | 学会"按指令作答"格式 | (指令, 回答) 对 | 交叉熵 | 行为对齐、格式 |
| 指令微调 | SFT 的一种（指令多样） | 多任务指令集 | 交叉熵 | 泛化到新指令 |
| RLHF/DPO | 对齐人类偏好/安全 | 偏好对/奖励 | 偏好损失 | 风格、安全、有用性 |

- **关键区别**：预训练补"知识"，SFT 补"格式与行为"，RLHF/DPO 补"偏好与安全"。
- **顺序**：基座 →（领域预训练）→ SFT →（RLHF/DPO）。先做对的事（SFT），再做对的事的"味道"（RLHF）。
- **面试坑**：SFT 不能替代 RLHF 解决"迎合式废话"；RLHF 不能替代 SFT 教格式。

## 📌 四、模拟面试（Mock Interview，3 题 + 参考答案要点）

### 🎯 模拟题 1：从零设计支持 100B+ 参数模型高效微调的训练系统

**考察点**：显存估算、PEFT、并行策略、工程落地。

**参考答案要点**：
1. **显存估算**：100B fp16 权重 ≈ 200GB，远超单卡 → 必须并行 + 量化。
2. **基座压缩**：QLoRA 4-bit 加载（NF4 + 双重量化），权重显存降到 ~50GB，单/少卡可载。
3. **可训参数**：注入 LoRA（r=16/32），仅训 0.1%~1% 参数 → 优化器状态显存骤降。
4. **大模型并行**（若不上 QLoRA 而全量）：3D 并行 = 数据并行(DP) × 张量并行(TP, 切矩阵) × 流水线并行(PP, 切层)；ZeRO-3 分片优化器状态。
5. **稳定性**：bf16 + warmup + gradient clipping(1.0) + 梯度检查点(用算力换显存)。
6. **数据**：领域语料去重 → SFT 对 → 质检门禁。
7. **防遗忘**：LoRA 冻结基座 + 通用回测集门禁；若全量则加 EWC/Replay。
8. **交付**：训完自动 Eval → 合并 LoRA → 量化导出 → 灰度上线。

**追问准备**：*单卡 80GB 能训 100B 吗？* → 能，QLoRA(4bit~50GB) + LoRA(优化器状态极小) + 分页优化器，实测 A100-80G 可跑 Llama-70B，100B 需 2 卡或更小 r。

### 🎯 模拟题 2：设计一条"从原始文档到高质量 SFT 数据集"的自动数据飞轮

**考察点**：数据工程、合成数据、质量控制、闭环。

**参考答案要点**：
1. **采集**：爬取/导出领域文档（合同、FAQ、工单、论文），统一入库。
2. **清洗**：去毒、去 PII、格式归一为 `(system, instruction, input, output)`，JSON Schema 校验。
3. **去重/防污染**：n-gram + 语义向量去重，训练/评测严格隔离。
4. **合成（Self-Instruct）**：用强模型基于文档生成 (指令, 回答) 对；加**多样性惩罚**避免同质；难例（模型易错）上采样。
5. **质检**：奖励模型打分 + 规则校验（长度/格式/事实一致性）+ 人工抽检闭环。
6. **配比**：按任务类型配比，避免长尾被淹没；保留通用样本防遗忘。
7. **闭环**：线上表现差的 case 回流 → 补采/补合成 → 重新进入飞轮。
8. **指标**：数据合格率、覆盖度、训练后验证集涨幅，作为飞轮健康度。

**追问准备**：*合成数据会不会"垃圾进垃圾出"？* → 会，所以必须有质检门禁（奖励模型 + 事实一致性 + 人工抽检）；合成用于"扩面"，真标注用于"立标杆"。

### 🎯 模拟题 3：线上领域模型突然出现"遗忘旧知识 + 幻觉上升"，如何定位与修复？

**考察点**：故障复盘、可观测、防遗忘工程。

**参考答案要点（按时间线）**：
1. **量化现象**：拉通用回测集（MMLU 子集）和领域集，确认"通用掉点 + 领域幻觉率升"→ 判定为灾难性遗忘 + 过拟合噪声。
2. **定位根因**：
   - 看训练数据：是否新批次数据混入大量低质量/错误样本（脏数据导致幻觉）。
   - 看超参：学习率是否过大、训练轮数是否过多（过拟合 + 覆盖旧权重）。
   - 看方法：是否误用了全量微调而非 LoRA（遗忘主因）。
3. **止血**：立刻**回滚**到上一稳定版本（LoRA 热插拔优势在此体现），恢复线上。
4. **修复**：
   - 切回 LoRA / 加 Replay（混入旧领域样本）+ 通用回测门禁。
   - 清洗脏数据，加强质检。
   - 降低 lr、加早停、加 EWC 正则。
5. **防复发**：把"通用回测集门禁 + 数据质检"固化进上线流水线，掉点超阈值自动阻断发布。

**追问准备**：*怎么证明是遗忘而不是数据分布漂移？* → 在**不变的通用回测集**上掉点即遗忘；若在线上真实分布掉点但回测集不掉，则是分布漂移，需补新数据而非改训练方法。
