## 1. 项目亮点（以 Agent Harness 为核心）

### 1.1 架构总览（六层 + 主循环）

Agent Harness 是我主导设计的 Agent 运行时，技术栈 `FastAPI(编排/网关) + Vue3(对话前端) + PyQt6(桌面宿主) + MainLoop(事件驱动主循环)`，对外屏蔽"大模型不确定性"，对内提供"确定性执行骨架"。

```
┌──────────────────────────────────────────────┐
│  L6 接入层  Vue3 组件 / PyQt6 宿主 / OpenAPI     │
├──────────────────────────────────────────────┤
│  L5 主循环层  MainLoop：事件总线 + 协程调度       │  ← 单线程事件循环，避免竞态
├──────────────────────────────────────────────┤
│  L4 编排层  DAG Scheduler：节点依赖 + 断点续跑    │
├──────────────────────────────────────────────┤
│  L3 能力层  Planner / ToolRouter / Memory / Critic│
├──────────────────────────────────────────────┤
│  L2 模型层  LLM Gateway：多模型路由 + 缓存 + 降级  │
├──────────────────────────────────────────────┤
│  L1 基础设施  KV/向量库/对象存储/可观测(Prometheus)│
└──────────────────────────────────────────────┘
```

**为什么不套用 LangGraph 现成图？** LangGraph 的图是"编译期静态图 + 状态机"，而我们的场景需要运行时动态增删节点（工具发现后注入子图）、且 PyQt6 宿主要求主线程不被阻塞。因此自研 MainLoop：用 `asyncio` 事件循环承载"模型推理(IO 密集) + 工具执行(可能 CPU/GPU 密集)"，工具调用以 `run_in_executor` 卸载，主循环永不阻塞——这是区别于"堆 API"的核心架构亮点。

## 2. 技术难点与解决方案（6 大共性难点 + 伪代码）

### 2.1 长程规划与上下文压缩（Context Compaction）

**难点**：Agent 跑 30+ 步后，上下文被历史淹没，模型"忘记"初始目标，且 token 成本爆炸。
**方案**：分层压缩——保留"目标 + 关键决策结论 + 未决子任务"，丢弃中间冗余 trace。

```python
def compact(messages, budget=6000):
    keep = [m for m in messages if m.role in ("system","goal")]
    # 1) 仅保留每条工具结果的"结论行"
    for m in messages:
        if m.type == "tool_result":
            m.content = summarize_result(m.content)   # 抽 1 行结论
    # 2) 语义摘要：把 N 轮对话压成 K 条 episodic 记忆写入向量库
    episodic = embed_and_store(rollup(messages))
    # 3) 仅当仍超预算，再做无损截断（保留最近窗口）
    if est_tokens(keep + messages[-W:]) > budget:
        messages = keep + truncate(messages, budget)
    return messages, episodic
```

### 2.2 工具调用的可靠性（Schema 约束 + 降级）

**难点**：模型常产出"幻觉参数"、缺必填字段、类型错、甚至 JSON 非法。
**方案**：(1) 用 JSON Schema 在网关层做结构校验；(2) 解析失败回退到"约束解码/二次纠正"；(3) 危险工具走沙箱 + 人工确认阈值。

```python
def call_tool(name, raw_args, schema):
    try:
        args = json.loads(raw_args)
        jsonschema.validate(args, schema)        # 强约束
    except (JSONDecodeError, ValidationError) as e:
        args = llm_repair(raw_args, schema, err=str(e))  # 让模型按报错修
        if not safe(args): return ToolResult(error="unrepairable")
    if schema.get("dangerous") and cost(args) > THRESHOLD:
        args = human_confirm(args) or return ToolResult(skip=True)
    return sandbox.run(name, args)               # 沙箱隔离
```

### 2.3 三层记忆架构（实现要点）

```python
class Memory:
    def read(self, query, k=5):
        # working: 直接取当前窗口
        # episodic: 向量召回近期会话片段
        hits = vector.search(self.episodic, embed(query), k)
        # semantic: 实体/偏好知识库（低写入频次、高可信）
        facts = self.semantic.get_about(extract_entities(query))
        return merge_by_relevance([hits, facts], self.working)
    def write(self, event):
        self.working.append(event)
        if event.important:                      # 仅关键事件落库，控成本
            self.episodic.add(event); self.semantic.maybe_update(event)
```

### 2.4 流式 SSE 与前端一致性

**难点**：SSE 断流、乱序、Vue3 响应式批量更新抖动、用户中途打断。
**方案**：(1) 前端用 `EventSource` + 指数退避重连；(2) 增量以"patch"而非整段替换，避免重渲染；(3) 中断信号经 MainLoop 事件总线取消在途协程。

### 2.5 RAG 幻觉治理

**难点**：召回噪声导致模型"无中生有"。
**方案**：混合检索(recall↑) → 重排(cross-encoder, precision↑) → 引用对齐(答案句必须映射到 chunk id) → 无证据则拒答。
拒答触发：`max_similarity < τ` 或 引用校验失败。

### 2.6 成本工程

- **Prompt Caching**：系统提示 + 稳定前缀启缓存，命中后输入 token 计费降至约 1/10。
- **KV 复用**：多轮对话复用前缀 KV，避免重复 prefill。
- **预算守卫**：单会话 `token_budget`，超限触发压缩(2.1)或优雅降级到小模型。

## 3. 常见面试问答（12 题深度版）

### Q1 为什么 Transformer 既要残差又要 Pre-LN？

深层网络反向传播梯度近似 `∂L/∂x ≈ ∂L/∂(F(x)+x)·(1 + ∂F/∂x)`。残差项 `1` 保证梯度恒有通路，缓解消失；但 Post-LN 把 Layernorm 放在残差**外**，深层梯度范数随深度放大、需 warmup 极小心。Pre-LN 把 LN 放进残差支路，使各层梯度范数更稳定、训练更"钝"但更稳，工程上几乎成为默认。代价：Pre-LN 最终层激活方差偏大，部分工作会在末尾补一个 LayerNorm。

### Q2 RoPE 的数学与长上下文外推

RoPE 把位置信息编码为"旋转"：对维度对 `(2i,2i+1)` 施加角度 `θ_i = 10000^{-2i/d}`，旋转 `m·θ_i` 后做内积，使 `q_m·k_n` 仅依赖相对位置 `m-n`（通过旋转的可加性 `R(m)R(n)^T = R(m-n)`）。外推问题：训练长度 `L` 内角度范围有限，超出后角度"绕回"失真。解法：
- **NTK-aware**：把基频 `10000` 改为 `10000·(L'/L)^{d/d-2}`，在不重训下平滑扩展。
- **YaRN**：对高频维度降缩放、低频维度插值，并引入注意力温度，兼顾外推与分布。

### Q3 FlashAttention 的 IO 复杂度推导

标准注意力：HBM 读写 `O(N²)` 次（先写出 `N×N` 分数矩阵再读回）。FlashAttention 把 `Q,K,V` 切块在 SRAM 内完成 `S=QK^T`、`P=softmax(S)`、`O=PV`，**不把 N×N 矩阵落 HBM**。IO 复杂度由 `O(N²)` 降到 `O(N²d²/M)`（M 为 SRAM 大小），当 `d² < M` 时趋近 `O(N²)` 次但常数极小；同时因不物化大矩阵，显存 `O(N²)→O(N)`。

### Q4 位置编码横向对比

| 方案 | 机制 | 优点 | 缺陷 |
|---|---|---|---|
| 绝对位置嵌入 | 每个位置一个向量相加 | 简单 | 不具长度外推性 |
| 相对位置(Transformer-XL) | 偏差项依赖相对距离 | 长程好 | 实现复杂 |
| ALiBi | 注意力加线性距离偏置 | 天然外推、无需位置向量 | 表达弱于旋转 |
| RoPE | 旋转映射 | 相对性 + 兼容性强 | 外推需 NTK/YaRN |

### Q5 KV Cache / PagedAttention / Continuous Batching

- **KV Cache**：解码第 t 步需所有历史 K,V；缓存后每步仅算新 token 的 K,V，复杂度 `O(t)` → 避免 `O(t²)` 重算。代价：显存随序列长度线性增长。
- **PagedAttention(vLLM)**：把 KV 按"页(block)"非连续存放，像虚拟内存一样按需分配、跨请求共享前缀(副本复用)，显存碎片从 ~30% 降到 <4%。
- **Continuous Batching**：不等一个 batch 全部生成完，哪条先结束就立刻塞入新请求，GPU 利用率显著提升(吞吐 2–4×)。

### Q6 训练稳定性：Loss Spike 成因与对策

**成因**：(1) 个别 bad token/离群样本引发梯度尖峰；(2) 学习率/ warmup 不当；(3) 数值（fp16 溢出、softmax 过大）。
**对策**：warmup + cosine decay；`z-loss`（约束 logit 幅度）；`μP`(最大更新参数化) 使最优 lr 与宽度无关；spike 时**回滚到上一 ckpt + 降 lr** 而非从头训；Embedding/LM-head 使用 fp32 主权重。

### Q7 RLHF vs DPO（核心公式）

RLHF 三阶段：SFT → 奖励模型 `r(x,y)`(Bradley-Terry) → PPO 优化 `max E[ r - β·KL(π‖π_ref)]`。
DPO 直接在偏好数据 `(y_w,y_l)` 上优化，消去显式奖励模型：
```
L_DPO = -E[ log σ( β·log(π(y_w)/π_ref(y_w)) - β·log(π(y_l)/π_ref(y_l)) ) ]
```
**对比**：DPO 训练稳、无 PPO 超参(价值网络/裁剪)烦恼、单阶段；但依赖偏好数据质量，且对分布外/长度泛化弱于带 RM 的 RLHF。工程上常"DPO 打底 + 少量 RLHF 精修"。

### Q8 采样算法：temperature / top-p / beam

- **temperature**：`p_i ∝ exp(z_i/T)`；T↑ 更随机，T→0 趋近贪心。
- **top-p(核采样)**：按概率降序累加，截到 `p` 的候选集再采样，动态控制多样性。
- **beam search**：保 `k` 条最高联合概率路径，适合"答案唯一"任务(翻译/SQL)，但对开放生成易生成平淡、重复文本。
**实战组合**：代码/数学用 `T=0` 或低 T + 自洽(SCoV 多数投票)；创意用 `T≈0.8, top_p≈0.9`。

### Q9 MoE：路由与负载均衡

每个 token 经门控 `G=Softmax(W·h)` 选 Top-k 专家。**问题**：训练坍缩——少数专家被过度选中，其余"饿死"。
**对策**：(1) **auxiliary load-balancing loss** `L_aux = α·N·Σ_i f_i·P_i`(f_i 选中频率, P_i 路由概率)，迫使均衡；(2) **token dropping**(超载专家丢 token)；(3) **router z-loss**。注意 aux loss 过大会损害主干质量，需调 `α`。

### Q10 量化：GPTQ vs AWQ

- **GPTQ**：逐层、逐列量化，用少量校准集做二阶补偿(Hessian)，精度高、速度快，但依赖校准数据质量。
- **AWQ(Activation-aware)**：观察到"仅 ~1% 显著权重决定量化敏感度"，对这些权重做 0.1~1.0 的激活感知缩放保护，不依赖反向、硬ware 友好(int4 易部署)。
**结论**：两者都能把 7B~70B 压到 4bit 且困惑度损失 <1%，AWQ 在端侧/推理引擎(如 vLLM)集成更顺。

### Q11 投机解码（接受率推导）

用小草稿模型 d 一次出 `k` 个 token，大模型 D 并行验证：对 j=1..k，以概率 `min(1, p_D(y_j)/p_d(y_j))` 接受，否则在分歧处重采样。
**加速比** ≈ `k / (1 + (k-1)(1-α))`，`α` 为每位置接受率。当 `α` 高(草稿与正文分布接近)且 `k` 适中时，接近 `k×` 无损加速(输出分布与 D 完全一致)。关键：草稿模型要与 D 同定义域、且便宜(1~2 个数量级)。

### Q12 Agent 评测体系（不被"准确率"骗）

单一准确率失效(任务长、路径多)。分层评测：
1. **任务级**：端到端成功率 + 步骤效率(步数/工具数)。
2. **能力级**：规划正确性、工具选择 F1、记忆召回@k、抗扰(注入攻击)通过率。
3. **成本级**：token/¥ 成本、P50/P99 延迟、失败恢复率。
4. **鲁棒级**：扰动输入、缺失工具、超时下的降级表现。
实践用"轨迹回放 + LLM-as-Judge 双盲"：但 Judge 本身有位置偏差/长度偏差，需校准(互换顺序、控制长度)。

## 4. 模拟面试（3 道针对性题 + 参考答案要点）

### M1 系统设计：从零设计一个"生产级、带工具调用的 Agent 服务"
> 场景：支撑内部 5 万员工使用，需调用 30+ 内部 API（含写操作），要求可观测、可回滚、不越权。

**参考答案要点**
- **分层**：接入网关(鉴权/限流) → 编排(MainLoop/DAG) → 能力(Planner/ToolRouter/Memory/Critic) → 模型网关(多模型+缓存+降级) → 基础设施。
- **工具安全**：JSON Schema 强约束 + 沙箱 + 写操作双人/阈值确认；工具权限按"员工角色×API 敏感级"矩阵收敛。
- **并发**：MainLoop 单线程事件循环 + `run_in_executor` 卸载阻塞工具；请求级隔离，避免会话串味。
- **可观测**：每条轨迹打 trace(parent/child span)，记录模型 IO、工具入参出参、token 成本、延迟分位；异常可"回放"。
- **可靠性**：工具超时/失败 → 重试(指数退避) → 降级(换小模型/跳步) → 整体失败优雅返回；DAG 支持单节点重放。
- **成本**：Prompt Cache + KV 复用 + 预算守卫 + 热点工结果缓存(短 TTL)。
- **评测闭环**：影子流量离线回放评测新版本，达标才灰度。

### M2 故障排查：Agent 上线后"越跑越笨"，如何定位与修复？
> 现象：同一类任务，早期成功率 92%，两周后掉到 61%；用户投诉"它开始忘事、乱调工具、答非所问"。

**参考答案要点（结构化排查）**
1. **先分桶**：是"模型退变"还是"系统退变"？看模型版本/提示词是否被改过（配置漂移，对应 ICC 重构痛点：参数应走实时接口而非本地文件）。
2. **上下文污染**：查长会话是否因未压缩导致目标被淹没(§2.1) → 加 compaction + 目标锚定。
3. **工具退化**：查工具 Schema/后端 API 是否变更（签名变、返回结构变）→ 加契约测试 + 监控 4xx 率。
4. **成本失控触发降级**：是否因超预算自动降到了小模型/截断 → 调预算或分级策略。
5. **数据/记忆中毒**：episodic 是否写入了错误结论被反复召回 → 加写入可信度门限 + 定期清理。
6. **评测回归**：用 §3.Q12 的分层评测在影子流量上复跑，定位退化维度，再针对性修；修完以"回放历史 bad case"验证不再犯。

### M3 开放设计：无人工标注，如何持续提升一个"代码生成 Agent"的能力？
> 约束：没有标好的 (需求→高质量代码) 数据集，且不能靠人肉 review 扩标。

**参考答案要点（自举数据飞轮）**
- **自举评测**：用"可编译/单测通过/静态扫描"作**可执行信号**替代人工偏好；构造 (需求, 候选代码) 自动打分。
- **SCOV 自洽**：同一需求多次采样，用单测/执行结果投票选最优，把"赢家"回灌为训练偏好对(近似 DPO 数据)。
- **缺陷挖掘**：主动生成"易错需求"(类型边界/并发/异常处理)，逼出失败样本 → 形成难例集(curriculum)。
- **在线信号**：把"用户采纳/编辑距离/运行失败"作为隐式奖励，做轻量 DPO/在线学习。
- **防退化**：新模型必须过"历史难例集 + 生产影子回放"才灰度；保留 `π_ref` 做 KL 约束。
- **数据飞轮**：执行信号 → 优选样本 → 训练/对齐 → 更强模型 → 挖掘更难例，循环。

## 5. 速记卡（高频考点一页纸）

- **残差/Pre-LN**：梯度恒通道 / 训练更稳。
- **RoPE**：旋转编码 → 相对位置；外推用 NTK-aware / YaRN。
- **FlashAttn**：SRAM 内算、不物化 N×N → IO `O(N²)→O(N²d²/M)`，显存 `O(N²)→O(N)`。
- **推理提速三件套**：KV Cache + PagedAttention + Continuous Batching。
- **稳定性**：warmup + z-loss + μP + spike 回滚。
- **对齐**：RLHF(BT+PPO+KL) vs DPO(单阶段、免RM)。
- **采样**：低 T/贪心+SCoV(代码数学)；高 T+top_p(创意)。
- **MoE**：Top-k 路由 + aux loss 防坍缩 + token dropping。
- **量化**：GPTQ(二阶补偿) vs AWQ(激活感知保护 1% 显著权重)。
- **投机解码**：草稿验证接受率 α，无损加速 ≈ `k/(1+(k-1)(1-α))`。
- **Agent 评测**：任务/能力/成本/鲁棒 四层，慎用单准确率。
