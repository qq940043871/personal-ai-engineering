## 一、项目亮点

### 1.1 Agent Harness 架构总览
Agent Harness 是一套面向"大模型驱动的多智能体应用"的端到端运行框架，四层职责清晰：

| 层 | 技术 | 职责 |
|---|---|---|
| 调度 / 推理编排 | FastAPI | 接收任务、管理会话、调用 LLM、调度工具、流式推送 |
| 桌面端 | PyQt6 | 本地桌面 GUI、文件 / 设备交互、长任务驻留 |
| Web 看板 | Vue3 | 任务流可视化、日志追踪、人工确认闸门 |
| 统一控制循环 | MainLoop | 驱动"思考-决策-执行-观察"的 Agent 主循环 |

**设计哲学（最值得讲的点）**：以 LLM 作为"控制器（controller）"，MainLoop 作为确定性的执行引擎，把不可控的生成式模型约束在一个**可观测、可中断、可回放**的状态机里。核心信条——**大模型负责"决策"，确定性的运行时负责"执行与兜底"**。这一分工把"幻觉/失控"的业务风险从"模型必须永远正确"转换为"运行时必须有护栏"，工程上可落地得多。

### 1.2 五大核心亮点

**亮点 1：自研 MainLoop 控制循环 + "反思-动作"状态机**
- 把 ReAct 范式工程化为显式状态机：`REASON → ACT → OBSERVE → (REFLECT) → REASON …`
- 每次状态转换都有 `trace_id` 埋点，便于事后复盘"模型为什么这么走"（可回放 = checkpoint 每步落盘）。
- 反思节点（REFLECT）强制每 N 步做一次"是否继续 / 是否需要人工确认"的显式判断，避免无脑循环；把"该停了"这种隐式认知变成可测试、可观测的显式决策。

**亮点 2：工具调用的强类型 Schema 校验与自愈 + MCP 化接入**
- 工具以 JSON Schema 注册（名称、参数、必填、类型、枚举）；破坏性工具（删除 / 发送 / 支付）必须有"人工确认闸门"。
- 进阶：用**约束解码（outlines / guidance / lm-format-enforcer）**在 token 级别保证 JSON 合法，把"解析失败率"从训练问题变成确定性问题。
- 新增强项：工具接入遵循 **MCP（Model Context Protocol）** 标准——工具以标准化 server 暴露（Resources/Tools/Prompts 三原语），Agent 一次集成即可复用所有 MCP server，把"每接一个工具写一套适配"的 N×M 问题降为 N+M，且天然支持远程工具的 OAuth 鉴权与审计。

**亮点 3：多端实时协同**
- 同一任务流，PyQt6 桌面端与 Vue3 Web 端通过 WebSocket / SSE 订阅同一事件总线，状态一致。
- 前端只渲染"状态快照 + 增量事件"，不持有业务逻辑；所有写操作带 `idempotency_key` 保证幂等。

**亮点 4：基于 LangGraph 的多智能体编排**
- 微信公众号自动发布流水线：选题 → 素材 → 配图 → 排版 → 审核 → 发布，6 节点以状态图编排。
- 利用 checkpoint（持久化中间状态）支持长任务断点续跑与回放；状态图天然支持环路（自我修正）与条件分支（审核不通过回退），并内建 human-in-the-loop。

**亮点 5：全链路可观测 + 难度路由降本**
- 请求流经每个阶段（入口 → LLM → 工具 → 观察 → 回流）都有结构化日志。
- 主动监控日志异常并触发告警 / 自愈；关键指标（准确率 / 延迟 / 成本 / 工具成功率）看板化，构建 golden set 做回归。
- 新增：对任务做**难度路由**——简单任务走小模型 / 直答，复杂任务才启用大模型或 o1/R1 类强推理模型，配思考预算上限，显著压低推理成本与延迟。

### 1.3 业务落地（证明不是玩具）
- 微信公众号 6 节点自动发布流水线（长文 + 配图排版长期运营）。
- 自动绘本生成智能体（故事生成 + 图像生成串联）。
- AI 学习系统（Transformer 学习材料拆分并集成到 HTML 页面展示）。
- 儿童编程 / 中文识字 uni-app、父子协作游戏（Agent 能力落地到教育场景）。

## 二、技术难点与解决方案（含架构权衡）

### 2.1 大模型输出不确定性 → 结构化输出约束
- **问题**：同一 prompt 多次结果不同，难以落地到确定性业务系统。
- **方案**：① 要求 JSON 并附 JSON Schema 强校验；② 解析失败自动重试 / 降级；③ 关键字段加校验器（正则 / 范围 / 枚举）；④ 关键路径低温（temperature≈0）+ 结构化 prompt；⑤ 进阶用约束解码在生成时即保证合法。
- **权衡**：约束解码牺牲一点吞吐换零解析失败；低温降低创造性但提升稳定性。

### 2.2 Agent 循环失控 → 步数 / Token 预算 + 反思节点
- **方案**：① `max_steps` 与 `max_tokens` 硬上限；② 每 N 步 REFLECT 显式判断"是否可结束"；③ 工具结果幂等 / 去重，重复观察直接终止；④ 成本与超时双护栏；⑤ checkpoint 回滚到安全点。

### 2.3 上下文窗口限制 → 滑动窗口 + 摘要压缩 + RAG
- **方案**：① 保留最近 K 轮 + 历史递归摘要；② 长文档走 RAG 检索注入；③ 分治 + 归并再总结；④ 指令强化"中间信息请重点注意"（对抗 lost-in-the-middle）。

### 2.4 工具调用可靠性 → 解析 + 自愈 + 闸门
- **方案**：① 工具失败返回"模型可消费的错误"而非抛异常；② 网络类加重试与超时；③ 结果长度裁剪；④ 约束解码替代脆弱的正则抽取 `{}` 块。

### 2.5 流式输出与多端一致性 → SSE / WebSocket + 状态机
- **方案**：① 后端 SSE / WebSocket 流式推送 token 与状态事件；② 前端乐观更新 + 断线重连（offset 续传）；③ 统一状态机保证多端同一时刻同状态。

### 2.6 多端状态同步 → 事件总线 + 幂等
- **方案**：① 单一事实源（FastAPI 会话状态）；② 多端订阅事件总线；③ 写操作幂等（`idempotency_key`）。

### 2.7 推理成本控制 → 模型路由 + 缓存 + 量化
- **方案**：① 简单任务路由小模型；② 语义缓存（embedding 相似度命中）；③ 批处理；④ 本地 INT4 量化；⑤ 投机解码降首 token 延迟；⑥ 难度路由决定何时启用强推理模型。

### 2.8 评估与可观测 → trace + eval 集
- **方案**：① 全链路 `trace_id`；② golden set 回归；③ 指标看板化；④ LLM-as-Judge 做开放质量评分（防位置 / 自我偏好 / 长度偏差，强模型 + 多轮 + 引用锚定）。

### 2.9 长程 Agent 的上下文成本 → 分层记忆 + 上下文压缩
- **问题**：多轮 + 工具结果累积，上下文窗口被撑爆、成本指数上升、模型注意力稀释。
- **方案**：① 分层记忆（短期/情节/语义/程序，见 Q17）；② 工具结果只存摘要进上下文，原文入向量库按需检索；③ 每轮只注入 top-k 相关记忆 + 时间衰减排序；④ 长文档用 RAG 代替全量注入；⑤ 用"规划-执行"分离，计划占短上下文、执行细节走工具返回。

### 2.10 推理模型（o1/R1 类）接入 Agent 的延迟与成本治理
- **问题**：强推理模型思考链长、token 消耗大、首答延迟高，直接套用会拖垮交互与预算。
- **方案**：① **难度路由**：用轻量分类器判断任务是否需强推理，简单题直答 / 走小模型；② **思考预算**：设 max_thinking_tokens 上限，超时截断思考直接给当前最优；③ **流式展示**：把思考过程流式推给前端（"正在思考…"），改善体感；④ **结果复用**：强推理产出的高质量推理链沉淀为 few-shot / 蒸馏数据反哺小模型。

### 2.11 高吞吐推理服务架构落地难点（PagedAttention / 抢占 / PD 分离 / chunked prefill）
- **问题**：单请求长上下文 + 多并发下，KV Cache 显存碎片严重、长 prefill 阻塞 decode、GPU 利用率上不去。
- **方案**：① **PagedAttention** 把 KV 按 block 分页，跨请求共享前缀、显存利用率从 ~20%→90%+；② **chunked prefill**：把长 prompt 的 prefill 切成 chunk 与 decode 请求在 iteration 级交错，避免长 prefill 霸占 GPU 导致 decode 的 P99 飙高（配合 continuous batching）；③ **抢占（preemption）**：显存不足时按优先级把低优请求 KV swap 到 CPU 或重算，resume 恢复；④ **Prefill/Decode 分离（PD disaggregation）**：prefill 计算密集、decode 访存密集，分到不同实例各自优化批大小/并行，整体吞吐显著提升（DistServe/Mooncake 思路）。
- **权衡**：分离增加跨实例通信（传递 KV，需高速 IB/NVLink）；chunked prefill 增加调度复杂度；抢占的 swap 引入 CPU↔GPU 拷贝开销——按 SLA（延迟敏感 vs 吞吐优先）选择组合。

### 2.12 RL 对齐微调（GRPO/PPO）在 Agent 工具调用优化中的工程难点
- **问题**：要把"工具调用轨迹"做得更准、更少步数、更少越权，需 RL 优化策略，但直接上 PPO 成本高、易崩。
- **难点与方案**：① **critic 缺失与优势估计**：GRPO 去掉 value 网络、用同一 prompt 采样一组输出的 reward 均值/标准差做 group-relative baseline（见 Q30），省显存更稳；② **credit assignment（信用分配）**：长轨迹里哪个动作导致最终成功/失败？用过程奖励（PRM 对关键工具结果打分）或奖励塑形（每一步合理调用给小奖励）缓解；③ **reward 设计**：可验证任务（代码/数学）用执行结果做确定性 reward，开放性任务用 LLM-as-Judge 但需防自我偏好，可加"步数惩罚"控成本；④ **reward hacking**：模型钻空子刷分（如反复调无副作用工具），需约束性奖励 + 多样性正则 + 人工抽检；⑤ **训练不稳定**：KL 约束偏离参考模型、学习率 warmup、裁剪更新幅度。

## 三、常见问答（40 题，深度版）

### Q1 讲讲 Transformer 的自注意力机制与复杂度
自注意力把输入 X 通过三个线性投影得到 Q、K、V：`Q=XW_Q, K=XW_K, V=XW_V`，注意力为 `softmax(QK^T / √d_k) V`。`√d_k` 是缩放因子，防止点积随维度增大而过大导致 softmax 进入梯度消失的饱和区，使 QK^T 点积的方差保持在 O(1)。多头注意力把 d_model 切成 h 个头，每个头维度 `d_k = d_model/h`，各自算注意力后拼接再投影，让模型在不同子空间关注不同关系。复杂度：对序列长度 n，时间 / 空间均为 **O(n²·d)**，n² 来自 QK^T 的成对计算——这是长上下文的核心瓶颈。Decoder 侧还要加因果掩码保证第 i 个位置只能看到 ≤i 的位置。

### Q2 位置编码有哪几种？RoPE 为什么重要？
- **绝对位置**（sinusoidal / learned）：直接给每个位置一个向量加到 token 上，长度外推差。
- **相对位置**（T5、Transformer-XL）：在注意力分数里引入相对距离偏置。
- **RoPE（旋转位置编码）**：把 Q、K 按位置做旋转变换 `f(x, m) = R_m x`，使 `q_m^T k_n` 只依赖相对位置 `m-n` 与内容，兼具相对位置性质且**长度外推好**。LLaMA、Qwen、ChatGLM、DeepSeek 均用 RoPE。配合 NTK-aware 缩放、位置插值（PI）、YaRN 可在不重训情况下扩展上下文（4k→128k）。**为什么重要**：让"位置"与"内容"解耦且可外推，是当今开源大模型事实标准。

### Q3 预训练、SFT、RLHF 三阶段分别做什么？
- **预训练（PT）**：海量网页语料上 next-token prediction（自监督），学通用语言与知识，占全周期 90%+ 算力成本。
- **监督微调（SFT）**：用"指令-回答"配对数据微调，学会遵循指令、规范格式、扮演角色。
- **RLHF**：① 训奖励模型（RM）拟合人类偏好排序（Bradley-Terry）；② 用 PPO 以 RM 为信号优化策略，对齐"有用、无害、诚实"。**DPO** 是离线替代：直接用语偏好数据做分类式优化 `L_DPO = -E[log σ(β log(π_θ(y_w)/π_ref(y_w)) - β log(π_θ(y_l)/π_ref(y_l)))]`，省去独立 RM 与 PPO 的复杂训练，更稳更简。

### Q4 RAG 的原理与常见优化
- **流程**：索引（切片 → 嵌入 → 向量库）→ 检索（query 嵌入 → ANN 近邻 → top-k）→ 生成（召回片段拼入 prompt，要求引用出处）。
- **优化**：① 切片策略（语义 / 标题层级，避免切坏表格代码，父子文档）；② 混合检索（BM25 + 稠密向量，RRF 重排）；③ rerank（cross-encoder）精排；④ query 改写 / 多路召回（HyDE、step-back）；⑤ 引用溯源降幻觉；⑥ 元数据过滤；⑦ 重排后上下文压缩。

### Q5 Agent / Function Calling 的原理
模型生成时除文本外还能输出"工具调用"：`{name, arguments(JSON)}`。框架解析参数 → 执行工具 → 把结果（observation）回灌给模型，进入下一轮。典型范式 **ReAct**（Reason + Act 交替）。工程要点：工具以 JSON Schema 描述、输出可解析（优先原生 function calling 或约束解码）、失败返回可消费错误、破坏性动作加人工闸门、长程任务用记忆与规划。

### Q6 幻觉的成因与缓解
- **成因**：参数化知识缺口、训练数据噪声、暴露偏差、解码过自由、训练目标不强制事实一致性、lost-in-the-middle。
- **缓解**：RAG 注入事实、要求引用出处、self-consistency 投票、事实核验工具、置信度校准、对齐训练惩罚编造、思维链强制"先检索再回答"。

### Q7 长文本处理有哪些关键技术？
- 位置编码外推：RoPE + NTK 缩放 / 位置插值（PI）/ YaRN。
- 注意力实现：**FlashAttention**（IO 感知、分块融合、省显存）、**MQA / GQA**（共享 K/V 头降显存提速，GQA 是 LLaMA2/3 默认）、**滑动窗口注意力（SWA）**。
- 工程：KV Cache 量化（INT8/INT4）、上下文分块 + 摘要、稀疏注意力（Longformer / BigBird）。

### Q8 模型量化（INT8 / INT4）怎么做？
- **PTQ** vs **QAT**；PTQ 无需重训，性价比高。线性量化：`q = round(x / scale) + zero_point`。
- **GPTQ**：逐层用二阶信息（Hessian 逆）补偿量化误差，weight-only，单卡可跑 70B/4-bit。
- **AWQ**：约 1% 的"显著权重"决定性能，只保护这 1% 不量化，其余量化，效果好且快。
- **SmoothQuant**：把激活量化难度"平滑"到权重上，解决激活离群值，使 W8A8 可行。

### Q9 参数高效微调 LoRA 是什么？
冻结原权重，只学低秩增量 `ΔW = B·A`，`B∈R^{d×r}, A∈R^{r×k}, r≪d`。可训练参数量从 `d·k` 降到 `(d+k)·r`（r=8 时仅 0.5%），显存存储大降，可多任务 hot-swap 多个 LoRA。**QLoRA** = 4-bit NF4 量化基座 + LoRA，单卡消费级显卡可微调 65B 级；**DoRA** 把权重分解为方向与量级分别微调。

### Q10 推理优化：KV Cache、PagedAttention、连续批处理
- **KV Cache**：缓存历史 K/V 避免每步重算，显存随序列长度线性增长。
- **PagedAttention（vLLM）**：像虚拟内存把 KV Cache 分页，按需分配、跨请求共享前缀、显存利用率从 ~20% 升到 ~90%+。
- **Continuous Batching**：iteration 级别动态并新请求，显著降排队延迟。
- 其他：投机解码、Medusa、张量 / 流水并行、算子融合、量化。

### Q11 LangChain 与 LangGraph 的区别？
LangChain 偏"链（chain）"——DAG 式顺序组合，适合确定性 pipeline；LangGraph 偏"图（graph）"——节点 + 状态 + 条件边，支持**环路、状态持久化（checkpoint）、人在回路、断点续跑**，更适合自我修正与长程编排。一句话：LC 是"写好的流程"，LG 是"能循环和暂停的状态机"。LG 的 State 是跨节点共享可变对象，checkpoint 把每步 State 落盘，崩溃后可 resume。

### Q12 多智能体协作有哪些模式？
- **Supervisor**：调度模型分发子任务给 worker（AutoGen、CrewAI）。
- **Hierarchical**：多层主管-worker；**Debate**：角色互驳提升质量（Self-Refine）；**Pipeline**：前一节点产物是后一节点输入（本项目 6 节点发布）；**Network**：Agent 自由通信（CAMEL）。
- 关键工程：状态共享、并发时机、轮数上限防无限协商、路由器 + 预算控成本。

### Q13 提示工程有哪些经典技术？
**CoT**（"Let's think step by step"）、**Zero/Few-shot CoT**、**Self-Consistency**（多采样取众数）、**ToT**（思维树，BFS/DFS + 价值评估）、**ReAct**（推理动作交替）、**PoT**（用代码当推理）、**ART**（自动 CoT）。工程上还要做角色设定、格式约束、少样本、防注入（严格区分系统/用户/工具边界）。

### Q14 对齐与安全（RLHF / DPO / Constitutional AI）
- **RLHF（PPO）**：奖励模型 + PPO，复杂、易训崩（reward hacking）、对超参敏感。
- **DPO**：偏好数据上做分类损失，无需 RM 与 PPO，更稳更简，但依赖数据质量。
- **PPO 关键机制**：① **GAE** 平衡偏差方差；② **clip** 把策略更新比 `π_θ/π_ref` 限制在 `[1-ε,1+ε]` 防毁灭性更新；③ **KL 惩罚**约束偏离参考模型过远。
- **Constitutional AI**：用原则让模型自我批评修正，减少人工标注。
- 安全还要防：提示注入、越狱、数据泄露、agent 越权调用工具。

### Q15 【进阶】Mixture of Experts（MoE）原理与工程要点
- **原理**：每个 FFN 层用多个专家子网络 + 路由器，每个 token 只激活 top-k 个专家，在**不增推理算力**下大幅扩参（总参大、激活参小）。代表：Mixtral 8x7B、DeepSeekMoE、Qwen-MoE。
- **路由**：`g = softmax(W_r · x)`，取 top-k；**auxiliary loss（负载均衡）**防 expert collapse；进阶用 router z-loss、分组路由。
- **工程**：专家并行带来 all-to-all 通信；显存大（全专家常驻）单次计算小；fine-grained MoE + 共享专家（DeepSeek）提升参数效率。

### Q16 【进阶】State Space Models（Mamba / SSM）与 Transformer 对比
- **核心**：SSM 用线性递归 `h_t = A h_{t-1} + B x_t; y_t = C h_t`，序列建模变 O(n) 递归 / 卷积，**无 O(n²)**，理论无限长度、推理恒定内存。
- **Mamba 创新**：**选择性状态空间**——A/B/C 依赖输入，获内容感知压缩，克服早期 SSM 不能内容相关推理的弱点；硬件感知并行扫描训练高效。
- **对比**：Transformer 擅长全局点对点检索；SSM 擅长压缩式长程记忆但内容检索弱。主流仍是 Transformer+改进（生态/Scaling 成熟），SSM 在超长序列/流式有优势。

### Q17 【进阶】Agent 的记忆架构怎么设计？
- **分层记忆**：① 短期/工作记忆（当前窗口 + 最近 K 轮）；② 情节记忆（episodic，具体事件，可检索）；③ 语义记忆（semantic，抽取事实/用户画像，向量库）；④ 程序记忆（procedural，可复用技能/工具链）。
- **写入**：交互后用 LLM 抽取"值得记住的事实"写向量库（去重/合并）；**读取**：每轮 query 检索相关记忆注入系统 prompt，时间衰减/重要性排序。
- **避坑**：记忆污染、上下文膨胀（只取 top-k + 压缩）、隐私（敏感记忆加密/可删）。MainLoop + checkpoint 可作"过程记忆"回放。

### Q18 【进阶】如何评测一个 LLM / Agent？（LLM-as-Judge）
- **能力评测**：MMLU / GSM8K / HumanEval / MT-Bench / Arena-Hard；Agent 用工具成功率、任务完成率、步数效率。
- **LLM-as-Judge**：强模型当评分员，按维度打分 + 给理由 + 引用原文。
- **偏差与缓解**：位置偏差（交换顺序多次评）、自我偏好（评测/被评不同模型）、长度偏差（长答易高分）、rubric 锚定 + 多轮投票。
- **离线 + 在线**：golden set 回归 + 线上 A/B（留存、采纳率、人工抽检）。

### Q19 【进阶】注意力机制的变体与稀疏化
- **MQA / GQA**：共享 K/V 头，降显存提速解码（GQA 折中质量速度成主流）。
- **稀疏注意力**：Longformer（窗口+全局）、BigBird（随机+窗口+全局），O(n²)→O(n·log n)。
- **线性注意力**：核技巧近似 `softmax(QK^T)V` 为 `φ(Q)(φ(K)^T V)`，O(n·d²) 但表达力弱。
- **FlashAttention**：IO 感知高效实现，非新注意力，已成标配。

### Q20 【进阶】大模型推理的服务架构与并行策略
- **并行维度**：数据并行（DP）、张量并行（TP，单层矩阵切分，Megatron）、流水并行（PP，层切分）、专家并行（EP，MoE 跨卡）。实际用 **3D 并行**（TP+PP+DP）。
- **调度**：continuous batching + 优先级队列；KV Cache 用 PagedAttention。
- **高可用**：多副本 + 健康检查 + 降级（超时切小模型）；流式 SSE + offset 续传。

### Q21 【进阶】推理时计算（Test-time compute / o1 / R1 类推理模型）是什么？与 CoT 有何本质区别？
- 传统 CoT 是"训练时学会推理模式，推理时一次前向输出思维链"；test-time compute 是"在推理阶段投入更多算力（更长思维链 / 搜索 / 采样-验证）换准确率"，是 scaling law 从训练侧向推理侧延伸。
- **o1/R1 类**：通过 RL（尤其过程奖励）训练模型生成长 Chain-of-Thought（隐式或显式），把"思考"作为可学习、可延长的过程；推理时设 token budget 控制思考长度。
- **PRM（Process Reward Model）vs ORM（Outcome Reward Model）**：PRM 对每一步推理打分，能定位错误步骤、支持 MCTS/beam 搜索；ORM 只看最终答案对错，粗糙但便宜。训 PRM 需逐步标注（贵），可用 LLM 自动标注 + 人工校正。
- **与 CoT 区别**：CoT 是 prompt 技巧（推理路径由预训练/微调固化分布采样）；o1 类把"长推理"内化为模型能力（RL 优化），且推理时可动态分配计算量（难题多想、易题少想）。
- **代价**：延迟高、成本高（每题消耗大量 token），需"难度路由"决定何时启用强推理。

### Q22 【进阶】大模型训练的工程栈：ZeRO、混合精度、3D 并行如何配合？
- **混合精度**：BF16（8 指数位，动态范围大不易溢出，transformer 默认）为主；FP16 易溢出需 loss scaling。前向 BF16、master weights FP32。
- **ZeRO（DeepSpeed）**：把优化器状态(OS)、梯度(G)、参数(P) 分片到各卡，消除数据并行显存冗余。ZeRO-1 分片 OS，ZeRO-2 分片 OS+G，ZeRO-3 分片 OS+G+P，显存从 O(全量) 降到 ~1/N（N 卡）。通信量随阶段上升。
- **3D 并行组合**：DP × TP（单卡放不下一层矩阵）→ PP（层分组，micro-batch 1F1B 调度降气泡）→ ZeRO 在 DP 组内再省显存。Megatron-LM 做 TP+PP，DeepSpeed 做 ZeRO。
- **梯度检查点**：算力换显存，反向重算中间激活只存部分。
- **序列并行（SP）**：超长序列把序列维切分（Ring Attention / sequence parallel）克服单卡序列上限。
- **显存粗算**：参数 P(fp16)=2P 字节；Adam 优化器状态=12P（fp32 master+momentum+variance+fp16 副本）；梯度=2P；总 ≈16P 字节（无 ZeRO），ZeRO-3 约 16P/N + 通信。

### Q23 【进阶】知识蒸馏（Knowledge Distillation）在大模型里怎么做？
- **白盒蒸馏**：student 访问 teacher logits，用 KL 散度对齐软标签（温度 T 软化概率，梯度乘 T²），可加 hard label CE。
- **黑盒蒸馏**：只调 teacher API，用其生成作监督数据训练 student（如 GPT-4 造 SFT 数据）。
- **推理蒸馏（reasoning distillation）**：用 o1/R1 类强推理模型的"长思维链 + 答案"作 student 训练数据，让小模型学会逐步推理（如 DeepSeek-R1-Distill 系列），是当前性价比最高的小模型能力提升方式。
- **关键点**：温度、数据质量覆盖、student 容量上限、过滤 teacher 错误避免复制。

### Q24 【进阶】多模态大模型（VLM）是怎么炼成的？
- **架构**：视觉编码器（ViT，如 CLIP/SigLIP vision tower）抽图像 patch 特征 → 投影器（projector/connector，MLP、Q-Former、resampler）把视觉特征映射到 LLM 词嵌入空间 → 与文本 token 拼接喂入 LLM 自回归生成。
- **训练两阶段**：① 对齐预训练（冻结 ViT+LLM，只训 projector，用图文对对齐）；② 指令微调（解冻 LLM，VQA/图文对话端到端）。
- **关键问题**：视觉 token 爆炸（一张图数百~数千 token）撑爆上下文 → 动态分辨率（切图）、token 压缩（pixel shuffle / 2×2 合并）、可变分辨率网格。
- **代表**：LLaVA（简单 MLP）、Qwen-VL、InternVL。视频把帧当多图加时间维；音频类似用 Whisper encoder。

### Q25 【进阶】模型上下文协议（MCP）与 Agent 接入外部能力
- **MCP（Model Context Protocol）**：Anthropic 提出的开放协议，统一"LLM 应用 ↔ 工具/数据源"接口标准，类似 AI 界 USB-C。三原语：Resources（读数据）、Tools（执行动作，带 JSON Schema）、Prompts（模板）。
- **价值**：工具标准化 server 暴露，Agent 一次集成复用所有 MCP server，N×M→N+M，支持远程 OAuth 与审计。
- **与 function calling 关系**：function calling 是模型"调用工具"能力（模型侧）；MCP 是"工具如何描述传输"的协议（传输侧），client 把 MCP tools 转成模型可用 schema。
- **A2A（Agent-to-Agent，Google）**：Agent 间互操作协议，补齐多 Agent 协作传输层。

### Q26 【进阶】RAG 进阶：Self-RAG、GraphRAG、RAG-Fusion
- **Self-RAG**：模型学会"按需检索"，用反射 token（Retrieve/IsRel/IsSup/IsUse）训练，减少无谓检索、降幻觉。
- **GraphRAG（微软）**：LLM 抽实体-关系图谱，检索结合向量 + 图遍历做全局/社区摘要，适合整个语料的聚合性主题问题（普通 RAG 对全局弱）。
- **RAG-Fusion**：query 改写多路 + RRF 融合，缓解单一 query 表达不全。
- **Corrective/Adaptive RAG**：检索质量评估后决定纠正（重检索 / web 兜底 / 直答）。

### Q27 【进阶】投机解码（Speculative Decoding）与多 Token 预测（MTP）深入
- **投机解码**：小 draft model 一次"猜" k token，大模型并行验证（一次前向验证 k 个），接受率 p 下加速约近 k 倍（接受率高时）。草稿可来自 n-gram / 小模型 / 同模型浅层。
- **EAGLE**：用大模型倒数第二层 hidden 训自回归 head 做草稿，比独立小模型更贴合分布，接受率更高。
- **MTP（DeepSeek-V3/R1）**：训练时同时预测未来多个 token（多个 head），推理可一次出多 token，也可作草稿提升投机解码。
- **注意**：投机解码不改输出分布（验证用 exact match / 温度采样修正），质量无损。

### Q28 【进阶】BF16 与 FP16 在训练中的选择与数值稳定性
- **FP16**：5 位指数，动态范围小，梯度易下溢/溢出，需 loss scaling（动态/静态）。
- **BF16**：8 位指数（同 FP32 范围），尾数少但范围够，transformer 默认选 BF16，几乎不需 loss scaling，训练更稳。
- **推理量化注意**：激活离群值集中在少数通道，SmoothQuant 把难度从激活移到权重，使 W8A8 可行。

### Q29 【新增·深度】Scaling Laws 与 Chinchilla 计算最优：参数 / 数据 / 算力如何配比？
- **Kaplan et al. (2020)**：测试/训练 loss 随模型参数量 N、数据量 D、算力 C 呈幂律下降：`L(N)= (N_c/N)^{α_N}`（α_N≈0.076）、`L(D)=(D_c/D)^{α_D}`（α_D≈0.095）、`L(C)≈C^{-α_C}`（α_C≈0.073）。其早期结论偏向"在固定算力下优先堆大模型"，导致 GPT-3(175B) 用 300B token 训练被普遍认为"训练不足"。
- **Hoffmann et al. (2022, Chinchilla)**：在固定算力预算下重新推导，发现**参数 N 与数据 D 应近似等比增长**才最优，而非单纯堆 N。Chinchilla(70B) 用约 1.4T token 训练，以 1/4 算力超越 Gopher(280B)。经验法则**约 20 token/参数**接近训练最优。
- **实践含义**：① 给定算力先定 C，再按 N≈D 分配（近似 `N_opt ∝ C^{0.5}, D_opt ∝ C^{0.5}` 数量级）；② 模型"不够大"往往是因为数据不够而非参数不够；③ 后期扩展要"双扩"——加参同时加数据，否则掉入"缩水训练"陷阱；④ 推理成本由参数量主导，所以服务器侧常选"小而训足"的模型。

### Q30 【新增·深度】GRPO 与 PPO / RLOO / DPO 的区别？为何 DeepSeek 用 GRPO？
- **PPO**：需独立 value/critic 网络估计 advantage（用 GAE），显存大、训练不稳定（reward hacking、超参敏感），但 reward 信号利用率高。
- **GRPO（Group Relative Policy Optimization, DeepSeekMath/R1）**：对**每个 prompt 采样一组 G 个输出**，用组内 reward 的均值 `μ` 与标准差 `σ` 做 baseline，advantage `A_i = (r_i − μ)/σ`，**去掉 critic**，省显存且更稳。策略更新同样受 KL 约束于参考模型。
- **RLOO（REINFORCE Leave-One-Out）**：无 critic，baseline 取"该 prompt 其余 G−1 个 reward 的均值"，是 GRPO 的特例（GRPO 用均值+标准差归一，RLOO 只用均值）。
- **DPO**：纯离线分类，不吃在线 reward 分布、无采样。
- **为何选 GRPO**：Agent/数学/代码等**可验证 reward** 场景，reward 来自执行结果（确定、便宜），无需再训一个 critic；去掉 critic 让 671B 级模型也能在可承受显存下做 RL，且组内相对比较天然抑制 reward 尺度漂移。代价：每步需采样 G 个完整输出，训练吞吐下降，需配合 vLLM 类高效 rollout。

### Q31 【新增·深度】FlashAttention 的 online softmax 与 tiling 算法本质：为何既省显存又快？
- **标准注意力的瓶颈**：需先算完整 `S = QK^T`（N×N），再对每行 softmax，再乘 V；N×N 中间矩阵要写回 HBM，显存 O(N²)、带宽受限是瓶颈（算得快但数据搬不动）。
- **IO 感知（IO-aware）**：GPU 的 SRAM（片上，快但小）与 HBM（片外，慢但大）带宽差百倍。FlashAttention 不写完整 S，而是把 Q/K/V 切成 **tiles（块）**，在 SRAM 内用 **online softmax** 增量计算。
- **Online softmax 数学**：对每行，维护 running max `m` 与 running sum `l`，逐块更新：`m_new = max(m_old, rowmax_block)`；`l_new = e^{m_old−m_new}·l_old + e^{rowmax_block−m_new}·rowsum_block`；输出 `O` 同步按修正系数累加。这正是 safe-softmax 的增量形式，保证数值稳定且无需见全部行。
- **收益**：① 显存从 O(N²) 降到 O(N)（只缓存 M、L 与输出）；② 大幅减少 HBM 读写（瓶颈在带宽）→ 提速；③ 因果掩码在块内直接处理；④ 与 backward 的重计算配合做反向。它是"实现优化非新注意力"，但让长上下文训练/推理在单卡可行。

### Q32 【新增·深度】DeepSeek-V3 的核心架构创新：MLA / 细粒度 MoE / MTP / FP8 训练
- **MLA（Multi-head Latent Attention，多头潜在注意力）**：对 K/V 做**低秩压缩**——把原本要缓存的完整 KV 投影到一个很小的 latent 向量（再上投影恢复），KV Cache 体积降到约 1/6~1/9，推理吞吐飙升；相比 MQA/GQA（物理共享 K/V 头、牺牲一定质量），MLA 在极致压缩下仍保质量。
- **细粒度 MoE + 共享专家**：每个专家参数更小、路由更细，并设**共享专家（shared experts）**承载通用知识、路由专家处理专项，配合无辅助 loss 的偏置项负载均衡，参数效率与训练稳定兼得。
- **MTP（Multi-Token Prediction）**：训练目标同时预测未来多个 token（多 head），既提升数据效率，又让推理时可用其头作**草稿**加速投机解码。
- **FP8 混合精度训练**：激活/权重用 FP8（E4M3）、关键累加/易溢出部分用 FP32，配合精细量化（per-block），把 671B 模型训练成本压到约 2.78M H800 GPU-hours（远低于同规模 FP16 训练）。
- **工程启示**：MLA 直击"KV Cache 显存=推理成本"这一最大瓶颈，对需在 Agent 服务里缓存长上下文/多轮历史的场景价值极高。

### Q33 【新增·深度】训练稳定性工程：warmup+余弦退火、AdamW、梯度裁剪、loss spike 处理
- **学习率调度**：先 **linear warmup**（数百~数千 step），避免早期大梯度破坏已初始化；之后 **cosine decay** 平滑降到峰值约 10%，长训练加 restart。突兀的大 LR 会直接毁掉训练。
- **AdamW**：自适应一/二阶矩（`β1=0.9, β2=0.999, ε=1e-8`），对稀疏梯度友好；**解耦 weight decay**（L2 正则与更新分离，W 表示 weight decay 不是加在 loss 上），比 Adam+L2 泛化更好。为何不用 SGD：transformer 参数量级巨大、梯度异质，自适应更稳。
- **梯度裁剪（clip grad norm）**：按全局范数裁剪，防极端 step 导致参数爆炸（尤其长序列/异常 batch）。
- **loss spike 处理**：训练中出现 loss 突增常见原因——脏数据、数值溢出、注意力注意力塌缩（少数 token 占全部 attention）。对策：① 回滚到 spike 前最近 checkpoint；② 跳过/清洗坏数据段；③ 临时降 LR；④ 检查混合精度（BF16 通常更稳）；⑤ 启用注意力数值稳定（如 qk 缩放、z-loss 正则防 logits 过大）。DeepSeek 系列用 **auxiliary z-loss** 约束 logits 幅度，防溢出与训崩。

### Q34 【新增·深度】高吞吐推理服务架构：chunked prefill / 抢占 / PD 分离怎么落地？
- **PagedAttention**：KV 按固定大小 block 分页，跨请求共享前缀（如系统 prompt）、按引用计数回收，显存碎片大幅减少（利用率从 ~20%→90%+）。
- **Chunked prefill**：长 prompt 的 prefill（计算密集、占满 GPU 数百 ms）若一次跑完会饿死 decode 请求。把它切成多个 chunk，与 decode 请求在 iteration 级**交错**调度，使 decode 的 token 间隔（TPOT）稳定、P99 延迟下降；与 continuous batching 天然配合。
- **抢占（preemption）**：显存不足时，按优先级把低优请求 KV 换出到 CPU（swap）或丢弃重算（recompute），恢复时再载回；swap 引入 CPU↔GPU 带宽开销，重算浪费算力，按 SLA 取舍。
- **Prefill/Decode 分离（PD disaggregation）**：prefill 是 compute-bound、decode 是 memory-bound，二者最优批大小/并行度不同；拆到不同实例各自优化，用高速互联（IB/NVLink）传递 KV，整体吞吐显著提升（DistServe/Mooncake 思路），代价是跨实例 KV 传输延迟——适合大并发场景。
- **组合策略**：延迟敏感（对话）→ 适度 PD 分离 + 不激进抢占；吞吐优先（离线批处理）→ 集中部署 + 大 batch + 投机解码。

### Q35 【新增·深度】Agent 安全：提示注入、越权调用、数据泄露、红队
- **攻击面**：① 提示注入（间接注入经工具返回/RAG 召回内容夹带恶意指令，最隐蔽）；② 工具越权（破坏性操作无闸门，如"删除全部文件"被模型误触发）；③ 数据泄露（上下文含 PII/密钥，输出时被带出）；④ 越狱（角色扮演/编码/分隔符绕过安全）；⑤ 多 Agent 投毒（某 Agent 被控制后向协作链注入错误/恶意信息）。
- **防护体系**：① **严格三界分离**：system（指令）/ user（输入）/ tool_result（不可信外部数据）明确隔离，工具结果一律当"不可信输入"做沙箱解析与校验；② **最小权限 + 人工闸门**：破坏性工具需显式授权、权限最小化；③ **输出过滤**：PII/密钥检测与脱敏；④ **RAG 可信域白名单**：只召回可信源；⑤ **越狱检测**：分类器识别异常请求；⑥ **多 Agent 信任边界**：跨 Agent 传递数据经校验，关键决策需多源验证；⑦ **全程审计日志**，便于事后溯源与红队复盘。
- **红队**：自动化红队（用 LLM 生成对抗样本、fuzz 工具边界）+ 人工评测，闭环进安全训练/规则。

### Q36 【新增·深度】过程奖励模型 PRM 与搜索（MCTS / beam / best-of-N）在推理时怎么用？
- **PRM vs ORM**：ORM 只看最终答案对错（粗糙、便宜）；PRM 对每一步推理打分，能**定位错误步骤**、支撑搜索。PRM 训练需逐步标注（贵），Math-Shepherd 用**过程监督自动标注**——对每个 step 用蒙特卡洛多次 rollout 估计"从该步出发能到达正确解的概率"作监督。
- **推理时搜索**：① **Best-of-N**：采样 N 个完整解答，用 PRM/ORM 选最高分；② **Beam search**：按 PRM 扩展 top-k 步，保留高分前缀；③ **MCTS**：节点=推理步、价值=PRM、用 UCT 选择/扩展/回溯，适合难推理题。OpenAI o1 类把"大规模 PRM + 强化学习内化搜索"作为核心能力。
- **难点**：PRM 可能 reward hacking（写出"看起来对"的步骤骗分）、长链标注贵、训练/推理分布偏移、搜索成本高（需与难度路由配合，只难题走搜索）。

### Q37 【新增·深度】检索重排序：cross-encoder 与 ColBERT 晚交互为何精度更高？
- **Bi-encoder（双塔）**：query、doc 各自独立编码成单向量，ANN 检索极快，但 query/doc 交互发生在"编码之后"——交互太晚，精度有限（尤其需要细粒度匹配时）。
- **Cross-encoder**：把 query+doc 拼接过同一 encoder（late interaction/早交互），精度最高，但每次都要重新编码，无法离线建索引，只能对 top-k（如 100）重排。典型用于 rerank 阶段（BM25+向量召回 → cross-encoder 精排）。
- **ColBERT（late interaction）**：折中方案——doc 编码成**多 token 向量**离线建库，query 在线编码，相似度用 `MaxSim`（query 每个 token 与 doc 所有 token 最大相似度之和）。兼顾"可离线索引"与"细粒度多向量匹配"精度，配合量化（PLAID）提速。
- **趋势**：多向量/晚交互检索在 RAG 召回质量上明显优于单向量，成本介于双塔与 cross-encoder 之间。

### Q38 【新增·深度】Agent 规划与反思：ToT / Reflexion / LLM+P / Self-Refine
- **ToT（Tree of Thoughts）**：每一步生成多个候选"思维"，用模型/PRM 做**价值评估**，BFS/DFS 搜索最优路径——把"搜索"引入推理，适合需探索/回溯的任务（比线性 CoT 鲁棒）。
- **Reflexion**：失败后让 Agent 做 verbal self-reflection，把"经验/教训"写入记忆（长期），下一轮迭代前读取避免再犯——元认知层面的自我改进，与本项目 MainLoop 的 REFLECT 节点精神一致但更重"记忆沉淀"。
- **LLM+P**：把问题转成**形式化表示（如 PDDL）**交给外部经典规划器求解，再把结果回填——弥补 LLM 在严格约束规划（最优路径、资源约束）上的不足。
- **Self-Refine**：生成→反馈（模型自评）→refinement 循环，无需外部工具。
- **工程落点**：把"反思/规划"显式化为可观测节点（REFLECT/PLAN），配合 checkpoint 回放与人工闸门，既提升质量又可控。

### Q39 【新增·深度】上下文窗口扩展的数学：PI / NTK / YaRN 为何有效？
- **问题根源**：RoPE 把位置 m 编码进旋转角，训练时只在 `[0, L_train)` 见过；直接在 `[0, L_new)`（L_new≫L_train）外推，旋转角超出训练分布，注意力退化。
- **Position Interpolation (PI)**：把位置整体缩放 `s = L_train/L_new`，即 `f(x,m) → f(x, m·s)`，把"外推"变"内插"，落在训练范围内。代价：高频维度被过度压缩，长程细节略损。
- **NTK-aware 缩放**：不全缩放位置，而是对**不同频率维度区别处理**——高频少缩放（保留精细位置）、低频多缩放，比 PI 更保高频信息，长外推更稳。
- **YaRN**：NTK-by-parts（按维度分段缩放）+ 对注意力 logits 做**温度缩放**修正（补偿缩放带来的注意力分布变化），既扩展长上下文又基本不影响短上下文性能；还可动态（推理时按长度调 base）。
- **工程**：三者无需重训即可扩上下文，但极端扩展仍需少量继续训练（"长上下文微调"）恢复质量；QLoRA + YaRN 是常见的"把 4k 模型扩到 128k"低资源方案。

### Q40 【新增·深度】FP8 与混合精度训练全栈：格式、风险与落地要点
- **FP8 两种格式**：`E4M3`（4 指数 3 尾数，动态范围适中，用于权重/激活）与 `E5M2`（5 指数 2 尾数，范围大，用于梯度），H100/新 GPU 原生支持。
- **混合精度层级**：master weights FP32（优化器状态）→ 前向 BF16/FP8 → 梯度 FP32 累加更新。FP16 需 loss scaling，BF16 几乎不需，FP8 则需更精细的缩放。
- **FP8 训练关键**：① 对输入/权重做 **per-tensor 或 per-block 量化**（找 scale 使张量落入 FP8 范围）；② **敏感层保留高精度**：layernorm 输入/输出、residual 连接、softmax 前、attention 的 QK 部分常用 FP16/FP32；③ **累加器用 FP32**（矩阵乘累加易溢出）；④ 通信（all-reduce）也可用 FP8 降带宽；⑤ 配合"延迟缩放（delayed scaling）"统计历史最大值定 scale，防突发离群。
- **风险**：激活离群值（少数通道极大）会压垮 FP8 范围 → 需 per-channel/per-block 量化或 SmoothQuant 先把难度移到权重；少数层数值敏感需回退高精度。
- **收益**：训练算力/显存/带宽成本显著下降（DeepSeek-V3 的 FP8 方案是低成本训练超大模型的关键），但工程复杂度远高于 BF16。

## 四、模拟面试（3 题 + 参考答案要点）

> 注：需求标题写"生成1个模拟面试问题"，但第 4 条明确要求 3 个，本版按第 4 条生成 3 个，均为 09-08 版之外的新题，且刻意加深到架构/算法/服务层。

### 模拟题 1：你有一个 Agent 需要用强化学习优化"工具调用轨迹"（更少步数、更少越权、更高成功率）。请讲清：为什么在 PPO / GRPO / DPO 里你会选 GRPO？group-relative advantage 的数学是什么？长轨迹的 credit assignment 怎么解决？reward 怎么设计，又如何防 reward hacking？
**参考答案要点**：
1. **为何 GRPO**：Agent 工具调用这类任务往往有**可验证 reward**（执行结果对/错、步数、是否越权），无需训独立 critic；PPO 的 value 网络在 70B+ 模型上显存与稳定性代价高，GRPO 去掉 critic、用组内相对奖励做 baseline，省显存更稳——契合 DeepSeek 在 R1 上的选择。DPO 是离线分类、不吃在线 rollout 的 reward 分布，不适合"边跑边学"的在线工具优化。
2. **group-relative advantage 数学**：对每个 prompt（记为 `q`）采样 G 个轨迹 `{o_i}`，reward `r_i`；`A_i = (r_i − mean(r)) / std(r)`（组内均值 μ、标准差 σ）；策略梯度用 `−A_i · log π_θ(o_i|q)`，并以 KL 约束于参考模型 `π_ref`。本质是"组内相对比较"，抑制 reward 绝对尺度漂移。
3. **credit assignment**：长轨迹里难以知道哪一步是关键。方案：① 过程奖励（PRM 对关键工具结果/中间状态打分）；② 奖励塑形（每步合理调用给小奖励、无效/重复调用给负奖励）；③ 把轨迹按"工具调用边界"切段分别赋权；④ 用反思节点显式标注"哪步导致失败"做监督。
4. **reward 设计**：可验证项（执行成功=+、越权=−大、步数>阈值=−小、格式非法=−）；开放性用 LLM-as-Judge 但需双模型互评防自我偏好；加步数惩罚控成本。
5. **防 reward hacking**：约束性奖励（只允许合法工具集）+ 多样性正则（避免反复调无副作用工具刷分）+ 关键决策人工抽检 + 定期用 held-out 真实任务验证泛化，而非只在训练 reward 上看分。

### 模拟题 2：请精确解释 FlashAttention 的 online softmax + tiling 为什么能省显存提速；并设计一套高吞吐推理服务，讲清 PagedAttention、chunked prefill、Prefill/Decode 分离、投机解码各自的吞吐/延迟权衡，以及 GPU 显存有限时如何安排 KV Cache 与 batch？
**参考答案要点**：
1. **FlashAttention 本质**：标准 attention 需把 N×N 的 `S=QK^T` 写回 HBM（显存 O(N²)且带宽瓶颈）；FA 把 Q/K/V 切 tile，在 SRAM 内用 online softmax（维护 running max `m`、running sum `l`，逐块修正）增量算出输出，只缓存 M/L/输出 → 显存 O(N)、HBM 读写大幅下降 → 又快又省。它是 IO 感知实现优化，非新注意力。
2. **PagedAttention**：KV 按 block 分页、引用计数回收、跨请求共享前缀，显存利用率 ~20%→90%+，是 vLLM 高吞吐底座。
3. **chunked prefill**：把长 prefill 切 chunk 与 decode 在 iteration 级交错，避免长 prefill 霸占 GPU 导致 decode 的 P99 飙升；配合 continuous batching。代价：调度更复杂、prefill 总耗时略增。
4. **Prefill/Decode 分离（PD disaggregation）**：prefill compute-bound、decode memory-bound，分实例各自优化批大小/并行，整体吞吐高；代价：跨实例传 KV 需高速互联（IB/NVLink），引入传输延迟，适合大并发。
5. **投机解码**：draft 模型猜 k token、target 一次验证，质量无损，降 decode 延迟（首 token 与 TPOT 都受益）；代价：draft 需与 target 分布接近（EAGLE/MTP 更优），低接受率时浪费算力。
6. **显存有限时的安排**：① 先按 PagedAttention 消除碎片；② 限制并发 batch（按剩余 KV 预算动态准入）；③ 长上下文用 KV 量化（INT8/INT4）或直接换 MLA 类架构；④ 低优请求抢占 swap 到 CPU；⑤ decode 实例用更小 TP、prefill 实例用更大 TP/更大 batch 提利用率。

### 模拟题 3：某产品要同时服务 7B（低延迟）与 70B（高质量）两套模型，且预算有限。请：① 用 Chinchilla scaling 讲清为何"小而训足"可能优于"大而欠训"；② 给出量化方案选择（INT4/AWQ/GPTQ/FP8）与取舍；③ 设计路由策略；④ 解释 DeepSeek-V3 的 MLA 为何对你的 KV Cache 与推理成本至关重要。
**参考答案要点**：
1. **Chinchilla 视角**：固定算力下 N 与 D 应近似等比；很多"大参数"模型其实训练 token 不足（如 GPT-3 175B 仅 300B token）而"缩水训练"。对**服务端**而言推理成本由参数量主导，因此选 7B/13B 充分训练（~20 token/参数）的模型，往往比堆更大但欠训的模型性价比高、延迟低；7B 用于大多数请求，70B 仅留给真正难的请求。
2. **量化选择**：① 本地/边缘低延迟用 **AWQ（保 1% 显著权重）或 GPTQ（二阶补偿）做 INT4**，单卡可跑；② 云端高并发用 **FP8 推理/训练**（H 系 GPU）省显存带宽；③ 激活离群严重时用 SmoothQuant 做 W8A8；④ 取舍：INT4 最省但质量略损（需校准集）、FP8 几乎无损但需硬件支持、BF16 最稳但最费显存。
3. **路由策略**：① 难度路由（轻量分类器/小模型自判置信度）决定 7B 直答还是升级 70B；② 语义缓存命中直接返回；③ 成本/延迟 SLA 维度做动态降级；④ 强推理题才走 o1/R1 类并设思考预算。
4. **MLA 的关键价值**：传统 MHA 的 KV Cache 随层数×头数×序列长度线性膨胀，是长上下文/多轮 Agent 推理显存与成本的最大头；**MLA 把 KV 低秩压缩到 latent，体积降到约 1/6~1/9**，同样显存能缓存更长上下文、更大 batch、更高并发，直接决定服务成本与可服务的最长上下文——这对"缓存多轮 Agent 历史"的场景是架构级优势。

## 五、速记清单（考前扫一眼）
- 注意力：`softmax(QK^T/√d_k)V`，O(n²·d)；FlashAttention 是 IO 感知高效实现（非新注意力）：tile + online softmax 把显存 O(N²)→O(N)。
- 长上下文三板斧：RoPE 外推（NTK/PI/YaRN）+ FlashAttention + KV Cache 量化。
- 三阶段：PT→SFT→RLHF/DPO。PPO=GAE+clip+KL 惩罚；DPO 更稳更简；GRPO=去 critic + 组内相对优势（DeepSeek 选它做 RL）。
- RAG 优化：切片 + 混合检索（BM25+向量）+ rerank（cross-encoder / ColBERT 晚交互）+ 引用溯源 + query 改写；进阶 Self-RAG / GraphRAG / RAG-Fusion。
- Agent 不死循环：步数预算 + 反思节点 + 结果去重 + 人工闸门 + checkpoint 回滚。
- 微调省显存：LoRA（ΔW=BA）/ QLoRA（4-bit NF4+LoRA）/ DoRA。
- 推理提速：PagedAttention（vLLM）+ Continuous Batching + chunked prefill + 投机解码（EAGLE/MTP）+ Prefill/Decode 分离。量化 GPTQ/AWQ/SmoothQuant/FP8。
- LC vs LG：链（DAG、顺序） vs 图（环路、状态、checkpoint、人在回路）。
