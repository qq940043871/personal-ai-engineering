## 一、为什么个人要自研一遍（定位与价值）

公司选 Dify 的理由成立：原型期"几周出东西"，自研编排、知识库界面、召回测试、Prompt 管理的工作量与业务价值无关。**但"省掉的基建"恰恰是能力盲区**——用 Dify 的人答不出"Dify 替你做了什么、怎么做的、坑在哪"。

ownrag 的价值恰好是把这个盲区填掉：

| 视角 | 回答的问题 |
|---|---|
| **技术验证** | 选型复盘 §3.1 说纯自研"工作量远超预期"——预期到底是多少？每一项的真实成本亲手量一遍 |
| **能力补齐** | Harness 六机制覆盖了**编排执行层**；ownrag 补齐 **RAG 数据链路层**（解析→切分→索引→检索→生成→闸门→评测） |
| **面试叙事** | "公司用 Dify"和"我自研过 Dify 替我们做的每一件事"**不矛盾且互相成就**：前者是组织决策，后者是工程底气 |
| **退路真实化** | 复盘 §六"保留换编排引擎的退出路径"——退出路径长什么样，ownrag 就是实物证据 |

**一句话定位**：

> Dify 解决"AI 怎么做得快"；公司中台解决"AI 怎么接得稳"；**ownrag 解决"如果这些都自己写，我知道每一件要写什么"**。

**三条边界（不得混）**：

1. ownrag **不能写进公司平台的能力清单**——同 Harness 纪律。
2. ownrag 与 Harness **共用思想但分工不同**：六机制在 ownrag 里是**承接与复用**（见 `02-低代码编排与中台机制.md` §五），不是重新设计一遍。
3. 公司项目里"参与过 MinerU 解析改造"是事实，ownrag 里的 MinerU 适配是**个人复刻**——两者口径分开讲，方法论同构可以点明。

## 三、工程范围（五件事）

1. **本地大模型**：Ollama 承载 chat / embedding（模型中立，OpenAI 兼容端点随时可换远程模型）。
2. **自研低代码业务中台**：管道 DSL（YAML 配置驱动"接入→解析→切分→索引"全链路）+ 应用模板 + 中台四件套（网关 / 权限 / 审计 / 计量）的自研实现——**不使用 Dify，也不引入 LangChain**（框架层自研，正是复盘 §3.1 的路线）。
3. **MinerU 识别 PDF**：pipeline / VLM 双后端页级路由 + 四层增强 → 统一 Markdown 中间态。
4. **ffmpeg + 本地语音识别处理音视频**：抽音轨 → faster-whisper / FunASR 本地转写 → 带时间戳锚点切分入库（可回跳源视频）。
5. **Excel 转临时表**：pandas 读取 → SQLite staging 临时表 → schema 推断与列语义映射 → 行级 / 聚合两种文本化策略入库。

三条解析链路（PDF / 音视频 / Excel）收敛到**同一个中间态契约**（`ParsedDoc`），下游切分、索引、检索不感知来源差异——这是"换解析器不动向量库"的个人版实现。

## 四、能力边界（不解决什么）

- **不做模型训练与微调**——本地推理与向量检索，不碰训练侧。
- **不做复杂前端**——管理侧只提供最小 API 与 JSON 配置，页面壳留待后续（配置驱动的表单方案即可承接，不展开）。
- **不做多租户 SaaS**——单机 / 单团队私有化定位。
- **不承诺零幻觉**——闸门只能拦"可校验的错"（引用不实、规则冲突），拦不住"像样的胡说"。
- **不替代业务决策**——数据类问题走工具网关查业务库，RAG 只答知识类。

## 六、面试 30 秒讲法

> "公司平台的智能层选了 Dify，但我在选型复盘里把纯自研路线完整否决过——否决理由是周期和人力，不是可行性。所以我自己用 Python + FastAPI 把那条路线做了一遍：Ollama 本地模型、配置驱动的管道编排、MinerU 解析 PDF、ffmpeg 加本地语音识别处理音视频、Excel 转临时表进 staging，检索混合召回加纯代码闸门。做完之后我对'Dify 替我们做了什么'这个问题，能答到模块级。"

**被追问时的两个标准答案**：

- *为什么公司用 Dify 你还自研？* —— "组织决策看投入产出周期，个人工程看能力地基。两件事不矛盾：正因为我亲手拆过每一项的成本，当时给团队的评估才有依据。"
- *自研到什么程度了？* —— "设计全量完成，代码是可运行的骨架：管道 DSL、三条解析适配、混合检索、闸门、评测脚本都落了位，重活（VLM 后端、rerank 服务）按接口留了降级位。指标没跑基线，全部标【待实测】。"

## 七、口径红线（写材料 / 讲述前自查）

1. ❌ 把 ownrag 说成公司项目 / 平台能力 → **个人工程，与公司平台是两条线**。
2. ❌ 把 ownrag 的技术栈说成公司平台后端栈 → 公司是 **Java 中台 + C 撮合**；ownrag 与 Harness 同属 **Python 个人线**。
3. ❌ "全自研所以比 Dify 好" → ownrag 验证的是**成本与盲区**，不推翻选型结论（Dify 赢在周期，复盘结论不变）。
4. ❌ 任何效率 / 成本 / 准确率数字 → 一律 `【设计】` / `【待实测】`。
5. ❌ 与 288 篇语料重复讲原理 → 原理指向 `../../personal-investment-notes/02-AI智能体/00-知识库/RAG/` 对应桶，本目录只写**工程方案**。
