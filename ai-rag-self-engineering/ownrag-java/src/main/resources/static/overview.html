解析阶段校验了什么A0-A3 · 入库前

做的是「宁可拦住、也不让脏正文进索引」：阻断项（blocking）直接判失败，提示项（warn）交给人对着三栏看一眼。 代码：index/ValidateParsedStep · index/CleanMarkdown · review/ReviewStore.qualityChecks · review/ReviewGateStep
闸校验项具体判据不通过会怎样
A0 接入准入 + 幂等 扩展名在 EXT_PIPELINE 内 · kb ∈ apps.yaml 白名单（∪ 运行时登记） · sensitivity ∈ {public, internal, restricted} · access_level ∈ {public, protected}（文档级权限，落 documents 一行） · 文件 SHA-256 是否已入库 415 不支持扩展名 / 422 非法库、非法敏感级或非法权限（前端过滤条件永远匹配不上，故必须在入口收敛）； 未登录却传 protected → 403（权限不能自助升级）； 指纹命中 → deduplicated，复用已有 doc_id，不产生新索引（已登录时按本次选择对齐权限， 匿名重传则沿用原权限——否则重传一份受限文件就能把它拉回公开）
A1validate_parsed
产物可用性		 markdown 非空，且 trim 后长度 ≥ min_chars_per_page（默认 20） 步骤 fail → 任务 failed 并入 todos（与「解析失败」同待遇：解析成功但产出不可用不算成功）
—clean_markdown
清洗安全阀		 ① 清洗后正文是否被洗空 ② 移除比例是否 > 25% 不阻断：洗空 → 回退未清洗正文并写 stats.fallback；移除过量 → 追加提示项 clean_removed_lots，提醒对照「解析后 / 清洗后」两栏确认不是规则误伤
A2 blocking硬缺陷（不可放行） empty_markdown 空产物 · too_few_chars 字符/页 < 20（疑扫描件未 OCR 或文本层缺失） verdict=fail → 复核记录置 fail，A3 直接拒绝入库；换解析后端或修正参数重传才可能好
A2 warn可疑（人看一眼） page_marker_mismatch 页标记数 ≠ 声明页数（引用页码可能错位）· empty_pages 有页无可提取文本 · mojibake 乱码/控制字符占比 > 0.5% · no_headings 正文 > 200 字符却无标题行（结构丢失→只能硬切）· table_flattened 有表格行文但 structures 里 0 张表 · oversized_chunk 块 > 1.5×max_tokens · degraded_path 走了降级链 · clean_removed_lots 清洗移除 > 25% verdict=warn → 仍可放行，但复核页必须人工确认（auto_approve 只对「无阻断项」生效， md/txt 两条无歧义管道才默认自动过闸）
A3review_gate
入库闸		 复核记录存在 · status=approved 无记录 / rejected（带驳回原因）/ verdict=fail → 拒绝写索引； pending → 任务挂起（awaitReview），人工通过后从本步续跑
—去重与写入一致性 块内容 hash（批内 + 跨文档，chunk_hashes）· 向量数必须 = 块数 重复块既不嵌入也不入库；两数不符 → 步骤 fail（避免「有版本号没向量」的静默残废）

大模型回答后校验了什么B0-B3 + S4 · 生成前后

口径：闸门只做「可校验的错」（引用不实、数字无据、越红线、越权），不承诺零幻觉。 代码：generate/Gates.citationCheck · generate/RedlineGate · auth/AccessPostCheck · api/ChatController.repairAnswer
闸校验项具体判据不通过会怎样
B0 前置提问原件 redline_terms.txt 是否命中问题文本（客户名 / 内网信息） 不检索、不生成，直接 no_evidence + done(source=gate)，qa_log 记「提问含红线禁词」
B1 闸门一有没有依据
sufficiency_check		 候选池非空；有重排分时 top-rerank ≥ 0.05（bge-reranker 校准：相关块 ~0.9、语义邻近无关块 ~0.0）； 无重排分时 top-RRF > 0 no_evidence：交付「未找到有效依据」——这是合法答案，不调模型、不产生幻觉
B2 闸门二引用是否真实
citation_check		 ① 引用的「块N」必须在候选池内（候选池 = 预算裁剪后真正进模型的块） ② 该行出现的数字/日期必须能在被引块原文找到（剔除引用标注与行首列表序号后再比） ③ 有数字却无任何引用 = 违规 ④ 答案 > 100 字符却零引用 = 违规 违规清单随 gate.post 下发（页面标红），触发重答
B3 闸门二有没有越红线
redline_check		 答案文本是否命中禁词表——禁词可能来自检索块（restricted 放行口径），也可能是对提问的复述 同 B2 触发重答；重答后仍未通过（尤其仍含禁词）→ redline_refused： 交付固定拒答话术，绝不把带禁词的答案交出去
S4 越权
(+ S3 前置)		来源是否有权
AccessPostCheck		 ① 进模型前（S3）：候选池每个 doc_id 独立回查 documents.access_level， 读不到的块剔除 ② 生成后（S4）：答案是否点名了"当前会话读不到"的文档 （比对受限文档文件名：去扩展名、≥4 字、排除已在候选里的） ③ 引用集合必须是可读文档的子集 S3 → gate:access_precheck 播报剔除块数，再走闸门一（全剔光则按"无依据"拒答）； S4 → gate:access_blocked + done.retracted=true：citations 清空、 答案换撤回话术（含登录入口）、首答不进 trace/qa_log，前端把流式期间显示的正文整段盖掉
—schema_check
输出结构		 JSON 模式下 readTree 语法合法性 apps.yaml 已声明该闸，但 ChatController 目前只接了 B2/B3——这一项还是骨架，状态如实标「未接线」
修复重答采纳策略 把「违规清单 + 只保留有候选块支持的结论 + 每个结论标 [来源: 块N]」作为新一轮 user 消息重答一次 新答「通过」或「违规数更少」→ 采纳并标 repaired； 重答调用异常 → repair_failed，交付「引用校验未通过，已按规则拒答原答案」

三步验证（每次改动后跑一遍）

这套顺序是刻意的：先证明“文档进得来”，再证明“检索找得到”，最后才看“模型答得对”。 跳过前两步直接看答案，等于没有验证。
