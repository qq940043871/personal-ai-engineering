# PDF 解析准确性校验：怎么证明 MinerU 的输出是对的

> 定位：ownrag 解析链路的**质量验收方法**——不依赖"看起来还行"的肉眼判断，而是可复现、可批量、可分桶报数的校验口径。
> 口径：全部阈值是 `【经验基线，需按自有语料校准】`，本文给的是**度量方法与判定逻辑**，不是最终数字。
> 配套工具：同目录 [`check_parse_accuracy.py`](./check_parse_accuracy.py)（零标注可跑的三层闸门）。

---

## 一、先把"准确"拆开：四个维度

"这份 PDF 转换准不准"不是一个指标能回答的问题。拆成四维，各自有独立的测法与失败表现：

| 维度 | 含义 | 不达标的表现 | 主要测法 | RAG 场景权重 |
|---|---|---|---|---|
| **完整性** | 页 / 段落 / 表格 / 公式 / 图有没有漏 | 整页缺失、段尾断掉、表格少一半 | 页覆盖、字符召回、结构计数 | ★★★★★ |
| **顺序与结构** | 多栏栏序、跨页段落、标题层级、表格行列 | 左右栏交错成一句、表头与内容错位 | 序列对齐、表格矩阵比对、人工抽检 | ★★★★☆ |
| **保真度** | 字符级有没有认错 | 乱码、`0/O` `1/l` 混认、标点全半角 | 近似 CER、乱码率、关键字段专检 | ★★★☆☆ |
| **可用性** | 切块后能不能被召回、引用跳不跳得对 | 命中块答不上、点引用跳错页 | 端到端 RAG 评测 | ★★★★★ |

**排序很重要**：RAG 里"漏一段"的代价远大于"错两个标点"——所以**完整性 + 顺序**是主战场，字符级 CER 是辅助信号。反过来做（死抠 CER 到 0.1% 却容忍整页丢失）是最常见的吃力不讨好。

## 二、真值从哪来（最容易被跳过的一步）

没有真值就没有"准确率"，只有"感觉"。四条路径，各有偏差，必须知道自己在用哪条：

### A. PDF 文本层对账（伪真值，但零成本，推荐做下限闸门）

电子版 PDF 自带文本层，用 `pymupdf` 抽出来当参照。**它能证明"下限"，不能证明"全对"**：

- 局限 1：文本层自身的阅读顺序就可能乱（多栏、跨页），所以顺序错乱时它会把"错"当"对"。
- 局限 2：表格在文本层是散落的文字流，无法判定结构对不对。
- 局限 3：**扫描件没有文本层**——这条路径直接失效，别硬套。
- 局限 4：页眉页脚、水印、行号会污染比对，必须做剔除与归一化，否则召回被虚低。

结论：**文本层对账用来抓"漏"，不用来背书"对"**。

### B. 人工标注（唯一真真值，抽样做）

金标准的唯一来源。关键是**抽样设计与标注粒度**，不是标得多：

- 粒度三选一（建议按用途）：字符级（算 CER）/ 块级（段落是否缺失、顺序是否正确）/ 表格级（行列数与单元格）。
- 分层抽样：按版式桶抽（见 §五），不是随机抽整库。
- 双人盲标 + 分歧仲裁；两人简单一致率 < 0.9 说明标注口径没定死，先对齐口径再标。

### C. 工具交叉验证（测"一致性"，不是测"准确"）

用另一个引擎（Docling / `pdftotext` / `pdfplumber` / 商业 OCR）跑同一份，**比差异点**，差异处人工裁决。

- 有价值：两个引擎都漏的地方极少，差异点就是高价值的可疑区。
- 红线：**不许用同一引擎同一后端自比**——那不是校验，是复现（充其量验证非确定性）。
- 红线：交叉验证的"一致率"不能当准确率报——两个引擎错得一样时它给你满分。

### D. 业务端验证（最终口径）

解析只是手段。最终判据是"检索到的那块能不能回答用户的问题、引用页码跳过去对不对得上"。见 §三 L4。

## 三、五档校验手段：成本 × 覆盖面

| 档 | 手段 | 需要真值 | 成本 | 能发现 | 发现不了 | 触发时机 |
|---|---|---|---|---|---|---|
| **L0** | 水位闸门（自动） | 否 | 秒级/篇 | 空页、乱码、重复行、围栏破损、图片掉链 | 顺序错、错字 | **每篇必跑** |
| **L1** | 文本层对账 | 文本层 | 分钟级/批 | 整段缺失、页丢失、字量异常 | 结构错、扫描件 | 每次解析参数变更 |
| **L2** | 结构对账 | 文本层结构 | 分钟级/批 | 表格错行/丢列、结构图缺失 | 语义错位 | 表格多 / 版式复杂时 |
| **L3** | 人工抽检 | 人工标注 | 人时 | 一切，包括语义级 | 只覆盖被抽到的部分 | 上线前 / 换后端 / 新语料 |
| **L4** | 端到端 RAG 评测 | 问答集 | 分钟级/批 | 解析错误是否真的伤了业务 | 定位不到具体页 | 版本升级前后 |

**日常节奏**：L0 全量常开（当闸门用，FAIL 不静默）→ 参数变更跑 L1/L2 → 换后端或季度跑 L3 抽样 → 上线与升级跑 L4 回归。

## 四、指标定义与阈值口径

### 4.1 指标

| 指标 | 定义 | 阈值基线【校准】 | 说明 |
|---|---|---|---|
| 页覆盖率 | 产出覆盖的页 / PDF 总页数 | = 1.0 | 少一页直接 FAIL，比任何平均分都硬 |
| 空页率 | 空页 / 总页数 | ≤ 0.02 | 空页 = 该页内容彻底丢失 |
| 字符召回（顺序敏感） | 对齐匹配字符 / 文本层字符 | ≥ 0.98 | 主判据 |
| 字量召回（顺序不敏感） | 多重集交集 / 文本层字符 | ≥ 0.99 | 与上者的**差值 = 顺序问题的信号** |
| 近似 CER | (真值长度 − 匹配字符) / 真值长度 | ≤ 0.05 | SequenceMatcher 估算，非严格 Levenshtein |
| 乱码率 | 替换符/控制字符数 / 正文字符数 | ≤ 0.001 | 突增通常意味着 OCR 层崩了 |
| 表格单元格召回 | 匹配单元格 / 真值单元格 | ≥ 0.95 | 真值来自 `find_tables`，本身也是下限 |
| 表格结构准确率 | 行列数一致 且 单元格全匹配的表 / 总表数 | ≥ 0.90 | 简化版 TEDS，够用不贵 |
| 页码锚点正确率 | 引用页码与源 PDF 实际页一致的比例 | ≥ 0.99 | RAG 引用可信度的地基 |

**口径纪律**：

- **precision 不作为判据**。产出必然比文本层"多"（标题符号、表格重排、图注），比例低于 1 是正常的，只有异常高（比如 2 倍）才说明多吐了重复内容。
- **分桶报，不报总平均**。一个 97% 的总平均可能藏着"嵌套表 60%"的事实。
- 阈值分桶不同：扫描件、多栏、公式密集各自一套；电子版简单版式可以压到 0.99。

### 4.2 分桶定义（建议与 05 文档的解析抽取集对齐）

`electronic`（原生电子版简单版式） / `scan`（扫描件，无文本层） / `multi_col`（双栏及以上） / `nested_table`（合并单元格、跨页表） / `formula`（公式密集） / `mixed`（图文混排）。

## 五、抽样与统计口径

- **每桶起步 30 篇**。n=30 时出现 1 篇失败，其真实失败率 95% 置信上限约 12%——所以桶内 30 篇全过，只能宣称"失败率大概率低于 10%"，不能宣称"99% 准确"。要报更小的数就在桶内加量。
- **篇内页抽样**：首 2 页 + 末 1 页 + 中间随机 2 页（目录页、封面页单独标记，不计入正文质量）。
- **失败必须可定位**：报告里给"哪一篇的哪一页"（工具已输出页级薄弱点表），否则无法归因、无法重跑。
- **标注一致性先过关**：双人标同 20 页，简单一致率 ≥ 0.9 再开标全量。
- **不做单篇结论**：单篇只能判"闸门过/不过"，不能用来估准确率。

## 六、错误模式归因手册（排障时最快的一节）

| 现象 | 最可能原因 | 定位方法 | 处置手段 |
|---|---|---|---|
| 整页丢失 / 空页 | 该页解析超时、OOM、异常页（旋转/超大图） | 页覆盖 + 空页率 | 单页重跑；改后端；放大超时 |
| 左右栏交错成一段 | 阅读顺序判定失败 | **字量召回高但序列召回低** | XY-cut 阅读顺序修复；该页切 VLM 后端 |
| 表格错行 / 丢列 | 单元格切分失败 | 单元格召回高但行列数不符 | 二次识别输出 HTML 表；嵌套表专项 |
| 表格整体变成图片 | 表格识别未开启 / 失败 | 表格召回 0 而图中有表 | 开启表格识别；失败计入待办 |
| 公式变乱码或消失 | 公式 OCR / 转写失败 | 乱码率突增 + 公式计数为 0 | 公式增强 + 低置信回填 |
| 页眉页脚混进正文 | 未做跑头剔除 | 重复行检查命中 | 预处理去页眉页脚；比对前两侧都剔 |
| 跨页段落被切断 | 分页即断句 | 检索命中但答案不全 | 切分阶段跨页合并；段落续接规则 |
| 图片引用存在但打不开 | 资源未落盘 / 路径变了 | 图片落地检查 | 校验 assets 目录；路径统一为相对 md |
| 引用页码跳错 | 页码锚点没注入或偏移 | 页码锚点正确率 | 解析阶段强制注入 `<!--page:n-->` |
| 数字被认错（0/O、1/l、5/S） | OCR 易混字符 | 关键字段专检（金额/文号/日期） | 业务关键字段单独正则复核，不等通用 CER |
| 竖排 / 旋转页内容错乱 | 页面方向未矫正 | 该页召回 ≈ 0 | 方向检测 + 旋转矫正后再识别 |
| 中文标点 / 全半角差异 | 后处理不统一 | 归一化后差异消失 | 归一化白名单，不计入错误 |

> 判断技巧：**"字量召回 ≈ 序列召回"说明顺序没问题；两者差距大而字量高，八成是栏序/跨页问题，不要去查 OCR。**

## 七、把校验变成日常（不然只做一次就废了）

1. **L0 当闸门常开**：每篇解析完成即跑自动闸门，FAIL 直接进待办表 + 告警，**不静默入库**。这正是 ownrag `validate_parsed` 步骤的职责，本目录工具是它的加强版（多出对账与报告）。
2. **参数即版本**：解析后端、预处理开关、识别语言、模型版本——任一变更，固定回归集先跑 L1/L2 再放量。
3. **阈值改动要有对照**：改阈值必须同时给出"改前改后同一批样本的通过率变化"，否则就是自欺。
4. **升级前后必比**：MinerU 升级（含模型权重变更）按"换 embedding"同等级对待——它同样会让下游悄悄变差。
5. **沉淀坏例**：每次人工抽检发现的错例归档成固定回归集，只增不减。这是唯一能让准确率长期上升的资产。

### 与 ownrag 现有设计的分工

| 层 | 位置 | 职责 |
|---|---|---|
| 轻量闸门 | `ownrag/steps.py` 的 `validate_parsed`（DSL 步骤） | 空 / 过短 / 页缺失 → 失败入待办，跑在管道里 |
| 深度校验 | 本目录 `check_parse_accuracy.py` | 水位 + 文本层对账 + 表格对账 + 报告，离线批量，可进 CI |
| 业务验收 | `ownrag/scripts/eval_recall.py` + 固定问答集 | 解析错误是否真的伤了召回 |

## 八、常见误区（每条都真实踩过）

1. **用 MinerU 自己校验自己**：同后端重跑比两次输出差异，只能证明非确定性，证明不了准确。
2. **只看总体准确率**：不拆桶等于隐藏了最差的那类文档。
3. **只看字符不看顺序**：多栏文档字量召回 99%、读起来完全不通。
4. **拿 precision 判好坏**：产出本来就该比文本层多。
5. **抽 3 篇就下结论**：样本量与置信区间的事，见 §五。
6. **让 LLM 当裁判当真值**：LLM 适合发现"段落串行、表格语义错位"这类结构性异常，但**不适合做字符级真值**（它会自己脑补通顺）。要用就固定 rubric、要求给出位置与原文对照，并用人工标注子集校准它与人的一致率。
7. **比对前不剔页眉页脚、不把表格文本算进正文**：这两个疏漏会让召回虚低 5-20 个点，然后你去改解析器——改错了方向。
8. **阈值直接抄互联网**：版式差异比模型差异大得多。

## 九、一页速查

```
这份 PDF 转得对不对？
├─ 先跑 L0（不需要真值）──────── 有 FAIL → 直接进待办，别往下看
├─ 有文本层吗？
│   ├─ 有 → 跑 L1 对账
│   │      ├─ 字量召回高 且 序列召回低 ──→ 顺序问题（多栏/跨页），切 VLM 或 XY-cut
│   │      ├─ 两者都低 ──────────────→ 真漏内容，看页级表定位哪页，重跑该页
│   │      └─ 两者都高 → 看 L2 表格
│   └─ 没有（扫描件）→ 跳过 L1，直接 L3 抽样人工；记录"无自动判据"这一事实
├─ 表格多吗？是 → L2 单元格召回 + 行列数一致性
├─ 上线/换后端？是 → L3 分层抽样人工 + L4 端到端召回回归
└─ 结论写在桶上，不写在"总准确率"上
```
