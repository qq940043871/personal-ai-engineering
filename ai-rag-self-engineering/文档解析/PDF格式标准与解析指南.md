# PDF 文档格式标准与解析完整指南

> 本文档整理自关于 PDF 格式标准与解析的系列问答，涵盖 PDF 的开放标准背景、文档整体结构、页面对象树、文本/图片/图形的判定方法、内容流中的全部原始操作符，以及实际解析策略与常见坑位。

---

## 一、PDF 是开放标准吗？

PDF 现在是 **ISO 维护的开放国际标准**，不是某个公司完全私有的格式。

| 时间 | 事件 |
|---|---|
| 1993 年 | Adobe 推出 PDF，并免费提供规范，开发者可以阅读和实现 |
| 2008 年 | PDF 1.7 成为 **ISO 32000-1:2008**，正式从 Adobe 专有格式转为开放标准 |
| 2017/2020 年 | PDF 2.0 以 **ISO 32000-2** 发布，不再依赖 Adobe 专有技术 |
| 2023 年起 | ISO 32000-2 规范已可**免费获取**，方便更多开发者实现 |

需要注意两点：

1. **开放 ≠ 完全无专利限制**：Adobe 仍持有部分与 PDF 相关的专利，但已提供免版税许可，前提是软件符合 PDF 标准。
2. **开放 ≠ 所有 PDF 子标准都完全一样**：PDF/A、PDF/X、PDF/E、PDF/UA 等是 ISO 定义的子标准，用途不同，获取方式也可能不同。

因此做 PDF 解析、生成或转换，完全可以基于公开规范开发，这也是 PyMuPDF、pdfplumber、pdfminer、PaddleOCR 等工具能存在的基础。

## 二、PDF 文档的整体结构

PDF 的"页"并不是像 Word 那样按行从上往下排，而是**以对象图 + 页面树的方式组织**。标准依据主要是 **ISO 32000**：PDF 1.7 对应 ISO 32000-1，PDF 2.0 对应 ISO 32000-2。

| 部分 | 作用 | 说明 |
|---|---|---|
| Header | 声明版本 | 例如 `%PDF-1.7` |
| Body | 存放对象 | 文本、图形、图片、字体、页面等都以对象形式存在 |
| Cross-Reference Table | 对象索引 | 记录每个对象在文件里的字节偏移，方便随机访问 |
| Trailer | 文档入口 | 指向根对象 `/Root`，也就是 Catalog |

阅读器打开 PDF 时，通常先看文件尾部的 `trailer`，找到 `/Root`，再顺着对象引用去读目录、页面树、页面内容。

## 三、"页"在对象树中的表示

```text
Catalog (/Type /Catalog)
 └─ Pages (/Type /Pages)        # 页面树根节点
      └─ Kids [...]             # 子页面树节点或页面对象
           └─ Page (/Type /Page) # 单页
                ├─ MediaBox      # 页面尺寸
                ├─ Contents      # 页面内容流
                ├─ Resources     # 字体、图片等资源
                └─ Rotate        # 旋转角度
```

关键点：

- **Catalog** 是文档根对象；
- **Pages** 是页面树节点，管理所有页面；
- **Page** 是真正的"一页"；
- 页面尺寸常用 **MediaBox** 表示，例如 `[0 0 595 842]` 接近 A4；
- 页面内容放在 **Contents** 流里，里面是绘制指令，不是普通纯文本；
- 字体、图片、颜色空间等资源放在 **Resources** 里。

### 为什么 PDF 解析比纯文本复杂

因为 PDF 的页面内容不是"一段文字"，而是：

- 文字、图形、图片、表格可能分散在不同对象里；
- 页面属性可以从父级 Pages 节点继承，比如尺寸、旋转；
- 同一个资源对象可能被多个页面共享；
- 扫描件里的文字甚至不是文本，而是图片，需要 OCR。

## 四、如何判断一页是图片还是纯文字

在 PDF 标准里，**没有"这一页是图片"或"这一页是纯文字"的标记**。要判断，只能看这一页里实际有哪些对象和操作符。

### 1. 从 Page 对象看

```text
Page (/Type /Page)
 ├─ MediaBox        # 页面尺寸
 ├─ Contents        # 页面内容流
 ├─ Resources       # 字体、图片等资源
 │    ├─ Font       # 文字相关
 │    └─ XObject    # 图片、Form 子流
 └─ Rotate
```

### 2. 判断文字：看 Font + 文本操作符

如果 `Page/Resources` 里有 `/Font`，并且 `Contents` 内容流里出现：

- `BT ... ET`：文本块
- `Tj` / `TJ` / `'` / `"`：真正画出文字的操作符

就说明这一页**有真实文字层**。

### 3. 判断图片：看 XObject /Image

如果 `Page/Resources/XObject` 里有某个对象：

```text
/Subtype /Image
```

并且 `Contents` 里用：

```text
/Im1 Do
```

引用它，就说明这一页包含图片。

### 4. 实际判断逻辑

| 情况 | 特征 | 判断 |
|---|---|---|
| 纯文字页 | 有 `/Font`，有 `Tj/TJ`，基本没有 `/Image` | 文字型 |
| 纯图片页 | 有 `/Image`，`Do` 引用大图，几乎没有文字 | 扫描/图片型 |
| 混合页 | 既有 `/Font` 又有 `/Image` | 图文混合 |
| 伪文字页 | 文字被转成矢量路径，没有真实字符 | 看起来像字，但程序抽不出文本 |

### 5. 用 PyMuPDF 快速判断

```python
import fitz

def classify_page(page):
    text = page.get_text("text").strip()
    images = page.get_images()
    font_count = len(page.get_fonts())

    has_text = len(text) > 20
    has_image = len(images) > 0

    if has_text and not has_image:
        return "text"
    if has_image and not has_text:
        return "image"
    if has_text and has_image:
        return "mixed"
    return "unknown"
```

更稳妥的做法是：**先看是否有字体和文本操作符，再看是否有 `/Subtype /Image`，最后再结合图片覆盖面积判断**。另外要注意，有些扫描 PDF 会叠加一层不可见 OCR 文本，所以"能抽到少量文字"不一定代表它不是图片页，最好同时看图片是否接近整页大小。

## 五、文字在 PDF 里怎么存：文本块与显示操作符

PDF 页面里有一块叫 **Contents 内容流**，里面是一串绘制指令。真正算"文字"的，必须同时满足两条：

1. 被 **`BT` / `ET`** 包起来；
2. 里面出现了 **`Tj`、`TJ`、`'`、`"`** 这类文本显示操作符。

比如：

```text
BT
/F1 12 Tf
100 700 Td
(Hello World) Tj
ET
```

这里：

- `BT` / `ET`：文本对象开始 / 结束；
- `/F1 12 Tf`：设置字体和字号；
- `100 700 Td`：把文字起点移到坐标 `(100, 700)`；
- `(Hello World) Tj`：真正画出文字。

### 判断"是不是文字"的硬规则

| 看哪里 | 出现什么 | 说明 |
|---|---|---|
| `BT ... ET` | 有 | 存在文本对象 |
| `Tj` / `TJ` / `'` / `"` | 有 | 真正绘制了文字 |
| `/Font` | 有 | 页面资源里有字体 |
| `/Image` + `Do` | 有 | 有图片对象 |
| `m/l/c/re/S/f` | 有 | 是矢量路径，不是文字 |

所以判断逻辑可以是：

```text
有 BT/ET + Tj/TJ → 有文字层
有 /Image + Do   → 有图片
有 m/l/c/re/S/f  → 有矢量图形
```

## 六、内容流中的全部原始操作符

除了 `Tj` / `TJ` / `'` / `"` 这几个"直接显示文字"的操作符，PDF 内容流里还有大量其他原始字符和操作符。

### 1. 文字相关操作符

| 操作符 | 作用 | 说明 |
|---|---|---|
| `BT` / `ET` | 开始 / 结束文本对象 | 所有文字操作必须在这之间 |
| `Tf` | 设置字体和字号 | 例如 `/F1 12 Tf` |
| `Td` / `TD` | 移动文本位置 | `TD` 还会同时设置行距 |
| `Tm` | 设置文本矩阵 | 控制旋转、缩放、倾斜 |
| `T*` | 移到下一行开头 | 依赖当前 leading |
| `Tj` | 显示字符串 | 最常见 |
| `TJ` | 显示数组字符串 | 可插入字符间距调整 |
| `'` | 换行并显示文本 | 等价于 `T*` + `Tj` |
| `"` | 设置间距、换行并显示文本 | 等价于 `Tw` + `Tc` + `T*` + `Tj` |
| `Tc` | 字符间距 | char space |
| `Tw` | 词间距 | word space |
| `Tz` | 水平缩放 | 百分比 |
| `TL` | 行距 | leading |
| `Tr` | 文本渲染模式 | 填充、描边、隐藏、裁剪等 |
| `Ts` | 文本上升 | 上标/下标效果 |

### 2. 图形与路径操作符

| 操作符 | 作用 |
|---|---|
| `m` | moveto，移动到路径起点 |
| `l` | lineto，画直线 |
| `c` / `v` / `y` | 贝塞尔曲线 |
| `h` | 闭合路径 |
| `re` | 画矩形 |
| `S` | 描边 |
| `f` / `F` | 填充 |
| `f*` | 偶数-奇数填充 |
| `B` / `B*` | 填充并描边 |
| `n` | 结束路径但不绘制 |

### 3. 图像与外部对象

| 操作符 | 作用 |
|---|---|
| `Do` | 绘制 XObject，比如图片或表单 |
| `BI` / `ID` / `EI` | 内联图像开始、数据、结束 |

图片一般出现在页面资源里：

```text
Page/Resources/XObject/Im1 → Subtype /Image
```

内容流里用：

```text
/Im1 Do
```

把它画出来。如果一页只有 `/Image` 和 `Do`，几乎没有 `BT/ET` 和 `Tj`，基本就是扫描页或图片页。

### 4. 图形状态与颜色

| 操作符 | 作用 |
|---|---|
| `q` / `Q` | 保存 / 恢复图形状态 |
| `cm` | 拼接变换矩阵 |
| `w` | 设置线宽 |
| `J` / `j` | 线端 / 线连接样式 |
| `d` | 虚线模式 |
| `g` / `G` | 灰度填充 / 描边 |
| `rg` / `RG` | RGB 填充 / 描边 |
| `k` / `K` | CMYK 填充 / 描边 |
| `CS` / `cs` | 设置描边 / 非描边颜色空间 |
| `SC` / `sc` | 设置描边 / 非描边颜色 |
| `SCN` / `scn` | 扩展颜色设置 |

### 5. 标记内容与兼容性

| 操作符 | 作用 |
|---|---|
| `BMC` / `EMC` | 标记内容序列开始 / 结束 |
| `BDC` / `DP` | 带属性的标记内容 |
| `BX` / `EX` | 兼容性段开始 / 结束 |

### 6. 解析时的归类速查

```text
BT/ET + Tj/TJ/'/"   → 文字
/Font + Tf           → 字体设置
/Image + Do          → 图片
m/l/c/re/S/f         → 矢量路径
BI/ID/EI             → 内联图片
q/Q/cm               → 坐标变换
g/rg/k/SCN           → 颜色
```

## 七、实际解析策略与常见坑

### 推荐解析路径

1. 先扫描 `BT/ET` 块；
2. 提取里面的 `Tj/TJ/'/"` 和 `Tf/Td/Tm`，还原大部分文本块的位置、字体和字号；
3. 遇到 `Do` 再去看 `Resources/XObject` 是不是 `/Image`；
4. 如果要把 PDF 里所有文本块、坐标、字体、字号都抓出来，可以用 PyMuPDF 的 `page.get_text("dict")`，它会直接给出 blocks → lines → spans → chars 的层级结构，比原始操作符好处理很多。

### 三个容易踩的坑

1. **矢量化的"伪文字"**：有些 PDF 看起来像字，但其实文字被转成了矢量路径，没有真实字符，程序抽不出文本；
2. **整页图**：整页就是一张图片（扫描件），需要 OCR；
3. **无 ToUnicode 映射**：字体没有 ToUnicode CMap 时，抽出来的是乱码。

所以最稳的判断方法是：**先看 BT/ET 和 Tj/TJ 是否存在，再看 /Image 和 Do，最后再结合图片尺寸判断它是不是整页图。**

### 快速选型建议（按场景）

| 场景 | 推荐方案 |
|---|---|
| 只想简单抽文字 | `pdfplumber` 或 `PyMuPDF` |
| 要提取表格 | `pdfplumber`、`tabula` |
| 扫描件转文字 | PaddleOCR / Tesseract / WPS OCR |
| 复杂 PDF 转 Markdown/JSON | MinerU、OpenDataLoader PDF |
| 构建知识库/RAG | 优先选能输出结构化 Markdown/JSON 的工具，并保留页码和坐标信息 |

**RAG / 知识库场景的切块建议**：

- 表格单独成块，不要拆散；
- 图片/流程图可生成文字描述；
- 页眉页脚、页码需要清洗；
- 每个块保留页码、章节、来源位置，方便溯源。

## 附：PDF 解析技术路线总览

| PDF 类型 | 特征 | 推荐路线 |
|---|---|---|
| 文字版 PDF | 能直接选中、复制文字 | PyMuPDF、pdfplumber、pdfminer 等 |
| 扫描版 PDF | 整页像图片，无法选字 | OCR：PaddleOCR、Tesseract、WPS OCR |
| 复杂版 PDF | 多栏、表格、公式、图表混排 | MinerU、OpenDataLoader PDF、Docling 等 |
