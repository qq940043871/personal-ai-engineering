# PDF 复杂页面与输出故障清单：都有哪些坑、怎么发现的

> 定位：`文档解析/` 系列的**故障分类册**——把「PDF 解析会踩哪些复杂页面」和「解析完内容为什么不能用」拆成可判定的条目，每条都给出**发现信号 → 处置动作 → 本仓库落点**。
> 口径：坏例分类来自教学场景（四类输入侧 bad case + 四类输出侧故障），本文只做工程化整理，**不声称任何真实项目已完成全部优化**；所有阈值均为 `【经验基线，需按自有语料校准】`。
> 一句话：**输入侧决定"能不能识别出来"，输出侧决定"识别出来的能不能用"**；两层混在一起排查，必然改错地方。

---

## 一、先分层：输入侧 bad case ≠ 输出侧故障

| 层 | 出问题的对象 | 典型症状 | 修复位置 | 改错了会怎样 |
|---|---|---|---|---|
| **输入侧**（页面 / 区域 / 资源） | 图像本身：方向、遮挡、模糊、服务不可用 | 该页没字、字错、字碎 | 预处理、换后端、重试策略 | 去调切块长度 / 换向量模型 = 完全无效 |
| **输出侧**（适配层 / 切分 / 索引） | 解析产物到入库之间的映射 | 重复、双份、标题丢、ID 变 | 适配层映射、去重、稳定 ID、回归 | 去重跑解析 = 结果一样，白烧算力 |

判断口诀：**症状在某一页的图里 → 输入侧；症状在"页与页之间/字段与字段之间" → 输出侧。** 方向类问题尤其典型：它发生在 OCR 之前，此时调分块或换 embedding 没有任何意义。

## 二、输入侧：四类复杂页面

### 2.1 页面方向 / 倾斜错误（整页级）

| 项 | 内容 |
|---|---|
| 表现 | 横向扫描件被当竖向处理：文本框大量缺失、整页退化成一张图、页级质量指标异常 |
| 为什么难 | PDF 的 `/Rotate` 与实际绘制方向可能不一致；一本书里混入横排表格页；扫描件带轻微倾斜（1°–3° 就足以让行切分错乱） |
| 发现信号 | ① 该页 `get_text()` 几乎为空，但 `get_images()` 有整页大图（= 整页图页）；② 抽样页平均字符数极低（`probe_pdf` 口径：每页 <50 字符判扫描件倾向）；③ `content_list.json` 里该 `page_idx` 只有 `image`、没有 `text`；④ 文本框 bbox 宽高比与内容方向矛盾（文字行按 90° 排列） |
| 处置 | 先做方向矫正 / 纠偏，再进识别；单页重跑可换后端；**判定错要允许人工改判重跑**（该慢的没慢、该准的不准，两头不讨好） |
| 落点 | `ai-rag-dify/01-minerU-block/00b_mineru_pdf_parse.py`（`probe_pdf` 页级路由、`-b vlm`）；`03-解析管道` §2.2 四层增强第 1 条；方法论 §六「竖排/旋转页内容错乱」 |

### 2.2 印章 / 水印 / 污渍遮挡正文（区域级）

| 项 | 内容 |
|---|---|
| 表现 | 印章压在字上 → 字符被拆成碎片或认错；浅色水印被当成正文**反复识别**，同一行在每页重复出现 |
| 为什么难 | 遮挡是**局部**的：整页其他文字都对，唯独压章那几行废掉；增强（去噪/提高对比度）能救字，也能吃掉细笔画 |
| 发现信号 | ① 重复行检查命中（浅色水印的典型指纹，同一短行 ≥N 次）；② 抽出的"文本块"是单字碎片、无词法结构，且与该区域图片重叠面积大；③ 关键条款页整体正常但个别字段（金额/编号）缺失；④ 人工抽检时"读得通但读不对" |
| 处置 | **保留原图**；先判"遮挡是否压到关键内容"（金额、编号、条款号、勾选区），没压到就不必动。要做图像增强就去噪/对比度/纠偏，但必须用样本验证效果，并**把增强版与原版两份都留、指标分开报**——处理后的结果不能直接当事实 |
| 陷阱 | 把增强结果当唯一真相 → 事后无法解释"为什么这行字和原件不一样"；只报总平均分 → 覆盖不了局部退化 |
| 落点 | `00b` 的 `--dedup-repeat`（重复短行按页眉/页脚删除，默认 ≥5 次）；`校验准确/check_parse_accuracy.py` 的 `max_dup_line_run`；`09_quality_gate.py` A 层「页眉页脚残留 <1%」 |

### 2.3 关键编号 / 选项框局部不可靠（字段级）

| 项 | 内容 |
|---|---|
| 表现 | 整页质量指标很好看，但金额、编号、勾选框、日期这类关键字段恰好模糊 |
| 为什么难 | 页级平均分**天生盖不住局部**：99% 的字符对，也可能把 `0` 认成 `O`、把 `8` 认成 `3`；而这类字段一旦错，下游答案就是错的 |
| 发现信号 | ① 关键字段专检（正则：金额、文号、日期、条款号、`☑/■/√`），不靠通用 CER；② **多来源比对**：md 正文 / `content_list` 的 text / 原图裁剪 → 三者不一致即打待复核；③ 同一页用两个后端或两个渲染 DPI 各跑一次，结果不一致处优先人工看 |
| 处置 | 无法确认的字段**保留候选 + 原图裁剪 + 页码/坐标**，标"待复核"；**禁止自动挑一个"看起来最像"的答案**补齐 |
| 落点 | `03-解析管道` §2.5 解析复核闸（`report.json` 页级明细 + `pending` 状态机）；方法论 §六「数字被认错（0/O、1/l、5/S）」 |

### 2.4 页面极模糊 / 识别服务失败（资源级）

| 项 | 内容 |
|---|---|
| 表现 | 分辨率过低、传输超时、服务 5xx/限流、文件损坏、版面类型不支持（纯手写、乐谱、极端竖排） |
| 核心动作 | **先分类，再决定重不重试**——把"可重试"和"确定性失败"混在一起重试，只会烧掉额度并掩盖原因 |

| 失败类型 | 是否重试 | 具体动作 |
|---|---|---|
| 网络超时 / 5xx / 临时限流 | 是（有限） | 指数退避，上限 2–3 次；超时阈值按页数放大 |
| OOM / 显存不足 | 是（换条件） | 降并发、分批（`-s/-e` 页区间）、换 pipeline 后端 |
| 低分辨率（提高 DPI 后仍有字） | 是（受控一次） | 渲染 DPI 150 → 300 重跑，比较两次结果再定 |
| 文件损坏 / 页对象坏 / 加密 | 否 | 立即终止，记录原因，进人工复核 |
| 严重模糊（提 DPI 仍无字） | 否 | 终止重试，标"不可解析"，人工换源或补扫 |
| 每日额度耗尽（开放平台 `code=-60018`）、单文件 >200 页/200MB | 否 | 终止并改走本地 CLI 或分批 |

| 项 | 内容 |
|---|---|
| 发现信号 | 异常分类计数 + 重试计数落库；页覆盖 <1、空页率 >2%、`failed` 状态集中出现 |
| 落点 | `03-解析管道` §2.4 兜底链（VLM↔pipeline 互换 → `parse_pymupdf` 纯文本 → `fail` 入待办）；`00b_mineru_pdf_parse.py --fallback pymupdf` 与 `--mode open` 的错误码语义 |

## 三、输出侧：四类故障（都发生在识别之后）

### 3.1 同一段文字被写入两次

| 项 | 内容 |
|---|---|
| 两种来源 | ① **MinerU 自身多字段**：同一区域在 `content_list` 的 `text` 与 md 正文里各出现一次；② **适配层重复映射**：重叠块被处理两遍、跨页段落两端各拼了一次 |
| 发现信号 | 用**坐标 + 内容指纹**双判据：同 `page_idx` 且 bbox IoU > 0.9 且规范化文本相等 → 同源重复。没有坐标时退化为块级 shingle（如 32 字滑窗）在同文档内命中 ≥2 次且页码相邻/重叠 |
| 陷阱 | "看着重复就删" —— 跨页**续表**是合法的重复形态，必须标 `continuation` 而不是删掉；目录页与正文首段也可能真的重复 |
| 处置 | 合并为一条，保留来源字段（`from: content_list.text / md_body`）便于回溯；入库前对 (doc_id, page, bbox) 做唯一约束 |
| 落点 | `校验准确/check_parse_accuracy.py` 的重复行/块检查；`09_quality_gate.py` B 层「体量分布 p95」异常偏高是重复的间接信号 |

### 3.2 表格同时出现结构化内容和扁平文本

| 项 | 内容 |
|---|---|
| 表现 | 同一张表在产物里有两份：HTML/Markdown 结构化表格 + 一串被拍平的文本 |
| 发现信号 | 同一 `page_idx` 上 `table` 块 bbox 与相邻 `text` 块 bbox 高度重叠，且 text 内容 ≈ 表格单元格按行拼接（Token 级 Jaccard 高） |
| 关键决策 | 这不是"二选一删掉一份"，而是**同一证据的两种视图**：结构化表用于切分/展示/取数，扁平文本用于检索召回 |
| 入库纪律 | 两份必须共用同一个 `evidence_id`；否则 rerank 之后同一张表占满 top-k 的多个坑位，用户看到"三条独立证据"，其实是一条 |
| 落点 | `03-解析管道` §一 `ParsedDoc.structures`（结构清单 + 指针）；方法论 §六「表格错行 / 丢列」「表格整体变成图片」 |

### 3.3 解析器升级后标题路径消失

| 项 | 内容 |
|---|---|
| 表现 | 升级 MinerU 后 md 里 `#/##` 明显变少，切出来的块失去标题语境（Dify 侧表现为"分段没有上下文"） |
| 根因 | 新版本换了字段名或层级载体（如标题从 `content_list.text_level` 迁到别的结构），**适配层没识别 → 全部降级成普通段落**。注意这不一定是"识别变差了" |
| 发现信号 | ① **固定输入回归**：同一批坏例在升级前后各跑一次，比「H1/H2/H3 计数」与「目录对齐率」；② 字段级 diff：对同一 PDF 的新旧 `content_list.json` 比 `type` 集合增删；③ 症状分流：md 有内容但无 `#` + content_list 里仍有标题字段 = 适配问题；两处都没了 = 识别问题 |
| 处置 | 在适配层加**版本映射**（`parser_version → field_mapping`），用固定输入回归验证；**不要在切分器里加临时兼容判断**——那等于把解析问题藏到下游，下次更查不出来 |
| 落点 | `09_quality_gate.py` A 层「目录对齐率 ≥90%（无书签 SKIP）」是最硬的判别指标；方法论 §七「升级前后必比：MinerU 升级按换 embedding 同等级对待」 |

### 3.4 同一页面重跑后所有 ID 都变

| 项 | 内容 |
|---|---|
| 表现 | 重跑一次，`chunk_id`/块 ID 全变 → 索引里新旧两份并存、增量更新失效、引用链接失效 |
| 根因 | ID 依赖数组下标/顺序、时间戳、随机 UUID；而页内块顺序会因并行、模型非确定性而变化 |
| 发现信号 | **幂等测试**：同一输入强制重跑 N 次，比 ID 集合——未变化内容必须 ID 相同。再拆解 ID 组成逐个置空，定位到底哪个字段不稳定 |
| 处置 | ID = f(规范化内容指纹 + 稳定位置)，**不依赖顺序**；内容真变的那部分生成新版本（`version` / `valid_from`），旧版本标 `superseded`；替换条件用 `evidence_id + content hash` |
| 落点 | `03-解析管道` §五「幂等键 `doc_id+step`、重跑不产生重复索引」；§1.1「版本指纹（内容 hash）」 |

## 四、怎么发现的：五条通用发现路径

| 序 | 路径 | 发现什么 | 具体手段 | 本仓库工具 |
|---|---|---|---|---|
| 1 | 抽样探测（解析前） | 扫描件/方向错/多栏/无书签 | 抽 3 页量文本层字符数、看 `get_toc()`、算图片覆盖率 | `00b_mineru_pdf_parse.py` 的 `probe_pdf`；`03` §2.1 `detect_pages` |
| 2 | 水位闸门（无需真值） | 空页、乱码、重复行、页覆盖、结构缺失、图片掉链 | 纯规则统计，秒级/篇，FAIL 直接进待办 | `09_quality_gate.py` A 层；`check_parse_accuracy.py` L0；`validate_parsed` |
| 3 | 对账（有真值才准） | 真漏内容 vs 顺序错乱、表格错行 | 文本层字符召回 + 字量召回，**两者差值 = 顺序信号**；表格单元格召回 | L1/L2；`09` A 层「字符保真度 / 目录对齐率」 |
| 4 | 差异定位（定位到页/块/字段） | 到底哪一页哪一块坏了 | `content_list.page_idx` + bbox；页级薄弱点表 | `report.json`；`check_parse_accuracy` 页级表 |
| 5 | 回归与幂等（变更前后） | 升级是否变差、重跑是否稳定 | 固定坏例集 + 升级前后 diff + 重跑 ID 比对 | `05-评测运维与路线图`；`校验准确` 的坏例沉淀 |

**四条判据纪律**（比指标本身更重要）：

1. **页覆盖 <1 一律 FAIL**——比任何平均分都硬，少一页就是丢了内容。
2. **字量召回高而序列召回低 → 查栏序/跨页，不要查 OCR**；两者都低才是真漏。
3. **页级平均分不能替代局部判断**——关键字段必须回到"该字段的文字框 + 候选字符 + 原图"三件套。
4. **分桶报数，不报总平均**（`electronic / scan / multi_col / nested_table / formula / mixed`）；一个 97% 的总平均可以藏着"嵌套表 60%"。

## 五、想发现故障，先落盘这些证据

| 要发现的问题 | 必须先落盘的证据 |
|---|---|
| 重复写入 | 页码 + bbox + 规范化文本 + **来源字段名** |
| 表格双形态 | `evidence_id` + 区域坐标 + 两种表示（结构 / 扁平）各一份 |
| 标题路径丢失 | `parser_version` + 原始 `content_list.json` 副本 + 结构计数（H1/H2/H3） |
| ID 漂移 | ID 组成拆解 + 重跑记录（同输入 N 次） |
| 局部字段不可靠 | 原图裁剪 + 候选字符集 + 页码/坐标 + 复核状态 |
| 方向/遮挡/模糊 | 页级 `get_text()` 字符数 + 图片覆盖率 + 预处理参数 + 异常类型标签 |

> 这正是"后处理不该只剩一个统一清洗函数"的原因：**清洗函数没有入口、没有证据、没有回归样本**，出问题时无法回答"这条内容从哪来、为什么被改、改前是什么"。可运维的形态是**故障处理链**：每个故障类型有独立入口（判据）、独立证据（坐标/字段/版本）、独立回归样本（坏例集只增不减）。

## 六、速查清单

| # | 类别 | 检查项 | 判据 | 失败动作 |
|---|---|---|---|---|
| 1 | 方向 | 该页文本框数 vs 图片覆盖率 | 文本框≈0 且整页图 | 方向矫正后重跑；换 VLM |
| 2 | 方向 | 文本行 bbox 方向与页面一致 | 行方向 90° = 异常 | 同上 |
| 3 | 遮挡 | 重复短行 | 同短行 ≥5 次（或连续 ≥3） | 去页眉/水印；人工看是否压关键内容 |
| 4 | 遮挡 | 碎片化文本块 | 单字块占比突增 | 保留原图，标记待复核 |
| 5 | 字段 | 关键字段专检 | 金额/编号/日期/勾选 正则全中 | 保留候选 + 原图，进复核 |
| 6 | 模糊 | 空页率 / 页覆盖 | ≤2% / =1.0 | 单页重跑；确认不可解析则终止 |
| 7 | 服务 | 失败类型分类 | 可重试 vs 确定性 | 有限重试 / 立即终止并记录原因 |
| 8 | 重复 | 同 bbox + 同文本 | IoU>0.9 且文本相等 | 合并，保留来源字段 |
| 9 | 双形态 | table 块与 text 块重叠 | bbox 重叠 + 内容 Jaccard 高 | 同一 `evidence_id`，分用途消费 |
| 10 | 结构 | H1/H2/H3 计数、目录对齐率 | 升级前后不应下降；对齐率 ≥90% | 适配层加版本映射 + 固定输入回归 |
| 11 | 幂等 | 重跑 ID 集合 | 未变内容 ID 不变 | 改 ID 生成规则，弃用下标/时间戳 |
| 12 | 全局 | 乱码率 / 图片掉链 / 围栏配对 | <0.1% / 全可打开 / 偶数 | 进待办，不静默入库 |
