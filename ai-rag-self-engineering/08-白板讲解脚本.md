# 08 · 白板讲解脚本（5 分钟版）

> 用途：面试现场手绘两条链路的时序，每写一步都能指到代码。
> 配套：`07-面试问答卡片.md`（被追问时切卡片答）。
> 口径：只画**已实现**的部分；未实现的用一句话带过，不画进图里。

---

## 〇 · 上白板前的三件事

**1. 先分区，再画流程。** 不要从头画到尾，那样画到一半就没地方了。

```
┌─────────────────────────┬─────────────────────────┐
│  ① 写路径（离线 / 批）    │  ② 读路径（在线 / 请求）  │
│  上传 → 解析 → 切分 → 索引 │  检索 → 重排 → 闸门 → 生成 │
│        （慢、可重跑、可人工）│      （快、要延迟、要拒答）│
├─────────────────────────┴─────────────────────────┤
│  ③ 存储层：SQLite（chunks / FTS5 / 任务 / trace）+ Chroma │
└───────────────────────────────────────────────────┘
```

**2. 符号约定**（讲之前先声明，省得对方看不懂）：

| 符号 | 含义 |
|---|---|
| 矩形 | 一个模块 / 一个步骤 |
| 菱形 | **闸门**（判定，有拒绝出口） |
| 实线箭头 | 正常流转 |
| 虚线箭头向下 | **失败出口**（降级 / 待办 / 拒答） |
| 双线框 | 人工介入点 |

**3. 开场那句定场的话**（20 秒）：

> "这个系统我按'写读分离'来设计：左边入库是批处理，慢、可重跑、可以停下来让人看；右边问答是请求响应，快、要控延迟、要敢拒答。两边唯一的契约是同一张 chunks 表和同一个向量 collection——所以换解析器不动检索，换模型不动管道。"

## 一、0:00–0:40 · 一句话定位 + 画分区

**白板写**：上面那张三分区图（只画框，不画细节）。

**口述**：
> "技术栈是 Python + FastAPI，不用 Dify 也不用 LangChain。五层：接入层是 FastAPI 的几组路由，编排层是 YAML 管道 DSL 加步骤注册表，管道层是解析/索引/检索/生成四组模块，模型层是云-本地可切的端点注册表，存储层是 SQLite 加嵌入式 Chroma。今天只讲两条主链路，其他都是这两条链上的零件。"

**代码锚点**（被问"五层在哪"时指）：
`ownrag/ownrag/main.py:40-54`（路由注册）、`ownrag/ownrag/configs/pipelines.yaml`（编排）、`ownrag/ownrag/api/routes_docs.py` + `routes_chat.py`（接入）

## 二、0:40–2:40 · 写路径：一份 PDF 从上传到入库

**总时长 2 分钟，8 步，每步 15 秒。** 顺序不要变，因为这就是 YAML 里的顺序。

### 白板序列

```
[POST /docs/upload]
      │ ① 校验：扩展名→管道、kb 白名单、分块落盘+体积上限
      ▼
[任务表 pending]───►(后台线程)───►[run_pipeline 循环]
                                        │
        ② detect_pages ◄────────────────┘   抽样判版式：电子版→pipeline / 扫描→vlm
              │
        ③ parse_mineru ──失败──► 换 backend ──失败──► parse_pymupdf ──失败──► 待办表
              │ 产出 ParsedDoc（markdown + metadata + structures + assets）
        ④ validate_parsed   ◆ 空/过短 → 与解析失败同待遇
              │
        ⑤ chunk_markdown    表格永不跨块；块头注入"标题 > 章节路径"
              │
        ⑥ prepare_review    ══ 人工闸 ══ 落盘 parsed.md / chunks.json / report.json
              │
        ⑦ review_gate       ◆ pending / rejected → 索引一步都不跑（任务 failed + 待办）
              │ approved
        ⑧ embed → index_upsert   双通道：SQLite chunks+FTS5 / Chroma；按 doc_id 先删后插
```

| 步 | 白板写 | 讲什么（照念） | 代码 |
|---|---|---|---|
| ① | 上传框 | "上传先过三道校验：扩展名映射到管道、kb 必须在 `apps.yaml` 里声明过、文件分块落盘并计体积上限，超限立刻删半截文件。" | `api/routes_docs.py:46-87`、`:29-43` |
| ② | 任务表 + 后台线程 | "建任务行是 pending，扔进后台线程执行。这里有个细节：后台执行体用**独立连接**，因为 SQLite 连接不是线程安全的。" | `routes_docs.py:145-156`、`core/tasks.py:12-22` |
| ③ | 循环 + checkpoint | "执行器只做四件事：每步开始前把黑板序列化到任务表当检查点、跑步骤、失败按 fallback 链再试、全败入待办。所以进程挂了重跑走同一个入口，按 current_step 续跑。" | `core/pipeline.py:31-117`、`:84-93` |
| ④ | MinerU + 虚线 | "MinerU 解析先做页级路由：抽 3 页数文本层字符数，有文本走 pipeline 后端，几乎没文本判扫描件走 VLM。真失败了走 fallback 链换 backend，再不行 PyMuPDF 纯文本兜底——**结构丢了但内容要在**。" | `ingest/pdf_mineru.py:18-45`、`:140-171` |
| ⑤ | 契约框 | "三条链路（PDF / 音视频 / Excel）都收敛到同一个 `ParsedDoc`：正文、元数据、结构清单、产物指针。锚点在解析层就固化，下游不感知来源差异。" | `ingest/base.py:19-40` |
| ⑥ | 校验菱形 | "第一道自动闸：空 Markdown、字符密度过低，和解析失败同待遇。" | `index/chunker.py:171-182`、`ingest/base.py:34-40` |
| ⑦ | 切分框 | "结构感知切分：先按标题拆段，表格整段不切，超长段独立成块；块头注入'文档标题 > 章节路径'，因为裸块缺主语会召回漂移。" | `index/chunker.py:30-134` |
| ⑧ | **双线框人工闸** | "**这是我最想讲的一步**。解析是整条链路最不可控的一段，而'错在解析'在问答阶段几乎查不出来——答案不对你只看到召回块很怪，看不到那一页本来就没解析出来。所以在切分之后、写索引之前停一下，把三份工件落盘给人看：解析全文、切分预览、质量报告。pending 或 rejected 时索引步骤一次都跑不到，不是提示，是直接 fail。" | `review.py:1-19`、`:279-297`、`:67-140` |

### 这一步的失败出口（用手指着虚线说）

> "这条链上每个失败点都有出口：解析失败走降级链穷尽后进待办，校验不过进待办，复核 pending 进待办，向量不可用显式降级。**没有静默丢文档这个选项**——原则叫'失败可见'。"

## 三、2:40–4:20 · 读路径：一次提问从检索到答案

**总时长 1 分 40 秒，9 步。** 这一步的讲法是"每步都在为一个失败场景服务"。

### 白板序列

```
[POST /chat]  → 取 app 配置（模板：模型+检索参数+Prompt+闸门开关）
      │
 ① 直击库 match ──命中──► hit + done（零检索零生成）──► 结束
      │未命中        L0 精确/别名 → L1 余弦≥0.86 → L2 沉淀
      ▼
 ② 混合检索 hyb ── FTS5(BM25) ─┐
      │            embed+向量 ─┴─► RRF 名次融合（k=60，等权）
      │  降级：向量不可用 → BM25 单路 + gate(retrieval_degraded)
      ▼
 ③ rerank ── 未配置/服务挂 → RRF 顺序兜底（说明进 trace）
      │
 ④ ◆ 闸门一 sufficiency_check ──不足──► no_evidence + done（零模型消耗）
      │通过
 ⑤ 上下文预算 fit ── num_ctx - prompt开销 - 输出预留 - 64 ──► 超了按序丢尾块
      │              （下发 gate(context_budget)）
 ⑥ candidates = ctx.blocks    ★ 闸门二与引用只认模型真正看到的块
      │
 ⑦ 流式生成（SSE token）
      │
 ⑧ ◆ 闸门二 citation_check ──违规──► 带反馈重答一次 ──仍违规──► 按规则拒答
      │通过
 ⑨ done(citations) + trace + qa_log
```

### 逐句台词 + 代码位置

| 步 | 白板写 | 讲什么（照念） | 代码 |
|---|---|---|---|
| ① | 直击库框 | "高频题不进 RAG。L0 是标准问加别名的精确匹配，L1 用 embedding 余弦按 0.86 阈值，L2 是沉淀候选。设计理由一句话：**直击库答错比 RAG 答错更伤信任，因为它看起来最权威**。" | `retrieve/direct_hit.py:25-60` |
| ② | 双路 + RRF | "向量和 BM25 双路各取 20，用 RRF 融合：`Σ 1/(60+rank+1)`。**只比名次不比分数**——余弦和 BM25 的量纲不可比，归一化怎么做都是猜；等权是因为没有评测集之前调权重就是盲人摸象。" | `retrieve/hybrid.py:17-28`、`:31-58` |
| ②注 | 降级虚线 | "中文这块有个必踩的坑：FTS5 的分词器不切 CJK，整段中文被当成一个 token，中文查询必然零召回。所以自己做了字符化，而且索引侧和查询侧必须同一个函数。" | `index/store.py:21-74` |
| ③ | rerank 框 | "重排是可选的。没配服务就退回 RRF 顺序，并且把降级说明写进 trace——不静默。另外 Ollama 本身没有 rerank 端点，本地档是走 reranker GGUF 的 embed 接口拿一维标量分，输出不是一维就显式报错降级。" | `retrieve/rerank.py:25-33`、`:94-123` |
| ④ | **闸门一菱形** | "生成前的纯代码闸门。这里有个很关键的认知变化：**向量通道一开，检索层永远捞得回语义邻近的块**，零召回几乎不会发生了，所以拒答语义必须从'零召回'迁移到'重排分不足'。阈值 0.05 是评测集校准出来的：相关块 0.9 以上，语义邻近的无关块接近 0。" | `generate/gates.py:17-50` |
| ⑤ | 预算框 | "`num_ctx` 是输入加输出的总窗口，超窗时 Ollama 静默截断——最坏情况先被截掉的是**问题本身**。所以预算显式算：窗口减 prompt 开销减输出预留减安全余量，超了按序丢尾块，丢了哪些通过事件下发。" | `generate/budget.py:18-39`、`api/routes_chat.py:101-122` |
| ⑥ | ★ 标记 | "这行赋值很关键：候选池要换成 fit 之后的块。否则模型引用了被预算裁掉的块，校验还认为合法。" | `api/routes_chat.py:220` |
| ⑦ | 生成框 | "SSE 流式，事件契约固定：hit / ctx / token / gate / no_evidence / done / error。**事件顺序是产品契约**，重构不许调。" | `api/routes_chat.py:1-15`、`:178-255` |
| ⑧ | **闸门二菱形** | "生成后逐行核验三件事：引用的块编号必须在候选池里；这一行里的每个数字和日期必须能在它引用的块原文找到；有数字但没引用直接算违规。确定性的事不交给模型。" | `generate/gates.py:54-89` |
| ⑧补 | 修复分支 | "违规就带反馈重答一次，但**只有通过了或者违规数变少才采纳**；修复请求本身失败就按规则拒答原答案。不能因为重答读起来顺就采纳。" | `routes_chat.py:131-153` |
| ⑨ | 落库 | "最后写 trace 和 qa_log——qa_log 是评测集扩充和直击库回流的唯一原料，不是日志垃圾。" | `routes_chat.py:65-73`、`core/trace.py:27-45` |

### 收口那句（一定要说）

> "注意这两条链路**没有互相调用**：入库只写存储，问答只读存储。所以我可以一边重灌索引一边继续回答旧问题，也可以把解析器整个换掉而不碰检索——这就是'写读分离'在这个项目里的实际收益。"

## 四、4:20–5:00 · 收尾三句

按这个顺序说，别乱：

1. **取舍**（10 秒）
   > "最大的取舍是**放弃可视化编排换可 Git 版本化的 YAML**，放弃知识库界面换没有黑盒。代价是页面壳要自己写，收益是管道变更可以走 diff 和 review。"

2. **诚实**（15 秒）
   > "没做完的说清楚：`apps.yaml` 里 `rerank.enabled` 和闸门的 `pre/post` 目前只是声明意图，实际由环境变量和代码固定顺序决定；聚合类问题的 SQL 路径、元数据级权限、任务队列都还在待办。代码里只有知识库级白名单，**不要把它当权限体系**。"

3. **钩子**（10 秒）
   > "如果继续做，我会先把权限过滤从 Prompt 挪到检索前——先过滤后召回，而不是让模型自己不去看没权限的块。"

## 六、纯口述版（没有白板时的 90 秒）

> "系统分写读两条链路。写链路是：上传校验后建任务进后台，执行器按 YAML 步骤串行跑，每步前落检查点、失败走 fallback 链、全败入待办——PDF 是页级路由加 MinerU 解析、再不行 PyMuPDF 兜底，产出统一中间态，然后结构感知切分，**在写索引前停一道人工复核闸**，approved 才双通道写入 SQLite 和 Chroma。读链路是：直击库先拦高频题，否则向量加 BM25 双路 RRF 融合、可选重排、生成前一道闸门判候选够不够、再算上下文预算、流式生成、生成后一道闸门核验引用和数字、违规带反馈重答一次。两条链路只通过存储相接，所以换解析器不动检索、换模型不动管道。"
